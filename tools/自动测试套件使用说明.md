# 自动测试套件使用说明

`run_full_test.py` 一键跑完整套工程验收测试（对应测试纪要 `docs/六轴机械臂测试纪要_2026-08-17.md` 第 1 层），并自动生成 Markdown 报告。

## 前置条件

1. 机械臂已上电、USB 已连接（COM 口正确）
2. **关闭串口助手**（否则打不开串口）
3. Python 环境（pyserial）已备好

## 运行

```cmd
# 完整测试（3 轮往返，推荐）
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe ^
  "C:/Users/Administrator/Desktop/ArmControl_HAL（1）/tools/run_full_test.py" ^
  --rounds 3 --outdir "C:/Users/Administrator/Desktop/ArmControl_HAL（1）/docs"

# 快速验证（1 轮，约 3-4 分钟）
... run_full_test.py --rounds 1 --outdir "C:/Users/Administrator/Desktop/ArmControl_HAL（1）/docs"

# 指定串口
... run_full_test.py --port COM8 --outdir "C:/Users/Administrator/Desktop/ArmControl_HAL（1）/docs"
```

## 测试项

| 项 | 内容 | 判据 |
|----|------|------|
| T1 冒烟自检 | `n`/`i`/`t a 1`/`T` | 总线、初始化、扭矩、温度全 OK |
| T2 IK 精度 | 4 个目标点 `g`+`f` | ΔPos ≤ 5 mm |
| T3 整臂往返稳定 | P0↔g100 往返 N 轮，到位后测 6 关节 | 每关节 avg std < 0.3° |
| T4 回竖直稳态 | g100 回 P0 后测 J2/J3 | J2/J3 std < 0.3° |

## 输出

- 控制台打印汇总
- 报告：`docs/测试结果_YYYYMMDD_HHMMSS.md`
- 每次运行生成一份独立报告，带时间戳

## 参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `--port` | COM8 | 串口号 |
| `--rounds` | 3 | T3 多轮往返轮数 |
| `--outdir` | docs | 报告输出目录 |

## 注意事项

- 固件 `n` 扫描、`i` 初始化会**阻塞主循环**且较慢，T1 耗时约 40-50 秒属正常。
- 测试过程中机械臂会实际运动，请确保工作空间无障碍物。
- 运动过程中的串口读数不可靠（STS3215 总线污染），本套件的稳定性指标测的是**到位后稳态**（到位后等待 1.5s 再测），不是运动瞬时。

# 全指令遍历测试（`test_all_commands.py`）

和上面的 `run_full_test.py` 是**互补**关系：

| | `run_full_test.py` | `test_all_commands.py` |
|---|---|---|
| 考什么 | 精度与稳定性（同一组动作重复 N 轮） | **覆盖面**（38 条网口二进制 + 114 条控制台文本，一条不落） |
| 判据 | ΔPos ≤ 5 mm / std < 0.3° | 每条命令是否有正确响应（含"闸门拦截是否生效"） |
| 会动吗 | 会，大幅运动 | 默认不动；motion 档也只做**原地回写** |

## 只测不改（重要）

命令按副作用分四档，**只有前两档会真的下发**：

| 档 | 含义 | 是否下发 |
|----|------|----------|
| `read` | 纯查询，零副作用 | ✅ 默认就跑 |
| `motion` | 会动电机，但参数取「读回当前值再原样写回」⇒ 不产生位移 | 需 `--level motion --i-know-it-moves` |
| `write` | 改运行期参数 / 落 Flash / 烧 EEPROM | ❌ **代码里没有执行路径**，只进报告 |
| `forbidden` | 改量纲基准 / 松力矩 / 卡死主循环 / 抢引脚 | ❌ 同上 |

`config/arm_config.json` 里登记的 114 条只要有一条没被脚本分级，就会按 `forbidden` 列出并标"⚠ 未分级"
（fail-safe：宁可漏测，不可错动）。报告开头会打**文本覆盖率**。

## 三种后端

```cmd
# ① 离线内存假臂（无需硬件）—— 只能测 38 条二进制
py -3 tools/test_all_commands.py --plan          # 先看清单，不下发
py -3 tools/test_all_commands.py                 # read 档

# ② 真机网口（需板子跑 NET 固件）—— 二进制走原生帧，文本走 TEXT_EXEC（113/124）
py -3 tools/test_all_commands.py --host 192.168.7.120

# ③ 真机串口裸文本 —— 像人在 COM11 上敲键，唯一覆盖全部 124 条文本的路径
py -3 tools/test_all_commands.py --serial COM11

# 附：出报告
py -3 tools/test_all_commands.py --serial COM11 --md outputs/命令测试.md --json outputs/命令测试.json
```

⚠ **离线跑文本命令没意义**：`arm_sdk/sim.py` 的文本解释器只覆盖自检用到的少数几条
（`s`/`h`/`zi`/`lk`/`f` + 闸门子集），其余会标 `SKIP ... 需真机`。要看 114 条文本的真实回显，必须上板。

## 结果怎么读

| 状态 | 含义 |
|------|------|
| `PASS` | 有正确响应 |
| `PASS*` | 无输出但属于"静默成功"；或**该被拦却没被拦**（构建差异，需人工确认） |
| `GATED` | 被固件闸门/抢引脚拦截 —— 对 `c` 和 11 条抢引脚命令而言这是**预期正确行为** |
| `SKIP` | 前置读数不可用 / 后端不支持 / 未分级，附原因 |
| `LISTED` | 按「只测不改」要求未下发，附原因 |
| `FAIL` / `TIMEOUT` | 真正的问题，退出码为 1 |

## 注意事项

- `--level motion` 之前：臂周围无人、E-Stop 可及、已回中位（`m 180 180 180 180 180 180 15`）。
- **绝不用 `M a` 回中位** —— 那是标定，会废掉量纲基准；本脚本已将它列入 forbidden。
- 真机跑之前先看报告开头的**预检**（`GET_INFO` 的 fw-tag）确认板子上是哪一版固件。
- 急停中固件只放行 `s`/`h`，其余会进 `GATED`，这是白名单行为不是故障。
