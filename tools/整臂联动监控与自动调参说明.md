# 整臂联动 自适应修正监控 + PID 自动调参工具

`tools/arm_auto_tune.py`

## 它解决什么问题

你要的是：**6 个舵机同时运行（m 命令联动），检测每个舵机的运行情况，自动调节 PID，让每个舵机都平稳、准确地到位，且尽量减少自适应修正的轮数。**

固件本身已经内置了这个机制（`m` 命令 → S 曲线 → 多关节自适应修正 J2/J3/J4，每 500ms 一轮自动调 PID）。本工具就是**围绕这个现有流程做监控 + 自动扫参**，让你能看到每个舵机的表现并选出最优 PID。

## 核心能力

| 能力 | 说明 |
|------|------|
| 整臂联动 | 发送 `m J1..J6 [v]`，6 个舵机同时运动 |
| 多路实时采集 | **逐个 `p J` 轮询读取 6 个舵机角度**（单点读可靠，规避 pv 连续读丢帧） |
| 修正日志解析 | 识别每轮修正、到位/超时、过冲/停滞、PID 自动调节 |
| 统计报表 | 每个舵机的修正轮数、最终误差、到位状态、PID 被调了几次 |
| 全程曲线 | 画出 6 关节运动+修正过程完整曲线（看平稳度/振荡） |
| 自动扫参 | 尝试多组 PID，重复跑同一套动作，对比哪组修正最少、最准、最稳 |

> **重要**：本工具默认用**逐个 `p J` 慢速读取**采集，而不是固件的 `pv` 连续周期反馈。原因是实测发现：单点 `p J` 读取 6 个舵机**100% 成功**，而 `pv` 连续密集读取时 J2~J6 频繁失败（固件连续读时序 bug）。逐关节读取虽然慢一点，但保证每个舵机都能读到，数据完整可靠。

## 运行方式

**先关闭串口助手**（同一串口只能一个程序用）。

### 1. 单次监控（看一次运动+修正的完整过程）

```cmd
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe "C:/Users/Administrator/Desktop/ArmControl_HAL（1）/tools/arm_auto_tune.py" --port COM8 --start 150 150 150 150 150 150 --target 165 161 170 182 155 200 --v 200
```

- `--start`：起始 6 关节角度（J1..J6）
- `--target`：目标 6 关节角度（J1..J6）
- `--v`：运动速度 deg/s

脚本会：初始化 → 使能扭矩 → 回初始位 → 发送 m 运动 + 开 pv → 采集整过程 → 输出报表 + CSV + 曲线图。

### 2. 自动扫参（对比多组 PID）

```cmd
C:/Users/Administrator/.workbuddy/binaries/python/envs/default/Scripts/python.exe "C:/Users/Administrator/Desktop/ArmControl_HAL（1）/tools/arm_auto_tune.py" --port COM8 --sweep --sets "32,4,12|48,4,12|64,4,20" --repeat 3 --start 150 150 150 150 150 150 --target 165 161 170 182 155 200
```

- `--sets`：多组 `P,I,D` 用 `|` 分隔
- `--repeat`：每组重复次数（取趋势，默认 3）
- `--joints-pid`：参与扫参的关节，默认 J2,J3,J4

每组都会被设定 PID 后重复跑同一套 `m` 动作，最后输出**对比表**（修正轮数总和 / 到位状态 / 耗时）+ **叠加曲线图**，一眼看出哪组 PID 最好。

### 3. 其他常用参数

| 参数 | 默认 | 说明 |
|------|------|------|
| `--port` | COM8 | 串口 |
| `--feedback-ms` | 200 | pv 反馈间隔，越小曲线越平滑但串口占用高 |
| `--timeout` | 30 | 单次运动+修正总超时秒数 |
| `--out-dir` | tune_results | 输出目录 |
| `--no-gravity` | 关 | 不发送 G 0.04（默认开 J2 重力前馈） |

## 输出文件

在 `tools/tune_results/` 下生成：

| 文件 | 内容 |
|------|------|
| `*_joint_curves.png` | 6 关节运动+修正过程曲线（多组 PID 叠加） |
| `*_#.csv` | 每个采样点的时间 + 6 关节实际角度 + 目标角度 |
| `*_report.txt` | 统计报表（修正轮数/误差/状态/PID 调节过程） |

## 报表怎么看

```
===== 采样 P32_I4_D12 | 耗时 8.5s =====
  修正完成: 3 轮, 阈值±1°
  J  修正轮  最后actual  最后err  状态   auto-tune次数
  J2    2         161         0        ok    1
  ...
  --- PID 自动调节过程 ---
    J2: D_Gain->16 (damp oscillation)   ← 发生振荡，固件自动加了D
```

- **状态 = "ok"**：该关节在阈值内到位
- **状态 = "timeout"**：达到最大修正轮数还没到位（说明 P 不够/负载太重）
- **auto-tune 次数多**：说明初始 PID 参数不佳，固件在反复救场 → 应调整
- **目标**：修正轮数少 + 全员 ok + auto-tune 少 + 曲线平滑无振荡

## 固化你的理解

这个工具**不修改固件**，只是监控和辅助选参。真正执行平稳/修正逻辑的是固件里已经写好的自适应修正服务。你要做的：
1. 用 `--sweep` 扫几组 PID，找出"修正最少、全员到位、曲线平滑"的一组
2. 把最优组通过 `N J P I D` + `F` 保存，让它开机自动生效
3. 之后上位机验证每个模块，如果某关节总在 auto-tune 救场，再针对它调
