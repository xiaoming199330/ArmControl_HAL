# 任务编排协议（Task Orchestration）

## 原子任务判定

满足全部条件才算原子任务：
- 单一角色一个会话内可完成
- 单一明确交付物（一个函数 / 一个文件 / 一组测试）
- 不需要中途切换上下文（如"改算法+烧录实测"应拆成两个任务）

## 分解模式（嵌入式版）

| 请求类型 | 分解模式 | 示例 |
|---------|---------|------|
| 新串口命令 | 解析分支 → 处理函数 → help/readme 同步 → 回测/实测 | 新增 `qa` 段加速度命令 |
| 运动算法修改 | 建立回测基准 → 算法修改 → 回归回测 → 评审 → 串口实测 | S 曲线 TJ 可调化 |
| Bug 修复 | 诊断 → 修复 → 评审 → 回测+实测 | 多点循环不停 |
| 驱动/总线修改 | 分层影响分析 → 修改 → loopback 诊断验证 → 全链路实测 | 换 74HC126 为其他缓冲器 |
| 配置/标定 | 改值 → 核对 drift 清单生效点 → 实测标定 → F 保存 | 更换臂长后重标定 |
| 性能优化 | 测量(计数器/日志) → 瓶颈定位 → 优化 → 前后对比 | 200Hz 插值 CPU 占用 |

## 依赖规则

```
驱动/协议层改动 → 先于 → 关节抽象层改动
关节抽象层改动 → 先于 → 规划/算法层改动
算法层改动     → 先于 → 业务层(命令/状态机)改动
所有代码改动   → 先于 → 评审
评审通过       → 先于 → 回测+实测
实测通过       → 先于 → 关闭 + 技能进化
```

## 任务清单格式

```markdown
## 任务计划: [名称]
**架构**: 基于 [模块] 记忆 | **风险**: [实时路径/安全限位/Flash 擦写] | **任务数**: [N]

| # | 任务 | 角色 | 预计 | 依赖 | 状态 |
|---|------|------|------|------|------|
| 1 | ... | @dev | 20m | - | pending |

执行序: #1 → #3(并行#2) → #4
确认: [是] / [修改] / [跳过#] / [取消]
```

## 执行状态机

| 状态 | 含义 | 下一动作 |
|------|------|---------|
| `pending` | 已创建 | 等依赖 |
| `ready` | 依赖满足 | 调度角色 |
| `in-progress` | 执行中 | 跟踪 |
| `completed` | 完成 | 解锁后继 |
| `failed` | 失败 | 重试/升级（见 dispatch-matrix 升级规则） |
| `blocked` | 需硬件/用户介入 | 提示用户（如需按急停、接线、给串口号） |
| `skipped` | 用户跳过 | 记为完成无交付 |

## 用户交互点

1. **计划后**：呈交任务清单等待确认
2. **每个任务后**：汇报结果，询问是否继续
3. **失败时**：给出错误与 重试/跳过/升级 选项
4. **需硬件操作时**：明确提示（"请确认机械臂已上电、急停已释放、串口 COMx 空闲"）
5. **关闭前**：总结 + 询问是否执行技能进化（默认执行）

## 命令

```bash
@armcontrol-hal-assistant --plan "描述"
@armcontrol-hal-assistant --execute --plan-id PLAN-001
@armcontrol-hal-assistant --execute-task #3 --plan-id PLAN-001
@armcontrol-hal-assistant --plans
@armcontrol-hal-assistant --cancel --plan-id PLAN-001
```
