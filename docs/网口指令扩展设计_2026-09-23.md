# 网口指令扩展设计 —— as-built（全指令覆盖）

> 2026-09-23 · 目标：让网口 UDP 覆盖文本控制台的能力，**帧格式零破坏**（老上位机不改也能跑）
>
> ⚠ 本文是**实现后的事实记录**，不是最初的提案。提案里列了 ~55 个候选码，
> 实际落地 **24 个**；其中最关键的一条把架构从"逐条加 opcode"改成了
> **文本命令透传**（见 §2.0）。凡是本文与代码不一致的，**以本文为准**，
> 说明代码漏改了 —— 请提出来。

---

## 0. 结论先行

| 项 | 数值 |
|---|---|
| 文本控制台命令总数 | **124 条** |
| 物理不可行（引脚冲突） | **11 条** |
| 网口可覆盖的总能力 | **113 条**（124 − 11） |
| 为此新增的网口命令码 | **24 个**（其中 `TEXT_EXEC` 一条就覆盖 113 条） |
| 需要分页的 | 文本输出、示教轨迹、参数列举 |
| 老上位机受影响 | **0** —— 帧格式、14 条老命令一个字节都没动 |

**为什么不是改帧格式加长包**：`APROTO_MAX_PAYLOAD = 64`
（`arm_control_protocol.h:34`）是硬上限，且它被 25 处缓冲引用（CAN 重组
`s_rx_buf`、串口 `payload[]`、`arm_net.c` 收发池、`main.c` 栈上 `frame[]`）。
示教轨迹一条几千点 × 12 B = 几十 KB，**提高上限到 255 也解决不了**
⇒ 正确做法是**分页**，帧格式一个字节都不动。

## 1. 硬约束（设计前提）

| 约束 | 出处 | 影响 |
|---|---|---|
| 命令码必须 `< 0x80` | `arm_control_protocol.c:162` 把 `cmd >= 0x80` 当回包丢弃 | 新码只能排 `0x01–0x7D` |
| `0x7E` / `0x7F` 已占 | ACK / NACK | 不能用 |
| 响应码 = 请求码 \| `0x80` | `arm_control_protocol.h:23` | 自动推导，无冲突 |
| 单帧 payload ≤ **64 B** | `APROTO_MAX_PAYLOAD` | 大数组必须分页 |
| 无主动推送 | 三承载都是"收请求→回响应" | 事件改**轮询队列** |
| 无重传 | UDP 无连接；CAN/串口也无 ACK 重发 | 危险命令加 magic |
| 无看门狗 | 本工程未启用（红线 5） | 任何"会阻塞主循环"的命令都不能上网口 |

约定：`u8/u16/i16/i32` 小端；角度 `i16×0.1°`、位置 `i16×0.1mm`、
速度 `u16×0.1°/s`、参数 `i32×0.001`。

## 2. 落地命令码总表（24 个）

### 2.0 ⭐ 架构决策：为什么最终是「文本透传」

提案打算给每条控制台命令都加一个 opcode。实现阶段否掉了，理由是**三条**
（记在这里，免得以后有人又想加回去）：

1. **追不上**。控制台 124 条而且在长；加 opcode 是"每加一条控制台命令就要
   同步改 4 个文件（头、分发、API 层、两份 SDK）"，实际上是永远落后。
2. **会分叉**。`M a` / `zr` / `F` 在控制台早就实现好了（含所有副作用与提示
   文本）。再写第二份 = 两份实现迟早不一致，而 **这几条的后果不可逆**。
3. **安全拦截天然继承**。11 条抢 ETH 引脚的命令，`ProcessCommand` 开头那段
   `#if ARM_LINK_NET` 会接住它们。走透传 = 自动继承；复制一份新实现 =
   要在新地方再写一遍，迟早漂移。

所以：**热路径留类型化 opcode，长尾走一条 `TEXT_EXEC`**。

```
TEXT_EXEC(0x0B)  →  ArmMain_TextGate() → ArmMain_ExecText() → ProcessCommand()
                                                              ↑ 与 COM11 同一条
```

`con_sink` 函数指针在执行期间从 `con_write_uart` 切到 `con_capture`，
把控制台输出收进 `g_text_buf[2048]`；执行完**必须**切回
（否则 COM11 静默失声）。

### 2.1 系统与诊断 `0x0X`

| 码 | 名称 | 请求 | 响应 | 覆盖文本 |
|---|---|---|---|---|
| `0x04` | `GET_JOINT_DETAIL` | `u8 joint``(0~5, 0xFF=全)` | `0x84`：`u8 n` + `u8 joint0` + n×**10 B**<br>`u16 pos_raw, i16 speed, i16 load, u8 volt(0.1V), u8 temp, u8 err, u8 ok` | `T` `O` `E` |
| `0x05` | `GET_LIMITS` | — | `0x85`：6×8 B `min,pos,max,zero u16` = 48 B | `zi` |
| `0x07` | `GET_INFO` | — | `0x87`：`u8 tag_len, char fw_tag[16], u8 build, u8 link, u8 nsrv` = 20 B | `h` 首行 |
| `0x0A` | `GET_FLAGS` | — | `0x8A`：`u8 flags, u8 run_id` = 2 B | `ms` 的部分 |
| **`0x0B`** | **`TEXT_EXEC`** | `u32 magic, char text[]`(NUL 结尾, ≤58) | `0x8B`：`u16 total, u8 flags, u16 off, u8 n, char text[n]` | ⭐ **全部 113 条** |
| **`0x0C`** | **`TEXT_FETCH`** | `u16 off, u8 n(1~58)` | `0x8C`：同 `0x8B` | 接上条翻页 |

**关键尺寸**（都是"恰好差 2 B 就超限"）：

| 项 | 计算 | 结论 |
|---|---|---|
| `GET_JOINT_DETAIL` 六轴 | 2 + 6×10 = **62** ≤ 64 | 加不了 `u16 current`（74 超限），要电流用单轴形态 |
| `GET_LIMITS` | 6×8 = **48** ≤ 64 | 直接塞得下，不用分页 |
| `TEXT_*` 每页正文 | 6 B 头 + **58** = 64 | `APROTO_TEXT_CHUNK = 58` |
| `TEXT_*` 单次捕获上限 | `ARM_TEXT_BUF_SZ = 2048` | `h` 帮助表 5406 B ⇒ 会截断，但有 flags 标记 |

`GET_FLAGS` 位图：`bit0=E-Stop bit1=轨迹 bit2=流模式 bit3=修正
bit4=示教录制 bit5=示教回放`。⚠ 它**只读变量、不碰舵机总线**
⇒ 可以 10~50 Hz 轮询做 UI 状态灯（`GET_STATUS` 要读 6 轴舵机，约 4~6 ms）。

`GET_INFO.build`：`0=net 1=can 2=both 3=uart 4=off`。
`GET_INFO.link` 是 **`LinkCfg_ActiveMode()` 的启动冻结值，不是 Flash 偏好** ——
「改了偏好但还没 RESET」时两者会分叉，这正是判断"到底跑在哪条链路上"的依据。

#### TEXT_EXEC / TEXT_FETCH 细节

```
0x0B 请求:  u32 magic(0x5A5A5A5A) + char text[](NUL 结尾)
0x8B 响应:  u16 total | u8 flags | u16 off | u8 n | char text[n]
            flags bit0 = 输出被 ARM_TEXT_BUF_SZ(2048) 截断
            flags bit1 = 被安全闸门拒绝（正文是**原因说明**，不是命令输出）
0x0C 请求:  u16 off + u8 n(1~58)
0x8C 响应:  同 0x8B
```

⚠ **`TEXT_EXEC` 无条件要求 magic**（不像 `0x7X` 只在那几条上要求）：这条命令
能做的事等于整个控制台，天然是最危险的一条，一律要求显式构造。

⚠ **`offset` / `total` 都是字节数**，不是字符数。控制台的中文提示是 UTF-8
字节 ⇒ PC 侧必须**按字节拼接、最后统一 decode 一次**；逐页 decode 会在分页
缝上拼出坏字符（一页 58 B 很容易正好切在一个 3 字节汉字的中间）。

⚠ 输出 > 2048 B 只**截断并置 flags.bit0**，绝不静默丢字符。

##### 安全闸门 `ArmMain_TextGate()`

| 返回 | 条件 | 含义 |
|---|---|---|
| 0 | — | 放行 |
| 1 | 空行 / 以空格开头 / `#` / 单独 `c` | **交互阻塞类**，拒绝 |
| 2 | E-Stop 激活且命令不是 `s` / `h` | 急停白名单 |

`c`（相位校准向导）被拒的理由：`cmdCalibrate()` 里是 `for(;;)` 等人在
**本机串口**上敲 `'0'/'s'/'q'`。从网口进 = 主循环永不返回，而本工程
**没有看门狗** ⇒ 板子彻底失联但 USB 还在枚举，最难查的一种死法。

⚠ 闸门**刻意不重复列那 11 条抢引脚命令**：那段判断就在 `ProcessCommand`
开头，抄第二份迟早漂移。那 11 条走的是"ProcessCommand 自己接住 + 说明"，
**不算闸门拒绝**（`flags.bit1 = 0`），PC 侧要能区分这两件事。

### 2.2 运动控制 `0x1X`

| 码 | 名称 | 请求 | 响应 | 覆盖 |
|---|---|---|---|---|
| `0x14` | `MOVE_JOINT_ONE` | `u8 joint(0~5), i16 deg×10, u16 v×10, u16 a×10` = 7 B | ACK | `a J deg` |
| `0x17` | `SET_BUS_MODE` | `u8 mode(0/1/2)` | ACK | `b` |
| `0x18` | `SERVO_INIT` ⚠ | `u8 joint(0~5, 0xFF=全)` | ACK | `i` `i J` |

⚠ `MOVE_JOINT_ONE` 的角度是**舵机度**（与 `MOVE_JOINTS` 同量纲），
**不是** `STREAM_JOINTS` 的逻辑角。
⚠ 固件先读**全场快照**、只改这一轴目标 ⇒ **任一轴丢读则整条回 `ERR_READ(7)`**。
这是有意的：拿不准位置时不动，比动错强。
⚠ `SERVO_INIT` 会重写该轴 PID/限位/中位并 RESET，副作用与文本 `i` 相同。

### 2.3 运动学 `0x2X`

| 码 | 名称 | 请求 | 响应 | 覆盖 |
|---|---|---|---|---|
| `0x22` | `IK_QUERY` | `i16 x,y,z(mm×10), i16 pitch×10` = 8 B | `0xA2`：6×`i16` 舵机度×10 | `g` 的解算部分 |

**只解不算**：做 IK 解算 + 限位检查 + FK 回代验证，**不启动运动**。
失败时用错误码区分原因：`ERR_UNREACH(3)` 不可达 / `ERR_LIMIT(4)` 超关节限位 /
`ERR_FK_VERIFY(6)` 回代超差。用于「先问能不能到，再决定动不动」——
比 `MOVE_CART` 撞失败更省事。

### 2.4 补偿与 PID `0x3X`

| 码 | 名称 | 请求 | 响应 | 覆盖 |
|---|---|---|---|---|
| `0x32` | `GET_GRAVITY` | — | `0xB2`：`i16 K(0.001 deg/mm)` = 2 B | 补 `SET_GRAVITY` 的反向 |
| `0x33` | `GET_CORRECTION` | — | `0xB3`：`u8 en, u16 thr×100, u8 rounds, u8 pending` = 5 B | `A` |
| `0x36` | `GET_PID` | `u8 joint(0~5)` | `0xB6`：`u8 p, u8 i, u8 d, u8 from_eeprom` = 4 B | 补读侧 |

⚠ `GET_PID` 的字段顺序就是 **p/i/d**。固件底层 `SERVO_ReadPidEeprom()` 的形参
顺序是 `(p, d, i)`，API 层已换算 —— 到这里**不要再换一次**（换两次等于没换）。
`from_eeprom = 0` 表示**读失败**，p/i/d 不可信（是那个从机没答，
不是"PID 就是 0"）。

### 2.5 参数与 Flash `0x4X`

| 码 | 名称 | 请求 | 响应 | 覆盖 |
|---|---|---|---|---|
| `0x43` | `PARAM_SAVE` ⚠ | `u32 magic` | ACK | `F` |
| `0x44` | `PARAM_LIST` | `u8 offset` | `0xC4`：`u8 total, u8 n` + n×**10 B**<br>`u8 id, u8 type, i32 vmin×1000, i32 vmax×1000` | `LP` |

⚠ `vmin/vmax` 必须是 **i32×1000**：参数范围里有超过 `i16` 的值
（如 `traj.approach_speed` 上限 4095、`MOVE_CART` 相关参数），压成 `i16`
会**静默截断**。10 B/条 × 6 = 62 B（含 2 B 头）≤ 64。
带上 i32 值会超 64 B ⇒ 固件刻意把"元数据"和"值"拆开，值用 `PARAM_READ` 单取。
翻页终止：`n == 0` 或 `offset + n >= total`。

⚠ `PARAM_SAVE` 走文本路径（= 控制台 `F`），magic 由 SDK 自动填。

### 2.6 示教与轨迹存储 `0x5X`

| 码 | 名称 | 请求 | 响应 | 覆盖 |
|---|---|---|---|---|
| `0x50` | `TEACH_LIST` | `u8 idx` | `0xD0`：`u8 total, u8 idx, u8 valid, char name[12], u32 samples` = 19 B | `list` |
| `0x51` | `TEACH_READ` | `u8 idx, u16 off, u8 n(1~5)` | `0xD1`：`u8 n` + n×12 B `6×u16 raw` | 新增（**分页**） |
| `0x53` | `TEACH_DELETE` | `u8 idx` | ACK | `del` |
| `0x54` | `TEACH_COMPACT` | — | ACK | `compact` |
| `0x55` | `TEACH_TOTAL` | — | `0xD5`：`u8 nfiles, u8 capacity, u32 total_samples, u32 free_bytes` = 10 B | `rec list` |

⚠ `TEACH_READ` 每页 12 B × 5 = 60 ≤ 64。1000 点轨迹 = 200 次请求；
网口 p50 1.61 ms ⇒ 约 **0.3 s 取完**。
**`off` 越界 ⇒ `n = 0`，那是"正常读完"，不是错误。**
`TEACH_LIST` 的 `valid = 0` 表示该槽位是 tombstone（已删未回收）。

### 2.7 危险操作 `0x7X`（全部强制 magic）

| 码 | 名称 | 请求 | 行为 |
|---|---|---|---|
| `0x70` | `CENTER_CALIB` | `u32 magic` | ACK（执行文本 `M a`，六轴推到 raw 2048） |
| `0x71` | `CALIB_ENTER` | `u32 magic` | ⚠ **一律 NACK(`ERR_PARAM`)** —— 见下 |
| `0x72` | `ZERO_RESET` | `u8 flags(bit0=落盘), u32 magic` | ACK（执行 `zr` / `zr save`） |
| `0x73` | `SYS_RESET` | `u32 magic` | ACK **之后** 150 ms 才复位 |

**magic = `0x5A5A5A5A`**。作用：无连接通道上防误包/防扫描器误触发。
这几条一旦误触发，量纲基准作废、整臂失去力矩，都是不可逆的。

⚠ **`ZERO_RESET` 没有关节号**：文本 `zr` 根本没有单轴变体（一次复位全部六轴）
⇒ 协议也不给，不猜。`flags.bit0 = 1` 等价 `zr save`（写 Flash，重启保持）。
SDK 里传了非法 flags（>1）一律回 `ERR_PARAM`。

⚠ **`CALIB_ENTER` 一律 NACK，这是设计而非实现漏项**。理由同 §2.1 的闸门。
保留这个码是为了让"不可用"在**协议层面显式可见** —— 比让上位机收到一个
没头没尾的参数错要好。

⚠ **`SYS_RESET` 先回 ACK、150 ms 后才 `NVIC_SystemReset()`**
（`ArmMain_RequestReset` → 主循环 `ArmMain_ServicePendingReset`）。
顺序反了上位机只会看到超时，分不清"复位成功"和"包丢了"。
复位后按 **Flash 里的链路偏好**重建 ⇒ 远程切链路的完整序列是：

```
TEXT_EXEC("link can")  →  TEXT_EXEC("link save")  →  SYS_RESET
```

## 3. 物理不可行清单（11 条）

| 命令 | 抢的引脚 | 为什么无解 |
|---|---|---|
| `cx` `cp` `cy` `cz` `cw` `ps` `can` | `PB12/PB13` = CAN2_RX/TX | 而这两脚是 **ETH_RXD1/ETH_TXD1**。F407 上 ETH_TXD1 **只有 PB13 一个选项** |
| `mg` `mp` `mo` | `PA0/PA1` | `PA1` = **ETH_RMII_REF_CLK**；这三条收尾**无条件**写回 `GPIO_AF8_UART4` |
| `ml` | `UART4` | 同上（`mg/mp/mo/ml` 本就被 `#if ARM_MASTER_BUILD` 挡着） |

`d`（CAN Bus B 回环）随 CAN 一起不可用。

**出路**：只有改硬件方案 —— MII 模式走 `PG11/PG13/PG14`，或双 MCU 分工
（一块管 CAN、一块管网口）。软件层面无解，`main.c` 里那段
"接住 + 说明"就是终态。

⚠ 走 `TEXT_EXEC` 敲这 11 条**不会静默失败**：固件把**原因当输出回给你**
（含引脚解释与 `link can` 的正确做法）。这是刻意的 —— 上位机要能区分
"被策略拒"和"这条命令在当前链路物理上不可用"。

## 4. 分页协议（统一形态）

所有可能超 64 B 的读操作，统一是：

```
请求:  u16 offset, u8 n
响应:  u8/​u16 total, u8 n, payload[n × item_size]
```

PC 侧循环直到 `n == 0` 或 `offset + n >= total`。
Python/JS SDK 都提供"一次调用自动翻页"的封装
（`teach_trace()` / `param_list()` / `text_exec()`）。

| 载体 | 每页 | 终止条件 |
|---|---|---|
| `TEXT_EXEC`/`TEXT_FETCH` | 58 B 正文 | `off >= total` |
| `TEACH_READ` | 5 样本 | `n == 0` |
| `PARAM_LIST` | 6 条 | `n == 0` 或 `offset+n >= total` |

⚠ 所有翻页循环都带一个**安全上限**（`guard` / `max_samples`），
防固件字段异常时死循环 —— 这是吃过亏的地方。

**为什么不加"长包"**：见 §0。分页的额外好处是**每包小 ⇒ 丢包只丢一页**，
比整包重传更省。

## 5. 事件队列（替代主动推送）

固件维护环形队列：`32 × 10 B = 320 B`。

| 事件码 | 含义 |
|---|---|
| `0x01` | E-Stop 触发/解除 |
| `0x02` | FAULT |
| `0x03` | STALL |
| `0x04` | 轨迹完成 |
| `0x05` | 参数落盘完成 |
| `0x06` | 链路状态变化 |

PC 轮询 `GET_EVENTS`。在网口 p50 1.61 ms 下，10 Hz 轮询的开销可忽略 ——
**这比长连接推送更简单，也不用改帧格式**。

> ⚠ 状态：`GET_EVENTS(0x06)` **本轮未实现**（码位保留）。
> 眼下用 `GET_FLAGS` 轮询代替 —— 它同样不碰总线，能覆盖
> E-Stop / 轨迹 / 流 / 录制 / 回放这几个最要看的状态位。

## 6. 流式命令的处理（网口反而更强）

`pv` `pf` `tm` `sp` `#P` 这 5 条本质是"固件按周期吐数据"。网口**不需要移植**：

| 文本流 | 网口替代 |
|---|---|
| `pv 20` 角度流 | 20 Hz 轮询 `GET_STATUS` |
| `pf 20` 位姿流 | 同上（`GET_STATUS` 已含 XYZ+pitch） |
| `tm` 遥测流 | 轮询 `GET_JOINT_DETAIL` |
| `sp` 主端位置流 | 主臂 20~50 Hz `STREAM_JOINTS`（已有） |
| `#P` PC 中继接收 | `STREAM_JOINTS`（已有） |

理由：网口单向时延 p50 只有 1.61 ms，跑 100 Hz 轮询毫无压力；
而且**采样时机由 PC 决定**，比固件定时更灵活。

> ⚠ 注意：这 5 条**是**控制台命令，所以走 `TEXT_EXEC` 也能敲；
> 但那样是"固件按自己的时钟吐"，不适合做闭环 —— 用轮询。

## 8. 风险与不做的事

| 不做 | 原因 |
|---|---|
| 改 `APROTO_MAX_PAYLOAD` | 25 处缓冲连带、栈压力、老上位机失联；分页已够用 |
| 引主动推送/长连接 | 要改帧格式，破坏兼容；轮询队列够用 |
| 无条件开放 `M a` / `c` / `zr` / `F` / RESET | 不可逆且会失去力矩，强制 magic |
| 在 NET 构建里放开 11 条引脚命令 | 物理冲突，放开=网口当场死 |
| 给 `CALIB_ENTER` 写一份"网口版"实现 | 它要人机交互；无看门狗 ⇒ 会彻底失联 |

## 9. 已知偏差与遗留

| 项 | 说明 |
|---|---|
| `GET_EVENTS(0x06)` | 码位保留，未实现；用 `GET_FLAGS` 轮询代替 |
| `RESET_CORRECTION(0x34)` / `SET_PID(0x35)` / `BURN_EEPROM(0x39)` | 未做类型化 opcode；需要时走 `TEXT_EXEC`（`R` / `I` / `Y`） |
| `SET_JOINT_RAW(0x15)` / `GOTO_ZERO(0x16)` | 同上（`r` / `z`） |
| 路点与循环（`q` `qv` `B` `S` `P` `W`） | 同上 —— 这些都需要"多步状态机"语义，逐条加 opcode 收益不高 |
| 零力示教参数（`teach *`，`0x60–0x65`） | 同上 |
| 全程**仅离线验证，未上真机** | 上板前必须先回中位 `m 180 180 180 180 180 180 15`，**绝不能用 `M a`** |

这些"未做 opcode"的命令**全都能通过 `TEXT_EXEC` 用**，只是没有类型化封装。
这是刻意的取舍：**短尾命令走透传，热路径才值得加 opcode。**
