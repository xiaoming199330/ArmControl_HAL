## 0. 一句话结论

用 **RadioLink AT9S Pro 发射机 + R9DS 接收机**（PWM 模式，**不用 SBUS**），
走 **`TIM4` 输入捕获（PD12~PD15）** 读摇杆脉宽，**再做一路扩到 TIM1** 读夹爪拨杆；
控制通路**必须用 `ArmApi_StreamJoints()` 流模式**（**不能用 `MoveCartesian`**，它会把 J5/J6 归零）；
映射 = **右杆 X/Y + 左杆 Z/J5 + 拨杆夹爪**（详见 §2.12）。
**上行电前必须先验证关节限位已标定**（红线 68，否则流模式会把六轴推向 raw 0）。

## 1. 器件事实

### 1.1 现行器件（2026-09-22 起）

| 项 | 内容 |
|---|---|
| 发射机 | **RadioLink AT9S Pro**（说明书已全文提取到工程根 `at9s_manual.txt`） |
| 接收机 | **R9DS**，PWM 模式（**红灯**）= 9 路独立 PWM；SBUS&PWM 模式（**蓝灯**）= 第 9 通道出 SBUS |
| 摇杆 | **4 轴全自复位**（需装随机附带的"油门回中配件"） |
| 旋钮/滑杆 | 正面 VR 旋钮 ×2 + 背面 VR 滑杆 ×2（**连续、不自复位**） |
| 开关 | 4 个二段 + 3 个三段（**不自复位**） |
| 映射自由度 | 任意通道都可由 `STK1~4` / `VrA~VrD` / `SwA~SwH` / 逻辑开关驱动（基础菜单 → 辅助通道） |

### 1.2 已作废的旧方案

**HotRC F-04A**（4 路 PWM）⇒ 只有 **3 个比例通道**（左杆 1 轴不自复位 + 右杆 2 轴自复位）
⇒ 做不了完整映射。**已换机，旧方案连同 §2.4 的方案 A/B/C 一并作废**（保留在历史记录里备查）。

### 1.3 ⚠ 三个必须实测、不能假设的量

1. **实际中位**：不同发射机的中位/端点/死区都不同，**1000~2000µs 只是标称值**
   （拿标称值直接映射的典型后果：死区判错 ⇒ 摇杆松手手臂一直慢慢爬 ⇒ **红线 68**）。
2. **实际行程**：每杆推到两端各停 1 s，读 `rc` 的"行程 µs"。
3. **失控行为（最重要）**：见 §1.4。

### 1.4 ⚠⚠ 失控保护语义（AT9S Pro 与旧机**完全不同**，旧判据失效）

手册 §2.11：失控保护是"让接收机在失控后**继续保持所设置的通道行程**"，可逐通道设 F/S 位置。

| 接收机 | 丢控时 | 我们的判据 |
|---|---|---|
| 旧 HotRC F-04A | 脉宽**消失** | 新鲜度/时间戳 ✅ 有效 |
| **AT9S Pro + R9DS** | **继续输出预设行程**（帧照发，只是值变了） | ❌ **新鲜度判据完全失效** —— `新鲜` 依然 ✔，`失控计数` 永远不涨 |

- ✅ 好处：把 X/Y/Z 的 F/S 设成**中位** ⇒ 丢控 ⇒ 值=中位 ⇒ 映射出的速度=0 ⇒ **臂停**。
- ⚠ 坏处：**没设、或误设成"保持最后行程"，丢控时臂会以最后的速度一直走，而软件完全发现不了**
  —— 没有任何异常可看。这是红线 67（"没脉冲"≠"值为 0"）的升级版：
  **"通道还在发" ≠ "还有人在控"**。

**必做四件事**：① 逐通道设 F/S（X/Y/Z/J5 → 中位 ✅ **09-23 已回报全部设好**；
夹爪 → ⚠ **09-23 也设成了中位** ⇒ 丢控时爪子会从"夹着工件"跑到半开，**必须靠心跳判据做软件冻结**兜住，
见 §4.2 / 复核 §7.4；**千万别设成闭合**）；
② 实测验证（记 `rc` → 关发射机 → 等 2 s → `rc`，看是跳到中位 / 冻结 / 消失）；
③ 使能档位若用，**必须接进 MCU**，不能只当操作习惯（红线 70）；
④ ⭐ **心跳通道**（09-23 拍板要做）：单独一路闲置通道（定案 `PG10`），
**正常位与 F/S 必须写成"两端"**（正常 ≈1000µs / F/S ≈2000µs，或反之）——
否则读出的是中位，判不出丢控（详见复核 §7.4）。

### 1.5 SBUS：能用，但**现在不该用**

R9DS 的 SBUS 是**反相**串口（100000 baud / 8E2 / 25 字节 / 起始 `0x0F` / 每通道 11 bit），
而 **STM32F407 无法在片内反转 RX 极性**。本地证据（可自行复核）：

| 查什么 | 结果 |
|---|---|
| `grep -rn "RXINV" Drivers/` | **零命中** |
| `USART_CR2` 位定义（`stm32f407xx.h:12564~12594`） | ADD(0-3)、LBDL(5)、LBDIE(6)、LBCL(8)、CPHA(9)、CPOL(10)、CLKEN(11)、STOP(12-13)、LINEN(14) ⇒ **位已占满，无反相位** |
| F4 HAL 的 `RxPinLevelInvert` / `ADVFEATURE_RXINV` | **零命中**（F4 根本不编译该特性） |

⇒ 要用 SBUS 必须外接反相器（NPN+两电阻，或 74HC14）。
**SBUS 唯一不可替代的好处**：25 字节帧**第 23 字节是标志位**（`bit2`=帧丢失、`bit3`=failsafe 生效）
—— RC 链路上**唯一协议级的失控检测**。但**必须实测乐迪有没有真的填这两个位**（不少国产接收机不填）。

**另两个坑**：R9DS **没有 PPM**（PPM 只有 R6DS 支持）；发射机背面教练口的 `OUT：CRSF/SBUS/PPM`
**是教练/模拟口输出类型，不是接收机输出**（出厂默认 PPM），别配错地方。

> 网上有文章说 F405/F407 支持 `BusInverted`，**与本地头文件对不上，以本地为准**（红线 40）。

**⇒ 结论：先用 PWM 模式（红灯），4~5 路进 MCU。SBUS 留作二期备选。**

## 2. 映射与控制通路

### 2.1 ⭐ 核心原则（红线 69）

**不自复位的杆/开关只能驱动"绝对量"，绝不能当速度轴。** 松手不归零 ⇒ 速度指令永久非零 ⇒ 臂一直走。
反之，**自复位杆天生适合速度轴**（松手自动回中 ⇒ 速度 0）。

### 2.2 ⚠⚠ 致命发现：`MoveCartesian` 会把 J5 与夹爪**归零**

`IK_Solve` 无条件 `joints[4]=joints[5]=0.0f`（**解析解与 CCD 兜底两条分支都是**），
而 `ArmApi_MoveCartesian()` 解完 IK 直接把 `deg[6]` 交给 `MoveJoints`
⇒ **每次平移都会把 J5 拧回 0、把夹爪指令到 0 位**。

⇒ **这套映射（平移 + J5 + 夹爪同时有效）用 `MoveCartesian` 做不出来。** 详见定稿页 §2.12.2。

### 2.3 ⭐ 正解：`ArmApi_StreamJoints()` 流模式

`ArmApi_StreamJoints(float jdeg[6])` —— 逻辑关节角、**不做轨迹规划/起点读/settle**、
用于主从实时跟随、建议 **20~50Hz**、**500ms 无调用看门狗自动退出**。
**接受完整 6 关节 ⇒ X/Y/Z 解出的 J1~J4 与 J5、夹爪可在同一次下发里 ⇒ 无互斥。**

| 机制 | 值 | 来源 |
|---|---|---|
| `stream_follow_en` | **默认 1（ON）** | `main.c:1821` |
| 跳变限制 | `STREAM_MAX_JUMP_DEG` = **25°/帧** | `main.c:1809` |
| 桌面 + 立柱检查 | `traj_z_floor_mm`、`TRAJ_COL_R_MM` | `stream_pose_ok()` |
| 断流看门狗 | `STREAM_TIMEOUT_MS` = **500ms** | `main.c:1808` |

### 2.4 通道预算账本

| 想要的量 | 需要什么输入 | AT9S Pro 供给 |
|---|---|---|
| X / Y / Z 速度 | 自复位比例 | 摇杆 4 轴（装"油门回中配件"后全自复位）✅ |
| J5 末端旋转 | 自复位（速度）或连续（绝对） | 摇杆第 4 轴 ✅ |
| 夹爪 J6 | 不自复位（绝对量） | VR 旋钮/滑杆 或 拨杆 ✅ |
| 使能 / 死手 | 两态 | 7 个开关 ✅ |

**⇒ 供给充足，"4 个通道不够"的问题在 AT9S Pro 上不存在。**
⚠ 但"自复位的比例通道有几个"才是真指标（旧机就是死在这条上）。

### 2.5 定稿映射

**见 `RC_cfg_final_2.12_2026-09-22.md` §2.12.1**（右杆 X/Y、左杆 Z/J5、拨杆夹爪）。

### 2.6 ⚠⚠⚠ 限位未标定 ⇒ 流模式把六轴推向 raw 0（**红线 68**）

`JOINT_MIN_RAW/MAX_RAW` 静态初值全 0，只在 `apply_calib_limits()` 里被填；
而该函数遇到"未校准哨兵"（`calib_min_raw={4095…}` / `calib_max_raw={0…}`）就跳过，
且**唯一上电调用点在 Flash 有标定的分支里** ⇒ 未标定时数组保持全 0 ⇒
`clamp_raw(want, 0, 0)` **返回 0** ⇒ 六轴目标全被改写成 raw 0。

**入口硬守卫 + 横幅判据**：详见定稿页 §2.12.5。

### 2.7 通道数：这套映射需要 **5 路捕获** ⇒ `TIM4`(4 路) 差一路

| 路线 | 需要 | 备注 |
|---|---|---|
| **A″. 夹爪 `TIM1_CH4`=`PE14`（硬件捕获）+ 心跳 `PG10`（EXTI）** ⭐ | **`PE14`（已确认引出）+ `PG10`（用户拍板）** | **09-23 三次定案**。第一轮曾定"全走 EXTI"，确认 `PE14` 引出后回到硬件捕获。⚠ `TIM1` 在 APB2 ⇒ `PSC=167` 才是 1µs（TIM4 是 83），且 `HAL_TIM_IC_CaptureCallback()` 要按 `Instance` 分派 |
| ~~A′. `PD11`+`PD10` 全走 EXTI~~ | ~~`PD11`（夹爪）+ `PD10`（心跳首选，后被改拍 `PG10`）~~ | 被 A″ 取代（`PD11` 本无定时器复用，事实保留作存档） |
| B. SBUS | 1 个空闲 USART RX + 反相器 | 二期（一次到位 16 通道；还能拿协议里的 failsafe 位，比心跳通道更权威） |
| C. 档位复用 | 0 硬件 | 夹爪已是连续量 ⇒ 不适用 |

**详细设计（引脚/代价/心跳通道/代码形态）见 `RC方案复核_2026-09-23.md` §7。**

## 4. 引脚与定时器选型

### 4.1 定案：`TIM4` 输入捕获（已实现并出固件）

| 项 | 内容 |
|---|---|
| 定时器 | `TIM4` |
| 通道/引脚 | `CH1~CH4` = **`PD12`~`PD15`**（AF2_GPIO_TIM4） |
| 计数 | `PSC=83` ⇒ **1 tick = 1 µs**；`ARR=0xFFFF` ⇒ 65.5 ms 回绕（无符号减法自然处理） |
| 极性 | `TIM_ICPOLARITY_BOTHEDGE`（`CCxP|CCxNP`）⇒ 能测脉宽。F407 四个通道的 `CCxNP` 都存在，HAL 按通道正确移位 |
| 滤波 | `ICF=0xF`、`ICPSC_DIV1`、NVIC 优先级 5 |
| 寄存器期望 | `CCER=0000BB0B`、`CCMR1=F1F1`、`CCMR2=F1F1`、`PSC=0053`、`ARR=FFFF` |

⚠ **F407 没有 AFIO/MAPR**（那是 F1）⇒ 选对 AF2 即可，无需 remap。

#### 4.1.1 为什么"按区间长度分类"而不是"记住上次边沿极性"

**按区间长度分类**：`dt ≥ 5ms` ⇒ 低电平段；`0.4~3ms` ⇒ 合法脉宽。
**验证**：`tools/rc_decode_repro.py` 离线复刻证明 —— 故意丢一个边沿时，
**区间法能自恢复并按原值走**；**记极性法永久错乱**，且产出的是看起来很像真值的 ~20 ms 整数
（**最危险的假阳性**）。复刻 PASS。

#### 4.1.2 ⚠ `nt` 会抢 TIM4

`nt`（REF_CLK 时钟体检）把 `TIM4` 拿去当从模式计数器，直接写 `PSC/ARR/CCER/CCMR`
⇒ RC 捕获**静默失效**。防护三层：① `nt` 收尾自动 `ArmRc_Reinit()`
（**必须 `HAL_TIM_IC_DeInit()` + 全量重配**，不能只重开中断）；② `rc` 回读寄存器逐项比对打 `!`；
③ `rc reinit` 手动兜底。→ **红线 67**。

### 4.2 第 5 / 6 路（**09-23 三次定案**：夹爪 = `PE14`/`TIM1_CH4` 硬件捕获，心跳 = `PG10`/`EXTI`）

| 通道 | 引脚 | 采集 | 状态 |
|---|---|---|---|
| CH5 夹爪 J6（**连续量**） | **`PE14` = `TIM1_CH4`（AF1，已确认引出）** | 硬件捕获（无 ISR 抖动，无需多帧平均） | 待接 |
| CH6 心跳（丢控检测） | **`PG10`**（用户拍板；上电前量一次通断） | `EXTI10` 软测宽（两档判据，抖动无关紧要） | 待接 |

路线演变：第一轮曾定 `PD11`+`PD10` 全走 EXTI（因当时以为没有已引出的捕获脚）；
用户随后确认 `PE14` 引出 ⇒ **夹爪回到硬件捕获**；心跳首选 `PD10` ⇒ 用户改拍 **`PG10`**。
`PG10` **代码层面已核实空闲**：`GPIOG` 只配置了 `PG0~PG5`（限位开关，`gpio.c:139-145`），
`GPIOG` 时钟本来已开（`gpio.c:77`）。`PD11` 无定时器复用的事实保留作存档：
（`AF7=USART3_CTS` / `AF12=FSMC_A16`；网上"`PD11`=`TIM4_CH4`"是错的，`TIM4` 四路只在 `PD12~PD15`/`PB6~PB9`）。
判据：翻自家型号 datasheet 的 AF 表（红线 40 家族：**AF 错在编译期完全不可见**）。

⚠ **TIM1 从零启用的 3 条新账**（详见复核 §7.3）：
① **`TIM1` 在 APB2，定时器时钟 168 MHz ⇒ `PSC=167` 才是 1µs**（照抄 TIM4 的 83 会让夹爪读数差一倍）；
② `HAL_TIM_IC_CaptureCallback()` 现在**两个 Instance 进来**（TIM4+TIM1）⇒ 必须按 `htim->Instance` 分派；
③ 只做输入捕获不碰输出（`MOE`/`BDTR` 默认即可），NVIC 用 `TIM1_CC_IRQn` 优先级 5（与 TIM4 同级）。

⚠ `EXTI`（现仅心跳 `PG10` 使用）的纪律（**建议登记红线 70/71**）：
① `HAL_GPIO_EXTI_Callback()` **全工程唯一符号** ⇒ 必须按 `GPIO_Pin` 分派；
② ⚠⚠ **`EXTI10` 线与 `PB10`(`USART3_TX` 总线 A)/`PE10`(`DIR_B` 总线 B 方向)** **共号** ⇒ 这两只**永远不能启用 EXTI**；
③ `EXTI11` 与 `PE11`(急停) 共号 ⇒ **急停永远不要改成 EXTI**。

### 4.3 接线（接收机**独立供电**）

- 接收机 `CH1~CH6` 信号 → **`PD12/PD13/PD14/PD15`（四杆，D 口一排 4 针）+ `PE14`（夹爪，E 口）+ `PG10`（心跳，G 口）**；
- 接收机 `GND` → 板子 `GND`（**必须共地**）；
- **接收机 `V+` 独立供电，不接板子**（用户已确认接收机独立供电）。

### 4.4 采样时序（RC 拍的位置）

- **必须挂主循环 50 Hz 拍**（`traj_do_update` 块内、`ArmRc_Poll()` 之后）；
- **绝不可进 TIM2 ISR** —— 因为 `StreamJoints`/`MoveJoints` 走阻塞式舵机总线 I/O。

## 7. 参考文章：能借鉴什么、不能照搬什么

> ⚠ 本节为重建，原文措辞可能不精确（原版有更细的逐条摘录）。

### 7.1 ✅ 可借鉴

1. 摇杆 → 速度的映射范式（自复位 = 速度轴）；
2. 死手/使能思想（松手即停）；
3. 分档调速（粗调/细调切换）；
4. 状态机隔离（IDLE / ARMED / MOVING / FAULT）；
5. 参数集中（死区、步长、速度上限进参数表）。

### 7.2 ❌ 不能照搬

1. **ROS/MoveIt 的方案**：本工程是裸机固件，没有 MoveIt 规划器，别引入 ROS 依赖；
2. **"摇杆直接映射关节角"**：会破坏笛卡尔一致性；
3. **假设 1000~2000µs 是准确值**；
4. **把"没脉冲"当成"值为 0"**（红线 67）。

### 7.3 文章里没有、但本工程必须处理的差异

- **失控保护语义**（§1.4，AT9S Pro 是"保持行程"型）；
- **`MoveCartesian` 归零 J5/J6**（§2.2）；
- **限位未标定 ⇒ 流模式推向 raw 0**（§2.6）；
- **`nt` 抢 TIM4**（§4.1.2）。
