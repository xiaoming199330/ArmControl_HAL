# 角度帧解析规则 — CAN 与 UDP 网口通用（2026-11-10）

> 真值来源：`Core/Inc/arm_control_protocol.h`（命令码/定点编码）、`Core/Src/arm_control_protocol.c`（组包/解包）、`Core/Src/kinematics.c`（raw↔度换算）。
> **两条链路的 payload 逐字节完全相同**，差别只在承载层（CAN 多帧重组 / UDP 单报文），见 §6。

---

## 1. 通用前提（先读这节，后面全部依赖它）

### 1.1 字节序与定点编码

| 规则 | 说明 |
|---|---|
| **字节序** | 所有多字节字段一律 **小端（LE）**：int16 `1796`(0x0704) 在线上是 `04 07` |
| **角度定点** | `0.1°` 单位 int16：发 90° 写 `900`(0x0384)；解析 `deg = raw / 10.0` |
| **位置定点** | `0.1mm` 单位 int16（x/y/z） |
| **速度/加速度定点** | `0.1(°/s 或 °/s²)` 单位 **u16**：v=25°/s 写 `250` |
| **编码取整** | 固件 `Aproto_EncDeg10` 是**四舍五入**（+0.5/-0.5），不是截断 |

```c
/* 固件源码（arm_control_protocol.h:230-235），上位机照抄语义 */
Aproto_EncDeg10(deg)  = (int16)(deg * 10 + (deg >= 0 ? 0.5 : -0.5));
Aproto_DecDeg10(v)    = v / 10.0f;
Aproto_EncVel10(v)    = (uint16)(v * 10 + 0.5);
Aproto_DecVel10(v)    = v / 10.0f;
```

### 1.2 丢读哨兵（最重要的一个数）

**`-32768`（0x8000）= 该轴本次读取失败。** 固件在任一关节读失败时把该轴角度填成 -32768
（`arm_control_protocol.c:221-223`），不是错误码、不是真实角度。解析时必须先判它：

```python
POS_SENTINEL = -32768
deg = None if raw == POS_SENTINEL else raw / 10.0
```

- 出现哨兵 ⇒ **舵机总线丢读**，立即停发一切运动指令（这就是"乱动+全 0x8000"事故的特征）。
- x/y/z/pitch 在六轴读失败时同样填 -32768。

## 2. 角度读取帧（上位机 = 解析方）

### 2.1 ⭐ 0x02 GET_STATUS → 0x82（主用，21B）

每拍角度首选这条。payload 21 字节，offset 表：

| offset | 长度 | 类型 | 字段 | 单位 |
|---|---|---|---|---|
| 0, 2, 4, 6, 8, 10 | 6×2 | int16 LE | **J1~J6 关节角**（舵机度） | 0.1°；-32768=丢读 |
| 12, 14, 16 | 3×2 | int16 LE | x / y / z | 0.1mm；-32768=丢读 |
| 18 | 2 | int16 LE | pitch | 0.1°；-32768=丢读 |
| 20 | 1 | u8 | flags 位图 | 见下表 |

**flags（payload[20]）位图：**

| bit | 含义 |
|---|---|
| 0 | E-Stop 触发 |
| 1 | **traj_active 轨迹执行中**（判到位就盯它变 0） |
| 2 | 自适应修正中 |
| 3 | **read_ok**（=0 表示本轮六轴有读失败，配合哨兵判断） |

**实测帧解析示例**（2026-11-10 折叠位，0x181 应答 payload）：

```
payload = 04 07 FF 02 8E 0A C8 09 1F 07 B1 05 | 6E 05 09 00 72 00 | A8 05 | 08

J1 = 0x0704 = 1796 → 179.6°     x = 0x056E = 1390 → 139.0mm
J2 = 0x02FF =  767 →  76.7°     y = 0x0009 =    9 →   0.9mm
J3 = 0x0A8E = 2702 → 270.2°     z = 0x0072 =  114 →  11.4mm
J4 = 0x09C8 = 2504 → 250.4°     pitch = 0x05A8 = 1448 → 144.8°
J5 = 0x071F = 1823 → 182.3°     flags = 0x08 = read_ok=1，空闲无轨迹
J6 = 0x05B1 = 1457 → 145.7°
```

### 2.2 0x21 FK_QUERY → 0xA1（FK 正解，21B）

和 0x82 同源（同一份 ArmApiStatus），布局不同：

| offset | 长度 | 类型 | 字段 |
|---|---|---|---|
| 0, 2, 4 | 3×2 | int16 LE | x / y / z（0.1mm） |
| 6 | 2 | int16 LE | pitch（0.1°） |
| 8~19 | 6×2 | int16 LE | J1~J6（0.1°，-32768=丢读） |
| 20 | 1 | u8 | read_ok（0/1） |

### 2.3 0x04 GET_JOINT_DETAIL → 0x84（62B 全轴 / 12B 单轴，含 raw 位置）

**payload[0]=n（轴数）**，全轴请求（joint=`0xFF`）时 n=6 且 payload[1]=0（起始轴号）；单轴请求（joint=0~5）时 n=1。之后每轴固定 **10 字节**：

| offset(轴内) | 类型 | 字段 | 说明 |
|---|---|---|---|
| 0 | u16 LE | **pos_raw** | STS3215 原始位置 0~4095，**不是角度**，换算见 §4 |
| 2 | i16 LE | speed | 舵机速度寄存器原始值 |
| 4 | i16 LE | load | 负载原始值 |
| 6 | u8 | voltage | 原始电压 |
| 7 | u8 | temp | 温度原始值；**0xFF = 该字段丢读** |
| 8 | u8 | hw_err | 硬件错误码；**0xFF = 读失败** |
| 9 | u8 | ok | 1=本轴读取成功 |

- 两种请求（单轴/全轴）**结构完全相同**，上位机一份解包代码通吃。
- 想要角度就用 0x82；0x84 的价值是温度/电流/负载/raw 三件套 + 分轴健康位。

### 2.4 0x05 GET_LIMITS → 0x85（48B，零点与限位 raw）

6 轴 × 8 字节，无包头：

| offset(轴内) | 类型 | 字段 |
|---|---|---|
| 0 | u16 LE | min_raw |
| 2 | u16 LE | pos_raw |
| 4 | u16 LE | max_raw |
| 6 | u16 LE | **zero_raw**（校准零点） |

**未校准判据：`zero_raw == 0`**（固件此时回落 180°/raw 2048）。0x84 的 pos_raw 换算成关节角必须用到这里的 zero_raw，见 §4。

## 3. 角度下发帧（上位机 = 组包方）

### 3.1 0x10 MOVE_JOINTS（16B，S 曲线多轴运动）——**舵机度**

| offset | 类型 | 字段 |
|---|---|---|
| 0~11 | 6×int16 LE | J1~J6 目标角（0.1°，**舵机度坐标系**） |
| 12 | u16 LE | v 速度（0.1°/s） |
| 14 | u16 LE | a 加速度（0.1°/s²） |

> 🔴 **非目标轴必须填当前实际角**（先 0x02 读回），**绝不能填 0**——五轴冲限位"乱动"事故根因。
> ACK err=0 只代表"已启动"，到位要等 flags bit1 变 0（UDP）或 0x280 TRAJ_DONE 事件（CAN）。

### 3.2 0x14 MOVE_JOINT_ONE（7B，单轴 S 曲线）——舵机度

| offset | 类型 | 字段 |
|---|---|---|
| 0 | u8 | joint（0~5） |
| 1 | int16 LE | 目标角（0.1°） |
| 3 | u16 LE | v（0.1°/s） |
| 5 | u16 LE | a（0.1°/s²） |

单轴动作用这条最省事，天然不存在"其它轴填 0"的坑。

### 3.3 0x13 STREAM_JOINTS（12B，遥操流式直写）——**逻辑关节角，另一套坐标系！**

| offset | 类型 | 字段 |
|---|---|---|
| 0~11 | 6×int16 LE | J1~J6 **逻辑关节角 ×10** |

⚠ **与 0x10 不是同一个坐标系**：0x13 填的是"相对本臂 Home 的逻辑角"（`ArmApi_StreamJoints` 内部经 `SERVO_OFFSET/JOINT_DIR` 映射），0x10 填的是舵机度。20~50Hz 连续发、不做轨迹规划，两端零点各自校准后逻辑角才对得上。

### 3.4 0x20 MOVE_CART（12B，笛卡尔 S 曲线）

| offset | 类型 | 字段 |
|---|---|---|
| 0, 2, 4 | 3×int16 LE | x / y / z（0.1mm） |
| 6 | int16 LE | pitch（0.1°） |
| 8 | u16 LE | v（0.1mm/s 或 0.1°/s，按固件语义） |
| 10 | u16 LE | a |

### 3.5 0x22 IK_QUERY → 0xA2（12B，先问能不能到）

请求 payload 8B：x/y/z（0.1mm i16×3）+ pitch（0.1° i16）。
应答 0xA2 = 6×int16 LE（J1~J6 目标角 0.1°，舵机度，可直接喂给 0x10）；不可达/超限位回 **NACK** 带错误码——这条命令的价值正是"先问后动"。

## 4. raw ↔ 角度换算链（0x84/0x85 的 pos_raw → 角度）

`pos_raw` 是舵机原始 12 位值，**必须走固件同款公式**（`kinematics.c:317-323`）：

```
① raw → 舵机度（0~360）:
   servo_deg = raw / 4095.0 × 360.0            （固件 servo_raw_to_deg）
   逆变换: raw = servo_deg / 360.0 × 4095 + 0.5 （deg_to_servo_raw）

② 舵机度 → 关节弧度（含方向与零点偏移）:
   rad = JOINT_DIR[j] × (servo_deg − SERVO_OFFSET[j]) × π / 180
   逆变换: servo_deg = SERVO_OFFSET[j] + JOINT_DIR[j] × rad × 180 / π
```

- `SERVO_OFFSET[j]` ≈ 180（各轴零点对应舵机度，Flash 校准值优先，未校准=180）。
- 精确对齐校准零点请用 0x85 的 `zero_raw`：`servo_deg = (pos_raw − zero_raw)/4095 × 360 + 180`（校准过的轴）。
- 0x82/0xA1 里的 J1~J6 是固件换算好的**舵机度**，上位机直接 ÷10 用，**不要**再叠加任何偏移。

## 5. 解析代码（两链路通用，payload 相同）

```python
import struct

POS_SENTINEL = -32768

def parse_status82(payload: bytes):
    """payload = 0x82 应答的 21B（CAN 重组后 / UDP rsp[3:] 切片均可）"""
    assert len(payload) == 21
    j_raw = struct.unpack("<6h", payload[0:12])
    x, y, z, pitch = struct.unpack("<4h", payload[12:20])
    flags = payload[20]
    return {
        "joints":  [None if v == POS_SENTINEL else v / 10.0 for v in j_raw],
        "xyz":     [None if v == POS_SENTINEL else v / 10.0 for v in (x, y, z)],
        "pitch":   None if pitch == POS_SENTINEL else pitch / 10.0,
        "estop":   bool(flags & 0x01),
        "traj":    bool(flags & 0x02),      # 轨迹执行中
        "read_ok": bool(flags & 0x08),
    }

def parse_detail84(payload: bytes):
    """0x84 应答：n + start_joint + n×10B，单轴/全轴同一份代码"""
    n, start = payload[0], payload[1]
    out = []
    for k in range(n):
        o = 2 + k * 10
        pos_raw, speed, load, volt, temp, hw_err, ok = struct.unpack(
            "<HhhBBBBB", payload[o:o+10])
        out.append({"pos_raw": pos_raw, "speed": speed, "load": load,
                    "volt": volt, "temp": None if temp == 0xFF else temp,
                    "hw_err": None if hw_err == 0xFF else hw_err, "ok": ok})
    return out

def enc_deg10(deg: float) -> int:
    return int(round(deg * 10)) & 0xFFFF        # 组包 0x10/0x14/0x13 时用

def build_move_joints(deg6, v_dps, a_dpss2) -> bytes:
    """0x10 payload：deg6 六轴目标(舵机度, 非目标轴填当前实际角!)"""
    p = b"".join(struct.pack("<h", enc_deg10(d)) for d in deg6)
    return p + struct.pack("<HH", int(v_dps * 10), int(a_dpss2 * 10))
```

## 6. CAN 与 UDP 的承载差异（payload 之外的唯一区别）

| 项 | UDP 网口 | CAN |
|---|---|---|
| payload 位置 | 报文 `[SEQ, CMD, LEN, payload..., CRC16]`，**payload 从 rsp[3] 开始** | 逻辑包重组后 payload，`res[1]`（can_host.py） |
| 0x82（21B）承载 | **1 个报文直接装下** | 拆 **4 帧 CAN**（首帧 `0x84`=0x80\|4 + 3 续帧），上位机按"首帧 d[0] 高位=总帧数"重组后再解 |
| 0x84（62B）承载 | 1 个报文 | 拆 8 帧（首帧 `0x88`） |
| 0x8A/0x85/0xA1/0xA2 | 1 个报文 | ≤4 帧 |
| 重组失败后果 | 无此概念 | 该包作废 + 正在重组的包一并作废 |
| 事件/心跳 | 无，全轮询 | 0x280 有心跳/TRAJ_DONE 事件（不带角度） |

**推荐**：CAN 上直接用 `tools/can_host.py` 的 `wait_response()`（自动重组）；UDP 用 §5 代码 + `rsp[3:3+LEN]` 切片。

## 7. 坑速查（解析/组包各踩过的）

1. **小端**：`76.7° → 767 → 0x02FF → 线上 FF 02`，按大端解会得到 767→76.7 变 65267→乱值。
2. **-32768 哨兵**：0x82/0xA1 的角度、xyz、pitch 都可能是它；**先判哨兵再 ÷10**。
3. **0x84 pos_raw 不是角度**：是 0~4095 raw，换算链见 §4；temp/hw_err 的 0xFF 是字段级丢读。
4. **0x10 vs 0x13 坐标系不同**：0x10 舵机度、0x13 逻辑角，混用 = 大幅乱跑。
5. **0x10 非目标轴填 0 = 乱动事故**：必须填当前实际角（或改用 0x14 单轴）。
6. **角度编码 10 倍坑**：发 90° 是 900(0x0384)，发 900 被钳到限位走满行程。
7. **速度/加速度是 u16**、0.1 单位；v=25°/s 写 250，别按 int16 有符号处理。
8. **四舍五入**：固件编码带 ±0.5 取整，上位机显示值与舵机内部 0.1° 步进可能有 ±0.05° 差，正常。
9. **0x85 的 zero_raw==0 = 该轴未校准**（固件回落 180°/raw2048），此时 §4 的校准换算不成立。
10. **0x82 的 J1~J6 已是舵机度**，直接 ÷10 使用；不要叠加 SERVO_OFFSET/JOINT_DIR 二次换算。
