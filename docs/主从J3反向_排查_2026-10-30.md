# 主从遥操 J3 反向到对侧限位 — 现象与排查结论（2026-10-30）

> 现象：主臂 J3 向下压时，从臂 J3 **朝反方向一路走到弧的另一端挡块**。
> 其他五轴（J1/J2/J4/J5/J6）表现正常，**只有 J3 表现极端**。
> 结论：**软件换算链在数学上恒等，已排除代码路径；根因落在「伺服数字 ↔ 物理转向」这一层（舵盘装配 / 舵机方向位 / 换过舵机）。**

---

## 1. 现场数据（两块板 `zi` / `L` 实测）

| 项 | 主臂（ROLE=master） | 从臂（ROLE=slave） | 判读 |
|---|---|---|---|
| `calib_zero_raw` | `[2046 2046 2048 2049 2048 2047]` ≈ 中位 | `[0 0 0 0 0 0]` = 从未记录 | 从臂 `zi` 报"未校准"**只指这一行**，不影响限位 |
| 等效 `SERVO_OFFSET[2]` | **180.0°** | **180.0°**（全 0 ⇒ 出厂中位 180） | ⭐ 两边完全相同 |
| J3 限位 raw | ~875 ~ 3083 | ~865 ~ 3085 | 基本相同，限位不是病因 |
| `L` 表 J3 | MIN 76 / MAX 271 | MIN 76 / MAX 271 | 一致 |
| `L` 表 J1 / J6 CUR | 280 / 231 | 0 / 158 | 两边**不在同一姿态**（后面判别实验要注意） |

> 关键推论：`calib_zero_raw` 全 0 ≠ 没校准过限位。Flash 里校准记录是**分字段**存的——
> `calib_min_raw / max_raw`（Phase 2 手推极限）与 `calib_zero_raw`（Phase 1 Home 零点）互不影响。
> 零点是 0 时固件按出厂中位处理（`SERVO_OFFSET=180`），**限位照常生效**，所以"未校准但限位对得上"并不矛盾。

## 2. 换算链推导：两边严格恒等

主从流帧传的不是伺服角度，而是**相对各自 Home 零点的关节角**：

```text
主臂:  joint    = JOINT_DIR[2] * (servo_m − SERVO_OFFSET_m)   = +1 * (servo_m − 180)
发帧:  int16    = joint * 10                                   (0x13 流帧, Deg10)
从臂:  servo_s  = SERVO_OFFSET_s + JOINT_DIR[2] * joint        = 180 + (servo_m − 180) = servo_m
```

代入实测 `SERVO_OFFSET`（两边都是 180.0）⇒ **`servo_s ≡ servo_m`，一步不差**：

| 主臂 J3 伺服读数 | 发出的 joint | 从臂目标伺服 | 结果 |
|---|---|---|---|
| 76° | −104.0° | 76° | 恒等 |
| 180° | 0.0° | 180° | 恒等 |
| 271° | +91.0° | 271° | 恒等 |

**换算要能致病，前提是两边 `SERVO_OFFSET` 不同。**
反例（本现象不是这种情况，但值得记住）：若从臂 J3 零点校准到 273°，则主臂 271° 会被算成
`273 + 91 = 364 → 环绕成 4°`，从臂直接冲向对侧 —— 那才是典型"零点错位型"反向。

同时排除的两项：
- J1/J2 零点记成 `2046` 而非 `2048`，偏移 179.87°，误差 **0.13°**，可忽略；
- J3 合法弧 `76~271` **不跨 0/360**，不存在 `fmod` 环绕错位。

## 3. J3 在代码里的特殊之处（为什么只有它"炸得这么彻底"）

| # | 特殊处理 | 位置 | 是否影响本次现象 |
|---|---|---|---|
| 1 | J3 历史上有**包裹弧特判**：伺服 10°~177° 为不可达禁入区，合法区是 `177→360→0→10` 跨零弧。Phase-2 手推改全行程后，实测行程几乎占满全圈（raw 23~4083）⇒ **等于没有保护死区** | `Core/Src/main.c:1405-1440`（`apply_calib_limits`） | ⭐ 方向一旦反，它有机会一路走到对侧死挡块 |
| 2 | 规划轨迹对 J3 有专门约束 `RISE_J3_DEG=-10` | `main.c:1743` 附近 | 只影响 `g` / `P 0` 轨迹，**不影响流帧** |
| 3 | 流帧链路上 J3 **没有任何**反向/偏移补偿，六轴一视同仁 | `cmdStreamJoints()` | 确认无隐藏逻辑 |
| 4 | 跳变保护允许 **25°/帧（≈750°/s）**，对"每帧都合法、整体却反向"完全不起作用 | `STREAM_MAX_JUMP_DEG` | 拦不住 |

⚠ 真正生效的限位是 `zi` 里那两行 raw（`JOINT_MIN_RAW / MAX_RAW`）；`L` 显示的是伺服度换算版。红线：**限位权威在 raw 层**，别拿 `L` 的角度直接填 `zi`。

## 4. 剩余唯一解释：伺服数字 ↔ 物理方向错位

同一个数字 `271`，在主臂上对应"肘朝下"，在从臂上对应"肘朝上" —— 换算链再正确也没用。可能出在：

| 层 | 具体 | 确认方式 |
|---|---|---|
| **舵盘装配** | J3 舵盘（或舵机本体）差 180° 装上，两臂镜像 | 见 §5 对照实验 |
| 舵机 EEPROM 方向位 | STS3215 在飞特上位机里有方向/相位选项被设成反向 | 读该 ID 配置对比两边 |
| 舵机型号/齿轮比 | J3 换过舵机、型号不同 | 看型号丝印 |

## 5. 判别实验（5 分钟，一锤定音）

**第一步：在从臂上摆两个标定点**（会开力矩，注意别夹手）

```text
sf 0            ← 先停跟随，免得主臂帧来抢
a 2 100         ← J3 走到伺服 100°
a 2 250         ← J3 走到伺服 250°
```

记下这两个姿态**肘部的物理形状**（拍照，记"朝上/朝下"）。

**第二步：手掰主臂 J3**，让它停在这两个读数上，反复敲：

```text
p 2             ← 读 raw= / servo= / rel-home=
```

**第三步：比对**

| 比对结果 | 结论 |
|---|---|
| 主臂 `servo=100` 的形状 **=** 从臂 `servo=100` 的形状 | 机械一致，方向没问题，回来查链路（少见） |
| 主臂 `servo=100` 的形状 **=** 从臂 `servo=250` 的形状 | ⭐ **镜像实锤，差 180°** |

## 6. 修法（三选一）

| 方案 | 做法 | 评价 |
|---|---|---|
| **A. 改装配（推荐）** | 任一臂（建议主臂）J3 舵盘拆下转 180° 重装，之后两臂各做一次零点校准 | 最干净；`a` / `L` / IK / 主从全部一致 |
| B. 改舵机方向位 | 飞特上位机把主臂 J3 方向位改成与从臂一致 | 不动机械，但依赖工具 |
| C. 固件补偿 | 主臂加 `mi 2 -1`（该轴发帧取反） | 最快，但把装配错误焊进软件；`a 2` 单独用时方向仍反 |

### 重装后必须做的校准（A 方案配套）

1. 两臂各自手摆到**官方 Home 姿态**（L 形），且两臂姿态必须完全一致
2. `c` 进校准向导 → `0` 记录六轴 Home 零点 → `n` 进 Phase 2 → 各轴手推到极限 → `s` 保存
3. `zi` 复查 `calib_zero_raw` / `SERVO_OFFSET` / `MIN~MAX_RAW`，两臂应接近

⚠ **两臂必须用同一种记法**：现在主臂零点 `[2046…]`（中位附近）、从臂 `[0…]`（默认 180）恰好数值一致才跟得动。
以后只要给一边在 Home 姿态记了零点（J3 会变成 ~3110 而不是 2048），**另一边必须同步做**，否则立刻回到"零点错位 93°"的老坑。

## 8. 一句话总结

> **限位一样、`SERVO_OFFSET` 一样 ⇒ 软件层不可能让 J3 反向；剩下只能是机械/舵机方向镜像。**
> 用 §5 的 `a 2 100 / a 2 250` 对照实验一次判死，再决定改舵盘（推荐）还是加 `mi 2 -1`。
