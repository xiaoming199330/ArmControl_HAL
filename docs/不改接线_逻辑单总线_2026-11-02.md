# 不改接线实现"单总线"：逻辑单总线（逐 ID 自动路由）

> 版本 **0924BA**（2026-11-02）。回答"在不改变接线（不短接 1Y/3Y、不拆 74HC126）的前提下，能不能实现单总线"。
> 相关：`docs/集成板单总线_1Y3Y短接_2026-11-02.md`（需要真单总线时看这份）、`docs/舵机总线开漏单总线_2026-11-02.md`（拆 126 的方案）。

---

## 1. 结论

| 你想要 | 不改接线能不能做到 | 说明 |
|---|---|---|
| 6 颗舵机**共用一根信号线**（线束减半） | ❌ **做不到** | 门1 输出（1Y）与门3 输出（3Y）是两个独立节点，中间隔着两个三态缓冲器。不合线就只能是两条物理总线 |
| 6 轴**当成一条总线来用**（按 ID 统一寻址、插哪都能认） | ✅ **能，且零硬件改动** | 即本文件说的"逻辑单总线"：软件把两条物理总线合成一条虚拟总线，按实测应答自动路由 |
| 采样率不变 | ✅ 能 | 两条 UART 继续**并行**，性能与双总线版完全一致（比 1Y+3Y 短接版快约一倍） |

**一句话**：物理单总线必须动线；**逻辑单总线不用动线**，用 0924BA 就有。

---

## 2. 为什么物理上合不了

74HC126D 是四路三态缓冲，本项目用其中两路：

| 门 | OE（方向） | A（输入） | Y（输出） | 去向 |
|---|---|---|---|---|
| 门1 | 1OE = **PA8** | 1A = **PB10**（USART3_TX） | **1Y = 第 3 脚** | J1~J3 三个座 |
| 门3 | 3OE = **PA10** | 3A = **PC12**（UART5_TX） | **3Y = 第 8 脚** | J4~J6 三个座 |
| 门2/门4 | 接地 | 接地 | 悬空 | 闲置 |

1Y 和 3Y 之间没有任何电气通路 ⇒ 两条总线。要让它们成为一条，只能**短接 1Y↔3Y**（或改板重新走线），没有软件办法。

反过来看也成立：**只要不改线，两条总线就都还在，而且都在正常工作**——这正是逻辑单总线能成立的基础。

## 3. 逻辑单总线怎么工作

### 3.1 已有的架构红利

整个驱动层（`servo_driver.c`）对外的所有接口都是**按关节索引**的，内部只通过一张表路由：

```c
uint8_t JOINT_BUS[6] = {BUS_A, BUS_A, BUS_A, BUS_B, BUS_B, BUS_B};
// 例如 SERVO_GetPosition(j) 内部：DXL_Read(JOINT_BUS[j], JOINT_ID[j], ...)
```

连六轴同步写 `sync_write_goalpos_by_bus()` 也是按 `JOINT_BUS[]` 分组的。**所以只要这张表填得对，6 轴在几条物理总线上对上层完全透明。**

### 3.2 0924BA 改了什么

新增 `SERVO_AutoMapBuses()`（`servo_driver.c`），上电时按**实测应答**重建这张表：

```
pass1：按现有映射逐轴 PING 一次
       6/6 命中 → 直接返回（正常开机走这条，只多 6 次 PING，亚毫秒级）
pass2：有缺失 → 对 ID 1..6 在两条总线上各探测一次，按实际位置重填 JOINT_BUS[]
```

判定规则：

| 探测结果 | 处理 | 标记 |
|---|---|---|
| 只在 Bus A 应答 | `JOINT_BUS[j] = BUS_A` | — |
| 只在 Bus B 应答 | `JOINT_BUS[j] = BUS_B` | 与默认不同则记 `moved` |
| 两条总线都应答 | 保持默认（不猜） | `?` DUP（两片舵机 ID 撞了） |
| 两条总线都不应答 | 保持默认（维持原来的"离线"报错行为） | `!` MISSING |

### 3.3 效果

- 舵机**插错座子**（ID=2 的插到了 Bus B 的座）→ 自动纠正，不用改线、不用换 ID
- 换过舵机、改过 ID → 自动认
- 布局本来就是对的 → 行为与旧版**完全一致**（pass1 直接返回，表都没动）

## 4. 命令

| 命令 | 作用 |
|---|---|
| `b` | 查看当前 bus mode **+ 六轴实际路由**（`J1=A J2=B ...`） |
| `b auto` | 重新逐 ID 探测并重建路由（**换过舵机/插错座子后不用重启**） |
| `b 0` | 重置为编译默认布局（A/A/A/B/B/B） |
| `b 1` / `b 2` | 诊断用：全部走 Bus A / 全部走 Bus B |

上电时若检测到错插，会打：

```
  [MAP] probe: online 6/6 -> J1:A J2:B J3:A J4:B J5:A J6:B
         (! = not found on either bus, ? = same ID on BOTH buses)
  [MAP] 2 axis re-routed by real reply (socket layout differs from default)
```

布局正确时（`bootlog on` 下）只打一行：

```
  [MAP] layout OK (J1-J3=Bus A, J4-J6=Bus B), no re-route needed.
```

## 5. 固件（0924BA，四种构建）

| 构建 | 适用硬件 | 大小 | md5 | 路径 |
|---|---|---|---|---|
| **`BUS_PP=1`** ⭐ | **126 在位、未短接、1kΩ→3.3V 上拉**（你的集成板现状） | 267,992 B | `fbe6d9ea` | `C:\STM32Tools\fw0924ba_pp.bin` |
| 默认（OD） | 已拆 126 且 TX/RX 短接 | 267,888 B | `117492a8` | `C:\STM32Tools\fw0924ba_od.bin` |
| `BUS_ONE=1` | 已把 1Y 与 3Y 短接 | 267,440 B | `c123429b` | `C:\STM32Tools\fw0924ba_one.bin` |
| `LINK=both` | 需要 CAN/网口运行期切换 | 271,272 B | `e0c6a4e1` | `C:\STM32Tools\fw0924ba_both.bin` |

⚠ **same-tag 陷阱**：四种构建 fw-tag 都是 `ARM-NET/BOTH-0924BA`，靠 `h` 首行的 `bus=` 字段区分：

```
fw-tag ARM-NET-0924BA ... bus=PP(74HC126)  map=auto      ← 126 在位，烧这一版
fw-tag ARM-NET-0924BA ... bus=OD(1k->3V3)  map=auto      ← 126 已拆
fw-tag ARM-NET-0924BA ... bus=PP+1Y3Y(1-wire) map=fixed(B)  ← 1Y/3Y 已短接
```

**你的板子（126 在位、未短接）必须烧 `fw0924ba_pp.bin`。** 烧默认 OD 版会让 DIR 引脚不再动作 → 126 永远关断 → 现象是扫描 0/6，看着像"固件坏了"。

## 6. 验证

```
h         → 首行 fw-tag ARM-NET-0924BA ... bus=PP(74HC126) map=auto
b         → Bus mode = 0 (NORMAL)  Route: J1=A J2=A ... J6=B
n         → Bus A: 3 servo(s)  Bus B: 3 servo(s)
nx        → crc err / tx err = 0
pv 100    → 六轴刷新稳定
```

想验证自动路由是否真在工作：**故意把一个舵机挪到另一组座子上**，敲 `b auto`，看路由表是否自动翻转，且 `s` 仍能读到六轴。

## 7. 边界与红线

1. **物理线束不会减少**。仍是一根 Bus A + 一根 Bus B。想减线必须短接 1Y/3Y（`BUS_ONE=1`）或改板。
2. **6 颗舵机 ID 必须唯一 1..6**。这是本项目既有约定（`JOINT_ID[6] = {1..6}`）。两片舵机同 ID 时 `b` 会打 `?`，用 `sid set <old> <new>` 改。
3. **`BUS_ONE` / `ROLE=master` 构建关闭该功能**（`map=fixed`）——那两种形态只有一条物理总线，逐 ID 探测会去 PING 空总线（`BUS_ONE` 下更会拉高 DIR_A，造成两路推挽对打），必须禁止。
4. **自动路由不改方向语义**。`JOINT_DIR[]` 是编译期常量，"J3 反向"这类问题它管不了——那属于舵盘装配/零点问题（见 `docs/主从J3反向_排查_2026-10-30.md`）。
5. 探测代价：仅在存在缺失时才走 pass2，最坏 12 次 PING（30ms 超时）≈ 360ms，只发生在上电一次或手动 `b auto`。

## 8. 和另外两个方案的关系

| 方案 | 改动硬件 | 线束 | 采样率 | 何时用 |
|---|---|---|---|---|
| **逻辑单总线（本文，0924BA）** | 无 | 2 根 | 100% | ⭐ **默认选这个** |
| 1Y+3Y 短接（0924AZ/BA `BUS_ONE`） | 焊一点 | 1 根 | ~50% | 必须减线束时 |
| 拆 126 + 开漏（0924AY/BA OD） | 拆芯片+短接 | 2 根或 1 根 | 100% | 拆得掉芯片时（略快，省 50µs/事务） |
