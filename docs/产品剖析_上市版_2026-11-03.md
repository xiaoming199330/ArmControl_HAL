## 1. 硬件层

### 1.1 电气拓扑

```
上位机 ──┬─ USB-TTL ──► USART6 (PC6/PC7)   控制台 115200
         ├─ 以太网 ────► RMII (PG11/13/14, PC4/5, PA1/2/7, PC1)
         └─ CAN ───────► CAN2 (PB12/PB13)

24V 电源 ──► TXS0108E (3.3V↔5V) ──► 74HC126D 四路方向切换
                              │
                    总线A: USART3 (PB10/PB11) ──► 舵机 ID 1..3
                    总线B: UART5  (PC10/PC11) ──► 舵机 ID 4..6
```

**关键引脚表**（变更历史见记忆铁律 2）：

| 功能 | 引脚 | 备注 |
|---|---|---|
| RMII TX_EN / TXD0 / TXD1 | PG11 / PG13 / PG14 | 2026-09-20 二次修正后现役 |
| RMII RXD0 / RXD1 | PC4 / PC5 | 让位后 **LED 不可用** |
| RMII REF / MDIO / CRS / MDC | PA1 / PA2 / PA7 / PC1 | |
| CAN2 | PB12 / PB13 | 已从网口腾出，**引脚上不冲突** |
| 74HC126 方向脚 | PA8 / PA10（`0924AX` 起由 PE8/PE10 改） | PE11 仍为 E-Stop |
| 控制台 USART6 | PC6 / PC7 | 恒常通 |
| 限位开关 | PG0–PG5 | |
| 主从链路 UART4 | — | 波特率可配 |

> **上市注意**：现役 RMII 脚位与旧版文档"PB13=ETH_TXD1 ⇒ CAN/网口物理互斥"的断言**互相矛盾**。旧红线 39/40 自相矛盾，已于 09-20 二次修正破除。出厂文档必须以本表为准。

### 1.2 舵机与总线

- **STS3215**：Feetech 总线舵机，0–4095 对应 0–360°，1 Mbps，TTL 半双工。
- **PID 寄存器在 EEPROM**：P=21、**D=22**、**I=23**（D 在 I 之前，非常见 P-I-D 顺序，三处默认值副本必须同步）。
- **EEPROM 默认上锁**：直接写 21/22/23 会被**静默丢弃**。正确写入序列必须是 `Torque OFF → Lock(addr55)=0 → 写 P/D/I → RESET → Lock=1 → 恢复 RAM(加速度/GoalSpeed/TorqueLimit) → 回读校验`，全程该关节**失力约 0.6 s**。
- **写入指令 `INST_WRITE(0x03)` 是正确的**——Feetech 官方协议手册中改 ID 的示例同样使用 0x03 写 EEPROM 区，`INST_REG_WRITE(0x04)` 是"延迟执行需配 ACTION"的另一语义。仓库中 `INST_REG_WRITE` 零调用并非缺陷。
- **单总线三方案**（详见 `docs/集成板单总线_1Y3Y短接_2026-11-02.md`）：

| 方案 | 代价 | 适用 |
|---|---|---|
| ① 逻辑单总线（`0924BA/BB`） | **零改线**，两条 UART 并行 | ✅ 推荐默认 |
| ② 物理短接门1 1Y ↔ 门3 3Y + `BUS_ONE=1` | `DIR_A` 须永久低，**禁烧双总线固件**（推挽对撞可烧 126/舵机），采样率约减半至 25–35 Hz | 仅在客户坚持单根线时 |
| ③ 开漏 `AF_OD` + 1 kΩ→3V3 | 需拆 126，省 50 µs/事务 | 126 已拆除时 |

**层间的三处破例（上市前应记录或修复）**：

1. `arm_control_api.c` **反向依赖** `main.c` —— 它 include `arm_main_exports.h`，依赖 main.c 导出的 19 个函数。抽象层依赖实现层，方向反了。
2. `arm_runlog.c:9` 裸 `extern UART_HandleTypeDef hconsole;` —— 工具层反向依赖 main.c 全局句柄。
3. `arm_control_api.c:31` 裸 `extern uint8_t correction_pending;` —— 绕过 `arm_main_exports.h` 的登记纪律。

## 3. 算法层（教学卖点）

### 3.1 逆运动学（IK）

- **策略**：J1 = `atan2(y,x)` 直解 → 2R 闭式解析解（肘上/肘下两解）→ 解析解 FK 校验失败则 **4 起点 CCD 兜底**（`{0,0,0}` / `{aim*0.5,0,0}` / `{fold,fold,-fold}` / `{aim*0.3,aim*0.3,aim*0.4}`）。
- **CCD 只保位置，俯仰自由** —— 这是刻意的（关节自由度多于任务维度）。
- **不是 DLS**：全仓库无阻尼最小二乘 / 伪逆 / 雅可比求逆。
- **几何常数**（`kinematics.h`，0924AD 实测标定）：`ROBOT_BASE_H`=63.13、`J2_OFF_Y/Z`=26.70/46.92、`L_UPPER`=112.45、`L_FORE`=134.13、`L_WRIST`=61.55、`L_TOOL`=104.35、`ARM_MAX_REACH`=412.48（注释写 418.80 **有误**）。
- ⚠ **静默降级**：解析解失败时不报警，直接转 CCD，用户会看到"位置对、姿态可能错"。

### 3.2 轨迹规划（七段 S 曲线）

jerk-limited 七段式：jerk 上升 → 恒加速 → jerk 下降 → 恒速 → 镜像减速三段。三种自适应降级：完整七段 / 五段（无恒速）/ 三段（距离过小压缩 jerk）。

- 插值 **200 Hz**，下发 **50 Hz**（每 4 tick）。
- 以最大位移关节为基准，其余按 `ratio = dist/max_d` 比例缩放（同步运动）。
- ⚠ 早期文档与实现按"梯形"估算时间，实际已是七段 S 曲线；**尚无"梯形 vs S 曲线"的对照实测**。

### 3.3 重力补偿（**当前为占位，需如实告知用户**）

- **J2 重力前馈已整体移除**（`main.c:1470-1472`），`gc.k` 参数保留为占位，`G k` 命令自打印"占位, 不影响任何运动"。
- 唯一实现的前馈是 **PWM 开环重力补偿**，只存在于示教（teach）模式的悬浮示教流程。
- **自适应修正**（`main.c:10642-10776`）是当前唯一闭环：到位后每 500 ms 一轮，按 `error × corr_gain[j]` 累积修正偏移（变比例控制器，**不是 PID**）；带坏读滤波（跳变 >8° 跳过）、单轮 ±3° 钳制、累积 ±30° 钳制；增益自适应（符号翻转 ×0.5 / 有进展 ×1.25 / 停滞 ×1.4）。
- ⚠ **自适应修正从未被端到端验证**：两份 `tune_results` 报告均警告"未检测到修正完成/停止"，修正轮数为 0，corr 事件数为 0。

## 7. 上市前必须处理的技术债

按优先级排序，每项都给了证据位置。

| # | 级别 | 问题 | 证据 | 建议动作 |
|---|---|---|---|---|
| 1 | 🔴 | **PID 参数开机不自动下发**：`SERVO_InitJoint` 的 `if (mode != 0)` 导致舵机出厂 Mode=0 时整段 EEPROM 写入被跳过，Flash 里的 PID 永远不会写进舵机，必须手工 `Y J` | `servo_driver.c:619` | 改为无条件执行 EEPROM 配置，或在 `pid_load_startup()` 后主动调 `SERVO_ApplyPidToEeprom()` |
| 2 | 🔴 | **固件"自动调 PID"是无效代码**：自适应修正检测到振荡/停滞时调 `set_pid_gain()` → 裸写上锁 EEPROM → 被舵机丢弃。日志 "J2 auto-tune: D_Gain->16" 是**误导性输出** | `main.c:10694-10725` + `main.c:1691` | 改用 `SERVO_ApplyPidToEeprom()`（含失力窗口，不能在修正循环里直接调），或直接删除该分支并去掉日志 |
| 3 | 🔴 | **IK 双实现、限位判据不同**：`cmdSolveIKPoint`(main.c:3906) 用 `raw_in_range`，`ArmApi_IkQuery`(arm_control_api.c:455) 用 `JOINT_MIN/MAX` ⇒ 同一目标点**文本命令与协议命令结果可能不一致** | 两处代码 | 先写实机对比用例集，再统一到严格版 |
| 4 | 🔴 | **`arm_params` 容量已满 24/24**：加第 25 项会因 `capacity < AP_TABLE_LEN` 导致 `count=0` 落盘，开机时**全部 24 个算法参数静默回默认值**（PID/限位不受影响） | `pid_flash.h:11` + `arm_params.c:132` | `PID_FLASH_ARM_PARAM_MAX` 提到 32，并给 `Snapshot` 加溢出保护 |

## 9. 代码重构路线（详见 `重构架构_分层方案_2026-11-03.md`）

**目标**：`main.c` 从 10,980 行压到 **≤1,500 行**，只保留 `main()` + 主循环调度 + TIM2 回调。

**Sprint 0（准备，0.5 天）**：修 `boot_verbose` 双定义；把 `ARM_ONE_BUS_BUILD`/`ONE_BUS*`/`NET_BLOCK_CAN_CMDS()`/`SID_BUS` 提升到新头 `arm_build_config.h`；`arm_runlog.c` 改 include。

**Sprint 1（低风险搬运，3–4 天）**：`master_link.c`（整块编译期隔离，最安全）→ `app_led.c` → `app_console.c` → `motion_limits.c` → `motion_plan.c`。验收：**从臂构建产物逐字节相同**。

**Sprint 2（中风险，5–7 天）**：`stream_follow.c` / `motion_settle.c` / `motion_multipoint.c` / `teach_mode.c` / `calib_wizard.c` / `rc_buttons.c`。纪律：**只搬不改行为**，每搬一个立刻实机回归。

**Sprint 3（接线注册表，5–8 天）**：`arm_commands.c` 表驱动分发 + `cmdHelp` 读注册表。先"旧 switch 与新表并行跑一个版本做 diff"。

**Sprint 4（消除重复，5–7 天）**：统一 IK → 合并状态读取 → 删除 `arm_main_exports.h`，让 `arm_control_api.c` 成为真正唯一上层入口。
