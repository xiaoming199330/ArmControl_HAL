# 主从臂联调步骤（UART4 串口直连，不用 CAN）

日期：2026-09-11
固件：从臂 `build/ArmControl_HAL.bin` / 主臂 `build_master/ArmControl_Master.bin`

---

## 一、先分清三条线（互不相干）

| 用途 | 引脚 | 主臂 | 从臂 |
|---|---|---|---|
| **两板链路** | PA0/PA1（UART4） | 有此线 | 有此线 |
| 舵机总线 | PB10/PB11（USART3） | 不用 | Bus A，J1-J3 |
| 舵机总线 | PC12/PD2（UART5） | **单总线，6 颗全在这** | Bus B，J4-J6 |

主臂 6 颗舵机全并联在 UART5 一条开漏线上；从臂仍是原来的双总线。

## 二、步骤 1 — 主臂离线校准（**链路先别插**）

> ⚠️ `master_service()` 是**无条件运行**的：主臂一上电就按 33ms 往外发流帧。
> 如果你插着链路做校准，手动摆动的每个姿态都会被送给从臂，从臂会跟着乱动。
>
> **现在不用拔线了**：主臂敲 `mf 0` 暂停转发 → 校准 → `mf 1` 恢复。
> （或者从臂侧 `sf 0` 忽略，效果一样。）

1. 只给**主臂**上电（从臂断电或链路不插）。
2. `c` → 逐关节记录 zero / 挡块极值 → `s` 保存 → **重启生效**。
3. 重启后核对 `Limits:` 一行与实机行程吻合。
4. `n` 确认 `Bus B: 6 servo(s)`（扫描已按主臂角色改成扫全 6 个 ID）。

> 主臂 Flash 里若残留旧的 `Home dock` 数据（开机打印会显示），建议在校准前清一遍，
> 避免半新半旧混用。

### 校准一致性自检（务必做）

校准 Phase 1 的定义是「**摆官方 Home 姿态（L 形），按 `0` 记录零点**」
⇒ 推论：**在 L 形姿态下，6 个逻辑关节角都应 ≈ 0。**

`ms` 现在两块板都能敲，打的就是 **`rel-home` 逻辑关节角** ——
与主臂 0x13 帧里传的量、与从臂 `p J` 里的 `rel-home` 完全同一语义
（注意 `pv` 打的是**舵机度**，不是这个量，别拿它对比）。

1. **单板自检（先做这个）**：把主臂摆成官方 Home L 形 → `ms`
   → 6 个数应**全部落在 ±2° 内**。哪一轴明显不为 0，就是那一轴的零点没测对。
2. **双板对拍**：把两臂摆成**同一物理姿态**（都收拢到机械限位最省事），
   主臂 `ms` 与从臂 `ms` 各来一次，**逐轴差值应 ≤ 1~2°**。
   - 某轴差一个**恒定值** → 那一端的 zero 偏了，回去重做 `c` Phase 1
   - 差异没规律 → 先确认是不是真的摆成了同一姿态

参考值（从臂折叠收纳位的逻辑角）：
`J1≈+0.4  J2≈−102.8  J3≈+90.6  J4≈+73.4  J5≈−5.3  J6≈−55.4`
—— 两臂都收拢到位时，主臂 `ms` 应读出接近这一组数。

## 三、步骤 2 — 接线（3 根，必须交叉）

| 主臂板 | | 从臂板 |
|---|---|---|
| PA0（UART4_TX） | → | PA1（UART4_RX） |
| PA1（UART4_RX） | ← | PA0（UART4_TX） |
| GND | ↔ | GND |

- 115200 8N1，两端 3.3V 推挽、线短 → **不用串阻，不用上拉**。
- **必须交叉**：两板同款 F407，UART4 都在 PA0/PA1，直连就是 TX 对 TX。
- GND 一定要接（两边各自供电时尤其重要）。若两块板都由同一个 PC 的 USB 供电，
  地已经通过 USB 连通；但只要舵机用自己的电源，**GND 那根线照样要接** ——
  舵机电流会灌进地线，地电位一抖，接收端的采样阈值就漂。
- 信号线尽量**远离舵机动力线和舵机数据线**（舵机总线是 1 Mbps，串扰很凶）。
  杜邦线长度控制在 20 cm 以内。
- **从臂 RX（PA1）固件里已加上拉**（2026-09-11）：这样"RX 悬空"会变成恒定的高
  电平 = **0 字节**，而不是"一直在收字节但帧头/CRC 全不对"的假象。
  外部推挽驱动时上拉被覆盖，对正常通信无影响。

### 接线三步自检（按顺序做，能一步定位到哪一段）

**① 主臂自环 —— 证明主臂的 TX/RX 和固件是好的**
拔掉接到从臂的两根信号线，用一根杜邦线把**主臂的 PA0 与 PA1 短接**，上电，敲 `lk`：
- `stream frames` 在涨、`CRC err 0` → 主臂自身完好，问题在"两板之间"
- 还是 `0` → 主臂这两个脚本身有问题（没引出 / 被别的外设占了）

**② 拔线看 `in bytes` 停不停 —— 判断 RX 到底接在哪**
在从臂上敲 `lk` 记下 `in xxx bytes`，然后拔掉**接在从臂 RX(PA1) 上的那根线**，再敲一次：
- 数字**停住不动** → 那根线确实是主臂的 TX，接线方向对，问题在电气质量（看 FE/NE）
- 数字**继续涨** → 从臂 RX 根本没接在主臂 TX 上（悬空捡串扰 / 接到别处了）

**③ 看主臂能不能收到从臂 —— 反方向单独验**
从臂 `lk` 显示 `NACK sent err=2` 就是在发。这时在主臂敲 `ms`：
- `Master RX` 有帧在涨 → 反方向也通
- 一直是 `0 frames` → **从臂→主臂那根线不通**（线错 / 脚错），
  说明两根信号线里至少有一根接错了

## 四、步骤 3 — 姿态对齐（最容易踩的坑）

从臂有单帧跳变限制 `STREAM_MAX_JUMP_DEG = 25°`，判据的基准是
**"进入流模式那一帧读到的从臂实际位置"**（不是主臂、也不是上一次目标）。

- 若主臂与从臂起始姿态**单轴相差 > 25°** → 从臂**每一帧都拒**，而且被拒时
  `stream_prev` 不更新 ⇒ 会**一直拒下去**。
  现象：从臂控制台刷 `Stream reject: Jx jump N deg (> 25)`。
- **做法**：上电前把两臂摆到同一姿态。同款臂几何一致，**都收到折叠位最省事**。
- 已经踩了也不怕：断电 → 把两臂摆一致 → 重新上电。

## 五、步骤 4 — 上电顺序与验收

1. **从臂先上电** —— 自检、抱闸保持姿态。应打印 `Bus A: 3 servo(s)  Bus B: 3 servo(s)`。
2. **主臂再上电** —— 应打印 `*** MASTER ROLE (ARM_MASTER_BUILD) ***`、`Torque OFF x6`、
   `Forwarding 0x13 @33 ms (~30 Hz) on UART4 (PA0/PA1).`
3. **主臂控制台敲 `ms`** → 看 `frames sent` 是否在涨。
4. **从臂控制台敲 `lk`** → 看 `stream frames` 是否在涨、`rejects(NACK)` 是否为 0。

### 判定表（`lk` 现在按层次给诊断，不用猜）

`lk` 逐层打印：**收到多少字节 → 组成多少帧 → 其中多少 CRC 错 → UART 硬件错误
（FE/NE/ORE）→ 实测字节率 → 最近一帧的 cmd 与原始字节**。

```
Link UART4 (PA0/PA1 @115200): idle
    follow: ON (sf 0 to pause)
    in 16119 bytes -> 82 frames (CRC err 82), responses 0
    uart err: FE(frame)=0 NE(noise)=0 ORE(overrun)=0
    rate: 576 B/s (delta 4698 B / 8156 ms), expect ~576 B/s
    last frame: cmd=0x13 seq=157 len=12 CRC=BAD
    raw: AA 55 9D 13 0C E9 FF 5B FC A5 21 0C 7F 6D FF 6E FF AA 55
    stream frames: 0, rejects(NACK): 82, overwritten: 0
    NACK sent err=2, NACK received err=0
```

| `lk` 显示 | 结论 |
|---|---|
| `stream frames` 在涨、`rejects` 不涨 | ✅ 链路通，直接 `sf 1` |
| `in 0 bytes` | ❌ 线上完全没信号：主臂没在发 / 线没接 / 脚插错 / **从臂 RX 悬空**（RX 已加上拉，悬空就是恒高 = 0 字节）。先在主臂敲 `ms`，确认它显示 `PA0/PA1`（固件是不是最新版） |
| 有字节但 `frames 0` | ❌ 帧头/长度不成立：波特率、接线（TX-TX 接反）、串阻 |
| `CRC err == frames` | ❌ 帧到了但没一帧合法 —— 靠下面两个新字段定位到具体物理原因 |
| `last frame cmd=0x7E / 0x7F` | ❌ 收到的是**回包帧**：链路接成回环，或两端在互相回 NACK |
| `last frame cmd=0x13 CRC=BAD` | ❌ 主臂流帧到了但被改坏 |

#### 新字段 `uart err`：把"物理原因"拆开（2026-09-11 加）

STM32 UART 自己就有三个硬件错误标志，`lk` 现在把它们也读出来了 ——
**这是区分"噪声"和"丢字节"和"波特率"最直接的证据**：

| 计数在涨 | 含义 | 先查什么 |
|---|---|---|
| `FE`（帧错误，停止位采样不对） | 位宽不对 | **波特率失配**（两端晶振不同？）或电平幅度不够 |
| `NE`（噪声错误，采样点电平不稳） | 线上有干扰 | **串扰**（线挨着舵机动力线）、**没共地**、线太长 |
| `ORE`（接收溢出丢字节） | 本端取数不及时 | 丢字节会让**后面整段帧错位**：表现为"帧头难得找到，但捞出来的字节是对的" |

⚠️ 这三个数是**按字节**累加的（一个坏字节可能同时置 FE+NE）。要"先读 SR 再读
DR"才能清标志，顺序写在 `UART4_IRQHandler` 里，改了 ISR 别把顺序弄反。

#### 新字段 `rate:`：实测字节率

期望 **576 B/s**（19 字节/帧 × 30 Hz）。**第一次敲 `lk` 不出这行**（没有基准），
之后再敲就出 —— 数值是**与上次 `lk` 之间的增量**，比"开机至今均值"更能反映当下。

| `rate` | 含义 |
|---|---|
| ≈ 576 B/s | 字节总数对得上 → 波特率基本 1:1，问题在**位错 / 丢字节**（看 FE/NE/ORE） |
| 明显偏低（< 400） | 线上在**丢字节**（干扰 / ORE），或主臂发得比 30 Hz 慢 |
| 明显偏高（> 750） | **两端波特率不成 1:1**（典型原因：两块板晶振不同），或线上有额外流量 |

最后一行的自动结论对应四种情形：`线上 0 字节` / `有字节但组不成帧` /
`帧结构成立但 CRC 全错` / `收到非 0x13 帧`；FE/NE 非零会指向**电气质量**，
ORE 非零指向**丢字节**，三者全零但 CRC 仍全错则直接提示**优先怀疑波特率不成 1:1**。

#### 用 `raw` 自证"格式对不对"

`raw` 里 `AA 55 SEQ 13 0C` 之后的 **12 字节就是 6 个关节角**（小端 i16 ÷ 10）。
把它解出来和主臂 `ms` 的数字对照：

- **大部分能对上** ⇒ 帧格式、字节序、标度、校准偏移全对，只是**个别字节在传输中被打坏**
  （→ 物理层排查，别再动协议代码）
- **完全对不上且成对错位** ⇒ 帧头是假阳性，帧流本身错位了（→ 查丢字节 / 波特率）

⚠️ **`rejects(NACK)` 涨 ≠ 限位/桌面在拒。** 它只统计"我方回了 NACK"，
包含 CRC 错、未知命令、回包帧三类。**真正的拒绝原因看 `NACK sent err=`**：

| err | 含义 |
|---|---|
| 1 | 参数非法（帧长不对） |
| 2 | CRC 校验失败 |
| 4 | 限位 / 桌面 / 立柱 / 跳变被拒 |
| 5 | 急停（PE11） |
| 7 | 舵机总线读取失败 |

主臂侧敲 `ms` 也能看到从臂的回应：`Master RX: N frames from slave (last NACK err=M)`
—— 主臂不用跑过去看从臂屏幕就知道从臂为什么拒。

### 现场开关（联调手感，2026-09-11 新增）

| 命令 | 在哪块板 | 作用 |
|---|---|---|
| `ms` | **两块板都行** | 打 6 轴 `rel-home` 逻辑角（主臂构建另带 `forwarding ON/OFF` + `frames sent` / `suppressed`）。**摆同一姿态两边各敲一次即可对拍校准一致性** |
| `mf 0` / `mf 1` | 主臂 | **暂停 / 恢复转发**。`mf 0` 后链路静默，主臂仍可自由拖动、`ms` 仍能读数。上电默认 ON |
| `ma 0` / `ma 1` | 主臂 | **只读 / 主动模式**。`ma 1` 上力矩并放行 `g`/`m`/`P`（可精确摆位并保持）；`ma 0` 释放回手拖。上电默认 `ma 0`（只读）|
| `lk` | 从臂 | 看链路：`follow ON/OFF` + `stream frames` / `rejects(NACK)` / `overwritten` |
| `sf 0` / `sf 1` | 从臂 | **暂停 / 恢复跟随**。`sf 0` 立刻退出流模式并忽略后续流帧，**从臂停在当前位置自锁**。上电默认 ON |

**推荐开机序列**（彻底避开"姿态不对齐就永久拒帧"）：
1. 从臂先上电 → `sf 0`（先别跟随）
2. 主臂上电 → `ms` 确认在发
3. 从臂 `lk` 确认收到（此时 follow **OFF**，`rejects` 不该涨 —— 帧被静默忽略）
4. 把两臂摆到同一姿态 → 从臂 `sf 1` 开始跟随

这个序列下，即使一开始姿态差很多也不会被拒到"粘住"，因为基准是在 `sf 1` 那一帧才建立的。

### 主臂的「只读 / 主动」模式（2026-09-11 新增）

**默认 `ma 0` = 只读**：主臂拒绝一切运动命令（`g`/`m`/`P`/`a`…），
`master_service()` **每秒重申一次六轴 Torque OFF**，所以它能被自由拖拽。
这是刻意设计 —— 主臂是被人扶着的，一条误发的轨迹会让它突然上力矩甩出去。

所以如果你在主臂上敲 `g`，会看到：

```
IK: x=280 y=0 z=250 -> J1=179 J2=139 ...     ← IK/FK/路径全部算完且正确
Safe path: direct (FK z-check OK).
MASTER role: read-only (ma 0). Send 'ma 1' to allow motion.   ← 只在执行前被拦
```

**这不是故障**，拦截点在 `cmdMove()` 入口。要让它动：

```
ma 1      → 上力矩 + 放行运动命令，主臂保持当前位姿，之后 g/m/P 都能驱动它
ma 0      → 停轨迹 / 清 swing / 释放力矩，回到手拖
```

`ma 1` 的实现细节（为什么不会"弹一下"）：上力矩**之前**先逐轴把 GoalPos 写成
【当前位置】。因为舵机上力矩会立刻朝"当前目标位"跑，而主臂从来没写过目标位
（可能还是上电置中的 raw 2048）—— 不先对齐目标位就直接上力矩，臂会猛地甩出去。

⚠️ **`ma 1` 时转发照旧**：主臂自己动了，从臂会**跟着一起动**。
这正好能用来"用命令驱动从臂"，但也要意识到从臂不会停在原地。

## 七、安全边界

| 情形 | 行为 |
|---|---|
| 从臂急停 PE11 拉低 | `IsEStop()` → 每帧返回 2（NACK），从臂完全不动。**硬手段** |
| 断流 > 500ms（`STREAM_TIMEOUT_MS`） | 从臂退出流模式；位置模式自锁保持最后目标，**不会失力砸臂** |
| 想停止跟随 | **从臂 `sf 0`** 立即停住（软开关）；也可拔链路/关主臂，500ms 后自动冻结 |
| 想暂停主臂发送 | **主臂 `mf 0`** 链路静默（主臂仍可拖动），`mf 1` 恢复 |
| 主臂要自己动（`ma 1`） | 上力矩前先把每轴 GoalPos 对齐【当前位置】→ 不会弹一下。**此时人手必须离开臂**，且转发仍在 → 从臂会跟着动 |
| 主臂想回到手拖 | **主臂 `ma 0`** → 立即 `Trajectory_Stop()` + 清 swing/校正 + Torque OFF |
| 从臂执行任何轨迹命令（`m`/`z`…） | 内部 `cmdStreamExit()` 主动踩掉流模式 |

## 九、【2026-09-11 18:10 实测】CRC 全错 —— 数据已把范围压到"物理层"

### 现象（从臂 `sf 1` → `lk`）

```
Link UART4 (PA0/PA1 @115200): idle
follow: ON (sf 0 to pause)
in 10873 bytes -> 46 frames (CRC err 46), responses 0
uart err: FE(frame)=1359 NE(noise)=10868 ORE(overrun)=0
last frame: cmd=0x5B seq=105 len=13 CRC=BAD
raw: AA 55 69 5B 0D EB FF 30 FD B7 20 0E FD 7F 4D FF 9D DD EA D7
stream frames: 0, rejects(NACK): 46, overwritten: 0
NACK sent err=2, NACK received err=0
```

### 三个"不可能是软件问题"的证据

**① 字节数分毫不差。** 一帧 = 头(2)+seq(1)+cmd(1)+len(1)+payload(12)+CRC(2) = **19 字节**
（`Aproto_BuildFrame(..., pl, 12, ...)`，main.c:2095）。
`10873 ÷ 19 = 572.2 帧` → 30 Hz 下正好 **≈19.1 秒**的流量。
**⇒ 一个字节都没丢、没多。** 线是通的、方向是对的、没有断线、`ORE=0` 没丢字节，
波特率也不是差到离谱（差得多连字节都切不出来）。

**② 只有 5 个字节采样干净。** `NE=10868` vs `bytes_rx=10873` ⇒ **10873 个字节里只有 5 个
没有噪声标志**。这不是"偶发干扰"的量级（正常短线偶发也就百分之几），而是
**几乎每一位的采样都被扰动** —— 系统性电气问题。

**③ 字节边界大体成立。** `FE=1359 (12.5%)`、`frames_any=46` ⇒ 停止位偶尔错，但接收端仍能
正确切分大部分字节；且 46 次真锁到了 `AA 55`（纯随机噪声下 10873 字节里期望只锁到
0.17 次，所以这 46 次是真表头）⇒ **波特率基本正确**。

**T2 看主臂侧的接收统计（几乎免费）。** 主臂敲 `ms`，读 `Master RX: N frames from slave

### 11.1 新证据（用户实测 `ms`）

⇒ "一半的帧因读失败被抑制"这条假设**死掉**。

### 11.2 一个可疑的整数比

`master_tx_ok` 与 `bytes_rx` **同起点**（都在 `LinkProto_Init()`/开机清零）：

| 项 | 值 |
|---|---|
| 主臂已发送 | 4583 帧 × 19 B = **87,077 B** |
| PA1 实际收到 | **43,959 B** |

`43959 B` 里只凑出 16 个假 `AA 55`（`cmd=0x01/0x0C`，不是我们的 `0x13`）。

### 11.3 一条硬性物理约束（这是本轮的关键推论）

**自环 = 同一颗 MCU、同一个 UART 外设、同一个 BRR 寄存器。**
所以 TX 与 RX **不可能**波特率失配 —— 波特率假设在自环场景下**被物理排除**。
而 3~5 cm 的杜邦线、CMOS 推挽输出、无负载，本该是教科书级干净波形（NE≈0）。

⇒ 如果 PA1 上**每一个字节**都带 NE，那只可能有两种情况：

| # | 情况 | 现象是否符合 |
|---|---|---|
| A | **自环跳线没有真正搭在 PA0/PA1 上**（搭错排针 / 杜邦头没通 / PA1 悬空） | ✓ 与 TX 同步（靠串扰感应）、NE=100%、组不成帧 |
| B | **PA0 网络上有第二个驱动器在打架** | ✓ 节点电平被顶到逻辑阈值（≈1.65 V）附近 ⇒ 每一位采样都在跳变沿 ⇒ NE=100% |

**情况 B 最可能的来源：通往从臂的那根线还插着，而且是"直通"接法（主臂 PA0 ↔ 从臂 PA0）。**
两端 PA0 都是 AF 推挽输出 ⇒ 两个输出对顶，节点被拉到中间电平；而两端 PA1 都是输入、线上没人驱动
⇒ 它变成一根紧贴"打架线"的天线 ⇒ 收到的字节与 TX 同步、比例约一半、全是 NE、永远组不成帧。
**这也同时解释了为什么"自环测试"也是 NE=100%** —— 如果做自环时那根线没拔。

### 11.4 新增命令 `mg` —— GPIO 级自环测试（不经过 UART）

`ml`/`lk` 仍受 UART 采样与解析影响，回答不了最底层的问题。`mg` **完全不走 UART**：
把 PA0 当普通推挽输出、**PA1 当"输入 + 内部下拉"**，直接读 PA1 跟不跟；再反向做一遍。

> 用**下拉**而不是浮空：线没接时 PA1 读到的是**确定的 0**，不会被悬空骗。

```
mg          ← 主臂板，插好自环线; 约 12 ms 完成
```

| 输出 | 判决 |
|---|---|
| 两向都 `low=0 high=1` | **通路完好** —— 线在直流层面是通的 ⇒ 问题只在 UART 波形/负载/串扰 |
| 两向都 `low=0 high=0` | **断路** —— 跳线没真正连到 PA0/PA1（或那两个排针不是 PA0/PA1） |
| 两向都 `low=1 high=1` | **恒高** —— 被外部强上拉/短路到 VDD |
| 其它 | **异常/打架** —— 有第三个驱动源，**重点怀疑从臂那根线还插着（PA0↔PA0 对顶）** |

跑完自动把 PA0/PA1 恢复成 UART4 的 AF8 配置（只动 GPIO，不碰 UART 外设）。

### 11.5 本轮的执行顺序（比上一轮更靠前）

1. **先拔掉通往从臂的整根线**（两端都拔；从臂最好断电），**只留主臂自环跳线。**
   不做这一步，`ml`/`lk` 的数据都会被"对顶/天线"污染。
2. `mg` —— 30 秒，**直接回答"线到底通不通"**，与 UART 无关。
3. `ml` —— 通路确认后在**隔离环境**里测位级质量。
4. `ms` —— 看 `Master TX: N frames sent` 增速；自环期间也在涨说明发帧链路正常。

### 11.6 顺带要确认的一件事

**你的主从线是"交叉"还是"直通"？** 协议要求主臂 PA0(TX) → 从臂 PA1(RX)。
若实际是 PA0↔PA0 / PA1↔PA1 的**直通**线，两个 TX 会对顶、两个 RX 都没人驱动 ——
**这条线本身永远不可能工作**，而且会精准产生上面所有症状。

## 十二、【2026-09-14 15:35 第三轮】真凶：**自环跳线把主臂 PA0 与从臂 PA0 并到了同一节点**

### 12.1 实测输出

```
mg
  PA0 drives : PA1 read low=1 high=1
  PA1 drives : PA0 read low=0 high=1
  -> [异常/部分] 电平跟不住或不一致 —— 有第三个驱动源或在互相打架。

ml   (200 帧)
  [ml] 快照: bytes=7578 NE=7578          ← 自环常态下 NE 就已经是 100%
  expected on wire : 200 frames = 3800 bytes
  actually sent    : 200 frames (HAL_UART_Transmit OK)
  rx bytes delta   : 2035  (53% of expected)
  rx NE / FE delta : 2035 / 819
  CRC-OK loopback  : 0 frames
  -> [D 通路在·位级被毁]
```

### 12.2 这两个输出为什么指向同一个物理原因

**① `PA0 drives : low=1`** —— PA0 的**推挽**输出拉低，PA1 却读到高。
此刻 PA1 是「输入 + 40 kΩ 内部下拉」，它读到 1 意味着外部源至少供流 ~80 µA；
而**能顶住 PA0 推挽输出**（8 mA 级）的，**只有另一个主动驱动器**——
被动上拉做不到：10 kΩ 拉到 5 V，PA0 一拉低节点就只剩 ~10 mV，照样读 0。

**② `PA1 drives : low=0 high=1`** —— PA0 跟得住 PA1 ⇒ 两根脚之间**确实有导电通路**。

①+② 合起来只剩一个解释：**两脚在同一条线上，而这条线上挂着第二个推挽输出。**
节点被顶在逻辑阈值附近 ⇒ 每一位的采样点都落在跳变沿 ⇒ `NE=100%`；
两个异步数据流互相覆盖 ⇒ 只能收到约一半字节（实测 **53%**）；⇒ **0 个合法帧**。

### 12.3 第二个驱动器是谁 —— 用「交叉线 + 自环跳线」一算就出来

只接交叉线、**不插**自环跳线时，是两个干净的独立节点：

```
N1 = 主臂 PA0(TX 输出) + 从臂 PA1(RX 输入)     ← 正确链路
N2 = 主臂 PA1(RX 输入) + 从臂 PA0(TX 输出)     ← 正确链路
```

**一旦把 PA0↔PA1 自环跳线插上，N1 与 N2 合并成同一个节点：**

```
M = 主臂 PA0(推挽输出) + 主臂 PA1(输入)
  + 从臂 PA0(推挽输出) + 从臂 PA1(输入)
```

⇒ **主臂与从臂的两个 TX 被并到同一根线上对顶。** 主臂 30 Hz 发帧、从臂收到残帧后回 NACK，
两个**异步推挽输出**持续打架 ⇒ 节点绝大多数时间停在阈值 ⇒
每字节 NE、只收到约一半字节、永不组帧。**已观测的每一个数字都对上了。**

> **⇒ 之前所有"自环"数据（含 1,111,542 字节 / NE=100%）都是在「跳线 + 从臂链路同时插着」
> 的条件下测的，是测量布置自己制造的假象，不是从臂链路的地弹。**
> "地弹"这条结论至此失去了它最后一条支撑证据。

### 12.4 `mg` 已增强：直接判「是不是同一个电气节点」

新增**基线**与**每一步的 `GPIOA->IDR`**。关键点：**输出脚的 IDR 仍然反映引脚真实电平**，
所以把 PA0 配成推挽输出低之后，读 IDR 就能看出"驱动到底有没有生效"：

```
baseline  (PA0/PA1 都输入+下拉): IDR=0x????  -> PA0=? PA1=?
PA0 drives: PA1 read low=? high=?
   IDR low =0x???? (PA0=? PA1=?)  high=0x???? (PA0=? PA1=?)
PA1 drives: PA0 read low=? high=?
   IDR low =0x???? (PA0=? PA1=?)  high=0x???? (PA0=? PA1=?)
自检: 向1拉低时 PA0=? PA1=? / 向2拉低时 PA0=? PA1=?   (0=低 1=高)
```

**向 1 拉低（PA0 推挽输出低）时读 IDR，三种结果三种结论：**

| IDR 里 | 判决 | 含义 |
|---|---|---|
| PA0=0, PA1=1 | **不是同一个节点** | PA0 驱动成功但 PA1 没跟上 ⇒ 跳线**没落在 MCU 的 PA0/PA1 上**；PA1 是被外部别的东西顶高的 |
| PA0=1, PA1=1 | **PA0 被顶住** | 连 PA0 自己都被顶回高 ⇒ 节点上有**更强的驱动源**（对顶） |
| PA0=0, PA1=0 | 跟随正常 | 通路完好（两向都如此才是真完好） |

### 12.5 本轮协议（4 步，一步都别省）

| 步 | 接法 | 动作 | 要回答什么 |
|---|---|---|---|
| 1 | **拔掉自环跳线**，交叉线接好，从臂上电 | 主臂 `ms`（看 `frames sent` 在涨）→ 从臂 `lk` | **链路本体好不好**（这才是原始问题） |
| 2 | 拔掉链路（两端都拔）+ 从臂断电，**只留**自环跳线 | `mg` | 直流层面 PA0/PA1 到底是不是同一个节点 |
| 3 | 同上 | `ml` | 隔离环境下的位级质量 |
| 4 | 把自环跳线也拔掉（PA0/PA1 全悬空） | `mg` | PA1 是不是被**板载**东西驱动（基线 IDR 会直接暴露） |

**第 1 步才是原始问题的答案** —— 此前几轮全被"跳线 + 链路同时插着"污染了。
`mg`/`ml` 只能在**完全隔离**（链路拔掉）的条件下做，否则测的是"两个 TX 打架"，不是链路。

> ⚠ **12.3 的结论（"从臂那根线还插着造成对顶"）已于 2026-09-14 15:50 撤回** ——
> 用户确认：那次 `mg`/`ml` 是**只插了一条跳线短接 PA0↔PA1，从臂一根线都没接**。
> 现场事实变了，指向的物理原因完全不同，见第十三节。

## 十三、【2026-09-14 15:50 第四轮】**重新判定：单跳线、无从臂，PA0/PA1 自己有问题**

### 13.1 现场事实（用户原话，这条推翻了第十二节）

> 「就单条线短接了 PA1 和 PA0，从臂的 stm32 板没有一条线接过来」
> 「主从是 A.TX→B.RX」（回答 11.6 的提问 → 链路本身是**交叉**的，接法正确）

即：**总线上只有一条跳线，只有主臂一块板。** 没有第二个 TX，没有从臂。

### 13.2 于是出现一个**物理上不可能**的矛盾

只有一条跳线、别无他物时，PA0 与 PA1 就是**同一个电气节点**，直流上必须**同进同出**。
但实测两个方向的结果**互相打架**：

| 方向 | 实测 | 若真是同一节点，应该 |
|---|---|---|
| 向 1：PA0 推挽驱动 → 读 PA1 | `low=1  high=1`（**不跟**） | `low=0  high=1` |
| 向 2：PA1 推挽驱动 → 读 PA0 | `low=0  high=1`（**跟**） | `low=0  high=1` ✓ |

两个方向**不可能**不一致 —— 推挽输出阻抗两边一样（同一颗 MCU 同一个 GPIO 外设）。
所以只能从下面三种里挑一个，**没有第四种**：

| # | 原因 | 为什么能造成"单向不跟" |
|---|---|---|
| A | 跳线**没真正落在 MCU 的 PA0/PA1 上**（插错排针 / 杜邦内部断） | 向 1 时 PA1 悬空 → 读到 1；向 2 时 PA1 输出经跳线仍能"感应"到 PA0 |
| B | **PA1 网络上另有通电才工作的驱动器**（板载收发器/缓冲器输出脚） | 它把节点顶住，顶得住 PA0 的推挽低、顶不住 PA1 的推挽低（非对称） |
| C | PA0 的**输出驱动级损坏**（曾误接 5V/12V） | 向 1 拉不低（PA1 读到 1）；向 2 它只当输入用，正常跟 |

### 13.3 【关键】为什么"万用表量 ∞"不能排除 B/C

用户此前 S3 用万用表量过 PA0↔GND、PA1↔GND，都是 ∞（期望值）。但：

> **那是断电量的。** 板载芯片（电平转换、收发器、缓冲器、模块插座上的器件）
> 在**断电**时输出脚是高阻，量到 ∞ 很正常；**一通电它就会主动驱动那只脚。**
>
> ⇒ 断电万用表**结构上无法**排除"板载器件在驱动"这一类原因。

### 13.4 新增命令 `mp` —— **不需要任何跳线**，直接量每只脚外部挂着什么

原理：用 MCU 自己的**内部上拉（≈40 kΩ）**和**内部下拉**各读一次。
任何不是高阻的东西都会把它拽偏，于是能一眼看出引脚上的外部环境：

| 上拉读 | 下拉读 | 判决 |
|---|---|---|
| 1 | 0 | **[浮空]** 引脚干净，外部什么都没有 |
| 1 | 1 | **[被顶高]** 外部有驱动源/强上拉 —— NE=100% 的直接原因 |
| 0 | 0 | **[被拉低]** 外部对地短路/强下拉 |
| 0 | 1 | **[不稳]** 容性耦合/振荡，采不到稳定电平 |

默认探测 **PA0 / PA1**，外加 **PC10 / PC11 作为对照脚**
（这两脚在本板上**没有引出**，因此必然是"浮空"，正好用来验证测法本身是否可靠）。
也可指定任意脚：`mp A 1` / `mp C 12`。

### 13.5 本轮执行顺序（`mp` 放最前，因为它是唯一不需要跳线的）

| 步 | 跳线 | 从臂线 | 动作 | 回答什么 |
|---|---|---|---|---|
| 1 | **拔掉** | 拔掉 | `mp` | PA0/PA1 上**有没有通电才工作的外来驱动源**（B/C 的判定） |
| 2 | 插上 | 拔掉 | 断电万用表量排针 PA0↔PA1，必须 < 1 Ω | 跳线本身通不通（A 的判定，30 秒） |
| 3 | 插上 | 拔掉 | `mp` 再敲一次 | 跳线插上后，**合并后的节点**被顶成什么电平 |
| 4 | 插上 | 拔掉 | `mg`（新固件，带 baseline + 每步 IDR） | 区分"不是同一个节点" vs "PA0 被顶住" |
| 5 | 插上 | 拔掉 | `ml` | 隔离环境下的位级质量 |

### 13.6 出口（按 1~5 的结果选）

| 结论 | 整改 |
|---|---|
| `mp` 显示 PA1 = 上1下1（外部顶高） | **板载器件在驱动 PA1** ⇒ 查原理图找那颗器件/拆掉/换脚位 |

## 十五、【2026-09-14 16:30 第五轮】`mp` 实测：**PA0/PA1 引脚本体是干净的**；附带两条自我纠错

### 15.1 现场数据（只拔了自环跳线、链路从未接）

PA1   in up=1 dn=0 [浮空(干净)]

### 15.2 结论一：PA0/PA1 上没有外部驱动源 —— "对顶/第二个驱动器"这条**作废**

### 15.3 结论二（自我纠错）：**"对照脚"选错了**

我当初挑 PC10/PC11 当对照，理由是 `usart.c:140` 注释"这两脚本板未引出 ⇒ 天然浮空"。

连带两点：

- 命令里对着 PC10/PC11 打的"^ 这就是 NE=100% 的直接原因"是**胡话**（那两脚不是链路脚），已删。
- **PC10/PC11 不是干净的备用脚**，不能无脑拿来当 UART4 的替代脚位（但有上拉对 UART RX 反而无害）。

### 15.4 结论三（自我纠错）：`mp` 有盲区，已补上"输出驱动自检"

`mp` 逐个测引脚、且**只测输入态**，因此：

| 测不了 | 原因 |
|---|---|
| **跳线插没插** | 测一只脚时另一只脚是悬空 AF 输入，不参与；读数与没插线完全一样 ⇒ **判跳线必须用 `mg`** |
| **输出驱动级还能不能工作** | `mp` 只把脚当**输入**读；而 `PA0` 是 **TX = 输出** —— 恰恰是它出了问题时看不到 |

第 2 条这次补上了：`mp` 现在对每只脚再做一步 —— **配成推挽输出，拉低/拉高后读它自己的
`IDR`**（输出脚的 IDR 仍反映引脚真实电平）。读到拉不下去/推不上去 = 该脚输出级损坏。
**这一步不需要任何跳线**，是"PA0 自己坏没坏"的唯一直接证据。输出形如：

```
PA0   in up=1 dn=0 [浮空(干净)]   out 0->0 1->1 [驱动级正常]
PA1   in up=1 dn=0 [浮空(干净)]   out 0->0 1->1 [驱动级正常]
```

### 15.5 结论四：旧 `mg` 那个"自相矛盾"有了唯一自洽解释 —— **判据本身有歧义**

旧 `mg` 用"输入**+下拉**"当 sense，判据"两向都跟得住 = 通路完好"。它给出的结果
"向1不跟 / 向2跟"在**单根纯导线 + 同一颗 MCU + 同推挽阻抗**下**物理上不可能**。
根因是判据不硬：**下拉输入读到 1 时，分不清"对端在拉高"还是"根本没连上"**
（悬空时自己的下拉本来是 0，可只要节点上任何地方有个上拉就变 1）。

**能精确重现这三条读数的假设只有一个：那根"跳线"并没有把 MCU 的 PA0 和 PA1 连起来，
而是把 PA1 连到了一个被拉高的节点上。**

| 测项 | 该假设下的预期 | 旧实测 |
|---|---|---|
| 向1：PA0 拉低，PA1(下拉) 读 | PA1 挂在被拉高的节点上 → **1** | 1 ✓ |
| 向2：PA1 拉低，PA0(下拉) 读 | PA1 推挽赢过弱上拉 → 节点低 → **0** | 0 ✓ |
| `mp`（拔线后）PA0/PA1 | 都干净 → **浮空** | 浮空 ✓ |

⇒ **重点怀疑：跳线/排针。** 要么杜邦内部断、要么这两根排针压根没连到 MCU 引脚本体。

### 15.6 `mg` v2：把 sense 脚改成"输入 + **上拉**"

- **上拉输入读到 0 ⇒ 只可能是被外部主动拉低 ⇒ 必然连通。硬判据，无歧义。**
- 于是三个结论能干净分开：

| `mg` 判决 | 含义 | 下一步 |
|---|---|---|
| **通路完好** | 两向都能把对方拉低 | 引脚与跳线都没问题 ⇒ 查 UART 波形 / 换回真链路查线 |
| **断路** | 两向都拉不动（读到的都是自己的上拉） | 跳线没落在 MCU 的 PA0/PA1 上 → 用 `mo` 找脚 |
| **单向** | 只有一向拉得动 | 那一向的**输出低边驱动损坏** → 换 UART 脚位 |

每一步仍 dump `IDR`，可看出"驱动脚自己是否被更强的源顶回来"。

### 15.7 新命令 `mo` —— 无原理图时把"排针 ↔ MCU 引脚"钉死

```bash
mo A 1 0     # PA1 输出低并保持   -> 拿万用表在排针上点, 哪根跟着变就是 PA1
mo A 1 1     # PA1 输出高并保持
mo r         # 释放 (PA0/PA1 恢复 UART4 AF8)
```

保持期间 UART4 的 TX/RX 从 AF 上摘下来（链路暂停）；`mo r` 或复位恢复。

### 15.8 本轮协议（按顺序，前两步零成本）

| 步 | 接法 | 命令 | 回答什么 |
|---|---|---|---|
| 1 | **拔掉跳线**，链路也不接 | `mp` | PA0/PA1 引脚本体干净吗？**输出驱动级还能不能工作？** |
| 2 | **插上跳线**，链路仍不接 | `mg` | 跳线到底有没有把 MCU 的 PA0/PA1 连起来？（完好 / 断路 / 单向） |
| 3 | 同 2 | `mo A 1 0` + 万用表点排针 | 若判"断路"：哪根排针才是 PA1 |
| 4 | 拔跳线，链路接好、从臂上电 | 主臂 `ms` + 从臂 `lk` | 链路本体第一次被干净地测到 |

### 15.10 一条一直被忽略的板级事实

`usart.c:161`：**PA1(UART4_RX) 配的是 `GPIO_NOPULL`**（2026-09-11 为治 NE 主动禁掉了内部上拉）。
⇒ 一旦线没接实/没落到 MCU 引脚上，**PA1 就是悬空的**，悬空 RX = 字节制造机 =
`NE = bytes_rx = 100%`。这条与当前所有现象吻合，所以"线到底有没有落在 PA0/PA1 上"
是本轮唯一还没被证实的前提 —— 第 1、2 步就是去证它。

## 十六、【2026-09-14 17:00 第六轮】`mg` v2 读数**自相矛盾** ⇒ 单次采样不可靠；工具升级 v3

### 16.1 本轮现场数据

```
mp:  PA0  in up=1 dn=0 [浮空(干净)]   out 0->0 1->1 [驱动级正常]
     PA1  in up=1 dn=0 [浮空(干净)]   out 0->0 1->1 [驱动级正常]
     PC10 in up=1 dn=1 [被外部顶高]   out ... [驱动级正常]
     PC11 in up=1 dn=1 [被外部顶高]   out ... [驱动级正常]

mg:  baseline  (PA0/PA1 都输入+下拉): IDR=0xBFCC  -> PA0=0 PA1=0
     PA0 drives (PA1 输入+上拉): low=0 high=0
        IDR low =0xBFCE (PA0=0 PA1=1)  high=0xBFCF (PA0=1 PA1=1)
     PA1 drives (PA0 输入+上拉): low=1 high=1
        IDR low =0xBFCF (PA0=1 PA1=1)  high=0xBFCF (PA0=1 PA1=1)
```

### 16.2 两个确定结论

1. **MCU 侧 PA0/PA1 引脚本体是干净的，输出驱动级正常**（`mp`，跳线拔掉时测）。
   ⇒ 第十四/十五轮里"对顶""被板载器件顶高""驱动级损坏"三说，**对 MCU 本体全部不成立**。
2. `mg` 相 2 自洽且有意义：**PA1 配成推挽输出拉低后，连它自己的 IDR 都读到 1**
   ⇒ 拉低那一刻，PA1 这个节点上**有比 GPIO 更强的源把它顶在高**。

### 16.3 但 `mg` 相 1 是**自相矛盾**的 —— 这才是本轮最有价值的发现

同一相内，前后只差一条指令：

| 通道 | 相 1 拉低时 PA1 |
|---|---|
| `HAL_GPIO_ReadPin(PA1)` | **0** |
| 紧接着的 `GPIOA->IDR` bit1 | **1** |

已核实 `Drivers/.../stm32f4xx_hal_gpio.c:375` 的实现是**干净的 0/1**：

```c
if ((GPIOx->IDR & GPIO_Pin) != (uint32_t)GPIO_PIN_RESET) bitstatus = GPIO_PIN_SET;
else                                                     bitstatus = GPIO_PIN_RESET;
```

**不是**"把掩码值直接强转"那种会把 PA1 读成 2 的写法。所以这**不是打印 bug**，
而是**电平真的在变**：同一个寄存器、同一个 bit、前后相隔约 100 ns，却给出不同结果。

> **一条物理约束**：一只挂着 40 kΩ 内建上拉的脚，**绝无可能在 100 ns 内自己翻转**
> （RC ≈ 40k × 十几 pF ≈ µs 级）。⇒ 该节点**不是"一根线 + 一个上拉"那么简单**，
> 线上要么挂着**在跳的活动信号源**，要么节点电压正卡在逻辑阈值（亚稳态，每次采样随机）。

⇒ **结论：`mg` v2 给出的"[单向]"判决不可采信，本轮不能据此下任何结论。**
错的不是现象，是**判据本身**：单次采样在一个"有活动/亚稳"的节点上必然随机。

### 16.4 工具升级 **v3**（已编译验证）

`master_sample8()`：对同一只脚**连采 8 次**（间隔约 40 µs 空转），打包成位图。

```
00000000 = 稳定低       11111111 = 稳定高       其它 = 节点不稳(有活动信号)
```

- **`mg` v3**：四个相位的 `PA0`/`PA1` 全部打出位图；**判据只用这一份数据**（不再混用
  `ReadPin` 与 `IDR` 两个通道——v2 的矛盾正是混用造成的）。新增判决：

| v3 判决 | 含义 | 下一步 |
|---|---|---|
| **通路完好** | 两向都能把对方拉到**稳定低** | 引脚/跳线没问题 ⇒ 查 UART 波形，或直接测真链路 |
| **断路** | 两向都拉不动 | 跳线没落在 MCU 的 PA0/PA1 上 → 用 `mo` + 万用表找脚 |
| **单向** | 只有一向拉得动 | 配合下面的自检行判断 |
| **节点不稳** | 有任何采样出现 0/1 混合 | 该节点上有活动信号源或卡在阈值，先查并线/串扰 |

  并新增一条**自检行**：若"两只脚自己的推挽都正常"却仍不连通，会直接判
  **"不是驱动级坏，而是两只脚没连在一起"**（v2 会把这种情况误报成"驱动级损坏"）。

- **`mp` v3**：上/下拉、输出低/高 四个状态**各自连采 8 次**打位图；任一状态混合
  ⇒ 判"**不稳!有活动信号**"。v2 的单次读数在那种节点上同样是随机值。
- 参考脚 PC10/PC11 的标题改成如实描述（同时是 **SDIO_D2/D3**，本板有外部上拉），
  不再写"备用出口"。

### 16.5 一条此前一直被忽略的推论

`usart.c:161`：**PA1(UART4_RX) = `GPIO_NOPULL`**（9-11 为治 NE 主动禁掉了内部上拉）。
⇒ 一旦线没接实，PA1 就悬空；而**悬空脚在我们这个环境里会拾取到 1 Mbps 舵机总线的串扰**，
表现为"读数随机变化"—— 这与 16.3 观察到的现象**在机理上完全一致**。

⚠ 因此 `mp` 判"浮空(干净)"与"线上有活动信号"**并不矛盾**：`mp` 测的是
**引脚外挂了什么直流负载**，它测不出"旁边一根线在往这里耦合高频"。

### 16.6 本轮协议（顺序很重要，第 1 步才是原始问题的答案）

| 步 | 接法 | 命令 | 回答什么 |
|---|---|---|---|
| **1** | **跳线彻底拔掉**；接**真链路**（A.TX→B.RX），从臂上电 | 主臂 `ms` ×2 + 从臂 `lk` ×2 | **链路本体第一次被干净地测到** |
| 2 | 跳线拔掉、链路也拔掉 | `mp` | 引脚本体干净吗？驱动级正常吗？有无活动信号？ |
| 3 | 只插跳线、链路不接 | `mg` | 跳线到底有没有把 MCU 的 PA0/PA1 连起来 |
| 4 | 若判"断路" | `mo A 0 1` / `mo A 1 1` + 万用表 | 哪根排针才是 PA0/PA1 |

前几轮所有"自环"数据都是在**跳线与链路状态不明**的情况下测的，只有第 1 步是干净的。
