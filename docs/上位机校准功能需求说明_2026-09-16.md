# 上位机「关节校准」功能需求说明

| 项目 | 内容 |
|---|---|
| 日期 | 2026-09-16 |
| 接收方 | 上位机软件工程师 |
| 关联文档 | `03_INTERFACE` §1.2/§1.5/§2.2、`05_HOST_APP_REQUIREMENTS` P0-9/P1-8 |
| 目的 | 把固件现有的 `M a` + `c` 两阶段校准，做成上位机里可用的**校准向导** |

---

## 一、为什么必须做这个功能

1. **每台臂的 Home 零点（`SERVO_OFFSET`）都不一样**，换舵机、拆装舵盘、重锚零点之后都会漂。
2. 固件**已经有**完整的校准能力（`M a` 置中 + `c` 两阶段校准），但操作方式是**在串口助手里手敲单个字符**。
3. 现场问题：`c` 模式下**没有提示符**、**按键不能带行尾**、**Phase 1 的数字键是"记录零点"而非"选择"** —— 靠串口助手敲极易误操作，而误操作的后果是**把错误姿态固化成官方 Home 零点**（写进 Flash，掉电不丢）。

**结论**：需要上位机把这两步包装成带引导、带确认、带状态显示的向导。

---

## 二、先分清四个命令的类别

| 命令 | 类型 | 作用 | 是否写持久化 |
|---|---|---|---|
| `M a` | **普通命令**（走命令解析器，**必须 `\r\n`**） | 把**当前物理位置**定义为舵机电气中位（raw 2048） | ✅ **写舵机 EEPROM** |
| `M <0-5>` | 普通命令（同上） | 同上，单轴 | ✅ 写舵机 EEPROM |
| `c` | **交互模式**（阻塞、逐字节、**禁止行尾**） | Phase 1 记 Home 零点；Phase 2 采限位；`s` 存 Flash | ✅ **写 MCU Flash**（仅在按 `s` 时） |
| `zi` | 普通命令（**只读**） | 查当前零点 / `SERVO_OFFSET` / raw 限位 | ❌ |
| `L` | 普通命令 | 查/设单轴限位（**舵机度**） | 改值仅 RAM |
| `i` | 普通命令 | 舵机初始化（设 joint 模式、扭矩 ON） | — |

---

## 三、⚠⚠ 行尾的两种模式（最容易做错的地方）

这是本功能**唯一一个"做错就完全不能用"的点**。

### 3.1 普通命令：必须 `\r\n`

固件是**按行**执行的（`Console_TryReadLine()`）：只有收到 `\r` 或 `\n` 才会执行命令。
**不带行尾 ⇒ 命令永远不会执行**，现象是"下发了没反应"。

```
M a\r\n        ← 正确
M a            ← 永不执行
```

### 3.2 `c` 校准模式内：**禁止任何行尾**，必须发裸单字节

`c` 模式内的按键走的是**另一个通道**（`calib_try_byte()` 直接从环形缓冲取字节），
它 **不过滤 `\r` / `\n`**。

**如果在校准模式内按普通方式发 `0\r\n`，会发生：**

| 字节 | 固件反应 |
|---|---|
| `0` | ✅ 正确记录 Home 零点 |
| `\r` | ❌ 落进 `else` 分支 → 打印 `Unknown key` |
| `\n` | ❌ 同上 → 再打印一次 `Unknown key` |

功能"看起来能用"，但每次操作都会吐两行报错，把校准表格刷乱，日志也没法看了。

### 3.3 结论：SDK 必须提供两个**不同**的函数

```python
def send_command(cmd):        # 普通命令用：自动补 \r\n
    ser.write((cmd + "\r\n").encode("ascii"))

def send_key(ch):             # c 模式内用：裸写一个字节，什么都不补
    ser.write(ch.encode("ascii"))
```

⚠ **进入 `c` 用前者**（`send_command("c")`），**退出用后者**（`send_key("q")`）。

### 3.4 另一个连带问题：`c` 模式没有提示符

普通命令每行执行完会打印 `> ` 提示符，上位机靠它判断"这条命令结束了"。
**但 `c` 模式全程不打印提示符** ⇒ 基于提示符超时的 `send_command()` **一定会超时**。

⇒ 校准模块必须**切到独立的收发通道**（读原始字节流，不依赖提示符）。

## 四、完整校准流程（上位机按键逐步照做）

### Step 0 — 前置检查（不可跳过）

| 动作 | 命令 | 判据 |
|---|---|---|
| 确认 6 轴在线 | `s\r\n` | 温度列不能有 `Err` |
| **备份当前零点** | `zi\r\n` | 抄下 `calib_zero_raw` 和 `SERVO_OFFSET` |
| **备份当前限位** | `L\r\n` | 抄下 6 轴的 MIN/MAX |

> `zi` 全程**只读安全**。⚠ **不要用 `zr` 去"查"零点** —— `zr` 是**复位** Home 零点，
> `zr save` 还会写进 Flash，会毁掉本来正确的零点。

---

### Step 1 — 摆官方 L 形 Home 姿态 → `M a` 置中

**为什么要在 Home 姿态下做**：`M a` 把"当前位置"定义成舵机的电气中位（raw 2048）。
只有在官方 L 形 Home 姿态（上臂竖直 / 前臂水平 / 工具朝前）下做，6 轴的 raw 才会都≈2048，
后续 `SERVO_OFFSET` 才会接近整齐的 180°，运动学模型才干净。

**操作顺序**

```
① 逐轴松力        t 0 0   →   t 5 0        (普通命令，带 \r\n)
② 手摆成官方 L 形 Home 姿态
③ 置中全部        M a                       (普通命令，带 \r\n)
```

**固件回显（逐轴一行）**

```text
  J1 (bus0 id1): writing 40=128... pos=2048 OK (≈2048)
  J2 (bus0 id2): writing 40=128... pos=2048 OK (≈2048)
  ...
  All 6 centered. WARNING: re-run 'c' Phase1+2 and save now!
```

**判定**

- 每行 `pos` 必须落在 **2035 ~ 2061** → 显示 `OK (≈2048)`
- 出现 `!unexpected` ⇒ 该舵机异常，**固件会立即 return 停止**（不会继续写后面的轴）
- 上位机必须**逐行解析并在界面上标出是哪一轴失败**

**⚠ 三条必须写进界面提示的危险点**

1. `M a` 写的是**舵机 EEPROM**，**掉电不丢**。执行后该舵机的编码基准**永久改变**。
2. **执行后必须紧接着做 Phase 1 并保存**，否则固件里的 `SERVO_OFFSET` 与舵机实际基准不一致
   ⇒ 会导致 IK 解出的舵机度整体错位（这正是"J2/J6 差 180°"那一类故障的成因）。
3. `M a` 内部会**先释放该轴扭矩**再写、写完再锁。

**二次确认文案（必须）**：
> ⚠ 此操作会把**当前姿态**设为该舵机的电气中位（raw 2048），并**写入舵机 EEPROM（掉电不丢）**。
> 请确认机械臂已摆成官方 L 形 Home 姿态。执行后必须立即完成校准并保存，否则运动学会错位。

---

### Step 2 — 进 `c`，Phase 1 记录 Home 零点

```
① 进入        c          ← 普通命令，带 \r\n
② （固件立刻释放全部 6 轴扭矩，打印 Phase 1 表格）
③ 保持 Step 1 的姿态不动（松力后会被重力拉下来，用手托住）
④ 记录零点    0          ← ⚠ 裸字符，不带任何行尾
```

**固件回显**

```text
  === Joint Calibration (2-phase) ===
  Phase 1: 摆官方 Home 姿态 (L形), 按 0 记录各关节零点.
  ...
  All torques released for hand positioning.

  --- PHASE 1: SET HOME ZERO (官方 L 形 Home) ---
  把整臂摆成官方 Home (上臂竖直/前臂水平/工具朝前), 按 0 全记录.
  +-----+----------------+------+------+
  |     | NAME           | POS  | ZERO |
  +-----+----------------+------+------+
  |   J1 | ...            | 2048 |    0 |
  ...
  Keys: 0=记录全部零点  1-6=单关节   n/N=next  s=save  q=quit

  [ZERO] Home 零点已记录: 2014 896 3106 2331 2022 1567
  ...按 s 保存生效 (无需等 Phase 2).
```

**⚠⚠ Phase 1 下最危险的一个坑：数字键 `1`~`6` 不是"选择"，是"记录该轴零点"**

固件行为：**Phase 1 状态下按 `1`~`6`，会把该关节的当前 raw 直接写成它的 Home 零点。**

```text
  [ZERO] J1 zero=2048 (官方 Home 需 6 关节都记录)
```

⇒ 上位机在 Phase 1 界面里，把 `1`~`6` 标注成**危险键**（红色 + 二次确认），
不要按普通"选择关节"来理解。（Phase 2 下它们才是普通的选择键。）

**⚠ 此时不要按 `s`**，除非确认姿态正确 —— `s` 会写 Flash 并**立即生效**。

---

### Step 3 — 按 `n` 进入 Phase 2，逐轴推挡块采限位

```
① 切 Phase 2   n          ← ⚠ 裸字符，不带行尾
② 用手把每一轴从一端极限缓慢推到另一端极限（顶到挡块）
```

**固件回显**

```text
  [phase] -> PHASE 2: SET LIMITS (auto track MIN/MAX)

  --- PHASE 2: SET LIMITS (auto track MIN/MAX) ---
  Rotate each joint through full range. MIN/MAX auto-expand.
  +-----+----------------+------+------+------+
  |     | NAME           | MIN  | POS  | MAX  |
  +-----+----------------+------+------+------+
  |   J1 | ...            |  885 | 2048 | 3112 |
  ...
  Keys: 1-6 select  r=reset J1  R=reset all  p/P=prev phase  s=save  q=quit
```

**固件机制**

- Phase 2 每 **200 ms** 轮询一次，自动把 `POS` 并入 `MIN` / `MAX`（只扩不缩）
- 因此**必须真的把每轴推到两端**，中途不停留太久不影响，但**没推到端就不会被记录**
- `1`~`6` = 选择/高亮某轴（**Phase 2 下不改零点**）
- `r` = 清除**当前轴**限位；`R` = 清除**全部**限位（注意大小写！）
- `p` = 回到 Phase 1
- **松手时不要用力顶死**：金属舵盘有齿隙，顶死的读数会比真实挡块偏浅

**限位来源：六轴完全一致**

`Phase 2` 手推结果对 **J1~J6 六轴全部生效**，填表即写入，没有特殊轴。
`L <J> <min> <max>` 同样可覆盖任意一轴（改值仅 RAM，重启恢复）。

**⚠ 界面义务：六轴都必须真正推到两端（重要）**

固件的合法性判据是：

```c
span = raw_dist_fwd(min, max);           /* 正向行程 */
if (span == 0 || span < 20U) continue;   /* 跳过: 该轴不写限位 */
```

后果：**某个轴如果没被真正推到两端**（或跨度 < 20 raw ≈ 1.8°），
固件会**跳过该轴、不写限位** ⇒ 该轴回到"无限制"状态
（`clamp_angle()` 在 `mn==0 && mx==0` 时直接放行）。

⇒ 界面上必须做到：

1. **六个轴的 MIN/MAX 全部非空且跨度合理**，任一轴不满足就在保存前**拦截并标红**；
2. 把 `跨度 < 20 raw（≈1.8°）` 明示为一条**校验规则**，并给出角度换算提示；
3. 校准完成后**必须读 `L` 回显逐轴核对**：六轴应分别等于刚推的值；
   任何一轴显示 `0 / 0` 即表示**该轴未写入**，必须重推，不能放行。

#### ⚠ 限位不随零点自动平移（界面必须提示）

限位存的是 **Phase 2 实测的绝对 raw 值**，零点变化时**不会自动跟随**。

⇒ 界面务必在**校准向导开头**写明："**换舵机、或重锚 Home 零点之后，必须重新完整走一遍
Phase 2 手推标定**，否则该轴限位会失效"；并在保存前做上面那三条校验。

---

### Step 4 — 按 `s` 保存

```
① 保存        s          ← ⚠ 裸字符，不带行尾
```

**固件回显**

```text
  [save] OK. PID+corr+speed+limits+zero written to Flash.
  Home zero applied: FK/IK 现在以官方 Home 为 0°.
```

**保存后立即发生的四件事（固件内部）**

1. `Kinematics_SetZeroRaw()` —— Home 零点重锚，FK/IK 立刻以新 Home 为 0°
2. `apply_calib_limits()` —— 按新零点重新计算全部限位
3. `refresh_pose_servo()` —— 预设位姿（HOME / READY / WAVE…）随新零点重算
4. `update_home_dock()` —— 折叠位白名单与桌面下限随新零点重算

**没做 Phase 2 就保存会怎样**

固件存**哨兵值**（min=4095 / max=0），重启后保持**编译默认**（官方 URDF 行程限位），并打印：

```text
  No Phase-2 captured: joint limits = official URDF ranges.
```

⇒ 界面要说明白：**"只做 Phase 1 也能保存（零点会生效），但限位会回到出厂默认，不是'没有限位'。"**

---

### Step 5 — 裸 `q` 退出，然后重读限位

```
① 退出        q          ← ⚠ 裸字符，不带行尾
② 固件恢复全部扭矩，保持当前姿态（防止失力垂落砸桌）
③ 退出后必须发 L\r\n 重新读取限位，刷新上位机本地限位表与 IK 约束
```

**固件回显**

```text
  Exiting calibration mode.
  Torque re-enabled (holding current pose).
```

## 五、上位机实现要点

| # | 要求 | 说明 |
|---|---|---|
| 1 | **独立的"校准终端"通道** | 不复用 `send_command()`；`c` 模式无提示符、按键无行尾 |
| 2 | **按键直发裸字节** | `send_key()`，一个按键一个字节，不补 `\r\n` |
| 3 | **状态机显示** | 至少三态：`Phase 1` / `Phase 2` / `已退出`，用户一眼知道现在按哪个键有效 |
| 4 | **表格只保留最后一帧** | 固件每 200ms 重绘整张表 ⇒ 逐行追加会刷屏。按 `--- PHASE` 分段，**整帧替换** |
| 5 | **危险键标红** | Phase 1 的 `1`~`6`、全程的 `s`、退出前的 `q` |
| 6 | **退出后自动刷新 `L`** | 并更新本地限位表、IK 约束、3D 视图 |
| 7 | **不缓存旧零点** | 每次进校准前先 `zi` 拉一次实时值 |
| 8 | **超时保护** | `c` 模式内没有提示符，要用"空闲超时"判断，不要用提示符超时 |

**参考状态机**

```python
def calibrate_wizard(ser):
    send_command(ser, "zi")            # 备份零点
    send_command(ser, "L")             # 备份限位

    # Step 1: 需要用户先手摆 Home，再置中
    send_command(ser, "M a")           # 普通命令，必须带 \r\n
    assert_all_centered(ser)           # 解析 pos≈2048

    # Step 2-4: 进入交互模式
    send_command(ser, "c")             # 进 c 也要带 \r\n
    set_channel_raw(ser)               # 切裸字节通道

    send_key(ser, "0")                 # Phase 1 记录零点，不带行尾
    send_key(ser, "n")                 # 进 Phase 2
    # ... 用户手推各轴，界面持续解析 200ms 刷新表格 ...
    send_key(ser, "s")                 # 保存

    send_key(ser, "q")                 # 退出，不带行尾
    set_channel_line(ser)
    send_command(ser, "L")             # 重读限位
```

## 八、常见坑速查

| 现象 | 真因 |
|---|---|
| 发 `0` 没反应 | `c` 模式内**不能**用带 `\r\n` 的 `send_command`；要发裸字节。反过来，普通命令**必须**带 `\r\n` |
| `send_command("c")` 一直超时 | `c` 模式**没有提示符**，靠提示符判结束必然超时 |
| 满屏 `Unknown key '\r'` | 按键带了行尾 |
| 满屏 `Unknown key` 且命令全失效 | 掉进了单字符模式：敲了未注册的**多字符命令**，首字符被当成按键吃掉，此后所有字符都被当按键。**断电重启最干净** |
| `c` 里按 `1` 后零点变了 | Phase 1 下 `1`~`6` 是**记录零点**，不是选择 |
| 六轴中某轴推完 `MIN/MAX` 没变化 | 该轴被固件**跳过**（跨度 < 20 raw ≈ 1.8°，或仍是哨兵值 4095/0）⇒ **这一轴等于没有限位**，必须重推 |
| 校准后 IK 报 "tool pitch NOT met" | 零点可能被污染。`zi` 看 `calib_zero_raw`（健康值接近 `[2048 ×6]`），必要时 `zr save` 复位 |
| 校准完臂往下掉 | 正常：`c` 模式会释放扭矩，退出时才恢复。**进 `c` 前先托住** |
| `L` 显示的限位和刚校准的不一致 | **六轴都应一致**。若某轴显示 `0 / 0` ⇒ 该轴未被写入（跨度不足 20 raw），必须重推 |

## 九、给固件侧的备注

本说明只描述**现状**（固件 `main.c` 的 `cmdCenterCalib` / `cmdCalibrate` / `apply_calib_limits`）。
若后续改动以下任一行为，**必须同步更新本文档**：

1. `calib_try_byte()` 开始过滤 `\r` / `\n`（则行尾差异消失，上位机可统一）
2. `c` 模式下开始打印提示符
3. 限位合法性判据（当前：`span < 20 raw` 的轴被**跳过、不写限位**）
4. `M a` 的 EEPROM 地址或判定范围（2035~2061）变化
