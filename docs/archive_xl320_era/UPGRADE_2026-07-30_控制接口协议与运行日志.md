## 2. 二进制控制协议规范（串口/CAN 共用）

### 2.1 帧格式（小端）

```
[0]  0xAA          帧头1（文本控制台不会输出，天然分流）
[1]  0x55          帧头2
[2]  SEQ           请求序号（响应回显，用于请求-应答配对）
[3]  CMD           命令码
[4]  LEN           负载长度 0~64
[5..] PAYLOAD      定点编码负载
[-2] CRC16 低字节  CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF)
[-1] CRC16 高字节  计算范围: SEQ..PAYLOAD（含 LEN）
```

### 2.2 定点编码约定

| 量 | 类型 | 比例 |
|----|------|------|
| 角度 | int16 | 0.1 deg |
| 位置 | int16 | 0.1 mm |
| 速度/加速度 | uint16 | 0.1 deg/s(²) |
| 重力增益 K | int16 | 0.001 deg/mm |
| 参数值 | int32 | 0.001 |

### 2.3 命令码表

| CMD | 名称 | 负载（请求） | 响应 |
|-----|------|-------------|------|
| 0x01 | PING | 空 | 0x81: u8 协议版本, u8 run_id |
| 0x02 | GET_STATUS | 空 | 0x82: 6×i16 角度, i16 x/y/z, i16 pitch, u8 标志 |
| 0x03 | LOG_SET_LEVEL | u8 level(0~4) | ACK |
| 0x10 | MOVE_JOINTS | 6×i16 角度 + u16 v + u16 a | ACK/NACK |
| 0x11 | STOP | 空 | ACK |
| 0x12 | SET_TORQUE | u8 joint(0~5,0xFF=全), u8 en | ACK/NACK |
| 0x20 | MOVE_CART | i16 x,y,z + i16 pitch + u16 v + u16 a | ACK/NACK |
| 0x21 | FK_QUERY | 空 | 0xA1: i16 x,y,z,pitch + 6×i16 角度 + u8 ok |
| 0x30 | SET_GRAVITY | i16 K(×1000) | ACK |
| 0x31 | SET_CORRECTION | u8 en, u16 阈值(×100), u8 轮数 | ACK |
| 0x40 | PARAM_READ | u8 id | 0xC0: u8 id, i32 value(×1000) |
| 0x41 | PARAM_WRITE | u8 id, i32 value(×1000) | ACK/NACK |
| 0x42 | PARAM_COUNT | 空 | 0xC2: u8 count |
| 0x7F | ACK | u8 原CMD, u8 err=0 | — |
| 0x7E | NACK | u8 原CMD, u8 err | — |

**错误码**（= `arm_control_api.h` 返回码）:
`0 OK / 1 参数非法 / 2 CRC错误 / 3 IK不可达 / 4 超关节限位 / 5 E-Stop激活 / 6 FK验证超差 / 7 总线读取失败`

### 2.4 执行语义

- **MOVE_JOINTS / MOVE_CART 与文本命令 `m`/`g` 走同一安全链**：E-Stop 检查 → 限位钳制 → 读当前位置 → 开扭矩 → 七段 S 曲线规划（200Hz 六关节同步）→ 轨迹结束后自适应重力补偿修正。
- v/a 传 0 时使用参数表默认值（`sc.def_vmax` / `sc.def_accel`）。
- MOVE_CART 内部：θ1 解析 → θ2~θ5 五起点 CCD → θ6 姿态补偿 → 关节限位检查 → FK 回代验证（容差 `ik.fk_verify_mm`）→ 执行。

## 3. 串口承载（arm_proto_serial.c）

- 与文本控制台**共用 USART6 @115200**：文本命令首字符是可打印 ASCII，协议帧以 0xAA 起始，无歧义。
- USART6 ISR 内分流：`SerialProto_FeedByte()` 返回 1 的字节被协议状态机消费，不再进入文本环形缓冲；ISR 内**只做状态机与帧缓存**（无打印、无总线通信），遵守工程实时纪律。
- 完整帧由主循环 `SerialProto_DispatchPending()` 分发执行并回送响应。
- 帧间字节超时 200ms 自动复位状态机；未及时处理被覆盖的帧计数（`SerialProto_DroppedCount()`）。

## 4. CAN 承载（arm_proto_can.c）

> 当前工程 HAL CAN 模块未启用（`stm32f4xx_hal_conf.h` 中 `HAL_CAN_MODULE_ENABLED` 被注释）。
> 因此本文件默认 `ARM_CAN_ENABLE = 0` **桩模式**：随工程编译但不产生硬件动作；
> 协议封装（ID 规划 + 分包重组）已完整实现，驱动通过 weak 钩子解耦。

### 4.1 CAN ID 规划（CAN 2.0A 标准帧）

| ID | 方向 | 用途 |
|----|------|------|
| 0x100 + node_id | 上位机 → 机械臂 | 命令 |
| 0x180 + node_id | 机械臂 → 上位机 | 响应 |

node_id 0~15，`CanProto_Init(node_id)` 指定（默认 1）。

### 4.2 分包格式（逻辑流 = SEQ,CMD,LEN,PAYLOAD,CRC16）

- 首帧: `d[0]=0x80|总帧数, d[1]=SEQ, d[2]=CMD, d[3]=LEN, d[4..7]=流前4字节`
- 续帧: `d[0]=帧序号(1..14), d[1..7]=后续7字节`
- 重组超时 200ms 复位；CRC 校验失败回 NACK(err=2)。

### 4.3 启用步骤（接 bxCAN 时）

1. `arm_proto_can.h`: `#define ARM_CAN_ENABLE 1`
2. `stm32f4xx_hal_conf.h`: 取消 `HAL_CAN_MODULE_ENABLED` 注释
3. Makefile 增加 `stm32f4xx_hal_can.c`
4. 在工程中实现三个强定义（替换 weak 桩）:
   `ArmCanDrv_HwInit() / ArmCanDrv_Tx(id,data,len) / ArmCanDrv_Rx(&id,data,&len)`
   （bxCAN 或 MCP2515 均可，API 为通用帧模型）

## 5. 统一配置参数文件（arm_params）

### 5.1 设计：指针绑定，单一生效点

每个参数表项持有**实际生效变量地址**（main.c / kinematics.c / trajectory.c / arm_params.c 中的全局变量），`ArmParams_Set` 范围钳制后直接写入生效点。**不存在第二份拷贝**——从根上杜绝 `arm_config.h` 式双轨漂移。

### 5.3 调参入口（三者等价，写同一生效点）

```text
文本:  LP                      # 列出全部参数（id/当前值/范围/单位）
       SP 16 0.20              # 设置 S 曲线 jerk 时间为 0.20s
       LL 4                    # 日志级别调为 DEBUG
协议:  PARAM_WRITE id=16 val=200(×1000)
代码:  ArmParams_Set(AP_SC_TJ_S, 0.20f);
```

### 5.4 持久化策略

- 本参数表为 **RAM 运行时调整**（掉电回默认值），便于调试期反复修改。
- PID / 修正阈值 / 轮数 / 速度的**掉电保存沿用原有 `F` 命令**（pid_flash.c，Sector 11）。
- 本次**未改动** `PID_Record_t` 布局与 `PID_FLASH_VERSION`，Flash 兼容。

## 6. 运行日志系统

### 6.1 固件端（arm_runlog）

- 每次上电输出 RUN-START 头：`[RUN] RUN-START id=0xXX build="..." proto=1 level=3`
- 消息格式（单行可检索）:
  `[RUN][<run_id>][T+<tick_ms>][LEVEL][MODULE] message`
- 级别 0~4（NONE/ERROR/WARN/INFO/DEBUG），默认 INFO，`LL` 命令或协议 0x03 可调。
- 事件级注入点（**不在 ISR / 200Hz 插值路径打印**，继承工程实时纪律）:
  启动完成、协议命令及 NACK、IK 不可达/超限/FK 超差、移动停止、
  修正 DONE/TIMEOUT、E-Stop 中止、参数修改、CAN 异常。

### 6.2 PC 端：每一次运行保存一个文件

```bash
# 持续采集（Ctrl+C 结束并输出故障摘要）
python tools/arm_run_logger.py --port COM5

# 定时采集 60 秒
python tools/arm_run_logger.py --port COM5 --duration 60

# 回放文本命令脚本并记录
python tools/arm_run_logger.py --port COM5 --script cmds.txt

# 通过二进制协议直接控制机械臂
python tools/arm_run_logger.py --port COM5 --proto MOVE_CART 150 0 200 0 30 60
python tools/arm_run_logger.py --port COM5 --proto MOVE_JOINTS 150 150 150 150 150 150 30 60
python tools/arm_run_logger.py --port COM5 --proto SET_GRAVITY 0.03
python tools/arm_run_logger.py --port COM5 --proto PARAM_WRITE 16 0.20
python tools/arm_run_logger.py --port COM5 --proto STATUS
```

每次启动采集自动创建独立文件：`logs/run_YYYYMMDD_HHMMSS.log`，
内容包括：带本地时间戳的全部串口行、协议帧收发记录（`# >>>` / `[proto] RX`）、
结束时的错误/警告统计。
