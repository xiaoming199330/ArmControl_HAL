# 六轴机械臂上位机同步改造操作文档

> 适用固件：STM32F407ZGT6 + 6×Dynamixel XL320
>
> 工程：`ArmControl_HAL（1）`
>
> 协议版本：二进制协议 `APROTO_VERSION = 1`
>
> 本文以当前固件源码为准。`config/arm_config.json` 是上位机/仿真配置镜像，STM32 固件**不会在运行时读取 JSON**。

---

## 1. 上位机通信方式与改造建议

固件在同一个 USART6 控制台端口上同时支持两种通信方式：

| 模式 | 适用场景 | 形式 | 建议 |
|---|---|---|---|
| 文本命令模式 | 调试、人工操作、快速验证 | ASCII 命令 + 换行 | 首版上位机可直接实现 |
| 二进制协议模式 | 正式 GUI、CAN、稳定控制 | 定长/变长二进制帧 + CRC | 正式控制功能优先采用 |
| CAN 承载模式 | USB2CAN / CAN 分析仪联调 | 二进制协议分包到 CAN 2.0A | CAN 收发器接好后使用 |

### 推荐的上位机结构

1. **设备连接页**：选择串口或 CAN；连接后先发送 `PING`。
2. **控制页**：关节运动、笛卡尔运动、停止、扭矩开关。
3. **监控页**：固定周期发送 `GET_STATUS`，显示六轴实际反馈、XYZ、轨迹和急停状态。
4. **参数页**：读取/写入 `LP/SP` 参数；参数修改后提示用户执行“保存到 Flash”。
5. **调试页**：保留文本控制台收发窗口，便于排错。

> 不建议同时在同一个 USART6 端口持续发送文本命令和二进制帧。调试时可共用，正式运行时应选定一种控制路径。

## 2. 物理通信参数

### 2.1 串口控制台

| 项目 | 值 |
|---|---|
| MCU 外设 | USART6 |
| 引脚 | PC6=TX，PC7=RX，AF8 |
| 波特率 | 115200 |
| 数据格式 | 8N1 |
| 文本结束符 | `\r\n` 或 `\n` |
| 二进制帧超时 | 相邻字节超过 200 ms，固件丢弃半帧 |

### 2.2 CAN 控制

| 项目 | 值 |
|---|---|
| CAN 外设 | CAN1（bxCAN） |
| 引脚 | PB8=CAN1_RX，PB9=CAN1_TX，AF9 |
| 位速率 | 500 kbit/s |
| 帧格式 | CAN 2.0A 标准帧，11 位 ID，数据帧 |
| 默认节点号 | 1 |
| 上位机 → 机械臂 | `0x100 + node_id`，默认 `0x101` |
| 机械臂 → 上位机 | `0x180 + node_id`，默认 `0x181` |
| 接收过滤范围 | `0x100 ~ 0x10F` |

CAN 物理层必须使用外置 CAN 收发器，例如 `SN65HVD230`；USB2CAN/分析仪的 `CANH/CANL` 不可直接接 STM32 的 PB8/PB9。总线两端各应有 120 Ω 终端电阻，断电测 CANH-CANL 推荐约 60 Ω。

## 3. 文本命令接口（串口 115200）

文本命令使用空格分隔，关节编号在绝大多数命令中为 **0~5**，对应机械臂 **J1~J6**。

### 3.1 基础配置、单关节与监控

| 命令 | 功能 | 上位机用途 |
|---|---|---|
| `h` | 打印帮助 | 调试 |
| `n` | 扫描两条 XL320 总线 | 上电自检 |
| `i` | 初始化全部舵机 | 初始化 |
| `i J` | 初始化单个关节 `J=0~5` | 故障恢复 |
| `s` | 全部关节状态、角度、运动状态、温度 | 状态页调试 |
| `t J 0/1` | 单关节扭矩关/开 | 维护功能 |
| `a J deg` | 单关节到指定舵机角度 | 维护功能 |
| `r J raw` | 单关节原始位置 `0~1023` | 标定/维护 |
| `p J` | 读取一个关节实际 raw/角度 | 单关节反馈 |
| `pv ms` | 周期输出全部关节实际角度；`pv 0` 停止 | 调试监控 |
| `pf ms` | 周期输出实际 FK 位姿；`pf 0` 停止 | 调试监控 |
| `z J` | 单关节回零 | 标定 |
| `z a` | 全部关节回零 | 标定 |
| `w J` | 单关节安全范围扫动 | 调试 |
| `T` / `T J` | 读取全部/单关节温度 | 温度监控 |
| `d` | Bus B 诊断 | 故障排查 |

### 3.2 运动控制

| 命令 | 参数与示例 | 说明 |
|---|---|---|
| `m a1 a2 a3 a4 a5 a6 [v]` | `m 150 120 110 150 120 150 30` | 六关节 S 曲线移动。单位：度；速度单位：deg/s。未给速度使用 `SP 17` 默认速度。加速度自动为 `v × SP 21`。 |
| `g x y z [pitch]` | `g 120 0 180 0` | IK 笛卡尔运动，单位 mm，pitch 单位度。未给 pitch 默认 0。 |
| `f` | 无 | 读取实际关节反馈并做 FK，输出当前末端 XYZ/Pitch。 |
| `P 0~4` | `P 2` | 预定义姿态：0 HOME、1 FOLD、2 READY、3 WAVE1、4 WAVE2。 |
| `W [n]` | `W 3` | 摇摆 n 次，默认 3、最大 20。 |
| `S` | 无 | 停止轨迹，同时清除循环、多点、等待、自适应修正等运动状态。 |

### 3.3 循环与重复定位试验

| 命令 | 功能 |
|---|---|
| `B a1..a6 b1..b6 rounds [speed]` | 两个关节姿态 A/B 循环。`rounds=0` 表示无限循环。 |
| `BG x1 y1 z1 p1 x2 y2 z2 p2 rounds [speed]` | 两个笛卡尔姿态 A/B 循环。 |
| `q n j1..j6` | 保存第 n 个关节目标点，n=1~8。 |
| `qg n x y z [pitch]` | 先 IK 校验，再保存第 n 个笛卡尔点对应的六关节角度。 |
| `qv n speed` | 设置第 n 段移动速度，单位 deg/s。 |
| `qd n ms` | 设置第 n 个点实际到位后的停留时间，单位 ms。 |
| `QL count rounds [speed]` | 按顺序循环已保存的点；逐点、逐关节输出实际角度与 `actual-target` 误差，并输出独立统计。`rounds=0` 无限循环。 |

`QL` 的记录前提：六轴反馈读取成功，并进入目标 ±2°。正常 `m/g/P` 运动完成判定更严格：六轴均在目标 ±1°，持续稳定 500 ms。

### 3.4 限位、坐标标定、PID 与 Flash

| 命令 | 功能 |
|---|---|
| `L` | 显示六轴软件限位。 |
| `L J min max` | 设置关节限位，度。该命令当前仅修改运行内存。 |
| `C` | 显示世界坐标偏移。 |
| `C dx dy dz` | 设置世界偏移，含义为 `actual = model + offset`。 |
| `G` | 查看自适应修正/PID 状态。 |
| `G k` | 设置 J2 重力前馈 K，单位 deg/mm。 |
| `K [J val]` | 查看/设置 XL320 P Gain；J 为 1~6。 |
| `I [J val]` | 查看/设置 XL320 I Gain；J 为 1~6。 |
| `D [J val]` | 查看/设置 XL320 D Gain；J 为 1~6。 |
| `N J P I D` | 一次设置某关节完整 PID。 |
| `V [value]` | 查看/设置全部 XL320 的内部 Moving Speed，范围 0~2047。 |
| `A` | 查看自适应配置。 |
| `A e 0/1` | 关闭/启用自适应修正。 |
| `A t val` | 设置自适应阈值，度。 |
| `A r val` | 设置最大修正轮数。 |
| `A g J value` | 设置关节初始修正增益，百分比。 |
| `R` | 重置并重新触发自适应修正。 |
| `LP` | 列出全部运行时算法参数。 |
| `SP id value` | 设置一个运行时算法参数，仅修改 RAM。 |
| `F` | 保存 PID、修正参数、Moving Speed、全部 SP 参数到 Flash。 |
| `X` | 应用固件默认 PID/相关运行参数到 RAM；如需断电后保留，应再执行 `F`。 |
| `LL [0~4]` | 查看/设置运行日志等级。 |

### 3.5 文本模式上位机注意事项

- 上位机必须按行读取，不应假设一次串口 Read 就是一条完整响应。
- `s`、`LP`、`G`、`A`、`QL` 输出是供人阅读的多行文本；不要把它作为正式数据协议。
- `pv/pf` 会持续占用输出带宽；开始正式二进制控制前先发送 `pv 0`、`pf 0`。
- `F` 会擦写 STM32 Flash 扇区 11；只在用户确认参数后触发，UI 应弹出确认提示并等待成功文本。

## 4. 统一二进制协议（串口与 CAN 共用）

### 4.1 串口二进制帧

```text
AA 55 SEQ CMD LEN PAYLOAD[0..LEN-1] CRC_LO CRC_HI
```

| 字段 | 字节 | 说明 |
|---|---:|---|
| HEAD | 2 | 固定 `AA 55` |
| SEQ | 1 | 请求序号；响应原样回显。上位机循环使用 1~255。 |
| CMD | 1 | 命令字。 |
| LEN | 1 | 负载长度，0~64。 |
| PAYLOAD | 0~64 | 小端定点数据。 |
| CRC | 2 | CRC-16/CCITT-FALSE，小端：低字节在前。计算范围 `SEQ..PAYLOAD`，不含 `AA 55`。 |

CRC 参数：多项式 `0x1021`，初值 `0xFFFF`，非反射，xorout `0x0000`。

### 4.2 数据编码与字节序

所有多字节整数使用**小端序**。

| 数据项 | 类型 | 编码 |
|---|---|---|
| 关节角、Pitch | `int16` | 实际值 × 10，单位 0.1° |
| XYZ | `int16` | 实际值 × 10，单位 0.1 mm |
| 速度 | `uint16` | 实际值 × 10，单位 0.1 deg/s |
| 加速度 | `uint16` | 实际值 × 10，单位 0.1 deg/s² |
| 重力 K | `int16` | 实际值 × 1000，单位 0.001 deg/mm |
| SP 参数 | `int32` | 实际值 × 1000，单位 0.001 |

### 4.3 命令与响应

控制成功统一响应 `ACK=0x7F`，负载为：

```text
[orig_cmd:u8, err:u8]
```

失败统一响应 `NACK=0x7E`，负载格式相同，`err` 不为 0。

| CMD | 名称 | 请求负载 | 正常响应 |
|---:|---|---|---|
| `0x01` | PING | 无 | `0x81`：`proto_ver:u8, run_id:u8` |
| `0x02` | GET_STATUS | 无 | `0x82`：21 字节状态快照 |
| `0x03` | LOG_SET_LEVEL | `level:u8`，建议 0~3 | ACK/NACK |
| `0x10` | MOVE_JOINTS | `J1..J6:int16` + `v:uint16` + `a:uint16`，共 16 B | ACK/NACK |
| `0x11` | STOP | 无 | ACK |
| `0x12` | SET_TORQUE | `joint:u8, enable:u8`；`joint=0xFF` 为全部 | ACK/NACK |
| `0x20` | MOVE_CART | `x,y,z,pitch:int16` + `v,a:uint16`，共 12 B | ACK/NACK |
| `0x21` | FK_QUERY | 无 | `0xA1`：21 字节 FK 与关节快照 |
| `0x30` | SET_GRAVITY | `K:int16`，值×1000 | ACK/NACK |
| `0x31` | SET_CORRECTION | `enable:u8, threshold_cdeg:uint16, max_rounds:u8` | ACK/NACK |
| `0x40` | PARAM_READ | `id:u8` | `0xC0`：`id:u8, value_x1000:int32` |
| `0x41` | PARAM_WRITE | `id:u8, value_x1000:int32` | ACK/NACK |
| `0x42` | PARAM_COUNT | 无 | `0xC2`：`count:u8` |

### 4.4 状态响应定义

#### `GET_STATUS` 响应 `0x82`（payload=21 B）

```text
Byte 0..11   J1..J6 实际角度，6 × int16，0.1°
Byte 12..13  X，int16，0.1 mm
Byte 14..15  Y，int16，0.1 mm
Byte 16..17  Z，int16，0.1 mm
Byte 18..19  Pitch，int16，0.1°
Byte 20      flags
```

角度读取失败时，某轴角度值是 `0x8000`（即 int16 `-32768`）。`flags` 位定义：

| Bit | 掩码 | 含义 |
|---:|---:|---|
| 0 | `0x01` | E-Stop 激活 |
| 1 | `0x02` | S 曲线轨迹执行中 |
| 2 | `0x04` | 自适应修正执行中 |
| 3 | `0x08` | 六轴反馈与 FK 均成功 |

#### `FK_QUERY` 响应 `0xA1`（payload=21 B）

```text
Byte 0..1    X，0.1 mm
Byte 2..3    Y，0.1 mm
Byte 4..5    Z，0.1 mm
Byte 6..7    Pitch，0.1°
Byte 8..19   J1..J6 实际角度，6 × int16，0.1°
Byte 20      read_ok：1=六轴反馈和 FK 成功；0=失败
```

### 4.5 NACK 错误码

| 错误码 | 名称 | 上位机处理建议 |
|---:|---|---|
| 0 | OK | 正常 |
| 1 | PARAM | 检查负载长度、参数 ID、输入范围 |
| 2 | CRC | 检查 CRC、CAN 分包顺序或字节序 |
| 3 | UNREACH | IK 目标不可达/不收敛；提示修改 XYZ/Pitch |
| 4 | LIMIT | IK 解超软件限位；提示修改姿态 |
| 5 | ESTOP | 急停激活；禁止继续运动 |
| 6 | FK_VERIFY | IK 反算验证误差超限；提示调整目标/参数 |
| 7 | READ | XL320 反馈读取失败；提示检查舵机总线 |

## 5. CAN 分包协议

CAN 不传输串口帧头 `AA 55`，而是传输逻辑流：

```text
SEQ CMD LEN PAYLOAD CRC_LO CRC_HI
```

### 5.1 首帧

```text
D0 = 0x80 | total_frames       // 总帧数 1~15
D1 = SEQ
D2 = CMD
D3 = LEN
D4..D7 = PAYLOAD 起始字节，若 payload 不足则继续放 CRC
```

### 5.2 续帧

```text
D0 = frame_index               // 从 1 开始递增
D1..D7 = 后续 PAYLOAD/CRC 字节
```

计算总帧数：

```text
tail_total = LEN + 2           // PAYLOAD + CRC
frames = 1 + ceil(max(tail_total - 4, 0) / 7)
```

完整 CAN 请求必须在 200 ms 内收齐，否则固件丢弃当前重组内容。

### 5.3 可直接测试的 CAN PING

默认 node=1，发送 CAN ID=`0x101`，DLC=6：

```text
81 01 01 00 9D C8
```

含义：单帧(`0x81`)、SEQ=1、CMD=PING(`0x01`)、LEN=0、CRC=`0xC89D` 小端。

正常应接收 CAN ID=`0x181`，第一帧以如下形式开头：

```text
81 01 81 02 01 <run_id> <CRC_LO> <CRC_HI>
```

### 关键限制：二进制协议当前没有 Flash 保存命令

当前二进制命令只到 `0x42`，**没有 `SAVE_CONFIG` 命令**。因此：

- 通过二进制/CAN `PARAM_WRITE (0x41)` 写参数后，只在 RAM 中生效；
- 如果要断电保持，仍需通过 USART6 文本通道发送 `F\r\n`；
- 若上位机未来只保留 CAN，建议下一版固件新增 `SAVE_CONFIG` 和 `LOAD_DEFAULTS` 二进制命令后再取消文本依赖。

## 7. 典型上位机流程

### 7.1 连接与自检

1. 打开串口 115200 或 CAN 500 kbit/s。
2. 发送 PING，等待 200~500 ms 响应。
3. 验证协议版本为 1。
4. 发送 `GET_STATUS`，若 `read_ok=0`，在 UI 报告“舵机反馈异常”，不可显示伪造坐标。
5. 如 `estop=1`，禁用所有运动按钮。

### 7.2 六轴运动

1. 输入 J1~J6 目标角（0~300°）。
2. 上位机应先根据软件限位做前置校验：J1 40~240、J2 70~240、J3 50~210、J4 40~260、J5 30~280、J6 0~300。
3. 用 `MOVE_JOINTS` 发送目标、最大速度和加速度。
4. 收到 ACK 仅表示“轨迹已成功启动”，**不表示已经到位**。
5. 每 80~200 ms 请求 `GET_STATUS`；当 `traj_active=0`、`corr_active=0` 且实际角度全部接近目标时，UI 才显示“完成”。

### 7.3 笛卡尔运动

1. 输入 X/Y/Z/Pitch。
2. 发送 `MOVE_CART`。
3. NACK=3/4/6 时显示目标不可达、关节限位或 FK 验证失败。
4. 收到 ACK 后以 `GET_STATUS` / `FK_QUERY` 跟踪实际末端位置。

### 7.4 参数修改与保存

1. 启动后请求 `PARAM_COUNT`，当前期望返回 16。
2. 依次 `PARAM_READ` 所有关心 ID，刷新参数 UI。
3. `PARAM_WRITE` 后再读回，显示固件钳制后的实际值。
4. 用户确认后，经串口文本发送 `F` 进行持久化。
5. 显示“已写 Flash”后建议重启并重新读取验证。

## 8. 上位机实现注意事项

1. **请求-响应配对**：使用 `SEQ` 作为唯一匹配键；不要仅按返回顺序匹配。
2. **串口接收缓存**：必须采用连续字节解析状态机，处理粘包、拆包、文本日志混入与半帧超时。
3. **CAN 发送顺序**：多帧报文不可乱序；首帧后续帧索引必须依次为 `1,2,...`。
4. **不要高速轮询**：`GET_STATUS` 内部会读取六个 XL320。建议 5~12.5 Hz（每 80~200 ms）轮询，不要每 10 ms 发送。
5. **STOP 优先级**：UI 停止按钮立即发 `STOP (0x11)`；文本模式发 `S`。
6. **扭矩安全**：扭矩开启前确认急停未激活、机械臂周围安全；首次联调用低速（例如 10~30 deg/s）。
7. **文本与二进制日志隔离**：如正式使用二进制协议，推荐 `LOG_SET_LEVEL=0` 或停止 `pv/pf`，避免 UI 日志解析干扰。
8. **JSON 同步策略**：上位机可读取 `config/arm_config.json` 生成默认限位、姿态和参数表，但运行时真值始终应以固件 `PARAM_READ/GET_STATUS` 返回为准。

## 10. 后续固件优化建议

为让上位机完全脱离文本命令，建议后续新增以下二进制命令：

- `SAVE_CONFIG`：等价文本 `F`，保存参数/PID/修正配置；
- `LOAD_DEFAULTS`：等价文本 `X`；
- `GET_JOINT_LIMITS` / `SET_JOINT_LIMITS`；
- 周期状态上报订阅（替代主动轮询）；
- 多点队列的二进制增删改查与 QL 统计返回；
- PID、Moving Speed 的二进制读写接口。

在上述命令加入之前，上位机应采用“二进制负责实时控制与状态、文本负责维护与保存”的混合模式。
