## 1. 一句话原理

从臂的示教录音缓冲（`teach_rec[4000][6]`，50 Hz 采样）本来就在**从臂**上。
遥操时从臂是被外部目标（`#P` 流）驱动的 —— 只要让从臂在这种状态下**只录不控**
（不松力、不改 PID、不写目标），就能一边跟流一边录。

录到的是**从臂自己实际走出来的轨迹**（已过限位 `clamp_raw` 与跳变守卫），
所以它对从臂是 1:1 可复现的；**它不等于主臂的原始轨迹**（主臂超出从臂限位的部分
已在从臂侧被夹掉）。

```
主臂(人力拖) ─ sp 60 ─► #P 行 ─► pc_relay.py ─► 从臂
                                        │
                                        └─► 从臂 teach rec 同时 50Hz 采样 ─► save ─► Flash
                                                                              └─► play 回放
```

## 2. 现场全流程

### 阶段 A · 上电与准备（两臂都别在跑）

```bash
# 两臂各敲一次（确认零点/限位是健康的）
zi            # calib_zero_raw 应接近 [2048 ×6]
L             # 记下限位表（回退/核对用）
```

### 阶段 B · 从臂进入"跟随录制"

```bash
# 从臂控制台（这一条现在敲，或交给脚本 --slave-cmd）
ec 0          # 关控制台回显：省发送带宽，跟随更稳（可选但强烈建议）
sf 1          # 跟随门闩（上电默认就是 ON）
teach rec     # ★ 开始跟随录制：只采样，不碰舵机
```

正常回显：

```
  Teach RECORD-ONLY started: servos untouched (torque/PID/speed unchanged).
  Sampling every 20 ms, max ~80 s. Stream follow (#P / sf 1) keeps working.
  Stop: 'teach exit'  -> then 'save <name>' to store, 'play <name>' to replay.
```

⚠ 此刻**臂不动**（`teach rec` 不松力、不改任何舵机寄存器）。要动它得靠后面的流。

### 阶段 C · 主臂开始转发 + PC 中转

```bash
# 主臂控制台
mf 0          # 静默自有直连链路（不静默会把控制台流帧率从 ~65 打到 ~46 Hz）
sp 60         # 开始吐 #P 位置行（60 是下限建议值，别更低）

# PC（Windows PowerShell / Git Bash）
py -3 tools/pc_relay.py --master COM22 --slave COM11
```

也可以一条命令自带开机动作（推荐，省得再开串口助手）。

⚠ **先看你用的是哪个终端**（`^` 是 cmd 的续行符，PowerShell 里会被当成自减运算符报
`一元运算符"--"后面缺少表达式`）：

```powershell
# PowerShell —— 最稳：写成一行
py -3 tools\pc_relay.py --master COM22 --slave COM11 --start --hz 60 --slave-cmd "ec 0" --slave-cmd "teach rec" --teach-name demo1
```

```powershell
# PowerShell —— 要多行就用反引号 ` （必须是行尾最后一个字符，后面不能有空格）
py -3 tools\pc_relay.py --master COM22 --slave COM11 `
    --start --hz 60 `
    --slave-cmd "ec 0" --slave-cmd "teach rec" --teach-name demo1
```

```bat
:: cmd.exe —— 用 ^
py -3 tools\pc_relay.py --master COM22 --slave COM11 ^
    --start --hz 60 ^
    --slave-cmd "ec 0" --slave-cmd "teach rec" --teach-name demo1
```

> `--start` 已经自动发了：主臂 `mf 0` + `sp <--hz>`，从臂 `sf 1`。
> 所以**不用再手加 `--slave-cmd "sf 1"`**（重复发无害，但没必要）。

脚本启动后会打印热键表：

```
运行中按键（不用回车）:
   r  -> 从臂 `rec clear + teach rec`  从臂: 清空缓冲并重新开始录制 (只采样, 不松力)
   x  -> 从臂 `teach exit`             从臂: 停止录制 (录音保留)
   t  -> 从臂 `teach list`             从臂: 看已录样本数/时长
   w  -> 从臂 `save demo1`             从臂: 存盘 (Flash)
   l  -> 从臂 `list`                   从臂: 列出已存文件
   s  -> 主臂 `sp 0`                   主臂: 停位置流 (从臂原地锁定) ← 存盘前按
   g  -> 主臂 `sp 60`                  主臂: 恢复位置流 (继续遥操)
   h  -> 重印这份热键表
```

> ⚠ **`r` 为什么是两条命令**：固件里 `teach rec` 在"已经在录"时只回
> `Already recording (N samples)`，**不会清缓冲** —— 清缓冲只发生在
> `teach_mode_prepare()` 的"全新进入"分支，而它在"已 active"分支就 `return` 了。
> 所以想让 `r` 真做到"重录"，必须先 `rec clear`（`rec` 与 `teach` 都在示教白名单里，
> 不会被 auto-exit 顶掉）。

### 阶段 D · 拖主臂做动作

人手拖主臂，从臂跟随。**随时按键**：

| 键 | 动作 | 说明 |
|---|---|---|
| `r` | 重新开始录 | 发 `rec clear` + `teach rec`，把已录内容清掉、从 0 开始。⚠ 会**丢**掉未存盘的内容，先看 `t`/`w` |
| `t` | 看进度 | 打印 `N samples, ~M ms` |
| `x` | 停止录制 | **录音保留**，不丢 |
| `w` | 存盘 | 名字用 `--teach-name`，没给就自动命名 `rec1`/`rec2`…。⚠ 它内部会**先自动 `teach exit`**，并**阻塞 1~3 s** 写 Flash |
| `l` | 列文件 | 看 Flash 里已存的文件 |
| `s` | 主臂停流 | 从臂停在当前位置（位置环自锁）；用于存盘/收尾前 |
| `g` | 主臂恢复流 | 继续遥操 |

**推荐的操作节拍（存盘这一步别省 `s`）**

```
拖一段 → s（停流，从臂原地锁定） → w（存盘，此时没有流在跑） → g（恢复流，接着拖）
```

⚠ **为什么存盘前要 `s`**：`save` 是把整段样本写进从臂**内部 Flash**，
量级是 **阻塞 1~3 秒**（n×12 字节逐字编程；首次存盘或满 80 s 的大录音最坏可到 ~5 s，
因为可能附带一次扇区擦除）。
这期间从臂主循环不转，而主臂的位置流照旧往从臂串口灌（60 Hz × 约 40 B/行），
从臂控制台的 **128 B 接收环只装得下 3 行** ⇒ 剩下全丢。主循环恢复后看门狗发现
已断流 >500 ms，会打一行：

```
  Stream watchdog: no cmd for 500 ms -> hold (total N)
```

然后**重新锚定当前位置作为跳变基准**。后果分两种：

- 你在这 1~3 秒里**没动**主臂 → 只是丢了几帧，`g` 之后照常跟，无影响；
- 你在这 1~3 秒里**继续拖**主臂 → 主臂那段位移会被**整段跳过**；若 J5 这类手腕轴
  在你手上甩得快，还会撞上从臂固件的「每帧 25°」跳变判据 → 连帧拒绝 → 拒帧不更新
  基准 → **自锁**（现象就是"从臂突然卡住不动，主臂怎么拖都不跟"）。

停流再存，这两个后果都不存在。停流后从臂打的那行 `Stream watchdog ... -> hold`
是**预期行为**（说明它锁在原地等你），不是故障。

从臂侧的确认行会实时出现在脚本输出里（`[从臂] Teach RECORD-ONLY started` /
`[从臂] Recording stopped: ... samples`）。

### 阶段 E · 收尾

脚本在跑的时候，**两个串口都被它独占**，你没法再开串口助手去敲命令 ——
所以收尾全部按热键：

```
按 x     # 从臂: 停止录制（录音保留）
按 w     # 从臂: 存盘进 Flash       ← 建议先按 s
按 s     # 主臂: 停位置流（省得它空转）
Ctrl+C    # 退出脚本，两个串口释放
```

然后开从臂串口助手做回放：

```bash
# 从臂（回放前必须做；脚本已退出，口已释放）
sf 0          # 停跟随：否则回放会和 #P 流抢同一个 goal
play demo1    # 回放刚存的；加 loop 循环：play demo1 loop
```

⚠ 回放**必须等脚本退出**：`play` 要在从臂控制台敲，而脚本运行期间从臂口是独占的。

回放期间固件会自己再关一次流式跟随并打印：

```
  (stream follow OFF for playback — from-arm: 'sf 1' to resume teleop)
```

回放结束、想继续遥操：**从臂 `sf 1`**，再回到 阶段 C 重新起脚本。

## 3. 硬上限与量级

| 项 | 值 | 说明 |
|---|---|---|
| 采样率 | **50 Hz**（20 ms/点） | `TEACH_REC_MS = 20` |
| 单条录音上限 | **4000 点 ≈ 80 秒** | RAM 缓冲 48 KB；满了会提示并停止记录，**已录部分不丢** |
| 存盘位置 | **从臂内部 Flash** | `save <名字>` → `TeachStore_Save()`，写完立刻对整段做 CRC 回读比对 |
| **存盘耗时** | **1~3 s，且阻塞主循环** | 写 n×12 字节 + CRC 回读（首存/大录音最坏 ~5 s，可能附带扇区擦除）；期间从臂不跑控制台/遥测/**流看门狗** ⇒ 遥操中存盘前必须先 `s` 停流（见 阶段 D） |
| 已有文件 | 用 `list` 看 | 删除用 `del <名字>`，回收空间用 `compact` |


⚠ **超 80 秒的动作要分段**：录满时打印 `Teach buffer full (~80 s)`，此时按 `x`
停止 → `w` 存 → 再按 `r` 录下一段，存成 `demo1` / `demo2` …，最后用
`play demo1` `play demo2` 顺序放。

### 3.1 ⚠ 录音只在从臂 RAM 里 —— 三条会把它抹掉的路（2026-09-17 现场丢过一条）
| 触发 | 后果 | 规避 |
|---|---|---|
| **Ctrl+C 退脚本** | 脚本停了，但**从臂还在录**（录制状态在从臂里，脚本只是转发）。下次 `teach rec` 会回 `Already recording (N samples)` 而不是重开 | 收尾按 `x` → `s` → `w`，别用 Ctrl+C 当"停止" |
| **退出后再 `teach rec`**（`teach exit` 之后 buffer 仍在 RAM，这是最危险的窗口） | `teach_mode_prepare()` 里 `teach_rec_cnt = 0U` ⇒ **整段静默清空**。唯一线索是提示语从 `Already recording` 变成了 `RECORD-ONLY started` | 新版固件（`06_slave` `26325992…`）会在清空前打 `⚠ Discarding UNSAVED recording: N samples` |
| **断电 / 重烧固件 / `rec clear`** | RAM 清空，无恢复手段 | **拖完就 `w` 存**，别攒着 |

> 判据：`teach list` 打印的样本数。退出录制后它**应该还是 4000**；
> 如果是 0 或很小的数，说明缓冲已被清掉、你刚才录的那段没了。

## 4. 回放不是"重放录像"——它没有安全过滤

`play` 是**逐点原样 SyncWrite 录下来的 raw 位置**，源码注释写明：
**replay 不重新跑 FK/桌面碰撞过滤**，它复现的就是当时那次物理运动。
所以：

- ✅ 因为录的是**从臂实际走出来**的位置，本来就已经在从臂限位内 ⇒ 可复现
- ⚠ 但**从臂重新标定（重锚 Home 零点 / 换舵机 / 改限位）之后，旧录音不再安全**
  —— 录音存的是 raw，零点一变语义就变了。改过校准就把旧文件删掉重录。
- ⚠ 回放的**起步段**是 S 曲线从当前位置回到录音起点（`TEACH_PLAY_RAMP`），
  这段是规划出来的，途中会走 FK 路径校验。

## 5. 这次改了什么（含两个不改就录不到的坑）

### 5.1 新命令 `teach rec`（`cmdTeachEnterRec()`）

"纯观察者"示教：**一个舵机寄存器都不写**，只把 `teach_mode_active` 置 1，
让 50 Hz 节拍去跑 `teach_record_tick()` 的"纯读"分支。

对比原有三种手拖示教：

| 命令 | 扭矩 | P/I/D | 目标 | 能用于遥操中吗 |
|---|---|---|---|---|
| `teach`（悬浮） | ON+限矩 | **改成极软** | 被拉到 present | ❌ 会跟 `#P` 流打架 |
| `teach free` | **OFF** | — | — | ❌ 松力，臂会掉 |
| `teach pwm` | J2/J3/J4 切 Mode2 | — | — | ❌ 同上 |
| **`teach rec`** | **不动** | **不动** | **不动（由流写）** | ✅ |

### 5.2 坑一：命令白名单必须放行 `#P`

`ProcessCommand()` 里有一条"示教期间敲非示教命令就自动退出示教"的保护。
`#P` 流帧**也走这条路径**，而它不在白名单里 ⇒ 开录后收到的**第一条 `#P`
就把录制顶掉**，现场表现为"`teach rec` 之后永远 0 samples"。

修法：条件里加 `tokens[0][0] != '#'`（整类 `#` 流帧豁免），
并把 `sf` / `ec` 加进白名单（录制期间要能开关跟随）。

### 5.3 坑二：退出时不能"恢复"从未改过的东西

`cmdTeachExit()` 原本无条件做三件事，在 `teach rec` 下**全是破坏性的**：

| 原动作 | `teach rec` 下的后果 |
|---|---|
| 用 `teach_punch_backup[]` 恢复 PUNCH | 该数组只在悬浮示教里被读过，`teach rec` 从没进那分支 ⇒ **数组还是初值 0 ⇒ 六轴 PUNCH 被清成 0** |
| 恢复 `GOAL_SPEED = all_servo_moving_speed` | `stream_enter()` 特意写过 `GOAL_SPEED = 0`(=最大)，这里再写"有限速度" ⇒ **之后继续遥操从臂会莫名变慢** |
| `SERVO_SetTorque(j, 1)` | 无害（本来就没关），但也没必要 |

修法：整段用 `if (!teach_record_only)` 包住。

### 5.4 回放与流互斥（顺带修）

- `teach_play_start()` 现在会**主动关掉流式跟随**并提示 —— 否则回放每 20 ms 写的
  goal 和 `#P` 流写的 goal 会互抢，现象是"回放被拖住 / 来回抖"。
- 回放的"被打断就中止"判据里也豁免了 `#P`：**主臂忘了 `sp 0` 也不会一帧打断回放**
  （那些帧会走 `stream_follow_en == 0` 分支被计进 `stream_ignored` 后丢弃）。

### 5.5 PC 侧热键

`tools/pc_relay.py`：非阻塞单键（Windows `msvcrt`，POSIX `select`，
环境不支持时自动退成桩、**绝不影响转发**）。新增 `--teach-name` / `--no-keys`。

### 5.6 2026-09-17 补：主臂侧停流/恢复热键 `s` / `g`

脚本起来后主臂口也被独占，你**没法**手敲 `sp 0`。而 `save` 写 Flash 是阻塞 1~3 s 的，
期间不能有位置流在灌（否则丢帧 + 看门狗重锚 + J5 自锁，见 阶段 D）。所以加了：

| 键 | 发给 | 命令 |
|---|---|---|
| `s` | 主臂 | `sp 0`（停位置流；从臂断流后原地自锁保持） |
| `g` | 主臂 | `sp <--hz>`（恢复位置流；`--hz 0` 时按 60 发） |

`s`/`g` 与从臂那五个键共用同一套非阻塞 reader，只是**发送目标换成主臂口**，
并顺手把 `master_told` 置位（主臂口确有流量，避免误报"端口选错"）。

### 5.7 2026-09-17 事故复盘：三条"隐形破坏"的修复

现场用 `--dry-run` 试跑参数时，**开机命令照样发到了真臂上**，其中 `teach rec`
走进 `teach_mode_prepare()` 的 `teach_rec_cnt = 0U`，把一条 80 s 未存盘的录音清掉了。

| 缺陷 | 根因 | 修法 |
|---|---|---|
| `--dry-run` 不拦开机命令 | `args.dry_run` 只在**转发路径**（读主臂行那一段）检查，`send()` 出口无守卫 | `send()` 里直接 `if args.dry_run: print(...); return`。**安全开关必须放在最底层出口，不是调用点**；启动时也打一行 `⚠ --dry-run：一条命令都不会发` |
| `r` 键不能"重录" | 固件 `teach rec` 在已 active 时**只提示不清缓冲**；清缓冲在 `teach_mode_prepare()` 的"全新进入"分支 | 脚本 `r` 改发 `rec clear` + `teach rec`（两条都在示教白名单里） |
| 清缓冲是静默的 | `teach_mode_prepare()` 直接 `teach_rec_cnt = 0U`，唯一线索是提示语变了 | 固件清空前打 `⚠ Discarding UNSAVED recording: N samples, ~M s (was it saved? 'list' shows stored files)` |
| 脚本误报"没有先发 mf 0" | `has_mf0 = any(...)` 只看 `--master-cmd`，**没把 `--start` 自带的 `mf 0` 算进去** | `has_mf0 = args.start or ...`；并把无条件的"提醒主臂要 mf 0 + sp"改成只在确实没发 `sp` 时打印 |

> 教训（可复用）：**任何"只测参数"的路径都不能有改变现场状态的副作用**；
> 破坏性操作在动手前必须**先报出将要失去什么**。

## 6. 现场判据（出问题先看这几行）

| 现象 | 判据 / 处理 |
|---|---|
| `teach rec` 后 `t` 一直 `0 samples` | ① 流没在跑（主臂 `sp` 没敲 / `mf` 没静默）② 从臂 `sf 0` 关着跟随（`#P` 被忽略）③ 这条固件是旧版（里面没有 `teach rec` 命令，会被单键模式吃字符）。**自检**：直接在 `outputs/link_pc/06_slave_PCrelay_ec.bin` 里搜字符串 `Teach RECORD-ONLY started`，搜得到就是新版 |
| `teach rec` 回 `Already recording (N samples)` | 上一轮录音**还活着**（多半是 Ctrl+C 后从臂没停）。要留住就 `save <name>`；要重录就 `r`（= `rec clear` + `teach rec`）。**别当成"已重开"继续拖** —— 那会只在旧缓冲尾巴上续几十个点就满了 |
| 清空前看到 `⚠ Discarding UNSAVED recording: N samples` | 你正要丢掉 N 点未存盘的录音。想留住它：**立刻**改敲 `save <name>` |
| 脚本里看不到 `[从臂] Recording stopped` | 从臂没收到 `x`；或从臂串口在脚本启动**之前**就被占用（`--slave` 端口选错） |
| 按 `s` 或按 `w` 时打 `Stream watchdog: no cmd for 500 ms -> hold` | **预期**（断流保护正常工作，从臂锁在原地等你）。按 `g` 即可继续跟；若 `g` 之后不跟，多半是那 1~3 秒里主臂被我拖动过 ⇒ 之后**先 `s` 再 `w`** |
| `g` 之后从臂卡住不动、主臂怎么拖都不跟 | 大概率是 J5 一类手腕轴撞了「每帧 25°」跳变判据自锁（存盘期间丢掉的那段位移太大）。处置：主臂回到**接近从臂当前姿态**的位置再拖；或从臂 `sf 0` → 手推把它对齐 → `sf 1` |
| 录到的轨迹有"直线抄近路"的一段 | 看 `teach exit` 打出的 `[rec-integrity]`：`lost_ticks>0` = 主循环卡顿压缩时间轴；`read-fail` **集中在某几轴** = 那几轴所在的**总线**回报率差（见下） |
| `[rec-integrity] read-fail` 数量很大 | 判"是整条总线还是单轴"：默认 **J1–J3 = 总线 A（USART3, PB10/PB11）**、**J4–J6 = 总线 B（UART5, PC12/PD2）**。2026-09-17 实测 A 总线 9878/12000 ≈ **82%**、B 总线 2664/12000 ≈ **22%** ⇒ 是**总线级**差异，不是某一颗舵机。`lost_ticks` 只有 16 ⇒ 失败是**快速返回**（帧坏 / 状态帧带告警位），不是 10 ms 超时等不到 |
| 回放回不到起点就停 | 起点姿态差异太大 / 起手段路径校验拒绝；先手动把从臂摆到接近录音起点再 `play` |
| 回放时手一碰就乱 | 回放是位置环保持，`S` 先停 |
