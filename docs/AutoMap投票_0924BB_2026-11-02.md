# AutoMap 投票 + 路由回落 BUGFIX（0924BB，2026-11-02）

> 触发场景：集成板 74HC126 在位、六颗舵机全部串到 **Bus B**、`BUS_PP=1` 构建。
> 现象是 `b auto` 在 `6/6` 与 `3/6` 之间跳，而且**每次跳完路由都变**。

---

## 一、现场指纹

```
b auto
[MAP] re-probe: online 3/6
J1 (ID 1) -> Bus B
J2 (ID 2) -> Bus B
J3 (ID 3) -> Bus A  MISSING     ← 本来是 B，被打回 A
J4 (ID 4) -> Bus B
J5 (ID 5) -> Bus B  MISSING
J6 (ID 6) -> Bus B  MISSING
7 axis re-routed.               ← 其实只动了 3 轴，7 是位掩码 0b111
```

三条线索指向两个独立 bug：

| 线索 | 指向 |
|---|---|
| `J3 -> Bus A` 而舵机物理在 B 段 | **Bug 1**：MISSING 时回落到编译期默认 A |
| 再跑一次又变回 `Bus B` | Bug 1 的自我维持：下次 pass1 继续失败 → 再改 |
| `7 axis re-routed` | **Bug 2**：位掩码被当数量打印 |

---

## 二、Bug 1（严重）：离线时回落到编译期默认

0924BA 的 pass2 里：

```c
uint8_t def = (j < 3U) ? BUS_A : BUS_B;   /* 编译期"默认布局" */
...
} else {
    JOINT_BUS[j] = def;   /* 离线: 保持默认 */
}
```

`def` 对 J1~J3 恒为 **Bus A**。而这台板子的物理事实是**六颗全在 B 段**，所以
"默认布局"本身就是错的 —— 它不是一个安全的回落目标。

于是形成闭环：

```
一次 PING 抖动（单帧误码约 37%）
   → J3 报 MISSING
   → JOINT_BUS[2] 被改成 BUS_A（空段）
   → 之后 SERVO_GetPositionRawTO 永远打 A 段空线 → RC 该轴丢读
   → 下次 pass1 用 A 探 J3 又失败 → 再进 pass2 → 随机再改
```

**误报一次，就等于把一条能用的路由废掉。** 这是比"探测显示 4/6"严重得多的问题。

### 修法

新增 `s_map_conf[6]` + `s_map_known` 位掩码，保存**上次实测确认过的路由**：

- MISSING 时 **`JOINT_BUS[j]` 原封不动**，只置 `miss` 位给上层报警
- 上次确认的路由作为第二候选，命中即"自愈"撤回被改坏的路由

---

## 三、Bug 2（显示）：位掩码当数量

```c
if (moved) cprint("  %u axis re-routed.\r\n", (unsigned)moved);
```

`moved` 是 bit0|bit1|bit2 = `0b111` = 7。改成逐位计数后才会显示真实的
`3 axis re-routed`。

---

## 四、新结构：三段式 + 投票

```c
#define BUSMAP_PING_MS     30U
#define BUSMAP_VOTE_ROUNDS 3U   /* 每候选投 3 轮 */
#define BUSMAP_VOTE_MIN    2U   /* >=2/3 才认定 */
```

| 段 | 何时执行 | 做什么 | 额外开销 |
|---|---|---|---|
| **pass1** | 每次 | 按现有 `JOINT_BUS[]` 逐轴 PING（内部已含 2 次重试），6/6 直接返回 | 正常布局 **0**（~1ms） |
| **pass2** | 有轴缺失 | 对失败轴在 `{当前路由, 上次确认路由}` 上各投 3 轮 | 抖动补中 ~1ms；真丢 ~180ms |
| **pass3** | 仍无定论 | 双总线全扫，**带空段短路**（某段一个 ID 都不应答就跳过后续轮次） | A 段空时 ~360ms |

### 判定规则（每轴独立）

| v(候选0) | v(候选1) | 结论 |
|---|---|---|
| ≥2 | ≥2 | **DUP-ID**：两段都应答（同 ID 两片 / 两段并线）。保当前路由，只告警 |
| ≥2 | <2 | 原路由正确，只是抖动 → **不改任何东西** |
| <2 | ≥2 | **自愈**：撤回被改坏的路由，`moved` 置位 |
| <2 | <2 | 进 pass3；pass3 仍失败 → `miss`，**路由保持不变** |

候选1 与候选0 相同时不重复投票（省一半时间）。

### 为什么投票是 3 轮 2 票

单帧原始成功率 $p_1 \approx 0.63$（由 6 次 `b auto` 平均命中 86%、`DXL_Ping` 内已 2 次重试反推）。
一次 `DXL_Ping` = 2 次尝试，命中率 $1-(1-p_1)^2 \approx 0.86$；
3 轮投票取 2 票，漏判概率降到约 **5%**；5 轴同时漏判的概率已可忽略。

要真正把 $p_1$ 拉上去只能靠硬件（上拉 1kΩ → 470Ω），软件这版只是把抖动
**挡在路由层之外**，不让它污染状态。

| 步骤 | 命令 | 期望 |
|---|---|---|
| 1 | `h` | `fw-tag ARM-NET-0924BB` + `bus=PP(74HC126)` + `map=auto` |
| 2 | 连敲 10 次 `b auto` | 全部 `online 6/6`，且 `J1=B … J6=B` **始终不变** |
| 3 | 观察 `axis re-routed` | 第一次可能报 1~3 轴（把被 0924BA 改坏的撤回）；之后恒为**不打印** |
| 4 | `n` | `busA=0 busB=6` |

| 6 | 断电重上电 | 横幅 `J1:B … J6:B`，无 `!` 无 `?` |

**判失败的唯一标志**：10 次里出现 `J3 -> Bus A`（或任何轴被打回 A）。
若出现，说明 `s_map_conf` 也没救回来 —— 直接 `b auto` 再来一次应该自愈；
连续两次都不行才是硬件问题。

## 七、这版治不了什么

`b auto` 会稳定，但**总线误码本身没有消失**：

- RC 遥操仍会有偶发停滞拍（`act_l1[]` 保旧值 + `act_last_ms[]` 老化兜着）
- `L`/`zi`/`s` 等诊断多字节读仍可能偶发 `FAIL`
- 写配置（`i` / `L J min max` / `sid set`）失败仍然静默 —— `DXL_Write` 在
  `Status Return Level=1` 下把超时当成功，这条待下一版加"写后读回校验"

**根治仍要靠 1kΩ 上拉改 470Ω。** 本版只是让抖动不再破坏路由状态。
