## 1. 通信链路要求（上位机必读）

### 1.1 串口参数

| 项 | 值 |
|---|---|
| 端口 | USB 转串口对应的 COM 口（板载 USART6：PC6=TX / PC7=RX） |
| 波特率 | **115200** |
| 数据位 / 校验 / 停止位 | **8 / None / 1（8N1）** |
| 流控 | **无**（无 RTS/CTS，无 XON/XOFF，无 DTR 握手） |
| 字符集 | **ASCII**（中文/全角不被识别） |

### 1.2 ⚠ 行尾类型（Line Ending）—— 最高优先级

固件在 `main.c Console_TryReadLine()` 中的判行逻辑：

```c
if (ch == '\r' || ch == '\n') {        /* CR 或 LF 都视为"一行结束" */
    if (console_rx_len == 0) return 0; /* 空行忽略 */
    console_rx[console_rx_len] = '\0';
    ...                                /* 到这里命令才会被执行 */
    return len;
}
```

| 行尾 | 字节 | 固件行为 |
|---|---|---|
| **CRLF** | `0D 0A` | ✅ 执行（**推荐**） |
| **LF** | `0A` | ✅ 执行 |
| **CR** | `0D` | ✅ 执行 |
| **无行尾** | — | ❌ **永不执行** → 现象即"下发了没响应" |
| 空行 | — | 忽略，不报错 |

**接口要求（强制）**：

1. 上位机下发**任意**命令，**必须**在末尾追加 `\r`、`\n` 或 `\r\n`；**统一使用 `\r\n`**。
2. 不得发送"命令本体 + 无终止符"的裸字符串。
3. 若上位机框架的 `Write()` 不自动补行尾，必须由业务层显式拼接。
4. `\r\n` 连发**不会**导致命令执行两次（`\r` 结束，`\n` 被当作空行丢弃）。

### 1.3 回包形态（解析必须容忍）

固件返回体的组成：

```
<命令回显><\r\n><命令执行输出...><\r\n><提示符 "> ">
```

- **逐字符回显**：上位机发出的每个字符都会原样返回。
- **提示符**：每个非空命令行执行完成后打印 `> `（`>` + 一个空格）。
- **日志行**：`[RUN]` 开头的运行日志（级别由 `LL` 控制）。
- **二进制帧**：`0xAA 0x55` 开头的协议帧（若使用二进制接口）。

**接口要求**：上位机解析器必须能**跳过**回显行、`> ` 提示符与日志行；建议按行读取、以关键词判定结果，并设置整体超时，**不要**用"读固定字节数"的方式。

### 1.4 命令解析规则（影响上位机构造命令）

| 规则 | 值 | 备注 |
|---|---|---|
| 单行最大长度 | **127 字符** | 超出部分丢弃 |
| 分词 | 空格 / Tab（`0x09`） | **不认逗号、分号、引号** |
| 参数个数 | 最多 **16** 个 token | 多余忽略 |
| 大小写 | **严格区分** | `m`≠`M`、`p`≠`P`、`s`≠`S`、`t`≠`T`、`b`≠`B`、`c`≠`C`、`d`≠`D`、`q`≠`Q` |
| 数字 | 角度/坐标 `atof`（支持小数）；关节号/枚举 `atoi` | |
| 退格 | `0x08` / `0x7F` | 上位机一般无需发送 |
| 不支持 | ANSI 转义序列、注释、引号包裹 | |

### 1.5 特殊模式下的命令限制

| 模式 | 限制 |
|---|---|
| 急停（E-STOP，PE11 低有效） | 轨迹立即停止；**仅允许 `s` 和 `h`**，其它命令回复 `E-STOP active!` |
| `teach` 录制中 | 白名单外命令会**自动退出 teach** 再执行（例如发 `m` 会先 `teach exit`） |
| 示教回放中 | 除 `S`/`s`/`h` 外的命令会**先中止回放** |
| `W` 挥动中 | 期间禁用其它命令，直到 `S` |
| `c` 校准中 | **交互式阻塞**，需按 `q` 退出，期间不响应常规命令 |

## 2. 文本命令接口

> 全部命令与其参数、范围、默认值、注意事项见 `config/arm_config.json` 的 `commands` 数组与 `config/arm_config_readme.md` 第 4 节。
> 本节只规定上位机接入必须遵守的约定与最常用命令。

### 2.1 关节号的两种约定（极易错，务必区分）

| 命令族 | J 取值 | 示例 |
|---|---|---|
| 单轴命令 `t` / `a` / `r` / `p` / `z` / `w` / `L` / `M` / `T` / `O` / `E` | **0~5** = J1~J6 | `a 0 90` = J1 转到 90° |
| PID / 自适应命令 `K` / `I` / `D` / `N` / `Y` / `A g` | **1~6** = J1~J6 | `K 1 16` = J1 的 P=16 |

### 2.2 上位机常用命令

| 场景 | 命令（末尾均需 `\r\n`） | 返回 |
|---|---|---|
| 探活 | `h` | 帮助文本 |
| 状态 | `s` | 6 轴 raw/角度/负载/温度/错误位 |
| 关节角 | `p J` | raw / servo deg / **rel-home 关节角** |
| 位姿 | `f` | XYZ + pitch + raw |
| 6 轴运动 | `m a1 a2 a3 a4 a5 a6 [v]` | 轨迹执行日志 |
| 笛卡尔运动 | `g x y z [pitch]` | IK + 安全检查 + 执行日志 |
| 预设位姿 | `P 0~4` | 执行日志 |
| 停止 | `S` | 停止确认 |
| 限位查询/设置 | `L` / `L J min max` | 当前限位表 |
| 参数表 | `LP` | id/名/值/范围/单位 |
| 设参数 | `SP id v` | 需 `F` 存盘 |
| 遥测流 | `tm 100 pti`（0=停） | 周期遥测行 |

### 2.3 上位机对命令返回的判定

| 结果 | 关键词 |
|---|---|
| 成功 | `OK`、`Saved`、`Stopped`、`complete` |
| 参数错误 | `Usage:` |
| 执行失败 | `FAIL`、`FAILED`、`reject`、`NACK`、`unreachable`、`out of range` |
| 安全拦截 | `path check fail`、`TCP z=`、`read FAILED`、`UNSTABLE` |

## 3. 二进制协议接口

### 3.1 帧格式

```
[0]=0xAA  [1]=0x55  [2]=SEQ  [3]=CMD  [4]=LEN  [5..]=PAYLOAD  [末2]=CRC16
CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF), 计算范围 = SEQ..PAYLOAD
CRC 低字节在前；最大帧 71 字节
```

### 3.2 命令码

| CMD | 名称 | 负载 | 响应 |
|---|---|---|---|
| 0x01 | PING | — | 0x81: u8 ver, u8 run_id |
| 0x02 | GET_STATUS | — | 0x82: 定点状态快照 |
| 0x03 | LOG_SET_LEVEL | u8 level(0~3) | ACK |
| 0x10 | MOVE_JOINTS | 6×i16 角度 + u16 v + u16 a | ACK |
| 0x11 | STOP | — | ACK |
| 0x12 | SET_TORQUE | u8 joint(0~5,0xFF=全) + u8 en | ACK |
| 0x20 | MOVE_CART | i16 x,y,z + i16 pitch + u16 v + u16 a | ACK |
| 0x21 | FK_QUERY | — | 0xA1: 位姿 + 六关节角 |
| 0x30 | SET_GRAVITY | i16 K(0.001 deg/mm) | ACK |
| 0x31 | SET_CORRECTION | u8 en, u16 thr(0.01 deg), u8 rounds | ACK |
| 0x40 | PARAM_READ | u8 id | 0xC0: u8 id, i32 val×1000 |
| 0x41 | PARAM_WRITE | u8 id, i32 val×1000 | ACK |
| 0x42 | PARAM_COUNT | — | 0xC2: u8 count |
| 0x7F | ACK | u8 orig_cmd, u8 err(=0) | — |
| 0x7E | NACK | u8 orig_cmd, u8 err(ARM_API_ERR_*) | — |

### 3.3 定点编码

| 量 | 类型 | 比例 |
|---|---|---|
| 角度 | int16 | ×0.1 deg |
| 位置 | int16 | ×0.1 mm |
| 速度 | uint16 | ×0.1 deg/s |
| 加速度 | uint16 | ×0.1 deg/s² |
| 增益 K | int16 | ×0.001 deg/mm |
| 参数值 | int32 | ×0.001 |

> 响应规则：查询类响应 CMD = 请求 CMD | 0x80；控制类成功 ACK，失败 NACK + 错误码。
> ⚠ 文本控制台与二进制协议**共用同一串口**，上位机须以 `0xAA 0x55` 作为二进制帧起始判据。

## 4. PID 调参接口（上位机需实现"优化"能力）

### 4.1 生效链（务必在 UI 上体现）

| 动作 | 命令 | 生效范围 | 掉电是否保留 |
|---|---|---|---|
| 改增益 | `K` / `I` / `D` / `N` | 立即写舵机 RAM | ❌（需 `Y`） |
| 烧舵机 EEPROM | `Y J`（`Y 0`=全部） | 舵机自身 | ✅（舵机掉电保留） |
| 存 STM32 Flash | `F` | 固件开机自动下发 | ✅ |
| 恢复固件默认 | `X` | 只写 RAM + 舵机 RAM | ❌（不动两处持久化） |
| 回读比对 | `N J` | 显示缓存值 vs 舵机 EEPROM 值 | — |

### 4.2 三个增益的调参方向（上位机应内置提示）

| 增益 | 何时**增大** | 何时**减小** |
|---|---|---|
| **P（位置刚度）** | 到点偏软、负重下沉、稳态误差大 | 高频抖动、嗡鸣、反馈噪声被放大 |
| **I（积分）** | 到位后缓慢下沉、反复微调 | 低频来回晃、超调、积分饱和 |
| **D（微分/阻尼）** | 到点来回荡、过冲 | 高频剧烈抖动、打摆（**齿隙关节 J3 尤其敏感**） |

### 4.3 调参流程（建议做成向导）

```
1) N J                记录基线（P/I/D + 是否与 EEPROM 一致）
2) 单变量调整：
     下沉   -> K J <P+4~8>
     抖动   -> D J <D-4>        (J3 优先)
     慢漂   -> I J <I+2>
3) 单关节动作验证（a J deg / m ...）
4) 满意 -> Y J              （烧舵机 EEPROM）
5) 全部满意 -> F            （存 STM32 Flash）
6) 变坏 -> X 恢复默认，回基线重来
```

### 4.4 硬性约束（上位机不得违反）

1. **一次只改一个关节、一个量**，改完必须验证。
2. `Y` 会导致舵机**失力约 0.6 s**，上位机必须提示用户**托住机械臂**。
3. `i` 会 Torque OFF → RESET，属危险操作，必须有二次确认。
4. 改 PID 前**必须先记录基线**（`N 1`~`N 6`）。
5. **不要把"到点顿两下"当成 PID 问题**：其根因是尾段流式微步（`#42 traj.approach_speed` / `#45 traj.handoff_deg`）。

## 6. 安全要求

| 项 | 要求 |
|---|---|
| 急停 | 上位机必须有独立"急停"入口；硬件急停 PE11 低有效 |
| 运动前确认 | 运动类命令下发前先 `s` / `f` 确认当前姿态 |
| 危险命令二次确认 | `i`（初始化）、`Y`（烧 EEPROM，失力）、`B`/`W`/`QL`/`QLC`（长跑循环）、`M a`（置中） |
| 姿态一致性 | 上位机构造位姿**不得写死舵机度**，必须用关节角或 XYZ（现场零点会漂移） |
| 读失败处理 | 上位机不得用"目标值"顶替"读失败"的反馈 |
| 超时 | 简单命令 200~500 ms；运动类 5~30 s（按行程） |

## 7. 上位机软件功能要求

### 7.1 必备功能

1. **连接管理**：串口枚举、打开/关闭、115200 8N1、无流控；打开后清空缓冲。
2. **命令下发**：所有命令自动追加 `\r\n`；提供原始命令透传输入框。
3. **回包解析**：按行读取；过滤回显/`> `/`[RUN]`；显示原始返回；关键词判定结果。
4. **状态显示**：6 轴角度/raw/负载/温度/错误位；末端位姿。
5. **PID 调参面板**：显示当前 P/I/D 与 EEPROM 是否一致；一键"应用/烧写/存盘/恢复默认"。
6. **参数表面板**：`LP` 解析成表格；`SP` 写回。
7. **遥测曲线**：`tm` 数据成图（角度/电流/温度）。
8. **日志**：保存原始收发日志（含时间戳）。

### 7.2 建议功能

- 示教文件管理（`list`/`play`/`del`/`compact`）。
- 位姿示教与回放（`q`/`qg`/`QL`/`QLC`）。
- 二进制协议通道（用于高频状态查询）。

### 7.3 明确不在本期

- 主从臂联调界面。
- 时间同步 / 微秒级时间戳。
- ROS2 节点封装。

### 步骤 1：新增 `ros_proxy_cmd.c / ros_proxy_cmd.h` 协议代理适配层

**原要求**：作为二进制协议命令分发桥接层，接收 `arm_control_protocol` 解析后的 `ProtocolFrame`，调用底层 `arm_control_api`、`teach_store`、`arm_params`、`arm_runlog` 模块；注册命令处理回调；扩展命令码（运动、笛卡尔 IK、示教读写、参数读写、高速状态流、时间同步、故障码）；所有返回携带 `ArmErrorCode`；支持高速状态上报流开关与分频。

**现状对照**：

| 子项 | 状态 |
|---|---|
| 协议分发桥接 | ✅ 已由 `Aproto_Dispatch()`（`arm_control_protocol.c`）承担，等价职责 |
| 命令处理注册机制 | ✅ 已有 `ArmProtocol_RegisterHandler` 风格分发 |
| 运动 / IK / 参数读写命令码 | ✅ `0x10/0x20/0x40/0x41/0x42` 已实现 |
| 示教读写命令码 | ⚠ 文本命令已完整（`save/list/play/del/compact`）；**二进制侧未单列命令码** |
| 故障码读取 | ✅ `GET_STATUS` 快照 + 文本 `E` / `E J` |
| 高速状态上报流（分频开关） | ❌ **未实现**；现以 `tm`（遥测，只读缓存）替代 |
| 时间同步命令 | ❌ **未实现** |

**结论**：新建 `ros_proxy_cmd.c` 已无必要，直接复用现有分层；缺的是"高速流"与"时间同步"两项。

### 步骤 2：生成独立跨平台 C++ SDK 库 `arm_sdk_cpp`

**原要求**：不依赖 ROS2；CMake 构建；`TransportBase` 抽象 + `SerialTransport` + 预留 `CanTransport`；`arm_types.h` 定义 `Pose`/`ArmStatus`/`ServoJoint[6]`/`TrajectoryPoint`/`TeachTrajectory`/`ArmErrorCode`；`ArmRobot` 门面类（`open/close`、`move_joints`、`move_cartesian`、`get_joints`、`get_current_pose`、`get_controller_status`、`stop`、`emergency_stop`、`home`、`read_teach_file`、`play_teach_file`、`read_param_block`、`write_param_block`、`enable_highspeed_report`、`read_controller_log`、`time_sync`、`set_status_callback`）；协议编解码模块；请求应答 + 异步回调；2 个示例。

**现状对照**：❌ **未落地**（无 `arm_sdk_cpp` 目录）。

**现状对照**：❌ **未落地**，且**依赖步骤 2** 先完成。
