# 路由持久化 + 网口降噪（0924BC，2026-11-02）

> 起因：单总线（6 颗全接 B 段）后启动仍报 `J3:A!`，且网线未插时串口每 9 秒刷一条
> `autoneg timeout, forcing 100M full-duplex`。

---

## 一、`J3:A!` 的根因：路由只活在 RAM 里

### 现场指纹

```
Rescan (round 2, prev 3/6)...
Bus A: 0 servo(s)  Bus B: 3 servo(s)
[MAP] probe: online 5/6 -> J1:B J2:B J3:A! J4:B J5:B J6:B
(! = not found on either bus, ? = same ID on BOTH buses)
[WARN] J1: mode read failed (offline?)
[WARN] J3: mode read failed (offline?)
```

`J3:A!` 拆开看是两件事：

| 部分 | 含义 |
|---|---|
| `A` | J3 当前映射指向 **Bus A** |
| `!` | 本次探测**两条总线都没应答**（miss） |

### 为什么 MISSING 会变成"指向 A"

`JOINT_BUS[6]` 的编译期初值是 `{A, A, A, B, B, B}`。六颗全接 B 段的板子上，
**J1~J3 的初值本身是错的**。0924BB 之前（含 0924BA）的 pass2 用

```c
uint8_t def = (j < 3U) ? BUS_A : BUS_B;   /* 编译期默认 */
...
} else { JOINT_BUS[j] = def; }            /* 离线: 回落到"默认" */
```

`def` 对 J1~J3 恒为 **Bus A**（空的段）。于是：

```
一次 PING 抖动 → J3 报 MISSING → 路由被打回 A（空段）
  → 之后读位置永远打空段 → RC 该轴丢轴、mode read failed
  → 下次 pass1 用 A 探 J3 又失败 → 再进 pass2 → 随机再改
```

**一次误报 = 废掉一条本来能用的路由，而且固件不知道自己是错的。**

### 0924BB 修了一半

BB 版改成"MISSING 时保持原路由不变"+ 3 轮 2 票投票。但 **`JOINT_BUS[]` 和
`s_map_conf[]` 都还是 RAM 变量**，一复位就回到编译期默认 A/A/A/B/B/B。所以：

- 同一次上电内：抖动不会改坏路由 ✅
- 跨复位：**又从 3 个错的默认值开始，每次上电都要重新赌一次 AutoMap** ❌

一次没赌中（当轮误码），J3 就停在 A 段，表现成"上次明明好了，重启又缺轴"。

## 二、修法：路由写进 flash（区 G）

### 新增模块

| 文件 | 内容 |
|---|---|
| `Core/Inc/busmap_cfg.h` | `BusMapCfg_Load/Save/Clear` |
| `Core/Src/busmap_cfg.c` | 16B 记录：`magic(4) + bus[6] + mask(1) + pad(1) + sum(4)` |
| `Core/Inc/flash_cfg.h` | 新增 `CFG_OFF_BUSMAP 0x6000`，`CFG_REGION_COUNT` 6→7 |
| `Core/Src/flash_cfg.c` | `s_region_off[]` 加区 G（保区写自动覆盖） |

扇区 11 布局（相对 `0x080E0000`）：

| 偏移 | 区 | 用途 |
|---|---|---|
| 0x0000 | A | PID / 校准零点 / 限位 |
| 0x1000 | B | CAN 通信配置 |
| 0x2000 | C | 链路偏好 |
| 0x3000 | D | RC 遥控速度 |
| 0x4000 | E | RC 键位映射 |
| 0x5000 | F | 几何偏好（C 偏移 + zf） |
| **0x6000** | **G** | **舵机总线路由（本版新增）** |

### 三个新接口（`servo_driver.c`）

| 函数 | 作用 | 调用点 |
|---|---|---|
| `SERVO_LoadSavedRoute()` | 把记录灌进 `JOINT_BUS[]` + `s_map_conf[]` + `s_map_known` | 启动期，**在 `ScanBothBuses()` 之前** |
| `SERVO_SaveRoute()` | 只写"已实测确认"的轴；内容没变直接跳过 | `AutoMap` 结尾，仅当 `moved != 0` |
| `SERVO_SaveRouteAll()` | 六轴全写 + `s_map_known` 全置位 | `b 0/1/2` |

### 关键设计：什么时候**不**写 flash

写 flash 要**擦整个扇区 11**，而 PID/校准零点就住在同一个扇区。擦除期间掉电
会连带丢校准 —— 代价远高于收益。所以：

| 场景 | 写不写 | 理由 |
|---|---|---|
| 启动 pass1 全中（布局正确） | **不写** | 直接早返回，路由没变 |
| 启动有抖动但投票确认"原路由就对" | **不写** | `moved == 0` |
| 启动探测到路由确实要改（六颗全在 B） | **写一次** | `moved != 0`，之后 pass1 就全中 |
| `b 0/1/2` 手动钉死 | **写** | 用户意图明确，不写等于白敲 |
| `b auto` 但路由没变 | **不写** | 内部比对，`dirty == 0` 就跳过 |

`BUS_ONE` 构建下 `b 0/1/2` 不写（`#if` 排除），因为该形态的路由是钉死 mode 2，
加载侧也不读。`b auto` 在 `BUS_ONE` 下本来就被守卫拒绝。

## 三、网口降噪：`no link` 只报一次

### 为什么每 9 秒刷一行

`arm_net.c` 的 `net_step_an()` 是个双态循环：

```
自协商态  --超时 6s-->  强制 100M-FD（打印 WARN）  
   ↑                          |
   └----超时 3s（静默）--------┘
```

网线没插时链路永远起不来，于是 6+3=9 秒转一圈，**每圈都打一条**。日志时间戳
`T+00367331` → `T+00376333` 差 9002ms，正好对上。

### 改法

```c
static uint8_t s_an_warned = 0U;   /* 新增 */

} else if (... > NET_AN_TIMEOUT_MS) {
    ...强制 100M-FD...
    if (!s_an_warned) {
        s_an_warned = 1U;
        RLOG_W("NET", "no link after %ums, tried forced 100M-FD once "
                      "(cable unplugged? retrying silently)", ...);
    }
}
```

链路 up 时 `s_an_warned = 0` —— 所以拔线后会再报一次，不会永久失声。

**逃生门保留**：`autoneg ↔ forced` 的循环继续跑，插上网线立刻就能连上，只是
不再刷屏。

```powershell
& "C:\STM32Tools\openocd\xpack-openocd-0.12.0-7\bin\openocd.exe" `
  -f interface/stlink.cfg -c "transport select swd" `
  -f target/stm32f4x.cfg -c "adapter speed 240" `
  -c "program C:/STM32Tools/fw0924bc_pp.bin verify 0x08000000" `
  -c "reset run" -c "shutdown"
```

### 推荐步骤（最不依赖误码运气）

| # | 操作 | 期望 |
|---|---|---|
| 1 | 烧 `fw0924bc_pp.bin` | `Programming Finished` / `Verified OK` |
| 2 | `h` 首行 | `ARM-NET-0924BC` + `bus=PP(74HC126)` + `map=auto`，fix 含 `busmap-persist` |
| 3 | **`b 2`** | `2 (ALL -> Bus B)` + **`Route saved to flash (survives reset).`** |
| 4 | `n` → `i` | `busA=0 busB=6`；⚠ `i` 会给六轴上力矩，先托住臂 |
| 5 | **按 RESET**（不断电） | 应出现 `[MAP] saved route restored: J1=B J2=B ...`，`Bus B: 6 servo(s)` |
| 6 | 连敲 10 次 `b auto` | 全 `online 6/6`，`J1=B … J6=B` 一次都不变 |
| 7 | 拔网线再上电 | 只有 **一条** `no link ... retrying silently`，不再每 9s 刷 |

**失败判据**：出现任何 `J? -> Bus A`。出现就再敲 `b 2`（强制钉死并落盘）；
若 `b 2` 之后重启还是回 A，说明区 G 没写成功（会打 `[WARN] route save FAILED`），
那就查 flash 写保护或扇区 11 状态。

## 六、这版治不了什么

| 问题 | 状态 |
|---|---|
| 单帧误码（约 37% 坏帧） | ❌ 物理层，软件只能掩盖 |
| J3 那颗偶尔 MISSING | ⚠ 修完仍可能偶发；路由不会再被改坏，但读位置会失败一拍 |
| RC 偶发停滞拍 | ⚠ 同上，靠 `act_last_ms` 老化 + 欠账优先兜 |
| 写配置失败静默（`DXL_Write` 把超时当 OK） | ❌ 未改，下一版建议加写后读回校验 |
| 生产环境误码率 | 仍需 **1kΩ → 470Ω** 上拉（五分钟、几毛钱） |

路由持久化的价值是**把"误码"和"路由状态"解耦**：误码只会造成单拍读失败，
不会再让固件把一个能用的轴"搬到"空总线上。误码本身还在。
