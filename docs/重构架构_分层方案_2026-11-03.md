# 重构架构与分层方案

> 生成日期：2026-11-03　　基线：`ARM-NET-0924BE` / `ARM-MASTER-1030D`
> 目标：`main.c` 10,980 行 → **≤1,500 行**，让后续加功能/改算法不必再往一个巨型文件里塞。

---

## 一、为什么要重构

| 症状 | 量化 |
|---|---|
| 单文件失控 | `main.c` 10,980 行 = 全工程 **41.3%** |
| 巨型函数 | `ProcessCommand()` 单函数 **4,143 行**（占 main.c 37%），34 个 `strcmp` + 38 个 `case` |
| 分层倒挂 | 抽象层 `arm_control_api.c` 反向依赖实现层 `main.c`（include `arm_main_exports.h` 拿 19 个函数） |
| 工具层倒挂 | `arm_runlog.c:9` 裸 `extern UART_HandleTypeDef hconsole;` |
| 登记纪律破例 | `arm_control_api.c:31` 裸 `extern uint8_t correction_pending;` |
| 现成的抽象被浪费 | `arm_commands.c` 已建好 85 条命令注册表，`CmdRegistry_Print` 是**空实现**，与 `ProcessCommand` 完全脱节 |
| 第三份重复 | `cmd_is_known_multichar`(main.c:5781) 是第三份手写白名单 |
| 功能重复 | IK 两份实现（限位判据不同）· 状态读取两份（总线事务差 3 倍） |
| 双定义 | `boot_verbose` 在 `main.c:5809` 与 `10036` 各定义一次（靠 common symbol 侥幸工作） |

**结论**：约 **4,450 行（40.6%）是纯命令分发**，应由已经存在的 `arm_commands.c` 注册表接管。这是投入产出比最高的一刀。

## 二、目标分层与依赖方向

```
┌───────────────────────────────────────────────────────────────┐
│ L7 接入/承载 (Transport)                                      │
│   arm_proto_serial.c  arm_proto_can.c  arm_net.c  arm_rc.c    │
├───────────────────────────────────────────────────────────────┤
│ L6 协议语义层                                                  │
│   arm_control_protocol.c   (Aproto_Dispatch, 38 opcode)       │
│   ★ 与传输无关，只依赖 L5                                     │
├───────────────────────────────────────────────────────────────┤
│ L5 业务门面层                                                  │
│   arm_control_api.c  (ArmApi_*)  ★唯一"上层入口"                │
│   arm_commands.c     (命令表 + 分发表)                         │
├───────────────────────────────────────────────────────────────┤
│ L4 领域/算法层                                                 │
│   kinematics.c  trajectory.c  arm_params.c                    │
│   ★ 纯计算，无 HAL 依赖，可脱离 MCU 单元测试                   │
│   ★新增: arm_limits.c  arm_safety.c  arm_motion.c             │
├───────────────────────────────────────────────────────────────┤
│ L3 设备驱动层                                                  │
│   servo_driver.c  arm_fault.c  arm_runlog.c                   │
├───────────────────────────────────────────────────────────────┤
│ L2 帧协议层                                                    │
│   scs_protocol.c  (DXL_*)                                     │
├───────────────────────────────────────────────────────────────┤
│ L1 物理/总线层                                                 │
│   servo_bus_hal.c  (74HC126 方向切换 + 半双工收发)             │
├───────────────────────────────────────────────────────────────┤
│ L0 外设初始化 (CubeMX 生成)                                    │
│   gpio.c  tim.c  usart.c  stm32f4xx_hal_msp.c                  │
└───────────────────────────────────────────────────────────────┘
```

**四条硬规则（必须写进团队文档）**

1. 上层可依赖下层，**下层绝不依赖上层**。
2. `main.c` 只允许依赖 L5 及以下，**不得被 L5/L6 反向依赖**。
3. `arm_main_exports.h` 过渡期保留，但**只能被 L5 使用**；`arm_control_api.c:31` 的裸 extern 必须补进去。
4. 跨层直接操作（如 `cmdCalibrate` 自己拼 `JOINT_BUS[j]/JOINT_ID[j]`）必须改走 L3 关节级 API。

## 六、纪律与验收

### Makefile 两条纪律（不可破）

1. **非默认编译宏必须进 `BUILD_DIR`**（Makefile:60/75/105/132/154/172）——否则现场会烧到旧固件。
2. **新增 .c 文件名必须全工程唯一**（`OBJECTS` 用 `notdir` 推导，Makefile:328）——撞名会静默覆盖 .o。

### 每个 Sprint 的验收门

| Sprint | 验收 |
|---|---|
| 1 | 从臂 `.bin` 与拆分前**逐字节相同** |
| 2 | 实机回归清单全绿：`m`/`g`/`P`/`Q`/`QL`/`teach`/`teach play`/`rc go`/主从跟随/`sf`/`lk`/`ms`/`Y`/`c` 校准/急停 |
| 3 | 新旧 `cmdHelp` 输出 **diff 为空**；124 条命令逐条回归 |
| 4 | IK 双路径实机对比用例集全绿；`arm_main_exports.h` 已删除；`main.c` ≤1,500 行 |
