## 2.12.1 定稿映射（以此为准）

> 用户原话：「两个摇杆都是全复位的。左边摇杆推上下是 Z 轴上下、推左右是末端旋转轴的左右转；
> 右边摇杆上下是 X 轴、左右是 Y 轴；不复位的拨杆是夹爪的实时开合。」

| 物理输入 | 控制量 | 类型 | 自复位? | 映射成 |
|---|---|---|---|---|
| **右杆 上下** | **X** | 平移 | ✅ | **速度** |
| **右杆 左右** | **Y** | 平移 | ✅ | **速度** |
| **左杆 上下** | **Z** | 平移 | ✅ | **速度** |
| **左杆 左右** | **J5** 末端旋转 | 姿态 | ✅ | **速度（增量积分 + 限位钳位）** |
| **拨杆（不复位）** | **夹爪 J6** | 开合 | ❌ | **绝对量** |

⭐ **这版映射与红线 69 完全相容，而且比前几版都好**：

- **4 个控制量全落在摇杆上、摇杆全自复位** ⇒ X/Y/Z/J5 都是速度轴 ⇒
  **松手即回中 ⇒ 速度 0 ⇒ 臂停**。"松手就停"从"要额外加死手开关"变成**结构自带的性质**。
- **夹爪用不复位拨杆** ⇒ 绝对量 ⇒ 松手停在原位，不会自己开合。红线 69 的正面用法。
- ⇒ 原 §2.10.2 那个"死手使能状态机"**降级为可选**（仍建议留一个开关做总使能，但不再是安全必需）。

⚠ **唯一代价**：J5 走速度轴后**没有"归零"手段** —— 转多了只能反向转回来（跟云台一样）。
必须：① 上电**读一次当前 J5 角作为基准**（别假设 0）；② 每拍累加后**钳到 J5 真实行程**。

## 2.12.2 ⚠⚠ 致命发现：`MoveCartesian` 会把 J5 与夹爪**归零**

写 R1 之前必须知道，否则会做出一个"一平移就把夹爪松开、把 J5 拧回 0"的固件。

代码事实（`Core/Src/kinematics.c: IK_Solve`，**两条分支都是**）：

```c
    if (ik_analytic(ty, tz, tool_pitch, ang)) {      /* Step 3a 解析解 */
        joints[1] = ang[0]; joints[2] = ang[1]; joints[3] = ang[2];
        joints[4] = 0.0f;                            /* ← J5 强制 0 */
        joints[5] = 0.0f;                            /* ← J6 强制 0 */
        return 1;
    }
    ...                                              /* Step 3b CCD 兜底 */
    joints[4] = 0.0f;                                /* ← 同样 */
    joints[5] = 0.0f;
```

而 `ArmApi_MoveCartesian()` 解完 IK 后**把 `deg[6]` 整包交给 `ArmApi_MoveJoints()`**：

```c
    return ArmApi_MoveJoints(deg, v_max, a);          /* deg[4]/deg[5] == 0 */
```

⇒ **每调用一次 `MoveCartesian`，J5 和夹爪都被指令到 0 位。**
⇒ 这套映射（平移 + J5 + 夹爪**同时**有效）**用 `MoveCartesian` 根本做不出来**。

> `kinematics.h:106` 注释早写明：「J1-J4 求解；J5/J6 输出 0（=保持中性，**调用方负责保持当前角度**）」
> —— 所谓"调用方负责"，就是**谁调 IK 谁自己把 J5/J6 填回去**。`MoveCartesian` 没填，所以它不适合我们。

## 2.12.3 ⭐ 正解：`ArmApi_StreamJoints()`（流模式）—— 互斥问题一并消失

`Core/Inc/arm_control_api.h:66` 早就有这个接口，注释极明确：

> 主从直写 (2026-09-11)：逻辑关节角直接下发六轴目标，**不做轨迹规划/起点读/settle**，
> 用于**主从实时跟随**。建议调用频率 **20~50Hz**；连续 500ms 无调用则看门狗自动退出流模式。

| 对比项 | `ArmApi_MoveJoints`(→`cmdMove`) | **`ArmApi_StreamJoints`(→`cmdStreamJoints`)** |
|---|---|---|
| 参数量纲 | **舵机度** 6 关节 | **逻辑关节角**（相对本臂 Home）6 关节 |
| 读起点 | ⚠ 每次都读（阻塞读 6 轴，多采样多数表决） | ❌ 不读（只在**首次**进流模式时读一次做跳变基准） |
| 轨迹规划 | 每次都 `Trajectory_Plan` | ❌ 不规划，直接写 GOAL_POSITION |
| 与流模式关系 | ⚠ `cmdStreamExit("trajectory move")` **踢掉流模式** | 就是流模式本身 |
| 呼出代价 | 高（读 6 轴 + 规划，几十 ms 量级） | 低（一次 SyncWrite） |
| 适合 | 点位运动、示教 | ⭐ **实时遥操作** |

**⇒ 因为 `StreamJoints` 接受"完整 6 关节"，X/Y/Z 解出的 J1~J4 与 J5、夹爪可放在
同一次下发里 ⇒ 原 §2.11.2/§2.11.3 说的"两条通路互斥、必须分时"直接消失。**

⚠ 但有两个**必须自己补**的环节：

### ① IK 要自己调，且必须照抄 `MoveCartesian` 的安全链

`IK_Solve()` 是公开接口（`kinematics.h:107`），但**不能只调它就下发**：

```c
    ik_ok = IK_Solve(&tgt, rad);   if (!ik_ok)                 丢弃本拍增量(不退出/不跳变);
    for j in 0..3: deg[j] = rad_to_servo_deg(rad[j], j);
    for j in 0..5: if (deg[j] < JOINT_MIN[j] || deg[j] > JOINT_MAX[j])  丢弃本拍;
    FK_Solve(rad, &v); if (|v - tgt| > KIN_FK_VERIFY_MM)        丢弃本拍;
    deg[4] = j5_now;      /* ★ 自己填，别让它变 0 */
    deg[5] = grip;        /* ★ 同上 */
    ArmApi_StreamJoints(logical_deg);            /* 注意量纲：要逻辑角 */
```

### ② 量纲转换

`cmdStreamJoints` 收**逻辑角**，而 `JOINT_MIN/MAX`、`rad_to_servo_deg` 给**舵机度**。
换算关系（main.c 里那两个函数就是这么写的）：

```
joint = JOINT_DIR[j] * (servo_deg - SERVO_OFFSET[j])
```

⚠ `joint_to_servo_deg` / `servo_to_joint_deg` 在 main.c 里是 **`static`**（`main.c:1675 / 1683`）
⇒ **RC 模块拿不到**，得自己写一份；或把这两个函数改导出到 `arm_main_exports.h`（更干净，R1 推荐）。

## 2.12.5 ⚠⚠⚠ 最危险的一条：**限位没标定 ⇒ 流模式会把六轴全部推向 raw 0**

**优先级高于一切功能**，已入册为**红线 68**。

证据链（全部代码级）：

1. 流模式逐轴钳位用 **RAW 限位**：`clamp_raw(want, JOINT_MIN_RAW[j], JOINT_MAX_RAW[j])`（`main.c:1952`）；
2. `JOINT_MIN_RAW / JOINT_MAX_RAW` 的**静态初值是全 0**（`main.c:998 / 999`）；
3. 这两个数组**只在 `apply_calib_limits()` 里被填**（`main.c:1419`），而它
   **遇到"未校准哨兵"就跳过**：
   ```c
   uint16_t span = raw_dist_fwd(mn, mx);
   if (span == 0 || span < 20U) continue;        /* 未校准/行程过短: 跳过, 不写限位 */
   ```
4. `calib_min_raw` 初值 = **`{4095,4095,4095,4095,4095,4095}`**、`calib_max_raw` = **`{0,…}`**
   （`main.c:1005 / 1007`）⇒ `span = raw_dist_fwd(4095, 0) = 1` ⇒ **必被跳过**；
5. `apply_calib_limits()` 的**唯一上电调用点**在 `pid_load_startup()` 内，
   且位于 `PID_FlashLoad(...)` **成功且 `limits_loaded`** 的分支里（`main.c:1466`）
   ⇒ **Flash 里没存过标定 ⇒ 它上电根本不会被调用**；
6. ⇒ `JOINT_MIN_RAW / MAX_RAW` 保持**全 0**，于是
   ```c
   clamp_raw(want, 0, 0)  →  raw_in_range 失败 → dm == dx → 返回 mn == 0
   ```
   ⇒ **六个关节的目标全被改写成 raw 0**。

**唯一的兜底是巧合**：改写成 raw 0 后 `stream_pose_ok()` 用 FK 算末端 z 会低于
`traj_z_floor_mm` ⇒ 拒帧 ⇒ 臂不动。**这是"安全但不工作"，不是设计意图**，不能依赖。

### ⇒ `rc ctl 1`（启用 RC 控制）入口必须加硬守卫

```c
/* 红线 68：未标定时 JOINT_MIN_RAW 全 0 ⇒ clamp_raw 把六轴推向 raw 0。
 * 六轴有一个是 0 就拒绝启动 RC 控制。 */
uint8_t lim_ok = 0;
for (uint8_t j = 0; j < 6; j++) if (JOINT_MIN_RAW[j] || JOINT_MAX_RAW[j]) lim_ok++;
if (lim_ok < 6) {
    cprint("  RC 拒绝启动: 关节限位未标定 (%u/6). 先跑 `c` 校准 + `s` 保存.\r\n", lim_ok);
    return;
}
```

### 你手上的判据（不用改代码就能查）

看**启动横幅**里有没有这两行：

```
  Joint calibration limits loaded from Flash.
  Work ranges applied (6 jnt): all axes = Phase2 hand-pushed travel.
```

- **两行都在** ⇒ 限位已装载，流模式可用 ✅
- **缺 `Work ranges applied`** ⇒ `JOINT_MIN_RAW/MAX_RAW` 全 0，**绝对不能让臂进流模式** ⚠

> ⭐ **2026-09-23 补充（更可靠的判据）**：横幅**只在上电打一次**，敲 `h` 看不到它
> ⇒ 别去 `h` 里搜。可靠做法有两条：
> 1. **看启动那行 `Limits: J1[..] J2[..] ...`**（`main.c:8969`）——
>    只要它**不等于代码初值**（初值参 `main.c:990`，如 `J5=180~340`），
>    就说明 `apply_calib_limits()` 跑过、限位有效。（同 `三链路延迟基准_操作手册 §5.4`）
> 2. **程序内判据**（R1 用）：`JOINT_MIN_RAW/MAX_RAW` 六轴**全非 0** ——
>    它才是 `clamp_raw()` 真正吃的那个数组（`main.c:1983`）；
>    或等价地用 `ArmApi_GetLimits()` 的 `loaded` + 非 0 记录。
>    ⚠ 该数组目前**未在 `arm_main_exports.h` 登记**，R1 要用得先按该文件纪律登记。
>
> ⚠ 另注：`stream_enter()` 会**无条件给六轴开力矩**（`main.c:1921`）⇒
> arm 之前先回中位（烧录/复位后臂已下沉到 J2≈76.4 / J3≈270.9，距限位 1.3°/0.1°）。

## 2.12.6 通道数：**5 路工作通道 + 1 路心跳 = 6 路**（09-23 三次定案：夹爪 = `PE14`/`TIM1_CH4`，心跳 = `PG10`/`EXTI`）

| 通道 | 引脚 | 采集方式 | 用途 |
|---|---|---|---|
| CH1 | `PD12` = `TIM4_CH1` | 硬件捕获 | 右杆 上下 → **X** |
| CH2 | `PD13` = `TIM4_CH2` | 硬件捕获 | 右杆 左右 → **Y** |
| CH3 | `PD14` = `TIM4_CH3` | 硬件捕获 | 左杆 上下 → **Z** |
| CH4 | `PD15` = `TIM4_CH4` | 硬件捕获 | 左杆 左右 → **J5** |
| **CH5** | **`PE14` = `TIM1_CH4`（AF1，已确认引出）** | **硬件捕获** | **连续量拨杆 → 夹爪 J6** |
| **CH6** | **`PG10`**（用户拍板；上电前量一次通断） | **`EXTI10` 软测宽** | **心跳 → 丢控检测**（两档判据，抖动无关紧要） |

路线演变（留作历史）：A′（`PD11`+`PD10` 全走 EXTI，第一轮定案）⇒ 确认 `PE14` 引出 ⇒ 夹爪回硬件捕获；
心跳首选 `PD10` ⇒ 用户改拍 **`PG10`**（三次回报）：

| 路线 | 结论 |
|---|---|
| **A″. 夹爪 `TIM1_CH4`=`PE14`（硬件捕获）+ 心跳 `PG10`（EXTI）** | ⭐ **现役定案**。⚠ **TIM1 在 APB2（168MHz）⇒ `PSC=167` 才是 1µs**（TIM4 在 APB1 用 83）；TIM1 从零启用（`TIM1_CC_IRQn` 优先级 5），只捕获不碰输出 |
| ~~A′. `PD11`+`PD10` 全走 EXTI~~ | 已被 A″ 取代（`PD11` 本无定时器复用，此事实保留作存档） |
| B. SBUS | 二期（一次到位 16 通道 + 协议级 failsafe 位） |

⚠ HAL 陷阱清单（A″ + 心跳）：① `HAL_TIM_IC_CaptureCallback()` 现在**两个 Instance 进来**（TIM4+TIM1）⇒ 必须按 `htim->Instance` 分派；
② `HAL_GPIO_EXTI_Callback()` **全工程唯一**（现仅 `PG10` 一个使用者）⇒ 按 `GPIO_Pin` 分派；
③ ⚠⚠ **`EXTI10` 线与 `PB10`(`USART3_TX` 总线 A)/`PE10`(`DIR_B` 总线 B 方向)** **共号** ⇒ 这两只**永远不能启用 EXTI**；
④ `EXTI11` 与 `PE11`(急停) 共号 ⇒ 急停永远不要改成 EXTI。
⇒ 详细设计见 `RC方案复核_2026-09-23.md` §7。
