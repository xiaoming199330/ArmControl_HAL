# `g x y z 90` 报 "tool pitch NOT met (J4 limit?)" —— 诊断报告

日期：2026-09-15　对象：`ArmControl_HAL` 六轴臂　固件：`Core/Src/main.c` + `Core/Src/kinematics.c`
触发命令：`g 260 0 300 90` / `g 250 0 300 90` / `g 280 0 300 90` / `g 230 0 300 90`（全部被取消）

---

## 1. 一句话结论

**这不是 bug，是一次正确的安全拦截。** 目标点本身位置可达（FK 回代 0 mm），但**"工具水平指前（pitch=90°）"这个姿态在该位置需要手腕 J4 转到 ≈214°**，
超过了当前固件里 J4 的上限（推断约 195~210），于是唯一的解析解被限位拒 → IK 静默降级到 CCD（只保位置、放弃方向）→ 俯仰守卫发现方向错了 → 取消动作。

同一位置的**另一个解析旁解（肘上）要求 J3≈24°**，而该臂肘关节的后挡块在 **≈78°**（2026-09-10 实测），所以那条路**机械上根本走不通**，放开限位也救不回来。

---

## 2. 触发链（逐行对应代码）

| 步骤 | 代码位置 | 行为 |
|---|---|---|
| ① 目标进来，pitch 当**硬约束** | `main.c:3255` `cmdGoto()` | `target.yaw = pitch` |
| ② 解析 IK：先算腕轴位置 | `kinematics.c:216` `ik_analytic()` | `J4轴 = 目标 − 167.8mm·u(pitch)`，再 2R 闭式解，**肘上/肘下两个旁解** |
| ③ 逐关节查限位 | `kinematics.c:250-252` | 任一旁解越限即 `continue`；**两个都越限 → 返回 0** |
| ④ 静默降级 CCD | `kinematics.c:383` Step 3b | `ccd_run()` 只拟合 ty/tz，**pitch 是自由量** → 方向丢失 |
| ⑤ `g` 先校验位置 | `main.c:3321` | FK 回代 err=0mm ⇒ 这一步**照样通过**（假阳性来源） |
| ⑥ 俯仰守卫取消 | `main.c:3330-3341` | `\|got−req\|>10°` ⇒ 打印 `tool pitch NOT met (J4 limit?)` 并 return |

⇒ 现场看到的 **"Verify FK err 0 mm" + "Pitch: req=90 got=44"** 就是 ④⑤⑥ 的指纹：**位置对、方向错**。

---

## 3. 几何反解（与固件逐行等价的 Python 复算）

平面目标（相对 J2 轴）：前向 `ty = 260 − 31.32 = 228.7 mm`，高度 `tz = 300 − (65.30+54.80) = 179.9 mm`。
工具指向 90° ⇒ **腕轴必须落在 `目标 − 167.8mm·u(90°) = (60.9, 179.9)`**（相对 J2 轴），即距 J2 轴 189.9 mm。

| 目标 | 旁解 | t2/t3/t4 (相对中性位) | J2 / J3 / J4 (舵机度) | 判定 |
|---|---|---|---|---|
| 260 0 300 90 | 肘上 | +49.5 / −155.8 / +108.5 | 229.5 / **24.2** / 288.5 | ✘ J3≈24° 低于后挡块 78°（机械不可达） |
| 260 0 300 90 | 肘下 | −40.0 / +8.1 / +34.1 | 140.0 / 188.1 / **214.1** | ✘ J4 超上限（唯一可能可行的一条，被限位挡） |
| 250 0 300 90 | 肘下 | −44.1 / +10.2 / +36.1 | 135.9 / 190.2 / **216.1** | ✘ J4 超上限 |
| 280 0 300 90 | 肘下 | −31.5 / +2.8 / +30.9 | 148.5 / 182.8 / **210.9** | ✘ J4 超上限 |
| 230 0 300 90 | 肘下 | −51.8 / +13.2 / +40.9 | 128.2 / 193.2 / **220.9** | ✘ J4 超上限 |

**四个点全灭，且四个点的肘下解 J4 需求都 ≥ 210.9°** ⇒ 反推出：**当前 J4 上限 < 211°**。
（现场 CCD 落点 J4 = 163/174/181/195 也全部落在这条线以下，与推论一致。）

**物理原因**：`pitch=90°` 要求工具水平 ⇒ 腕轴必须与 TCP **等高**（都在 300mm），而 J2 肩轴只有 120.1mm 高。
臂要一边抬到 300mm、一边把腕轴收到前向 92mm 处，**前臂被顶成近似竖直向上，腕子必须向前多弯 ~31~41°** 才能把工具掰回水平。位置越靠前（x 越大）腕轴越远，需要弯的角度越小 ⇒ 所以 x 越大越容易（210.9 < 214.1 < 220.9）。

## 4. 判决表：J4 上限 ↔ 该点能撑到的最大俯仰

（J3 用实测挡块弧；数据由 `tools/ik_pitch_check.py` 生成）

| J4 上限（servo deg） | (260,0,300) 可达 pitch | pitch=90 能否达成 |
|---|---|---|
| 190 | ≤ 75° | ✘ |
| 195 | ≤ 80° | ✘ |
| 200 | ≤ 80° | ✘ |
| 205 | ≤ 85° | ✘ |
| 210 | ≤ 85° | ✘ |
| **215** | **≤ 90°** | ✔ |
| 230 | ≤ 95° | ✔ |
| 250 | ≤ 105° | ✔ |
| 265 ~ 290 | ≤ 110° | ✔ |

即：**把 J4 上限放开到 ≥215°，`g 260 0 300 90` 立刻能跑**（如果手腕真的转得到那儿）。

## 5. 一步确认（现场，2 条命令）

```
L                     # 显示六轴 MIN/MAX（舵机度）—— 看 J4 那一行
                      # 现固件开机横幅也打同一组: Limits: J1[..] J2[..] J3[..] J4[..] ...
```

判读：

| `L` 里 J4 上限 | 结论 |
|---|---|
| < 211 | **确认就是 J4 被限住** → 走第 6 节 |
| ≥ 215 但仍报 pitch 未达成 | 说明卡的不是 J4 而是 J3 那条弧（把 `L` 全表 + `f` 输出贴回来，重算） |

**不依赖 `L` 的旁证法**（二分，看哪条能过）：

```
g 260 0 300 80      # 需 J4≈193°   → 过  ⇒ J4 上限 ≥193
g 260 0 300 85      # 需 J4≈203°   → 过  ⇒ ≥203
g 260 0 300 90      # 需 J4≈214°   → 过  ⇒ ≥214
g 260 0 300 100     # 需 J4≈236°   → 过  ⇒ ≥236
```

过了哪一档，就把 J4 上限钉在哪一档附近 —— 比读 `L` 更直接，且顺手证明了"pitch 越高、J4 需求越大"这个单调关系。

## 6. 两条修法（先分清"限位是真是假"）

> ⚠ **铁律：永远不要为了迁就算法去收紧限位；反过来，也绝不允许把限位放到真实挡块之外** ——
> 放到外面 = 舵机顶死堵转（红灯/过载），比"动作被取消"严重得多。

### 6.1 如果手腕**物理上转得到 215° 以上** → 是限位标定偏窄，重标

J4 的上限来自 `c` 校准的 **Phase 2 实测行程**（`calib_max_raw[3]`，见 `main.c:1229`）。
手推没推到挡块 / 推得不够狠（金属舵盘齿隙）就会记小。

```
（断电或扭矩释放）手把 J4 推到两个硬挡块顶死，各读一次 f 的 servo 读数 → 得到真实 [min,max]
L 4 <min> <max>       # 临时放开，立刻生效（不落盘，断电即回）
  或重跑 c 的 Phase 1/2 + s   # 落盘
g 260 0 300 90        # 复测
```

### 6.2 如果手腕**确实到不了 215°** → 姿态无解，换姿态/换目标

- **降俯仰**：同位置 pitch ≤ 80° 可达成（`g 260 0 300 45` 在 x=260 可到 z=460）；想把工具放平又必须够高，就只能降 z。
- **降高度**：`pitch=90` 保持，z 往下压到 J4 上限允许的范围（J4=200 时约 z ≤ 260）。
- **分清需求**：如果任务只是"抓住/放置"而不是"工具绝对水平"，把 pitch 放宽到 ±15° 通常仍然可用。
