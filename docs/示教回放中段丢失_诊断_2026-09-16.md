# 示教保存后回放「中后段没被复刻出来」— 诊断与修复（2026-09-16）

> 现象（用户报）：`teach` 录一段 → `save <name>` → `play` 回放，
> **中间偏后有一段没被复刻出来，但尾段是对的。**
>
> 结论：**问题在录音侧，不在回放侧。** 已加固固件并加了仪表。

---

## 一、先把不可能的先排除（三条硬证据）

### 1. 回放侧没有跳样本的路径

`teach_stream_tick()`（main.c）每个节拍只做一件事：

```c
if (teach_play_idx < teach_play_src_cnt) {
    SERVO_SetPositionsRawSync(teach_play_src[teach_play_idx]);
    teach_play_idx++;          /* 严格 +1, 全工程唯一写入点 */
    ...
}
```

`teach_play_idx` 的**全部写入点**只有 5 处：`play_finish` / `play_abort` /
`ramp_done(=1)` / `play_start(=0)` / 上面这个 `++`。
节拍被主循环吞掉时，节拍标志是 1 bit 标志位 —— 回放只会**变慢**（时间被拉长），
**不会跳样本**。⇒ 回放本身不可能"漏掉中段"。

### 2. Flash 里的数据与录音数组逐字节相同

`TeachStore_Save()` 写完立刻回读整段并比对 CRC：

```c
uint32_t crc  = ts_crc32((const uint8_t *)samples, n * 12U);
ts_program_words(dst + TS_ENTRY_HDR, (const uint8_t *)samples, n * 12U);
uint32_t crc2 = ts_crc32((const uint8_t *)(dst + TS_ENTRY_HDR), n * 12U);
if (rn != n || rf != TS_FLAG_ACTIVE || rc != crc2 || crc2 != crc) return TSTORE_ERR_FLASH;
```

不一致会直接返回错误（控制台会报），装载时 (`ts_load_dir`) 还会再校验一次。
⇒ **存盘这一段是无损的。**

### 3. 不是舵机被限速拖住

回放期下发 `TEACH_STREAM_SPEED = 600`，而平时运动默认 `STS_DEFAULT_GOAL_SPEED = 200`、
轨迹收尾只用 `30`。600 是工程里最快的档，**远高于物理极限** ⇒ 舵机没有被限速卡住。

### ⇒ 推论

回放是「按索引顺序重放一个 CRC 校验过的数组」。
数组里若有一段是"一步跨过去"的，回放必然也一步跨过去。
**所以那一段在录音时就没被记下来。**

## 二、录音为什么会缺一段

节拍源在 TIM2 ISR（2 kHz ÷ 40 = 50 Hz）：

```c
if (++traj_tick_div >= 40) { traj_tick_div = 0; traj_do_update = 1; }   /* 1 bit */
```

`traj_do_update` 是**布尔标志**。主循环只要有一拍超过 20 ms，
中间的节拍就被**静默合并**（新边沿只是把一个已经置 1 的标志再置 1），
不计数、不告警。录音是"每消化一拍记一个样本" ⇒ **被合并的节拍 = 录音里的时间空洞**。

旧版还有第二个放大器（`teach_record_tick` 旧实现）：

```c
raw[j] = SERVO_GetPositionRaw(j);     /* 超时 100 ms */
if (raw[j] == 0xFFFFU) return;        /* ← 整拍放弃, 连这一拍样本一起丢 */
```

一次总线读失败 = 烧掉 100 ms（**5 个节拍**）+ 这一拍样本也不记。
几次连在一起就是肉眼可见的一大段空洞，而空洞之后照常 1:1 记录 ⇒ **尾段看着是对的**，
正好对上用户描述。

### 录音拍里主循环可能被谁拖长（都在主循环里，可查）

| 位置 | 为什么可能超 20 ms |
|---|---|
| `teach_record_tick` 自己 | 6 次单轴读，每次最坏 100 ms（旧版） |
| `FeedbackSampleService()` | 每拍 1 次舵机读，与录音抢总线 |
| `cmdRealtimeFeedback()` / `cmdRealtimePoseFeedback()` | **若开了周期回传**（`tf`/`tp`），每来一次就整读 6 轴 + 阻塞打印 |
| `TelemetryPrintService()` | `tm` 开着时每拍打印 |
| `cprint()` | **阻塞式**（红线 6），控制台一旦有长输出就占时间 |
| `SerialProto_DispatchPending()` 等 | 二进制帧执行时做总线事务 |

## 三、本次改动（已编入 v3 固件）

| # | 改动 | 目的 |
|---|---|---|
| 1 | 新增 `SERVO_GetPositionRawTO(joint, to_ms)`，录音拍用 **10 ms**（原 100 ms） | 一次失败只损失半个节拍，不再是 5 个 |
| 2 | `teach_record_tick()` 重写：单轴读失败 → **沿用上一拍该轴的值**，不再 `return` | 保证**每拍必记一个样本**，时间轴不再被打断（20 ms 微保持肉眼不可见） |
| 3 | TIM2 ISR 里统计 `teach_tick_lost`（被合并的节拍数，仅示教期） | 把"主循环卡顿"量化出来 |
| 4 | 统计 `teach_smp_held` / `teach_read_fail[6]` | 定位是**哪个关节**在读上抖动（姿态相关接触不良的指纹） |
| 5 | `teach exit` 打印 `[rec-integrity] ...` | 现场一眼看出这段录音干不干净 |

**顺带修掉的一个隐性问题**：旧版缓冲写满（4000 点 ≈ 80 s）时会在
`teach_assist_write()` **之前** `return` ⇒ 悬浮托举会突然消失。新版把读和控制
放到写满判定之前，写满后托举照常。

## 四、现场怎么用（判据表）

录一段 → `teach exit`，看那行 `[rec-integrity]`：

| 输出 | 含义 | 下一步 |
|---|---|---|
| 完全不打印 | 干净（无丢拍、无读失败） | 录音侧没问题，转看第五节的"其他可能" |
| `lost_ticks=N` | 主循环有 >20 ms 的卡顿，时间轴被压缩 N×20 ms | 关掉周期回传（`tf 0` / `tp 0`）、别在录音时敲命令，再录一次对比 |
| `held_axes=N` | 有轴读到 `0xFFFF`，已用上一拍值顶替 | 看 `read-fail J1..J6` 是哪一轴；**记住那个姿态**，反复停在那个姿态附近试，若稳定复现 ⇒ 舵机线/插头在该姿态受力接触不良 |
| `read-fail` 集中某一轴 | 该关节在特定姿态读失败 | 用 `n`/`s` 看该轴温度与错误位；检查线束在那一姿态是否被拉紧 |

⚠ 判据重点：**如果 `read-fail` 集中在某一轴**，那就是硬件（线束/插头/舵机）在
特定姿态下的接触问题，跟固件无关 —— 这也解释了为什么"同一段动作每次都缺同一个地方"。

## 五、如果仪表显示录音是干净的

那说明数据没丢，问题在别处，按顺序查这三点：

1. **是不是放错了文件**：`list` 看各文件的**样本数与时长**，
   和刚才那一段动作的实际秒数对比 —— 时长明显短的，就是一段旧录音。
   （`play <name>` 支持名字和 1-based 序号两种写法，序号搞混很容易。)
2. **起手那段 S 曲线**：`teach_play_start()` 会先规划一段 30 °/s 的
   轨迹把臂拉回录音起点（RAM 里打印 `Returning to start...`）。
   如果臂离起点很远，这段会占一段时间，别把它当成"回放内容"。
3. **记录里有没有单个野值**：某一拍读到一个错值会让臂抖一下再回来。
   如果症状是"抖一下"而不是"缺一段"，那是另一回事（需要加野值滤波）。
