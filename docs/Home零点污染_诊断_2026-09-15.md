# Home 零点被污染 —— `g` 报 "(J4 limit?)" 的真正原因

> 2026-09-15 定案。**上一轮（09-15 上午）把根因判成"J4 限位太窄"，那个结论是错的**，本文推翻并给出新结论。
> 触发问题：`g 200 150 200 90` / `g 260 0 300 90` 等一批点全部报
> `IK: tool pitch NOT met (J4 limit?) - move cancelled.`，而用户明确反馈"**以前都能到，今天不行**"。

---

## 1. 结论（一句话）

**不是 J4 的问题，是 `calib_zero_raw`（官方 Home 零点）被写成了"当时随意摆放的姿态"。**

它的值现在是：

```
calib_zero_raw = [2035, 896, 3106, 2331, 2022, 1567]      (从现场数据反推)
                  ↑J1   ↑J2   ↑J3   ↑J4   ↑J5   ↑J6
正确值应为         [2048 2048 2048 2048 2048 2048]  (出厂中位, SERVO_OFFSET=180°)
```

**而这组数正是 2026-09-14 现场在示教模式里被误打入的那一行**：

```
[ZERO] Home 零点已记录: 2014 896 3106 2331 2022 1567
```

（当时敲 `cz`/`cy 1000`/`mf 0` 这些命令时，首字符 `c` 把控制台带进了 `c` 校准模式，
之后**输入流里的每一个 `0` 都被当成"记录全部 Home 零点"**。J2=896 / J3=3106 / J5=2022 三个数完全对上。）

## 3. 证据链（三条，互相独立）

### 3.1 `L` 输出的 J3/J5 与编译默认值对不上 —— 说明限位被运行时数据覆盖

```
| J  | MIN  | MAX  | CUR  |        固件默认 JOINT_MIN/MAX
| J1 |    0 |  360 |  180 |        0 ~ 360     ✔ 一致
| J2 |   58 |  264 |   77 |        58 ~ 264    ✔ 一致
| J3 |  171 |    9 |  273 |        10 ~ 177    ✘ 整体偏移 +161° 且跨零
| J4 |   83 |  289 |  240 |        83 ~ 289    ✔ 一致
| J5 |   88 |  248 |  179 |        180 ~ 340   ✘ 整体偏移 −92°
| J6 |    0 |  360 |  129 |        0 ~ 360     ✔ 一致
```

J3/J5 的 IK 限位由 `apply_calib_limits()` 用 **`calib_zero_raw[j] + 固定偏移`** 算：

```c
mn = wrap_raw(calib_zero_raw[2] + (-1163));   // J3 后挡块
mx = wrap_raw(calib_zero_raw[2] + (+1090));   // J3 前挡块
JMIN[4] = wrap_raw(calib_zero_raw[4] + (-1033));  // J5
JMAX[4] = wrap_raw(calib_zero_raw[4] + (+787));
```

而 `L` 打印的 MIN/MAX 是 `servo_raw_to_deg(mn/mx) = raw/4095*360`（**与 zero 无关**，纯 raw→度）。

反解：`171/360*4095 = 1945` ⇒ `zero[2] = 1945 + 1163 = 3108 ≈ 3106` ✔
　　　`88/360*4095 = 1001` ⇒ `zero[4] = 1001 + 1033 = 2034 ≈ 2022` ✔

**⇒ 零点就是 3106 / 2022 —— 昨天那行误记录的值。**

### 3.2 现场 `g` 打印的 J2/J3/J4 数字，只有配上"污染后的零点"才合理

`g` 打印的是 `rad_to_servo_deg()` 的输出：

```c
servo_deg = SERVO_OFFSET[joint] + JOINT_DIR[joint] * 关节角
SERVO_OFFSET[j] = calib_zero_raw[j] / 4095 * 360      // 零点一变, 整条输出平移
```

`g 200 150 200 90` 打印 `J2=106`：

| 假设 | SERVO_OFFSET[1] | 反推 J2 关节角 | 物理含义（上臂方向 psi = 13.97° + 关节角） | 判定 |
|---|---|---|---|---|
| 零点正确 | 180.00° | **−74.0°** | psi = **−60°**，上臂指向**后下方** | ❌ 不可能指向正前方目标 |
| 零点污染(=896) | 78.77° | **+27.2°** | psi = **+41.2°**，上臂前倾指向目标 | ✔ 合理 |

**⇒ 零点被污染，这是从现场数据本身反推出来的，不依赖任何猜测。**

### 3.3 离线逐行复刻：干净零点下这个目标**完全可达**

`tools/ik_repro.py` 逐行照抄固件的 `ik_analytic()` / `IK_SetJointLimitsRaw()` / `apply_calib_limits()` / `cmdGoto()` 判定链，跑同一个 `g 200 150 200 90`：

| 零点状态 | 解析解（肘下旁解） | raw 检查 | 结果 |
|---|---|---|---|
| **干净**（zero=0） | J2=+119.6°(**采纳**) | 全通过 | 打印 `J1=143 J2=120 J3=243 J4=180`，**pitch 达标 → 执行动作** ✔ |
| **污染**（过去那组） | J2=−60.45°(采纳) → 舵机度 18.3° → **raw 208 超出 [660,3003]** | **失败** | 解析解被废 → **降级 CCD** → 位置对、pitch 自由 → **正是报错现场** ✔ |

旁解本身：
```
肘上: J2=+97.49  J3=−210.30  J4=+115.01   FKerr=0.0000mm
肘下: J2=−60.45  J3= +62.65  J4= +0.01   FKerr=0.0000mm   ← 唯一物理可用解
```

**⇒ 「零点干净 → 可达」「零点污染 → 不可达」在同一份代码上同时成立，与用户"以前能到、现在不行"完全吻合。**

## 4. 失效链（为什么零点一错，pitch 就丢）

```
Home 零点被误记录 (calib_zero_raw = 当时姿态)
        ↓  落盘 (示教模式按 's' 会把 zero 无条件写进 Flash, 见 main.c:1033)
        ↓  开机 pid_load_startup() 读出 → Kinematics_SetZeroRaw()
SERVO_OFFSET[] 全体偏移 (J2 −101°, J3 −93°, J4 +25°)
        ↓
rad_to_servo_deg() 输出整体平移
        ↓
IK 解析解求出的舵机度落到 JOINT_MIN_RAW..MAX_RAW 之外 / jlim 之外
        ↓
ik_analytic() 两个旁解都进不去 → IK_Solve() 降级到 CCD 兜底
        ↓
CCD 只拟合位置 (pitch 是自由量) → Verify FK err=0mm, 但 pitch 差 40~50°
        ↓
cmdGoto() 的守卫拦下 → "tool pitch NOT met (J4 limit?) - move cancelled"
```

报错文本里的 **"(J4 limit?)" 是误导性的**——它只是 `main.c:3337` 的一句固定文案，实际越界的是 **J2**（见 3.3）。

**顺带说明为什么 J3/J5 的 `L` 显示离谱却"不影响"可达性**：J3/J5 的保护限位是用 **`calib_zero_raw + 偏移`** 定义的（相对量），
零点平移后 `wrap_raw` 仍然自洽 ⇒ `jlim` 不变。而 **J2/J4/J6 用的是 Phase2 实测的绝对 raw**（`calib_min/max_raw`），
它们折算成关节角时要减 `SERVO_OFFSET` ⇒ **零点一变就错位**。这就是为什么坏的是 J2。

## 5. 修复

### 5.1 现场（新固件已带这两条命令）

```
zi            # 只读: 打印 calib_zero_raw / SERVO_OFFSET / raw 限位 / IK jlim
zr            # 把 Home 零点复位为出厂中位 (本次运行有效)
zr save       # 同上 + 写 Flash 固化 (重启保持)
```

**判读**：
- `zi` 里 `calib_zero_raw` 若是 `[2048 2048 2048 2048 2048 2048]` 或全 `0` ⇒ 正常；
- 若是 `[20xx 8xx 31xx 23xx 20xx 15xx]` 这种参差的读数 ⇒ **就是被污染的，敲 `zr save`**；
- 复位后 `g 200 150 200 90` 应当直接执行（pitch 达标）。

⚠️ **`zr` 的语义**是"Home = 出厂中位（raw 2048 / 180°）"。这依赖装配前提：**装舵盘时零位对准官方 Home**。
若你的臂确实是在非 2048 位置装的盘（例如某次换舵机后重锚过），那正确值不是 2048 —— 那就**不要用 `zr`**，
而要用 `c` 校准：**把臂摆成官方 L 形 Home → 按 `0` → 按 `s`**（`s` 才会用新 zero 重算 IK 限位）。
从 09-14 示教表的 `ZERO` 列（记录前）是 `2048 2047 2048 2048 2048 2048` 来看，**你的臂属于前者，`zr save` 是对的**。

### 5.2 代码（本轮已改，`main.c`）

| 位置 | 改动 | 原因 |
|---|---|---|
| `pid_load_startup()` | **`Kinematics_SetZeroRaw()` 提到 `apply_calib_limits()` 之前** | 原来 apply 在前，`IK_SetJointLimitsRaw(..., SERVO_OFFSET)` 拿到的是**默认 180°**，算出的 `jlim` 与 `rad_to_servo_deg` 的输出错位 |
| 示教模式 `s` 分支 | 同上调换顺序 | 同一 bug |
| 新增 `zi` / `zr [save]` | — | 零点/限位自助自查与复位 |
| `kinematics.c/h` | 新增 `IK_GetJointLimitsDeg()` | 供 `zi` 打印实际生效的 jlim |

### 5.3 仍需你决策的两个"根因加固"（未改，怕影响你的用法）

1. **`c` 模式里 `0` 键太易误触**：任何输入流中的字符 `0` 都会触发"记录全部 Home 零点"，
   并且**即使没做 Phase 2，按 `s` 也会把 zero 无条件写进 Flash**（`main.c:1033`）。
   建议加二次确认（`0` 后要求再按 `y`）或要求"必须先做 Phase 2 才能保存 zero"。**要不要加？**
2. **`zr save` 之前先确认 `zi` 的读数**，别在零点本来就正确时乱复位。

## 6. 自我纠错（上一轮结论作废）

| 上一轮我说过 | 实际 | 为什么错 |
|---|---|---|
| "反推你现在的 J4 上限 < 211°" | **J4 上限就是 289°，根本没挡** | 我拿"文档限位"当已知量去反推，没先核对**运行时**限位；而且 `L` 明明打了 83~289 我仍沿用旧假设 |
| "要改大 J4 行程才通" | **改 J4 无用** | 真正的越界关节是 **J2**（舵机度 18.3° 掉到 raw 208，低于下限 660） |
| "`g` 打印的 J1..J6 是关节角" | **是舵机度**（`rad_to_servo_deg` 输出，含 SERVO_OFFSET 偏移） | 没查 `cmdGoto` 的打印点就默认了单位，导致 3.2 那步的关键信号被我漏掉一整轮 |

**方法论教训（已写进技能）**：
- 报错文案里括号内的猜测（"(J4 limit?)"）**不是证据**，必须回到代码看守卫到底在比什么；
- 判定"限位是否合理"必须用**运行时** `L` / `zi` 的值，不能用文档/注释里的设计值；
- 打印出来的关节数字，**先确认它的单位与参照系**（servo deg ≠ joint deg，差一个 SERVO_OFFSET）。
