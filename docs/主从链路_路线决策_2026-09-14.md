## 2. 已被逐行排除（不要再回头翻）

- `usart.c:147-166`：PA0/PA1 = `AF_PP` + `GPIO_AF8_UART4` + `NOPULL` + speed LOW，**全工程唯一配置点**。
- `huart4` 全工程仅 7 处引用，全部正确；`MX_UART4_Init()` 排在 `MX_GPIO_Init()` **之后**（无覆盖）。
- `gpio.c` 只配 PA5(LED)，**未碰** GPIOA Pin0/Pin1；`SERVO_BUS_TX_MODE(=AF_OD)` 只作用于 PC12/PB10·PB11，**不含 UART4**。
- `arm_can_driver.c` 的 CAN = **PB8/PB9(AF9)（已按 `.ioc` 修正）**，与 PA0/PA1 不冲突；`.ioc` 里 PA0/PA1 无第二归属、工程无 ETH/RMII/SDIO。
- 两构建共用同一份 `usart.c`；168 MHz / APB1=42 MHz ⇒ 实际 115068 baud(−0.11%)，**两端同代码不可能相对失配**。
- **同板自环（同 MCU / 同外设 / 同 BRR）场景下波特率失配物理上不可能**；几 cm 杜邦 + CMOS 推挽本该 `NE≈0`。
- `HAL_UART_Transmit` 返回 OK 与线通不通无关；`ms` 已证实在发。

⇒ 唯一未闭合的只剩：**"你插跳线的那两排针，到底是不是 MCU 的 PA0/PA1"**，以及 **PA1 这一只脚本身**。

## 3. 三条候选路线

### 路线 ① 先做 3 分钟「钉死排针」（零成本，**先做这个**）

板上无原理图时，唯一能证明"排针 ↔ MCU 引脚"对应关系的办法：

```
mo A 0 1      # PA0 输出高并保持
mo A 0 0      # PA0 输出低并保持
mo r          # 释放, 恢复 AF8
```

拿万用表在排针上量：**哪根针跟着变，哪根就是 PA0**。

- **跟着变** ⇒ 排针没错 ⇒ 问题在**引脚本体/焊点** ⇒ 直接走 ② 或 ③。
- **不变** ⇒ 你一直在测**别的脚**（或那根排针是断的 / 没焊上）⇒ 换到真正跟着变的那两根针，
  现有 UART4 代码**一行都不用改**，链路立刻可用。

> 注：`mo A 1 1` / `mo A 1 0` 可同理找 PA1。

### 路线 ② 换一对 UART 引脚（零硬件成本）

把主从链路从 `UART4 / PA0·PA1` 挪到：

| 候选 | TX | RX | 备注 |
|---|---|---|---|
| **USART1** | PA9 | PA10 | 最通用、最常被引出 |
| **USART2** | PA2 | PA3 | 亦常见 |

**改动范围（协议层完全不动）**：
- `usart.c`：新增 `MX_USARTx_Init()` + `HAL_UART_MspInit()` 分支，把 `huart4` 引用改到 `huart1`/`huart2`（7 处）。
- `stm32f4xx_it.c` + 主臂 RX 中断（`main.c` 内的 `UART4_IRQHandler`）：IRQ 向量换名。
- `Makefile`：加 `LINK=usart1|usart2` 开关，**非默认时 BUILD_DIR 必须带该后缀**（否则重蹈"拷出假固件"）。
- ⚠ **前提**：`usart.c:9` 注释写着 *"USART1 and USART2 are NOT used (pins not available on board)"* ——
  **这条注释没有任何证据支撑**（当初只是推断）。必须先用路线 ① 的办法在排针上把它们找出来。

### 路线 ③ 换总线走 CAN（工程上最稳，需 2 个收发器模块）

```
CAN1: PB8=CAN1_RX / PB9=CAN1_TX (AF9)   ← .ioc 里这么写的
```

- `arm_proto_can.c` + `arm_can_driver.c` **已经写好**，协议层（`arm_control_protocol.c`）早已传输无关
  ⇒ 换 CAN 主要就是"把 `huart4` 的承载换成 `arm_proto_can`" + 收发器接线。
- 需要：**两个 3.3V CAN 收发器**（TJA1050 是 5V 器件，**SN65HVD230 / VP230 更适合**）+ 120 Ω 终端电阻 + 双绞线。
- 500 kbps 下 19 字节帧 ≈ 0.6 ms，30 Hz 占用率 ≈ 2% —— 余量极大。
- **差分信号天然免疫**你现在遇到的全部症状：共地电位差、RX 悬空、1 Mbps 舵机总线串扰。
- ⚠ **两处必须先统一**：
  1. 现固件 `arm_can_driver.c:153` 用的是 **PA11/PA12**，而 `.ioc` 写的是 **PB8/PB9** —— 走 CAN 前先定死用哪一组。
  2. **PA11/PA12 在 F407 上同时是 USB_DM/USB_DP** —— 若本板有 USB 座引到这两脚，就别用 PA11/PA12，选 PB8/PB9。

## 4. 建议顺序

```
① 万用表钉死排针（3 分钟，零成本）
   ├─ 排针没错 → ② 换脚（零硬件成本）或 ③ 换 CAN（最稳）
   └─ 排针错了 → 换到真脚，原代码直接用
```

**若手里已有 CAN 收发器模块，③ 是投入产出比最高的终点方案** —— 这条链路的可靠性需求（30 Hz、19 B、跨越两个独立供电的臂）本来就更适合差分总线。

## 5. 已实施：CAN 承载 —— `make LINK=can`（2026-09-14）

### 5.0 回答「官网用的是哪条路」

**两根裸 TTL 串口线跨两块独立供电的板子，不是工业/厂商标准做法。** 标准做法是**带收发器的差分总线**（CAN 或 RS-485）。
而这个工程**本来就按这条路设计过**：`.ioc` 里配了 CAN1，`arm_can_driver.c`(bxCAN 500 kbps) 与
`arm_proto_can.c`(分包 / 重组 / 分发) 都在，`ARM_CAN_ENABLE` **默认就是 1**，主循环里 `CanProto_Poll()` 一直在跑，
甚至已有内部回环自检命令 `e`。缺的只是**"主从链路"这一端没接上去**。现在补齐了。

### 5.1b 引脚统一（2026-09-14 修正，重要）

初版 `arm_can_driver.c` 凭印象写成 **PA11/PA12**，而 `.ioc` 里 CAN1 定的是
**PB8=CAN1_RX / PB9=CAN1_TX (AF9)** —— 正是 UART4 那一轮"引脚凭记忆"踩过的同一个坑。
现在**默认按 `.ioc` 走 PB8/PB9**，PA11/PA12 作为备选保留：

```
make LINK=can                  -> PB8=RX / PB9=TX   (build_can/)       ← 默认
make LINK=can ROLE=master      -> build_master_can/
make LINK=can CANPIN=pa        -> PA11/PA12         (build_can_pa/)    ← 备选
```
两组都是 AF9。`-DARM_CAN_PINS_PA=1` 编译期切换，板上表现出的症状与"线接错"一模一样，
所以务必确认板上排针到底引的是哪一组（`cn` 会打印当前固件用的引脚）。

### 5.3 接线 —— 「CAN PHY V1」模块（用户手上的那块，2026-09-14）

模块特征：**5V / 3.3V 电平选择跳线**（黄色跳线帽帽，3 针）、`5V GND TX RX` 四线接口（排针 + 蓝端子各一份）、
`CAN H` / `CAN L` 端子（J1）、支持 CANFD、板上 `通信指示` / `电源指示` 两个 LED。

**一块模块对应一块 MCU 板，两块板接法完全相同：**

| 模块脚 | 接到 F407（默认固件） | 备选固件（`CANPIN=pa`） | 说明 |
|---|---|---|---|
| `VCC`（丝印 5V 那只脚） | 板 **5V**（或 3.3V，见下） | 同 | 模块有内部电平选择，见下面「跳线」 |
| `GND` | **必须共地** | 同 | 非隔离收发器，不共地必错 |
| `TX`（= 收发器 TXD，**输入**） | **PB9** = CAN1_TX | PA12 | ⚠ **直连，不交叉** |
| `RX`（= 收发器 RXD，**输出**） | **PB8** = CAN1_RX | PA11 | ⚠ **直连，不交叉** |
| `CANH` / `H` | 对板 **CANH**（不交叉） | 同 | 用同一对**双绞线** |
| `CANL` / `L` | 对板 **CANL**（不交叉） | 同 | |
| 终端电阻 | **两个物理末端各 120 Ω** | 同 | 短桌面临时可用 1 个 120 Ω 先跑通 |

**跳线（`电平选择 5V/3.3V`）与供电：**

- 先设 **3.3V 侧**（与 STM32 IO 同电平，最干净）。模块的 `5V` 脚给电，跳线选 3.3V。
- 若完全不通（`ct` 对端计数不涨、`cn` 里 `lec=3`），把跳线换到 **5V 侧**再试一遍：
  - 很多这类模块的收发器是 5V 器件（TJA1050/SIT1050 系列）；5V 供电时它的 RXD 输出 5V，
    而 **STM32F407 的 PB8/PB9/PA11/PA12 都是 FT(5V 容忍)脚**，电气上安全。
  - MCU 侧 3.3V 推挽驱动 5V 器件的 TXD 输入也没问题（VIH≈2.0V）。
- **最确定的做法**：把模块上那颗收发器芯片（U2）的丝印读出来 ——
  `TJA1050 / SIT1050` 类 = 必须 5V；`SN65HVD230 / VP230 / TJA1051T/3 / TJA1042T/3 / SIT1042` 类 = 3.3V 可用。
- ⚠ 两个模块的跳线/供电**必须一致**（一个 5V 一个 3.3V 时，隐性电平对应的共模点不同，容易偶发误码）。

**终端电阻自检（10 秒）**：断电后用万用表量模块的 `CANH–CANL`：
- 读出 **≈120 Ω** ⇒ 这块模块自带终端电阻；两块板都带时总线合计 ≈60 Ω（正常）
- 读出 **≈60 Ω** ⇒ 已经有两处 120 Ω 并上了
- 读出 **几 kΩ / 开路** ⇒ **没有终端电阻**，必须在总线两端各外接一个 120 Ω

### 5.4 联调步骤（顺序重要，★ 是新增的判据）

```
0) 两块板都烧 CAN 版（BOOT0 拉高 → RESET → 烧 → BOOT0 拉回低 → RESET）
     make flash ROLE=master LINK=can PORT=COM11
     make flash           LINK=can PORT=COM11

1) 单板先证明 MCU 侧 OK（不接总线、不接模块也能跑）
     两块板各敲  e     → 应看到 "RESULT: PASS - CAN controller OK"
     （内部回环，证明 bxCAN 内核/时钟/过滤器都正常）

2) ★ 接上收发器模块后先敲  cp  —— 直接量引脚, 分清"模块没接/没上电"与"线不对"
     RX 脚 内部下拉 -> 11111111 ⇒ [被外部驱高] 模块已上电且 RX 真的接上了 ✔
                       00000000 ⇒ [悬空] 模块 RX 线没接到该脚 / 模块没上电
     TX 脚 推挽低->00000000 高->11111111 ⇒ [驱动级正常]
     → 这一步不通就别往下走, 先把线/供电/跳线解决

3) 各敲  cn
     → "hw init" 应为 ok, 且打印的引脚要与你的接线一致
       （若印的是 PA11/PA12 而线接在 PB8/PB9 ⇒ 烧错固件, 换 04/03 号）

4) ★关键一步：两边对拍帧计数
     主臂敲  ct 50    发 50 帧到 0x7E0
     从臂敲  ct       看"本板自检帧 已收"增加了多少
       增加 ≈50  ⇒ 物理链路真的通了（收发器/双绞线/终端/共地全 OK）
       不增加    ⇒ 查 VCC / 跳线电平 / CANH-CANL 接反 / 120R / 共地
       cn 里 lec=3(ACK 错) ⇒ 对面没应答：没上电、线断、或两端波特率不一致
            → 别急着拆线! 直接按 5.4b 定位表走: 先 `cz`(我方发得出去吗) 再 `cy`(对面在不在发)
       cn 里 lec=6(CRC 错) ⇒ 线上有干扰/终端不匹配（差分总线极少见）

5) 链路通之后：
     主臂  ms   → "Master TX: N frames sent" 应在涨
     从臂  cn   → "合法好帧" 应以 ~30/s 涨  ⇒ 0x13 流帧真的到了并在执行
       （涨但不跟动 ⇒ 是安全判定拒帧，看从臂串口打印；与链路无关）

6) 摆齐两臂 → 从臂 `sf 1` 开始跟随（跳变基准在 `sf 1` 那一帧建立）
   ⚠ 两臂上电前摆同一姿态；主臂校准必须拔链路（上电即 30Hz 外发）
```

### 5.4b 现场实测：`lec=3`「无人应答」怎么一层层剥（2026-09-14 第八轮）

**症状**：两板都 `ct 50` → `本板 已收 0 / 已发 100..150`、`tec` 每轮 +16、**`rec=0`、`lec=3`**，
两边「已收」都停在 0 ⇒ **总线上两个节点互相看不见**。
注意这与 UART4 那轮不同：UART4 是「收到字节但 CRC 全错」，这次是**一个字节都没有**。

**为什么 `lec=3` 是硬结论**：CAN 的 ACK 是接收方**在位时间里主动驱显性**。
只要线上有两个活着的节点，ACK 必然出现。`lec=3 + rec=0` 同时成立 ⇒ 发送方在总线上
从来没被第二个节点看见。可能性只剩三类：① 模块没工作；② 线断/接反；③ MCU 引脚没接上。

**新增/增强四条命令（**都不需要对端应答**，专治这个死局）**

| 命令 | 量什么 | 判据 |
|---|---|---|
| `e` | bxCAN 内部回环（不接总线） | PASS ⇒ MCU 侧内核/时钟/过滤器全 OK |
| `cn`（增强） | 追加 `MCR/MSR/ESR/TSR` 原始值 + **`MSR.RX`（CAN1_RX 引脚实时电平）** | `MSR.RX=1` 隐性/空闲 ⇒ 模块在输出高；`=0` ⇒ 总线被拉死 或 模块没供电。另看 `INAK`/`SLEEP`/`BOFF` |
| `cp`（增强） | 探测前先印一次 `MSR.RX` | 同上，且不需要任何接线信息 |
| **`cy [窗口ms]`** | 1ms 采一次 `MSR.RX`，默认 500ms，统计高/低/跳变 | 全高+0 跳变 ⇒ 总线上毫无活动；**有跳变 ⇒ 对面确实在发帧，收侧通路通 ✔** |
| **`cz`** | 发 1 帧的同时微秒级高频采 `MSR.RX` | 发送期间出现显性(低) ⇒ **我方 TX 真的上总线了 ✔**；全程无显性 ⇒ 模块没把信号送上去 |

**一次定位表**

| 现象 | 结论 | 动作 |
|---|---|---|
| `e` FAIL | MCU 侧 bxCAN 内核/时钟有问题 | 查 HSE/PLL、`HAL_CAN_Init` 返回码 |
| `e` PASS | MCU 侧 OK，别再怀疑固件 | 继续往下 |
| `cp` RX `[被外部驱高]` | 模块已上电 且 RXD 线接对了 | 继续 |
| `cp` RX `[悬空]` | **模块没上电** / RXD 没接到该脚 / 该脚没引出 | 查 VCC+GND、跳线电平；或换 `CANPIN=pa` |
| `cp` TX `[驱动级异常]` | 该脚被外部顶住 | 换 `CANPIN=pa` 重烧 |
| `cz` 采到低 | 我方 TX 已上总线 | 故障在对端或收侧 |
| `cz` 全程无低 | 模块没把信号送上去 | 查模块供电 / TXD 接线 / 跳线电平 / 器件型号与供电电压 |
| `cy` 有跳变 | 对面在发帧，**收侧是通的** | 那问题只剩我方发侧 |
| `cy` 恒高 | 总线上毫无活动 | 对面没发 / 线断 / 对面模块没电 |

**⚠ 头号嫌疑**：那块「CAN PHY V1」模块的 `电平选择 5V/3.3V` 跳线。跳线位置必须与 VCC
电压匹配（`TJA1050/SIT1050` 类是 5V 器件；`SN65HVD230/VP230/TJA1051T-3/TJA1042T-3` 类可 3.3V）。
`cp` 的 RX 读数会直接回答"模块到底有没有在工作"。

**⚠ `cy` / `cz` 的前提（2026-09-15 修正 —— 上一版这里写反了）**：
这两条命令都是"看总线电平"，**分不清是谁的帧**，所以"谁在发"必须先定死：

| 在**哪块板**敲 | 前提 | 实际测的是什么 |
|---|---|---|
| **从臂** `cy` | **主臂保持转发 ON**（默认就是 ON，~30 Hz 外发），什么都不用做 | ★ 最有价值：从臂听不听得到主臂的帧 ⇒ 一次判掉**主臂发侧 + 两根总线 + 共地 + 终端** |
| 主臂 `cy` | **必须先 `mf 0` 停发** | 主臂能否听到从臂（从臂平时静默，多半恒高） |
| **从臂** `cz` | **主臂必须先 `mf 0`** | 从臂的 TX 有没有真的变成总线上的显性 |
| 主臂 `cz` | 先 `mf 0`（自己停发才干净） | 主臂的 TX 有没有真的变成总线上的显性 |

### 5.5 UART 路径保留

`LINK` 默认仍是 `uart`，`make` / `make ROLE=master` 行为与以前完全一致；
UART4 的 `ml`/`mg`/`mp`/`mo`/`lk` 诊断命令全部保留，随时可切回来继续查。

## 6. 现场第二轮（2026-09-15）：`e` / `cn` / `cp` 全绿，但仍然 `lec=3`

### 6.1 现场数据（主臂、从臂完全一致）

| 命令 | 两块板的结果 |
|---|---|
| `e` | `RESULT: PASS - CAN controller OK` |
| `cn` | `hw init: ok`，`tec=0 rec=0 lec=0`（复位后干净） |
| `cp` | RX 脚 `内部下拉 -> 11111111`、`内部上拉 -> 11111111` ⇒ **[被外部驱高]**；TX 脚 `推挽低 -> 00000000`、`推挽高 -> 11111111` ⇒ 驱动级正常；`CAN 恢复: ok` |
| `cz` / `cy` | **没跑起来**（被当成单键 `c` 送进了示教校准模式） |

### 6.2 三条硬结论

**① MCU 侧彻底无罪。** `e` 内部回环 PASS + `cp` 的 TX 驱动级自检正常 ⇒ bxCAN 内核、时钟、
位时序（500 k / PS=6 / BS1=11TQ / BS2=2TQ）、引脚 AF 全部就位，固件不必再查。

**② `cp` 的 RX 读数不是弱旁证，是强证据。** 探测时**内部下拉是接通的**（STM32F4 典型 40 kΩ），
它把 3.3 V 分到 `40 kΩ / (40 kΩ + R外)`：

| 外面是什么 | 读数 |
|---|---|
| 什么都没有（悬空） | `00000000` |
| 一颗普通上拉 4.7 kΩ（I²C 那种） | `00000000`（≈0.35 V，读 0） |
| **上电后的收发器 RXD（推挽输出、空闲隐性=高）** | **`11111111`** ← 实测就是这个 |

所以 **PB8 的电学节点上确实挂着一个低阻强驱动源 = 已上电的收发器**。
反过来说，如果 RXD 那根线没接到 PB8，PB8 只剩 40 kΩ 下拉，**必然读 0**。
⇒ **PB8 ↔ 模块 RXD 这根线是通的，而且模块是上了电的。** 这一条已经从"存疑"变成"已验证"。

**③ 你烧的是首版 CAN 固件（`03`/`04` 的第一版），不是 `cz`/`cy` 那一版。** 三条同时成立的证据：

| 现象 | 说明 |
|---|---|
| `cn` 输出里没有 `reg` / `mode` / `state` / `bus pin` 四行 | 新版 `cn` 必有（读 `CAN1->MCR/MSR/ESR/TSR`） |
| `cp` 输出里没有 `bus pin : MSR.RX=` 那行 | 新版 `cp` 必有 |
| `cz` 不被识别，`c` 直接进了示教模式 | 新版固件里 `cy`/`cz` 是注册过的正式命令 |

⇒ 必须重烧，否则 `cy`/`cz` 这两条唯一还能取证的命令用不上。

### 6.3 ★ 当前最大盲区：`cp` 测不到 PB9 → 模块 TXD 这根线

`cp` 的 TX 项做的是**把 MCU 自己的引脚配成推挽输出、再读自己**——走的是 MCU 内部回路，
**跟外面接没接一根线毫无关系**。所以到此为止：

| # | 检查点 | 状态 |
|---|---|---|
| 1 | **PB9 ↔ 模块 TXD** | ❌ **从未验证** ← 头号嫌疑（`cp` 对此完全无感） |
| 2 | PB8 ↔ 模块 RXD | ✅ 已验证通（`cp` 强证据） |
| 3 | 模块 VCC 上电 | ✅ 已验证（`cp` 间接证明） |
| 4 | 模块 GND | ✅ 同上 |
| 5 | **两板 GND 互连（共地）** | ❌ 从未验证 ← **非隔离收发器不共地必然 `lec=3`**，而所有板上命令都在各自板内测，**结构上看不见它** |
| 6 | CANH ↔ 对板 CANH | ❌ 从未验证 |
| 7 | CANL ↔ 对板 CANL | ❌ 从未验证 |
| 8 | 总线两端各 120 Ω | ❌ 从未验证 |
| 9 | 模块 5V/3.3V 跳线 与 VCC 是否一致 | ⚠ 待确认 |

**注意 5 和 1 这两条的性质不同**：`cz`/`cy` 能把 1 测出来，但**永远测不出 5**。
所以万用表那一步不能省。

### 6.5 安全事项（本轮现场夹带的两次误操作）

- `cz` 不是命令 ⇒ 单键 `c` 把控制台带进了**示教 / 校准模式**，之后 `cy 1000`、`mf 0` 的每个字符
  都被该模式当按键吃掉（现场满屏 `Unknown key`）。
  **从臂的最后一段输出停在示教模式里 ⇒ 从臂力矩是松开的**，先敲 `q` 退出（会重新抱闸）。
- 主臂在示教模式里被误打入了 `[ZERO] Home 零点已记录: 2014 896 3106 2331 2022 1567`
  —— 该值**只写进 RAM，没有落盘**（落盘只走 `s`）。所以：**千万不要按 `s`**（按了就会把
  当前姿态永久定成 Home 零点，之后 `sf 1` 跟随会直接猛动）；最干净是**两块板断电重启**。
- 示教模式里高频轮询下的 `[ZERO] Jx read FAILED (offline?)` 是常见现象，先别当成舵机故障。
