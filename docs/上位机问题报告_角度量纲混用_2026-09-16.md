| 项目 | 内容 |
|---|---|
| 提交人 | 刘炜钦（固件 / 整机侧） |
| 日期 | 2026-09-16 |
| 接收方 | 上位机软件工程师 |
| 涉及模块 | 路点表「读取当前角度填充」；IK / FK 互解 |
| 严重级别 | **高** —— 写进路点的数据是错的，而且**界面不报错**，下发后关节跑到完全错误的位置 |

---

## 一、一句话结论

**「读取当前角度填充」把两套不同量纲的角度写进了同一行：**

| 关节 | 软件填进去的 | 量纲判定 |
|---|---|---|
| J1 / J3 / J4 / J5 | 舵机度（0~360，恒为正） | 正确 |
| **J2 / J6** | **关节角 rel-home（相对 Home 零点，可正可负）** | **错误，漏了换算** |

而路点命令 `q n j1..j6` 按协议**只接受舵机度**。
所以 J2、J6 两轴的数据偏差约 **180°**，且界面完全无提示，下发后这两轴会跑到完全相反的方向。

> **不需要看代码就能判定**：舵机度的定义域是 0~360，**永远不可能是负数**。
> 而那两行数据里出现了 `-103.12` 和 `-36.31` —— 这两个数在物理上就不可能是舵机度。

---

## 二、现象

### 2.1 同一姿态，两条路径读数不一致

操作：机械臂停在「折叠收纳位」不动，先用固件串口读取 6 轴角度，再点界面上的「读取当前角度填充」。

| 关节 | ① 固件串口实测 | ② 软件「读取当前角度填充」 | 差异 |
|---|---|---|---|
| J1 | 178.82 | 179.43 | +0.61 |
| **J2** | **76.22** | **−103.12** | **−179.34** |
| J3 | 270.33 | 270.24 | −0.09 |
| J4 | 250.55 | 250.37 | −0.18 |
| J5 | 182.68 | 181.89 | −0.79 |
| **J6** | **140.40** | **−36.31** | **−176.71** |

第二组数据（另一个姿态，编号 2）复现同样的模式：

| 关节 | ① 固件串口实测 | ② 软件读出 | 差异 |
|---|---|---|---|
| J1 | 170.60 | 179.52 | +8.92 |
| **J2** | **146.37** | **−32.53** | **−178.90** |
| J3 | 180.66 | 180.57 | −0.09 |
| J4 | 225.14 | 224.26 | −0.88 |
| J5 | 180.57 | 181.01 | +0.44 |
| **J6** | **176.88** | **−3.08** | **−179.96** |

**规律：J1 / J3 / J4 / J5 两路读数吻合（<1°），J2 / J6 稳定相差约 180°。**

> 注：编号 2 的 J1 有 8.92° 偏差，是因为两次读取**不在同一瞬间**（中途切到串口工具、机械臂有负载回差），
> 属于时刻差，不是结构性问题。编号 1 的证据最干净。
> 如果要更严格的对照，见第五节。

### 2.2 差异不是噪声，而是一整套精确的换算

当前这台臂的折叠收纳位，固件内部记录的**关节角**是：

```text
{ +1.05, −103.65, +90.29, +70.59, +2.64, −39.56 }   (deg, rel-home)
```

固件的换算关系是 `舵机度 = 180 + JOINT_DIR[j] × 关节角`，其中 `JOINT_DIR = [−1, +1, +1, +1, +1, +1]`（**注意 J1 是反向的**）。代入：

| 关节 | 固件关节角 | → 应有舵机度 | ① 串口实测 | 吻合度 | ② 软件读出 | ② 实际是什么 |
|---|---|---|---|---|---|---|
| J1 | +1.05 | **178.95** | 178.82 | 0.13 ✅ | 179.43 | 舵机度 ✅ |
| J2 | −103.65 | **76.35** | 76.22 | 0.13 ✅ | **−103.12** | **关节角 ❌** |
| J3 | +90.29 | **270.29** | 270.33 | 0.04 ✅ | 270.24 | 舵机度 ✅ |
| J4 | +70.59 | **250.59** | 250.55 | 0.04 ✅ | 250.37 | 舵机度 ✅ |
| J5 | +2.64 | **182.64** | 182.68 | 0.04 ✅ | 181.89 | 舵机度 ✅ |
| J6 | −39.56 | **140.44** | 140.40 | 0.04 ✅ | **−36.31** | **关节角 ❌** |

**看到问题了吗：**

- ② 列的 J1 / J3 / J4 / J5 = 换算后的舵机度（179.43 ≈ 178.95、270.24 ≈ 270.29、250.37 ≈ 250.59、181.89 ≈ 182.64）
- ② 列的 J2 / J6 = **没有经过换算的关节角**（−103.12 ≈ −103.65、−36.31 ≈ −39.56）

> **同一行数据里，4 个轴走了「→ 舵机度」的换算，2 个轴直接把关节角填了进去。**

第二组数据同样成立：J2 软件值 −32.53 换算成舵机度应是 147.47，实测 146.37（差 1.10）；J6 软件值 −3.08 换算后应是 176.92，实测 176.88（差 0.04）。

## 三、两个次要可能性（先排除，避免排查跑偏）

1. **不是 XL320 量程残留问题。** 如果是把 4095 的 raw 按 XL320 的 1023 去折算，**6 个轴会一起错**，不会只错 2 个。
   目前已确认 `arm_config.json` 里的 `raw_to_deg_formula` 已是 `raw / 4095 * 360`、`control_mode` 已是 STS3215 语义，这一层是干净的。
2. **不是限位 / 钳制造成的。** 如果只是被限位夹住，数值会停在限位边界（如 89.23 / 249.23 这类整齐值），不会是"恰好等于关节角"。

---

## 四、正确口径（固件侧已确认，以此为准）

### 4.1 两套量纲，各有各的地盘

| 量纲 | 定义域 | 用在哪 |
|---|---|---|
| **舵机度** | 0 ~ 360，恒为正 | 路点 `q n j1..j6`、`a J deg`、`m`、`B`、`q`、`L` 的入参 |
| **关节角（rel-home）** | 可正可负（典型 −180 ~ +180） | **3D 视图 / 姿态显示**、固件内部 IK、`f` / `p` 的 `rel-home` 输出、二进制 `0x13` / `#P` 流 |

> 这与 `05_HOST_APP_REQUIREMENTS` 里 P0-7 第 2 条（3D 视图用关节角驱动）和 P1-6 第 5 条（路点用舵机度）完全一致。

### 4.2 换算公式

```text
舵机度 = SERVO_OFFSET[j] + JOINT_DIR[j] × 关节角
关节角 = JOINT_DIR[j] × (舵机度 − SERVO_OFFSET[j])

JOINT_DIR = [ −1, +1, +1, +1, +1, +1 ]      ← J1 反向，容易漏
SERVO_OFFSET[6]                           ← 每台臂不同，必须运行时读取，禁止硬编码
```

当前这台臂实测 `SERVO_OFFSET ≈ 180`（全轴），但这只是**这一台**的值。

### 4.3 一条命令同时看全三个值（建议直接照抄成 UI 三列）

固件 `p <J>`（`J` = 0~5）会**在一行内同时打印 raw / servo / rel-home**：

```text
  J2: raw=867 servo=76.35 deg  rel-home=-103.65 deg
```

这是唯一权威口径。**建议上位机把这个格式直接做成三列显示**，量纲混用的问题会当场暴露。

### 4.4 关节号的两种约定（另一个高频坑）

| 命令族 | 取值范围 |
|---|---|
| 单轴命令 `t` `a` `r` `p` `z` `w` `L` `M` `T` `O` `E` `U` | **0~5** = J1~J6 |
| PID 命令 `K` `I` `D` `N` `Y` `A g` | **1~6** = J1~J6 |

### 4.5 读取运行时零点（只读、安全）

```text
zi          # 只读打印 calib_zero_raw / SERVO_OFFSET / JOINT_MIN_RAW / JOINT_MAX_RAW
```

⚠ **不要用 `zr` 取这个值** —— `zr` 是**复位** Home 零点（会改写整臂 SERVO_OFFSET），
`zr save` 还会写进 Flash。上位机启动时如需同步零点，只发 `zi`。

## 五、复现步骤（约 5 分钟）

1. 机械臂**上电但不要运动**，停在任意一个姿态。
2. 串口工具连控制台口（115200 8N1），逐轴敲 `p 0` ~ `p 5`，记录每行的 `servo` 和 `rel-home`。
3. 在上位机点「读取当前角度填充」，把 6 个数抄下来。
4. 对照：第 2 步的 `servo` 列应当与上位机读数**逐轴吻合 ≤0.5°**；当前版本 J2、J6 会差约 180°。
5. 再验证换算关系：把第 4 步对不上的轴，用 `180 + JOINT_DIR × (上位机读数)` 反算 —— 如果结果正好等于 `servo` 列，就坐实了"填进去的是关节角"。

## 七、IK / FK 互解不一致（独立问题）

「上位机自己算的 IK/FK 与固件 `f` 的解对不上」——这是**预期内的**，原因有三：

1. **固件的 IK 是「解析解 + CCD 兜底」。** 解析解两个旁解都被限位拒绝时，固件会**静默降级到 CCD**：保住位置、放弃俯仰角，且**不报错**。上位机不可能复刻这条降级路径。
2. **固件 FK 的几何参数与公开资料不同。** 必须用 `sdk_package/model/arm_model.urdf` 或 `link_geometry.json`，**不要**用网上 SO-ARM100 的官方 URDF（差约 5.6mm）。
3. **每台臂的零点不同**，`SERVO_OFFSET` 一变，同一组关节角解出的舵机度就变。

**要求：**

| 编号 | 要求 |
|---|---|
| R6 | **不要在上位机里实现 IK。** 笛卡尔目标直接发 `g x y z [pitch]` / `BG` / `qg`，以固件回显为准 |
| R7 | **FK 一律用固件的**（文本 `f`，或二进制 `0x21` FK_QUERY）来驱动 3D 视图，不要本地重算 |
| R8 | 若必须本地预览，几何参数只能取自 `sdk_package/model/`，且必须用**关节角**驱动 |
| R9 | 运动被拒时把固件回显的原因**原样显示**，不允许静默失败 |

**验收**：固件敲 `f` 得到 `x/y/z/pitch`，与上位机 3D 视图 tooltip 比对，**差值 ≤1mm / ≤1°**。

**如仍有偏差，请回传这三条**（否则无法定位）：

```text
1. 上位机下发的参数：      例如 g 245 213 180 90
2. 固件控制台的原样回显：    （整段复制，含 [RUN] / 警告行）
3. 上位机自己算出的关节角 / 舵机度：
```

## 附：验算脚本（可直接运行）

```python
JOINT_DIR    = [-1, 1, 1, 1, 1, 1]
SERVO_OFFSET = [180.0] * 6           # 本台臂实测值；换臂请用 zi 重新读

def joint_to_servo(joint):
    return [(SERVO_OFFSET[j] + JOINT_DIR[j] * joint[j]) % 360.0 for j in range(6)]

# 折叠收纳位（固件内部关节角）
pose_joint = [1.05, -103.65, 90.29, 70.59, 2.64, -39.56]
print("应有舵机度:", [round(v, 2) for v in joint_to_servo(pose_joint)])
# → [178.95, 76.35, 270.29, 250.59, 182.64, 140.44]

serial_read = [178.82, 76.22, 270.33, 250.55, 182.68, 140.40]   # ① 串口实测（舵机度）
gui_read    = [179.43, -103.12, 270.24, 250.37, 181.89, -36.31] # ② 软件读出
gui_as_servo = joint_to_servo(gui_read)                         # ②「若它其实是关节角」对应的舵机度

print(f"{'轴':<4}{'① 串口实测':>12}{'② 软件读出':>12}"
      f"{'②若按关节角换算':>18}{'判定':>10}")
for j in range(6):
    d = gui_as_servo[j] - serial_read[j]
    verdict = "是关节角 ✗" if abs(d) < 5 else "是舵机度 ✓"
    print(f"J{j+1:<3}{serial_read[j]:>12.2f}{gui_read[j]:>12.2f}"
          f"{gui_as_servo[j]:>18.2f}{verdict:>10}")
```

运行结果：

```text
轴      ① 串口实测  ② 软件读出  ②若按关节角换算      判定
J1          178.82      179.43           0.57   是舵机度 ✓
J2           76.22     -103.12          76.88   是关节角 ✗
J3          270.33      270.24          90.24   是舵机度 ✓
J4          250.55      250.37          70.37   是舵机度 ✓
J5          182.68      181.89           1.89   是舵机度 ✓
J6          140.40      -36.31         143.69   是关节角 ✗
```

**判据**：把软件读出的值**当作关节角**换算成舵机度 ——

- 若换算结果与串口实测吻合（J2 差 0.66、J6 差 3.29）⇒ **它填的确实是关节角**
- 若换算结果与串口实测差约 180（J1 / J3 / J4 / J5）⇒ 它填的本来就是舵机度，无需换算（换算反而错了）

**一行数据、两种量纲，铁证。**
