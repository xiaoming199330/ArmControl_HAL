## 0. 一句话

**串口（USART6）永远常通；CAN 与网口物理互斥，用 `link can|net|off` 选一条，
`link save` 写进 Flash，RESET 后生效。Flash 里没记录时默认「两条都不开」。**

```
link                # 看当前状态（本次生效 / 下次开机 / 是否已落盘）
link can            # 偏好改成 CAN   (仅 RAM)
link net            # 偏好改成网口   (仅 RAM)
link off            # 偏好改成全关   (仅 RAM)
link save           # 落盘 (Flash 扇区 11 区 C)
# 然后按 RESET（或重新上电）—— 只有重启才会真正切换
```

## 1. 为什么必须「二选一」

CAN 从站与网口（RMII）在**引脚层面**就冲突，只有两处，但都是硬冲突：

| 引脚 | 网口（RMII）用途 | CAN 用途 | 结论 |
|---|---|---|---|
| **PB13** | `ETH_TXD1`（AF11） | `CAN2_TX`（AF9） | 同一根脚，AF 只能选一个 |
| **PC4** | `ETH_RMII_RXD0` | 原「绿」LED | 让位给 RMII 后不能当 LED |
| **PC5** | `ETH_RMII_RXD1` | 原「红」LED | 同上 |

而 **串口控制台 `USART6 = PC6/PC7` 与上面任何一个都不冲突** ⇒
**它是唯一的常通通道，也是"切换链路"这个动作唯一可靠的入口**
（两条链路都被关掉时，你只剩串口能说话）。

> 所以这不是"软件上想不想同时开"的问题，而是**硬件上开不出来**。
> 过去只能用编译期宏 `LINK=net|can` 二选一，换链路 = 重新烧固件。
> 本模块把"这次开哪条"降级成**一条 Flash 里持久化的偏好**，开机读它，只初始化被选中的那条。

## 2. 命令用法

控制台（**串口 115200，COM11**）命令；命令结尾发 `\r`。

### 2.1 `link`（无参数）—— 看状态

```
  ===== 链路偏好 (link) =====
  本次生效 : net   (串口恒通)
  下次开机 : can
  配置来源 : Flash 记录(扇区11 区C)
  待生效   : **有未保存的改动** -> 用 `link save`
  串口     : USART6 PC6/PC7 @115200 -- **永远常通**,
             与 CAN/网口都不冲突, 是切换链路唯一可靠的通道
  物理约束 : CAN 与网口**互斥**(共用脚):
             PB13 = ETH_TXD1, 同时 = CAN2_TX
             PC4/PC5 = ETH_RMII_RXD0/RXD1, 同时 = 原绿/红 LED
  用法     : `link can|net|off` 改偏好 -> `link save` 落盘 -> RESET 生效
  ============================
```

⭐ **「本次生效」与「下次开机」是两个不同的东西**，别混：
- `本次生效` = **本次启动实际初始化**的那条（启动时从 Flash 读出后就**冻结**，运行期永不改变）；
- `下次开机` = Flash 里的偏好（或 RAM 里还没落盘的改动）。

### 2.2 `link <mode>` —— 改偏好（只写 RAM）

```
link can     # 或 link 1
link net     # 或 link eth / link udp / link 2
link off     # 或 link none / link 0
```

回显会明确告诉你两件事，避免产生"已经切过去了"的假象：

```
  [LINK] 偏好已改为 can (仅 RAM, **未落盘**, 也**不会立即生效**)。
         引脚 AF 与外设是启动时一次配好的, 运行期挪不动。
         执行 `link save` 落盘, 再 RESET 重启才生效。
```

### 2.3 `link save` —— 落盘

```
  [LINK] 写入 Flash(扇区 11 区 C; 保区写入, 不动 PID/CAN 两区) ...
  [LINK] 已保存: can
  ⚠ **下次开机生效** -- 现在按 RESET(或重新上电)。
```

⚠ **阻塞**：整扇区擦除典型 ~1 s 量级。只在控制台命令上下文调用，不要在流模式/自动运行时敲。

### 2.4 别名与容错

| 输入 | 解析为 |
|---|---|
| `off` / `none` / `0` | 全关 |
| `can` / `1` | CAN |
| `net` / `eth` / `udp` / `2` | 网口 |

无法识别的参数会明确报错，不会静默当成功。
⚠ 注意 `link` 与已有的 **`lk`（主从链路诊断，完全不同的一条命令）** 是两个命令；
控制台对等宽字体有容错（`1k`/`ik` → `lk`），所以 `link` 的分发必须**排在 `lk` 之前**匹配。

## 3. 生效时序（**不做热切换**）

```
link can  →  link save  →  RESET  →  开 CAN（网口消失）
                    ↑
              这一步之前，一切照旧跑原来的链路
```

**为什么必须重启**：`PB13` 的 AF11(RMII) / AF9(CAN2)、`PC4/PC5` 的 AF 与 GPIO 模式，
都是**启动时一次性配好**的（`MX_GPIO_Init()` / 外设 `HAL_*_Init()`）。
运行期改一个变量**挪不动**已经写进寄存器的 AF 与模式位。
强行做"热切换"意味着运行期重配引脚 AF + 关停/重启 MAC + 重配 USB-CAN 过滤器，
失败面远大于收益，且失败后果是"两条都不通"。**所以第一版故意只做"写偏好 + 提示重启"。**

> 这与已有的 `cx 1|2`（CAN 接口 CAN1/CAN2 运行期切换）**不是一回事**：
> `cx` 只换过滤器与外设实例，不涉及引脚 AF 冲突；`link` 换的是**物理层**。

## 4. Flash 持久化布局

链路偏好落在 **Flash 扇区 11** 的 **区 C**，与既有两个配置区并存：

| 区 | 偏移（相对扇区基址 `0x080E0000`） | 绝对地址 | 内容 | 归属模块 |
|---|---|---|---|---|
| A | `0x0000` | `0x080E0000` | PID / 标定 | `pid_flash.c` |
| B | `0x1000` | `0x080E1000` | CAN 节点/波特率/心跳/接口 | `arm_can_config.c` |
| **C** | **`0x2000`** | **`0x080E2000`** | **链路偏好** | **`arm_link_cfg.c`** |

- 每区跨度 `0x1000`（4 KB），扇区总计 128 KB；`teach_store` 占 S7~S10，S11 由这三区独占。
- **扇区只能整片擦除**，所以多区共存靠「**搬其余区 → 擦 → 回写 → 写本区 → 双向校验**」的保区写入实现
  （`flash_cfg.c` 已从原来的"两区互保"泛化为**多区互保**；保区缓冲由 4 KB 扩到 **8 KB**）。
- 空白区（全 `0xFF`）会被**跳过**搬移/回写，省掉 1024 次字编程。
- 记录格式（20 字节，远小于 4 KB 跨度）：

```
偏移  字段      长度   说明
 0    magic      4    "LNK1" = 0x4C4E4B31；未写过时读出 0xFFFFFFFF
 4    version    2    当前 = 1
 6    len        2    = sizeof(ArmLinkCfg) = 2
 8    cfg.mode   1    LINK_MODE_OFF=0 / CAN=1 / NET=2
 9    cfg.rsv    1    保留
10    crc        4    CRC-32 (poly 0xEDB88320, 反射)，范围 = crc 之前全部字节
                     （与 pid_flash.c / arm_can_config.c 同一算法）
```

⚠ **禁止整区擦除扇区 11**（会连带抹掉 PID 标定与 CAN 配置）—— 一律走 `flash_cfg.c` 的保区写入。

## 5. 默认语义 = **全关**（2026-09-22 定）

| 情形 | 结果 |
|---|---|
| Flash 从未写过（`magic = 0xFFFFFFFF`） | **全关**（两条都不启用） |
| 整片擦除后 | **全关** |
| `version` 不匹配 / `CRC` 校验失败 | **全关** |
| `mode` 字段越界（不在 0/1/2） | **全关** |
| 参数非法 / 扇区读失败 | **全关** |

**为什么默认全关而不是"默认网口"**：上电默认不暴露任何网络口/总线口，
要开必须**由人显式**敲 `link can|net` + `link save`。
这是"**我没开 ≠ 它是关的**"（红线 66）的同源推论 ——
**默认值必须等于硬件实况**：一个从未被写过的配置区，它的实况就是"没人配过"，
不能替用户猜一条链路出来，否则等于"我以为我没开，其实它开着"。

全关时启动打印：

```
  [LINK] 两条链路均未启用(默认全关) —— 只留串口控制台。
         开 CAN : `link can` -> `link save` -> RESET 重启
         开网口 : `link net` -> `link save` -> RESET 重启
         (二者物理互斥: PB13 与 PC4/PC5 是共用脚, 只能二选一)
```

## 6. 构建

```bash
# 新：单固件，运行期二选一
PATH="/c/STM32Tools/arm-gcc-full/bin:/c/STM32Tools/make:$PATH" make -j4 LINK=both

# 旧：编译期定死的单链路固件，全部保留、行为不变
make -j4 LINK=net      # 与改动前逐字节同构（除下面那点 bss）
make -j4 LINK=can
make -j4 LINK=uart     # 主从链路，无 CAN 无网口
```

`LINK=both` 的宏：`-DARM_LINK_NET=1 -DARM_LINK_CAN=1 -DARM_LINK_MULTI=1`。

### 6.1 实测资源（`arm-none-eabi-size`，Berkeley）

| 构建 | text | data | bss | Flash = text+data |
|---|---|---|---|---|
| **both**（新） | 237,624 | 1,036 | **77,972** | **238,660** |
| net | 233,064 | 1,036 | 77,884 | 234,100 |
| can | 207,936 | 1,032 | 63,136 | 208,968 |

⇒ **both 只比 net 多 4,560 B Flash / 88 B RAM**。
原因：两条链路的源文件（`arm_net.c` / `arm_can.c` 系列）**本来就在 `C_SOURCES` 里无条件编译**，
`LINK=` 宏只决定"哪一段被调用"，不是"哪一份被编进去" ⇒ both ≠ 两份固件相加。

### 6.2 旧构建的 bss 变化（必须能解释，否则有隐藏增长）

三种旧构建都多出 **+4,108 B bss / +608 B Flash**（`LINK=can`：63,136 vs 原 61,596 附近）。
全部来自 `flash_cfg.c` 的保区缓冲 **4 KB → 8 KB**（`CFG_REGION_COUNT` 2 → 3），
再加 `arm_link_cfg.c` 自身十几个字节的静态量。**无隐藏增长。**
⚠ 跨构建比大小时**必须统一 `size` 的格式**（`-A` 与 Berkeley 的分类不同），
否则会得出"bss 涨了 5.6 KB"这种假结论（本工程踩过）。

## 7. 安全设计（三条铁律）

### 7.1 运行期判定**必须锚定"本次启动生效值"**

`LinkCfg_Get()` 返回的是**偏好**；运行期的一切判定（LED 去留 / 主循环轮询哪条 / 命令拦截）
**只能用 `LinkCfg_ActiveMode()`**（启动时冻结）。

**反例（如果不这么做会怎样）**：用户敲 `link can` 只改偏好，如果主循环按偏好判定，
就会立刻：
1. **停止 `NetProto_Poll()`** ⇒ 正在跑的网口**当场停摆**；
2. 转而 `CanProto_Poll()` / `CanProto_Service()` ⇒ 访问**这次启动压根没初始化**的 CAN 外设。

**访问一个未使能的外设比"它不工作"更糟**（可能读野地址、抢总线、配置寄存器写入被静默丢弃）。
⇒ 偏好可以随时改，**生效值不会因为敲命令而变**。这条已写入红线 69。

### 7.2 没选中的那条**一次都不能 poll**

`NetProto_Poll()` 会驱动 PHY 状态机并操作 MAC **描述符**；`CanProto_Poll()` 会读 CAN 寄存器。
两者在 OFF / 另一条模式下外设都没初始化 ⇒ **OFF 时两条都不碰，只留串口。**

### 7.3 没开的功能**不能读自己的结构体当证据**

- both 构建下、当前链路不是网口时敲 `nx` ⇒ **明确拒绝**，而不是打出一张"看起来正常
  其实是未初始化内存"的状态表（这是"宁可不工作，也不骗人"，同红线 66）。
- `gpio.c` 里 PC4/PC5 是配成 LED 还是整段让位给 RMII，由**同一次启动的生效值**决定。

## 8. 上板验证清单

烧 `LINK=both` 后，**一步不过不跳下一步**：

| # | 操作 | 期望 |
|---|---|---|
| 1 | 烧录后敲 `h` | 首行 `fw-tag ARM-BOTH-0922A  build=LINK=both  usart6=console(always-on)`，且带 `link active=… pref=…` 与 `fix=both-link,link-cfg-flash,multizone-guard,pc45-runmode,led-runmode` |
| 2 | `link` | `本次生效` = `off`（**首次烧录应为全关**，因为 Flash 区 C 还没写过） |
| 3 | `link net` → `link` | `下次开机 : net`、`待生效 : **有未保存的改动**` |
| 4 | `link save` → `link` | `待生效 : 无改动`、`配置来源 : Flash 记录` |
| 5 | **RESET** → `h` | `link active=net  pref=net`；**`ping 192.168.7.120` 4/4 回** |
| 6 | `link can` → `link save` → RESET | `link active=can`；CAN 侧上位机（PCAN-USB 500k）能收到心跳/应答 |
| 7 | `link off` → `link save` → RESET | `link active=off`；网口不通、CAN 无应答、**串口一切照常** |
| 8 | 断电再上电 | 保持第 7 步的选择（**持久化生效**） |

⚠ 烧录/复位会**丢力矩、臂下沉**（两次实测 J2≈76.4°、J3≈270.9°，距限位只剩 1.3°/0.1°）
⇒ 上运动测试前先回中位 `m 180 180 180 180 180 180 15`；
**绝不能用 `M a`**（那是 `cmdCenterCalib()` 标定，会废掉量纲基准）。

## 9. 已知缺口 / 边界

| 项 | 说明 |
|---|---|
| 不支持热切换 | 只能"写偏好 + RESET"。见 §3 |
| 单链路固件上敲 `link` | 会明确回「本固件是**单链路构建**，不支持运行期切换…要能切换请烧 `LINK=both`」，**不会静默无操作** |
| `link` 与串口常通的关系 | `link off` **不影响串口**，串口是唯一恒通通道 |
| both 固件下 `cx`/`ps`/`can`/`cp`/… | 当生效链路是**网口**时，这些命令被拦截（它们会掐网口 / REF_CLK），提示改用 `link can` |
| 上级脚本兼容 | `h` 首行指纹变了（`ARM-BOTH-0922A`）⇒ 依赖"指纹精确匹配"的脚本需更新；`ARM-NET-0921A` 之后的指纹判据继续有效 |
| 未验证 | 本文档基于**编译通过 + 代码级核对**；**上板验证（§8）尚未执行**（板子当前仍跑 `ARM-NET-0921A`，需切 BOOT0 才能烧） |

## 10. 常见问题

| 现象 | 原因 / 怎么查 |
|---|---|
| 敲了 `link net` 但网口还是不通 | ①忘了 `link save`；②忘了 RESET；③先看 `link` 的「本次生效」是不是还是 `off` |
| `h` 看不到 `link active=` 行 | 烧的不是 `LINK=both` 固件（旧构建里 `cmdLink()` 走 `#else` 分支，只说"单链路构建不支持切换"） |
| 网口在跑，敲 `link can` 后网口就断了？ | **不应该发生**（运行期判定用 `LinkCfg_ActiveMode()`，见 §7.1）。若真发生 ⇒ 记录现象，说明有判定点漏改 |
| 网口敲 `nx` 报「当前链路不是网口」 | 正常且**是刻意的**（§7.3）。先 `link net` + `save` + RESET |
| `link save` 之后 PID 标定丢了？ | 不该发生（保区写入）。**若发生 = 保区逻辑 bug**，立即停止烧写并保留现场 |
