## 1. 物理层与 CAN ID 分配

| 项目 | 值 |
|---|---|
| 波特率 | **500 kbit/s**（可配 50~1000，出厂默认 500） |
| 帧类型 | **标准帧（11 位 ID）**，数据帧，DLC 按需（**不补足 8**） |
| 节点号 | 1~15，出厂默认 **1** |
| 采样点 | 固件默认 bxCAN 配置（约 75%），与常规 PCAN 默认一致 |

| ID 段 | 方向 | 用途 |
|---|---|---|
| `0x100 + node` | **上位机 → 臂** | 命令（带分包） |
| `0x180 + node` | **臂 → 上位机** | 命令响应（带分包） |
| `0x280 + node` | **臂 → 上位机** | 周期状态帧 + 异步事件帧（**不分包**，固定 8 字节） |

node=1 时即：命令 `0x101`、响应 `0x181`、状态/事件 `0x281`。

## 2. 分包帧格式（0x100/0x180 段）

一条"逻辑帧" = `SEQ(1) + CMD(1) + LEN(1) + PAYLOAD(LEN) + CRC16(2, 小端)`，
总长超过单帧数据场时按下面规则切分：

**首帧**（DLC ≤ 8）：

```
字节0: 0x80 | 总帧数N        （例：N=3 → 0x83；N=1 → 0x81）
字节1: SEQ                    命令序号，同一条命令的所有帧相同
字节2: CMD                    命令码
字节3: LEN                    整条命令的 PAYLOAD 长度
字节4~7: PAYLOAD 的前 0~4 字节（有多少装多少，装不下进续帧）
```

**续帧**（每帧最多装 7 字节，DLC = 1 + 实际字节数）：

```
字节0: 帧号 1,2,3,…（续帧索引，从 1 开始）
字节1~7: 逻辑帧流的后续字节（PAYLOAD 余下部分 + CRC16 两字节）
```

**分帧公式**（与固件同一份代码）：`尾段总长 = LEN + 2`；首帧装 `min(尾段总长, 4)` 字节；
剩余按每帧 7 字节切。**LEN=0~4 ⇒ 单帧；LEN=5~18 ⇒ 2~3 帧；以此类推。**

**CRC16 算法**（覆盖 `SEQ+CMD+LEN+PAYLOAD`，**不含**首帧的帧数头）：

```
CRC16-CCITT:  初值 0xFFFF，多项式 0x1021，无反射，无异或输出
```

### 上位机接收响应的格式

响应与命令**同构**：首帧 `0x80|N, SEQ, CMD|0x80, LEN`（响应码 = 请求码 | 0x80，
例 PING→0x81、GET_STATUS→0x82、FK_QUERY→0xA1、PARAM_READ→0xC0、PARAM_COUNT→0xC2），
续帧同上。控制类命令的响应是 ACK/NACK：

```
ACK: CMD=0x7F, PAYLOAD = {原命令码, 0x00}
NACK: CMD=0x7E, PAYLOAD = {原命令码, 错误码}     （错误码见 §6）
```

## 4. 各命令 PAYLOAD 字段定义（全部小端）

单位约定：**角度 ×10**（int16，0.1° 分辨率）、**毫米 ×10**（int16）、
**速度/加速度 ×10**（u16，deg/s 与 deg/s²）、**参数值 ×1000**（i32）。

### 4.1 PING（0x01）→ 0x81
请求无负载。响应 2 字节：`{协议版本 0x01, run_id}`（run_id 每次上电随机，可当"这次开机"的会话标识）。

### 4.2 GET_STATUS（0x02）→ 0x82，21 字节

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0~11 | 6×int16 | J1~J6 角度（×10） |
| 12 | int16 | X（mm ×10） |
| 14 | int16 | Y（mm ×10） |
| 16 | int16 | Z（mm ×10） |
| 18 | int16 | Pitch（deg ×10） |
| 20 | u8 位域 | bit0=急停激活 bit1=轨迹执行中 bit2=修正中 bit3=读角成功(read_ok) |

⚠ **读数无效哨兵**：某关节读不到时该 int16 = **-32768（0x8000）**，上位机必须识别而不是当角度用。

### 4.3 LOG_SET_LEVEL（0x03），1 字节
`{level}`：0=NONE 1=ERROR 2=WARN 3=INFO 4=DEBUG（>4 按 4 处理）。

### 4.4 MOVE_JOINTS（0x10），16 字节 —— **最常用**

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0,2,4,6,8,10 | 6×int16 | J1~J6 目标角度（×10），单位**舵机度**（0~360 全圈量纲，与 `GET_STATUS` 同一量纲） |
| 12 | u16 | 最大速度 deg/s ×10（0 = 用臂内默认 `sc.def_vmax` = **25.0**，可经参数 #17 改） |
| 14 | u16 | 加速度 deg/s² ×10（0 = 用 `v × sc.accel_factor`，默认 factor=2.0） |

⚠ 目标角超限时**静默钳制**（按校准 raw 限位），**不回错**；未校零时限位为空 ⇒ **不拦**。
⚠ 读起点失败时轨迹不启动，但**仍回 ACK err=0**。⇒ 判"动没动"必须用 `GET_STATUS` 看角度。

### 4.5 STOP（0x11）
无负载。立即停止轨迹（平滑减速）。

### 4.6 SET_TORQUE（0x12），2 字节
`{joint, enable}`：joint=0~5 单关节、**0xFF=全部六关节**；enable 0/1。
注意：MOVE/CART 会自动上力矩；但**它们不会自动下力矩**——需要松臂时显式发本命令。

### 4.7 STREAM_JOINTS（0x13），12 字节
`6×int16 逻辑角(×10)`。实时流跟随模式（遥操跟随）：**建议 20~50 Hz 连续发送**；
**断流 500 ms 后臂自动退出流模式**（看门狗 `STREAM_TIMEOUT_MS`），臂保持当前位置自锁。
⚠ 这里是**逻辑角**（相对本臂 Home，带符号），**不是** `GET_STATUS` 的舵机度，两者差一次
`SERVO_OFFSET/JOINT_DIR` 变换。
⚠ 单帧单轴跳变 > 25°（`STREAM_MAX_JUMP_DEG`）或落点不安全 ⇒ **整帧丢弃**，回 NACK err=4。
⚠ 逐轴超限是**静默钳制**（整帧照发、不回错）。
流模式与轨迹互斥：任何轨迹命令会先退出流模式。

### 4.8 MOVE_CART（0x20），12 字节

| 偏移 | 类型 | 含义 |
|---|---|---|
| 0,2,4 | 3×int16 | X/Y/Z（mm ×10） |
| 6 | int16 | Pitch（deg ×10） |
| 8 | u16 | 速度 deg/s ×10（0=默认） |
| 10 | u16 | 加速度 ×10（0=默认） |

IK 不可达回 NACK err=3(UNREACH)；运动后固件自动做 FK 验证，超差回 err=6(FK_VERIFY)。

### 4.9 FK_QUERY（0x21）→ 0xA1，21 字节
`{X,Y,Z,Pitch(各int16×10), J1~J6(6×int16×10), read_ok(u8)}`——**响应里先位姿后关节**，与 GET_STATUS 顺序不同，别搞混。

### 4.10 SET_GRAVITY（0x30），2 字节
`{int16 K}`，K = 系数 ×1000（单位 deg/mm，范围 0~0.5，默认 0）。写的是参数表 #32。

### 4.11 SET_CORRECTION（0x31），4 字节
`{u8 enable, u16 threshold(deg×100), u8 max_rounds}`（例：1, 2.00°, 10 轮）。

### 4.12 PARAM_READ（0x40，1 字节 `{id}`）→ 0xC0（5 字节 `{id, int32 val×1000}`）
### 4.13 PARAM_WRITE（0x41，5 字节 `{id, int32 val×1000}`）→ ACK/NACK
### 4.14 PARAM_COUNT（0x42）→ 0xC2（1 字节 `{count}`，现役 24）

## 5. 状态帧与事件帧（0x280+node，固定 8 字节，不分包）

### 5.1 周期状态帧（默认 1 Hz，`can hb` 可设 0~60000 ms）

| 偏移 | 含义 |
|---|---|
| 0 | 固定 `'S'`(0x53) = 状态帧 |
| 1 | node id |
| 2 | flags 位域：0x01 急停 / 0x02 轨迹执行中 / 0x04 流模式 / 0x08 修正中 / 0x10 示教录制 / 0x20 示教回放 / **0x40 CAN 硬件正常** / 0x80 协议就绪 |
| 3 | 最近一次命令错误码（见 §6） |
| 4~5 | 已执行命令计数（u16 小端）——**看它是否在推进** |
| 6~7 | 运行秒数 u16（约 18 h 回绕） |

⚠ **首帧状态帧的解锁条件**：臂上电后**收到第一条合法命令**才开始发状态帧——上电后先发一条 PING。

### 5.2 异步事件帧

| 偏移 | 含义 |
|---|---|
| 0 | 固定 `'E'`(0x45) = 事件帧 |
| 1 | node id |
| 2 | 事件码：1=急停触发 2=**轨迹结束**(d[3]: 1 正常/0 中止) 3=流模式退出 4=示教缓冲满 5=配置已落盘 |
| 3 | 事件参数 |
| 4~7 | 事件时刻 HAL_GetTick()（ms，u32 小端） |

上位机应当**以状态帧为主时钟源、以 TRAJ_DONE 事件确认运动完成**，不要靠轮询 GET_STATUS（每轮要读 6 轴舵机总线，是重操作）。

## 6. 错误码（ACK/NACK 第二字节、状态帧 d[3]）

| 值 | 名称 | 含义 |
|---|---|---|
| 0 | OK | 成功 |
| 1 | PARAM | 参数非法（长度/范围/未知 ID/未知命令） |
| 2 | CRC | 逻辑帧 CRC 校验失败 |
| 3 | UNREACH | IK 不可达 |
| 4 | LIMIT | 超关节限位 |
| 5 | ESTOP | 急停激活，命令被拒 |
| 6 | FK_VERIFY | 运动后 FK 验证超差 |
| 7 | READ | 舵机读角失败 |

## 7. 参数表 ID 速查（PARAM_READ/WRITE 用）
> ⚠ **写超范围不会回 NACK** —— `ArmParams_Set` 是"钳制后返回成功"，应答仍是 `err=0`
> （只有 **ID 不存在** 才回 NACK PARAM）。⇒ **写完必须 `PARAM_READ` 回读确认**。
> （2026-09-21 与 `arm_params.c` 逐行核对后修正，原表述"写超范围回 NACK PARAM"有误。）
> `AP_PARAM_COUNT = 46` 是**表长哨兵，不是参数**，读写它回 NACK。

| ID | 参数 | 范围（默认） |
|---|---|---|
| 1 | IK 收敛阈值 mm | 0.1~5.0 (0.5) |
| 2 | IK 最大迭代 | 10~500 (100) |
| 3 | IK 失败阈值 mm | 0.5~10.0 (1.0) |
| 4 | FK 验证容差 mm | 1.0~20.0 (5.0) |
| 16 | S 曲线 jerk 过渡 s | 0.02~0.50 (0.15) |
| 17 | 默认速度 deg/s | 5~300 (**25**) |
| 18 | 默认加速度 deg/s² | 10~600 (**80**) |
| 19 / 20 | 速度下限/上限 | 1~50 (5) / 50~300 (300) |
| 21 | 加速度因子 | 1.0~4.0 (2.0) |
| 32 | J2 重力前馈 K | 0~0.5 (0) |
| 33~35 | 修正开关/阈值/轮数 | (1) / 0.5~10 (2.0) / 1~20 (10) |
| 36~41 | J1~J6 修正增益 | 0~0.85（0.20/0.50/0.30/0.20/0.20/0.20） |
| 42/43 | 收尾段速度/占比 | (30) / 0~0.25 (0.05) |

## 8. 现成帧字节示例（node=1，已含 CRC，可直接在 PCAN-View 里手敲）

PCAN-View 填法：Transmit → New Transmit Message，**ID 填 `101`（hex 框）**，Length/Data 按表；
Message Type **四个框全不勾**（标准帧）；Cycle Time = 0。一条命令的多帧**按顺序逐条发**。

| 命令 | 帧（Len 与 Data） |
|---|---|
| PING (seq=01) | Len=6: `81 01 01 00 9D C8` |
| GET_STATUS (seq=02) | Len=6: `81 02 02 00 9E C4` |
| LOG_SET_LEVEL 3 (seq=03) | Len=7: `81 03 03 01 03 1E 45` |
| MOVE_JOINTS J1=182.3 其余保持 v=10 (seq=04) | Len=8: `83 04 10 10 1F 07 00 03` ｜ Len=8: `01 93 0A C7 09 21 07 BF` ｜ Len=8: `02 05 64 00 00 00 DD 83` |
| STOP (seq=05) | Len=6: `81 05 11 00 2E 17` |
| SET_TORQUE 全部上电 (seq=06) | Len=8: `81 06 12 02 FF 01 F8 57` |
| STREAM_JOINTS 六轴给定值 (seq=07) | Len=8: `83 07 13 0C 01 07 00 03` ｜ Len=8: `01 93 0A C7 09 21 07 BF` ｜ Len=4: `02 05 84 CB` |
| MOVE_CART 140.5,1.5,17.4,145.7 v=10 (seq=08) | Len=8: `83 08 20 0C 7D 05 0F 00` ｜ Len=8: `01 AE 00 B1 05 64 00 00` ｜ Len=4: `02 00 38 A2` |
| FK_QUERY (seq=09) | Len=6: `81 09 21 00 DA 67` |
| SET_GRAVITY K=0.1 (seq=0A) | Len=8: `81 0A 30 02 64 00 C5 D2` |
| SET_CORRECTION 开,2.0°,10轮 (seq=0B) | Len=8: `82 0B 31 04 01 C8 00 0A` ｜ Len=3: `01 63 01` |
| PARAM_READ #17 (seq=0C) | Len=7: `81 0C 40 01 11 7E E7` |
| PARAM_WRITE #17=30.000 (seq=0D) | Len=8: `82 0D 41 05 11 30 75 00` ｜ Len=4: `01 00 CC F0` |
| PARAM_COUNT (seq=0E) | Len=6: `81 0E 42 00 33 BC` |

⚠ **换目标角度 / 换 SEQ ⇒ CRC 全变 ⇒ 必须重新生成**，不能在表上手改字节。
生成工具：`python tools/can_forge.py --move J1..J6 --speed 10`（与上位机同一编码函数）。

## 9. 注意事项（按踩过的坑排的，**逐条都真实发生过**）

### 9.1 协议层
1. **多字节字段一律小端**（int16/u16/int32 都是低字节在前）。
2. **续帧可能乱序到达**（bxCAN 3 个发送邮箱的硬件行为，4 帧回包实测顺序 F1,F4,F2,F3）。
   上位机重组器**必须按帧号缓冲、收齐再拼**，不能要求严格递增。
   （固件 `0918F` 起发送侧已保证按序，但接收侧仍不应做该假设。）
3. **每条新命令 SEQ 递增**。臂侧重组器以 SEQ 区分新包；同 SEQ 重发按"重试"处理。
4. **DLC 不补 8**：按实际字节数填 Length。PCAN-View 手发时 Length 必须逐帧照表。
5. 响应超时建议 ≥ **200 ms**（多帧回包 + 6 轴读角时间）。
6. **不要向 0x180+node 发数据**——那是臂的发送通道，发进去会污染重组状态。

### 9.2 运动安全
7. MOVE/CART **自动上全部力矩**，第一次动臂会有上电声，属正常。
8. 角度目标是**绝对目标**（舵机度 0~300，不是增量）。先 GET_STATUS 拿当前值，第一次试动每关节只给"当前值 ±3°"、速度 10°/s。
9. **急停（E-Stop）激活时一切运动命令被拒**（NACK err=5），先解除急停。
10. **主臂角色默认只读**（防误发把被人扶着的主臂甩起来）；要在主臂上运动须先在其串口敲 `ma 1`。从臂无此限制。
11. 超限位回 NACK err=4，不会硬闯；IK 不可达回 err=3。
12. STREAM_JOINTS 是**直写模式**（无 S 曲线规划），必须从小角度、低频率起步，且与轨迹模式互斥。

### 9.3 链路层（CAN 特有）
13. **"卡一关，臂就自锁"的机理与自愈**：上位机程序退出后总线上无人 ACK，臂每发一帧 TEC+8，约 16 s 后进入 error-passive，状态帧降为**每 500 ms 探一帧**（0918G/H）。上位机**重新打开卡后 1~4 s 内自动恢复** 1 Hz。**这不是故障**；旧固件 ≤0918F 则是永久锁死，需臂侧人工恢复。
14. **验证链路是否正常**的最快方法：发 PING → 收 0x81；收不到就看臂侧 `cn` 的 `tec`。
15. **上电后先发一条 PING**，否则状态帧不发（§5.1 的解锁条件）。
16. **不要用"PCAN 卡报不报总线错"判链路好坏**（它不敏感）；也不要用示波器瞬时采 RX 脚。判据只用臂侧计数器（串口 `cn`/`can` 命令）或状态帧 d[4~5] 的命令计数是否推进。

### 9.4 固件版本 / 配置
17. **判手里固件是哪版**：串口控制台敲 `h`，首行 `fw-tag ARM-CAN-0918H …`。
    `fix=` 字段：`cprint-overread`（上电死机修复）、`frameseq`（按序发送）、`tec-latch`（TEC 自锁自愈）、`defcan2`（开机默认 CAN2）。
18. **烧录固件 = 整片擦除**：CAN 配置区一并被抹。`0918H` 起开机默认 **CAN2**（本板卡的卡插在 CAN2 口），无需配置；`≤0918G` 烧完必须先在臂侧串口敲 `cx 2`，否则"指纹对、就是不通信"。
19. `cx save` / `can save` 只跨复位，跨不了重烧。
