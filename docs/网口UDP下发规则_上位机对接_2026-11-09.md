# 网口(UDP) 下发协议规则 — 上位机对接完整规范（2026-11-09）

> 适用固件：**ARM-BOTH-0924CC**（`LINK=both`，net+can 双链路均编入；纯 net 构建为 `ARM-NET-*`）
> 真值来源：`Core/Inc/arm_net.h`（承载定义）、`Core/Src/arm_net.c`（实现）、
> `Core/Inc/arm_control_protocol.h`（命令码）。
> **结论先行：是 UDP。板子没有 TCP**（固件是手写极简栈：ARP/IPv4/ICMP/UDP 四个头，
> 静态 IP + 单端口，~500 行）。一包一报文，**没有分包、没有流重组**，比 CAN 承载还简单。

---

## 1. 网络参数（编译期固定，`arm_net.c:34-36`）

| 项目 | 值 |
|---|---|
| 传输层 | **UDP**（无 TCP、无 HTTP；HTTP 仅 PC 侧边车 `armctl http-bridge` 可选） |
| 臂的 IP | **192.168.7.120**（静态，写死在固件） |
| 臂的端口 | **5000**（`NET_UDP_PORT`） |
| 臂的 MAC | `02:4E:45:54:00:01`（本地管理地址） |

PC 侧网卡请配同网段静态 IP，如 `192.168.7.1 / 255.255.255.0`。

## 2. 报文格式（一包一报文，无分包）

```
UDP 数据报 payload = 逻辑包 [SEQ, CMD, LEN, PAYLOAD..., CRC16-LE]

  SEQ     u8   请求序号（响应回显同值，用于请求-应答配对）
  CMD     u1   命令码（见 §4，与 CAN 完全相同）
  LEN     u8   PAYLOAD 长度，上限 64
  PAYLOAD …    定点编码负载（见 §5）
  CRC16   u8×2 小端；CRC-16/CCITT-FALSE(poly 0x1021, init 0xFFFF, 非反射)
               计算范围 = 前 3+LEN 字节（SEQ..PAYLOAD）
```

**硬性校验（固件 `handle_cmd`，arm_net.c:297-326）：**
- 数据报总长必须**精确等于** `5 + LEN`，不等直接静默丢弃（不回包）
- `LEN > 64` 无效（协议上限 APROTO_MAX_PAYLOAD=64）
- CRC 错 → 回 **NACK(0x7E)**，payload = `{orig_cmd, 2(ERR_CRC)}`
- 一个数据报**只能装一条命令**；连发两条不会被拆分执行
- **没有 0xAA 0x55 帧头**（那是串口帧的；UDP 直接裸逻辑包）

## 3. 应答规则（回源）

| 项 | 规则 |
|---|---|
| 回包地址 | **回源**：目的 MAC/IP/端口 = 请求方的 MAC/IP/端口（`udp_send(srcmac, srcip, sport, …)`） |
| 回包格式 | 同构逻辑包 `[SEQ, CMD, LEN, PAYLOAD, CRC16-LE]`，SEQ=请求 SEQ |
| 应答 CMD | 查询类 = 请求 CMD \| 0x80（0x02→0x82）；控制成功 = **0x7F ACK** `{orig_cmd, 0}`；失败 = **0x7E NACK** `{orig_cmd, 错误码}` |
| UDP 校验和 | 固件发 0（IPv4 UDP 合法），PC 侧不必校验 |
| 错误码 | 0~10，与 CAN 完全一致（OK/PARAM/CRC/UNREACH/LIMIT/ESTOP/FK_VERIFY/READ/MAGIC/BUSY/NOTCAL） |

**没有 0x280 等价物**：UDP 上没有周期状态帧/事件帧（那是 CAN 独有的主动推送通道）。
上位机要状态就轮询 GET_STATUS(0x02) / GET_FLAGS(0x0A)；轨迹完成判定轮询 0x82 flags bit1（轨迹中）变 0。

## 4. 命令码 — 35 条，与 CAN 逐字一致（直接复用 CAN 文档）

命令码、payload 编码、应答布局、错误码**与 CAN 完全相同**，详见
`docs/CAN下发协议规则_上位机对接_2026-11-09.md` §4~§8，此处只列目录：

| 组 | 命令 |
|---|---|
| 系统 | 0x01 PING, 0x02 GET_STATUS, 0x03 LOG_SET_LEVEL, 0x04 GET_JOINT_DETAIL, 0x05 GET_LIMITS, 0x07 GET_INFO, 0x0A GET_FLAGS |
| 文本透传 | **0x0B TEXT_EXEC**（u32 magic 0x5A5A5A5A + 文本≤58B + 0x00）、**0x0C TEXT_FETCH**（u16 off, u8 n）——覆盖全部 144 条控制台指令；输出>2048B 截断置 flags.bit0，翻页循环 0x0C 直到 off+n≥total |
| 运动 | 0x10 MOVE_JOINTS(16B), 0x11 STOP, 0x12 SET_TORQUE(joint 0xFF=全), 0x13 STREAM_JOINTS(逻辑角!), 0x14 MOVE_JOINT_ONE, 0x17 SET_BUS_MODE, 0x18 SERVO_INIT |
| 运动学 | 0x20 MOVE_CART(12B), 0x21 FK_QUERY→0xA1(21B), 0x22 IK_QUERY→0xA2 |
| 补偿 | 0x30/0x31 SET_*, 0x32/0x33/0x36 GET_* |
| 参数表 | 0x40~0x44（READ/WRITE/COUNT/SAVE/LIST 分页） |
| 示教 | 0x50/0x51(分页读)/0x53/0x54/0x55；录制/回放走 0x0B 文本 |
| 危险 | 0x70 CENTER_CALIB(magic), 0x71 恒 NACK, 0x72 ZERO_RESET(flags+magic), 0x73 SYS_RESET(magic) |

⚠ **NET 链路会拦 11 条 CAN 命令**：`can cx cp cy cz cw ps mg mp mo ml`
（这些是 CAN 链路自己的管理命令，在 NET 模式下发文本也会被 `NET_BLOCK_CAN_CMDS()` 拦掉）。
⚠ **没有 node 概念**：UDP 无需 CAN 的 0x100+node 寻址，一个网口一个目标。

## 5. 定点编码（同 CAN）

| 量 | 类型 | 单位 | 例 |
|---|---|---|---|
| 角度 | int16 LE | 0.1° | 90°→900(0x0384)；**发 90 只会走 9°** |
| 位置 | int16 LE | 0.1 mm | — |
| 速度/加速度 | uint16 LE | 0.1 / 0.1² | v=25°/s→250；0=用默认(25°/s, 80°/s²) |
| 重力 K | int16 LE | 0.001 deg/mm | — |
| 参数值 | int32 LE | 0.001 | PARAM_READ/WRITE |
| 丢读哨兵 | — | — | GET_STATUS/FK_QUERY 关节角 **-32768(0x8000)** = 该轴读取失败 |

## 6. 实测性能与推荐用法（2026-09-24 真机 0924L）

| 场景 | 实测 |
|---|---|
| UDP 单程 p50 | **1.03 ms** |
| 流式跟随 | 1200 fps 追平，18 档速率 0 超时，crc/tx err=0 |
| HTTP-keepalive | p50 1.71ms（比 UDP 慢 +1.08ms） |
| HTTP-close | p99 48ms（**复用连接省 2.25ms/次 ≈57%**） |

**推荐**：上位机直接 UDP 直连 5000 端口；一个 socket 常开；请求-应答串行（发一条→等回包→再发下一条）。
GET_STATUS 全流程 ≈1ms（读 6 轴舵机总线是大头），遥操流式用 0x13 STREAM_JOINTS 20~50Hz。

## 7. 上位机必守规则（对齐 CAN 文档 §9 + UDP 特有）

1. **MOVE_JOINTS 非目标轴填当前实际角**（先 0x02 读回），绝不能填 0——五轴冲限位"乱动"事故根因。
2. **发运动前查 read_ok**（0x82 flags bit3）且轨迹不在跑（bit1=0）；read_ok=0 停发一切运动。
3. **ACK err=0 ≠ 已到位**：轮询 0x82 直到 flags bit1 变 0（UDP 没有事件帧可等）。
4. **ERR_BUSY(9)**：轨迹中再发运动被拒；先 0x11 STOP。
5. **超时建议 ≥3s**（舵机总线阻塞时 GET_STATUS 可达 3~4s）；超时后**不要盲目重发运动指令**。
6. **TEXT_EXEC 必须 magic、文本≤58B**；长输出（如 `h` 5406B）必须 0x0C 翻页——UDP 一包只装 ≤64B 逻辑负载，翻页规则与 CAN 相同。
7. **0x13 流帧用逻辑关节角**（相对 Home），0x10/0x14 用舵机度，两套坐标系不混用。
8. **危险命令（0x70/0x72/0x73、TEXT_EXEC 里 M a/zr）工具内禁自动重试**，用户二次确认后才发。
9. **一报文一命令**：不要在一个 UDP 报文里拼两条逻辑包；SEQ 逐请求 +1（uint8 回绕）。
10. 链路三态：臂端 `link net` → `link save` → `rb`（或 0x73 SYS_RESET）切到 NET；NET 与 CAN **同一时刻只有一条活动**。

## 8. 遥测轮询方案（不改固件，UDP 上一切皆轮询）

UDP 是**纯请求-应答模型**：没有心跳帧、没有事件推送、没有周期遥测——角度/温度/电流/轨迹完成判定**全部靠上位机自己轮询**。

### 8.1 各数据源与推荐频率

| 数据 | 命令 | 应答 | 单次代价 | 建议频率 |
|---|---|---|---|---|
| 六轴角度 + xyz + flags | 0x02 GET_STATUS | 0x82（21B） | 读 6 轴舵机总线 **4~6ms**（网络仅 ~1ms，瓶颈在舵机总线） | **10~20Hz**；轨迹执行中降到 5Hz |
| 温度/电流/负载/电压 | 0x04 GET_JOINT_DETAIL（payload=`FF` 全轴） | 0x84（62B） | 同样读舵机总线 | **1Hz** 足够 |
| 状态位/活体 | 0x0A GET_FLAGS | 0x8A（2B） | **不碰舵机总线，极轻** | 10~50Hz 随意 |
| 轨迹是否跑完 | 0x82 的 flags bit1 变 0 | — | 随 0x02 覆盖 | 运动后 10Hz 盯到位 |

### 8.2 轮询主循环骨架

```python
import socket, struct, time

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.settimeout(3.0)
ARM = ("192.168.7.120", 5000)

def crc16(data: bytes) -> int:            # CRC-16/CCITT-FALSE
    crc = 0xFFFF
    for b in data:
        crc ^= b << 8
        for _ in range(8):
            crc = ((crc << 1) ^ 0x1021) & 0xFFFF if crc & 0x8000 else (crc << 1) & 0xFFFF
    return crc

def cmd(seq, cid, payload=b""):
    body = bytes([seq, cid, len(payload)]) + payload
    return body + struct.pack("<H", crc16(body)), seq

t_status = t_detail = 0.0
seq = 0
while True:
    now = time.monotonic()
    if now - t_status >= 0.05:                       # 20Hz 角度
        seq = (seq + 1) & 0xFF
        pkt, _s = cmd(seq, 0x02)
        sock.sendto(pkt, ARM)
        rsp, _ = sock.recvfrom(1024)
        if rsp[1] == 0x82 and rsp[2] == 21:
            j = struct.unpack("<6h", rsp[3:15])      # ×0.1°, -32768=丢读
            flags = rsp[23]                          # bit3=read_ok, bit1=轨迹中
        t_status = now
    if now - t_detail >= 1.0:                        # 1Hz 温度/电流
        seq = (seq + 1) & 0xFF
        pkt, _s = cmd(seq, 0x04, b"\xFF")            # 0xFF=全六轴
        sock.sendto(pkt, ARM)
        rsp, _ = sock.recvfrom(1024)                 # rsp[1]==0x84, 62B
        # 每轴10B: pos u16, speed i16, load i16, volt u8, temp u8, err u8, ok u8
        t_detail = now
    time.sleep(0.005)
```

### 8.3 节奏设计

1. **串行发收**：发一条 → `recvfrom` 等应答 → 再发下一条，不要并发狂发；应答 SEQ 回显请求 SEQ 用于配对。
2. **错峰**：0x02 与 0x04 别在同一拍发，舵机总线一次只能跑一个事务。
3. **轨迹感知降速**：flags bit1=1 时把 0x02 降到 5Hz，给轨迹的舵机事务让路。
4. **read_ok=0（flags bit3=0）立即停发运动指令**——这是舵机总线丢读的信号。
5. **超时 ≥3s**；超时重发查询可以，**重发运动指令不可以**（可能双发）。
6. **再省舵机总线**：0x04 每拍换一根轴（joint=0~5），六拍扫全臂，单次事务减到 1/6。
7. **想更高频遥测 → 串口并行**：COM11 恒常通，`tm 150 pti` 每 150ms 推角度/温度/电流；**网口管控制、串口管遥测**，互不干扰。
8. UDP 没有 CAN 的 0x280 事件帧：发 MOVE 后在轮询循环里盯 flags bit1 变 0 判定到位。

### 最小 Python 示例（一条 GET_STATUS 往返）

```python
import socket, struct
sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.settimeout(3.0)
ARM = ("192.168.7.120", 5000)

def crc16(data: bytes) -> int:            # CRC-16/CCITT-FALSE
    crc = 0xFFFF
    for b in data:
        crc ^= b << 8
        for _ in range(8):
            crc = ((crc << 1) ^ 0x1021) & 0xFFFF if crc & 0x8000 else (crc << 1) & 0xFFFF
    return crc

def cmd(seq, cid, payload=b""):
    body = bytes([seq, cid, len(payload)]) + payload
    return body + struct.pack("<H", crc16(body))   # 注意 CRC 小端

sock.sendto(cmd(1, 0x02), ARM)                     # GET_STATUS
rsp, _ = sock.recvfrom(1024)                       # [SEQ,0x82,LEN=21,payload...,CRC]
assert rsp[1] == 0x82 and rsp[2] == 21
j = struct.unpack("<6h", rsp[3:15])                # J1~J6 ×0.1°, -32768=丢读
flags = rsp[23]                                    # bit3=read_ok, bit1=轨迹中
```
