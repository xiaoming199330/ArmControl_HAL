⇒ 下方各节的"手动试验步骤"**已成为历史记录**，现场无需再照做。

| 轴 | 限位来源 |
|---|---|
| J1 ~ J6（**含 J3/J5**） | `calib_min_raw[j]` ~ `calib_max_raw[j]`，即 Phase 2 手推实测值 |

## 1. 核查："没把 4095 换算"能不能解释当年的内置决定？

**不能。** 三条证据：

### 证据 1 —— Phase 2 全程就在 raw 空间，压根没有"换算"这个环节

`main.c` 里 Phase 2 的取值与打印：

```c
/* 200 ms 轮询 (main.c ~1117) */
uint16_t cur = SERVO_GetPositionRaw(j);          /* ← uint16_t raw, 0~4095 */
if (cur < calib_min_raw[j]) { calib_min_raw[j] = cur; ... }   /* 同单位比较 */
```

```c
/* Phase 2 表格 (main.c ~907) */
| NAME | MIN  | POS  | MAX  |
  打印 calib_min_raw[j], cur, calib_max_raw[j]     /* ← 三个值全是 raw */
```

⇒ 显示的是 raw、存的是 raw（`uint16_t calib_min_raw[6]`）、比较的是 raw、生效的也是 raw
（`uint16_t JOINT_MIN_RAW[6]` + `raw_in_range()`）。
**中间没有任何"角度 ↔ raw"的转换点可以出错。**

固件里还有一条明文铁律（2026-09-02 复盘后写的）：

> 限位定义与检查一律使用"行程量"(raw 0-4095)，**严禁退回角度/关节角推导**!

### 证据 2 —— 换算改变不了结论，因为它是"占满全行程"

| | raw | 换算成 servo 度 | 占全行程 |
|---|---|---|---|
| J3 手推记录 | 23 ~ 4083 | **2.02° ~ 358.89°** | **99.1%** |
| 内置 J3 窗口 | 885 ~ 3138 | 77.80° ~ 275.90° | 55.0% |

`23 / 4096 = 0.56%`、`4083 / 4096 = 99.68%`。
**不管用 raw 读还是换算成角度读，它都表示"几乎转过一整圈"。**
换算只改变刻度标签，不改变"覆盖 99% 行程"这个事实 —— 所以当年判断"这是整圈绕行途中的记录，
不是挡块位置"与量纲无关。

### 证据 3 —— 同一批数据，另外四个轴一直在用，而且好用

`apply_calib_limits()`（`main.c` ~1275）里：

```c
} else {
    /* J1/J2/J4/J6: 直接用 Phase2 手动实测的行程量 MIN/MAX */
    mn = calib_min_raw[j];
    mx = calib_max_raw[j];
}
```

**J1/J2/J4/J6 用的就是这同一个 `calib_min_raw/calib_max_raw`、同一条链路、同一套 raw 比较。**
它们工作正常（J2/J4 的实测限位一直生效）。
⇒ 同一份数据、同一条链，**4 个轴好用、J3 不好用** ⇒ 问题出在 **J3 这个轴的区间形状**，
不是出在"换算"上。

> J3 的区间形状问题：合法区是跨 0/360 的包裹弧，而 `raw_in_range()` / `raw_dist_fwd()`
> 按"正向弧 min→max"解释数据，**表达不了跨 0 的区间**。详见
> `上位机校准功能需求说明_2026-09-16.md` §"为什么这两轴必须内置"。

## 2. 那还要不要试？—— 要，而且理由充分

即便上面的理由成立，下面这条担心仍然成立、并且值得用实验消除：

- **"J3 的 198° 窗口、J5 的 160° 窗口，是不是白白牺牲了可用行程？"**
  特别是 J5 —— 09-15 已实测物理行程 241.2°，而固件只给 160° ⇒ 从臂被**静默夹住**
  （这就是"J5 跟得慢"的真因）。**J5 的窗口确实偏窄，这一条是明确的 bug，该修。**
- 区别在于：**J5 该改的是"放宽容度到物理挡块"，而不是"沿用手推记录 14~357"。**
  两者不是一回事（见 §4 判据）。

## 3. 为什么不用改固件？—— `L` 命令就是现成的 RAM 试验台

已核实 `cmdLimits()`（`main.c` ~3706）：

```c
JOINT_MIN[joint]     = min_val;
JOINT_MAX[joint]     = max_val;
JOINT_MIN_RAW[joint] = deg_to_servo_raw(min_val);
JOINT_MAX_RAW[joint] = deg_to_servo_raw(max_val);
IK_SetJointLimitsRaw(JOINT_MIN_RAW, JOINT_MAX_RAW, SERVO_OFFSET);   /* 立刻同步给 IK */
```

**对 J3 / J5 没有任何特殊处理** —— 不跳过、不覆盖。也就是说：

| 想复现哪种配置 | 现场敲（0-based 索引！） |
|---|---|
| 当前内置的 J3 窗口（77.8°~275.9°） | `L 2 77.8 275.9` |
| 当前内置的 J5 窗口（89.2°~249.2°） | `L 4 89.2 249.2` |
| 手推值的 J3（2.0°~358.9°） | `L 2 2.0 358.9` |
| 手推值的 J5（14°~357°） | `L 4 14 357` |

⚠ **`L` 的关节号是 0-based**：`L 2 ...` 改的是 **J3**，`L 4 ...` 改的是 **J5**。
（`L` 无参数时显示的表格打的是 J1~J6，别被那张表带偏。）

### 天然的回退机制

`apply_calib_limits()` 在**开机路径**上被调用（`main.c` ~1338，`pid_load_startup()` 内）：

```
上电 → PID_FlashLoad(含 limits) → ... → apply_calib_limits()
                                            ↑ J3 回内置偏移宏、J5 回卡区保护带
```

⇒ **`L` 改的值只活在 RAM 里，断电重启自动回到内置保护带**。这就是"不行就改回来"最省事的形式。

### ⚠ 试验期间的两条禁令

下面两条路径会调用 `apply_calib_limits()`，**会立刻把 `L` 设的值冲掉**：

1. **不要进 `c` 校准模式并敲 `s`**（`main.c` ~1082 / ~1088）
2. **不要敲 `zr`**（`main.c` ~4993，复位六轴零点 —— 而且它会动 J2/J3/J4 的 IK 精度）

> 这就是注释里"J3/J5 **任何情况下都覆盖校准数据与 `L` 命令**"的准确含义：
> 不是"`L` 设不进去"，而是"校准保存 / 复位零点时会把你 `L` 设的值覆盖掉"。

`L` 的另一个硬限制（源码注释原文）：

> 这里只允许 min < max 的常规区间；**跨越 0/360 的行程请用 `c` 校准**。

⇒ `L` 设不出跨 0 的弧。**但当前两个内置窗口都不跨 0**（J3 raw 885~3138、J5 raw 1015~2835），
所以短期试验够用。

## 4. 阶段 0 + 阶段 1：零风险前置判定（**必做，再谈试跑**）

### 阶段 0 —— 前置检查（3 条命令）

```
zi            ← 确认 calib_zero_raw 健康：应为全 0 或接近 [2048 ×6]
                 （参差读数 = Home 零点被污染，任何限位讨论都不成立，先 zr save 复位）
L             ← 记下当前六轴限位（角度，display only）
p 2  /  p 4   ← 记下 J3 / J5 当前 raw / servo / rel-home 三个读数
```

> `zi` 不健康就不要往下做。零点错时**绝对不要**跑跟随或大动作。

### 阶段 1 —— 松力手推实测（不驱动电机，零风险）

目的：**先确定"手推记录 23~4083 / 14~357 到底是不是真实可达行程"**，而不是直接采信。

```
V 500         ← （可选）先把全局速度压下来，为后面试跑做准备
t 2 0         ← J3 松力
（手推 J3 全程，重点：能不能推过 servo 10°~177° 这一段）
p 2           ← 读两端顶死位置的 raw / servo
t 2 1         ← J3 上力
t 4 0         ← J5 松力
（手推 J5 全程，重点：能不能推过 servo 77°~174° 卡区）
p 4           ← 读两端顶死位置
t 4 1
```

**判据（决定下一步怎么走）**

| 观察 | 结论 | 下一步 |
|---|---|---|
| **J3 推不过** servo 10°~177°（被硬挡死） | 挡块真实存在 ⇒ 手推记录 23~4083 是"推过挡块/绕圈"的产物，**不是行程端点** | ❌ **不要沿用手推值** —— 那等于把挡块区设成合法区 |
| **J3 推得过** | 挡块不在那儿（或已被压变形）⇒ 09-02 那条"挡块 10/177"的记录需要重判 | ✅ 继续阶段 2 |
| **J5 两端顶死** ≈ servo 17.9° / 259.1°（跨度 ≈241°） | 与 09-15 实测一致 ⇒ 手推记录 14~357（跨度 343°）**超出物理行程约 100°** | ❌ 不要沿用老数据；改用**这次实测的挡块值**去放宽窗口 |
| **J5 两端顶死** ≈ servo 14° / 357° | 与手推记录一致 | ✅ 说明物理行程确实更宽，继续阶段 2 |

⚠ **手推顶死要点**：轻推感受挡块，**不要砸**；顶死瞬间立刻读数（松手会回弹）；
金属舵盘有齿隙，顶死的读数会比真实挡块**偏浅**（J3 曾因此差 26 raw / 2.3°）。

> 为什么要重测而不是直接用老数据：老数据（23~4083 / 14~357）是**当年那次排查现场**记的，
> 而 09-10 换过 J2/J3 舵机、零点基准变过。**拿零点基准不可考的老数据去放宽限位**，
> 风险比重新量一次大得多。

## 5. 阶段 2：RAM 试跑（有风险，小步扩）

**只在阶段 1 判定"该轴允许试"时才做。**

### 5.1 先看"被夹到哪里"——用 `a` 探测边界（不冒进）

`a <J> <deg>` 单轴移动走 `clamp_angle()`（`main.c` ~1168），被夹**会打印**：

```
a 2 120
  J3: 120 -> 77 deg (raw 1365 -> 885 limit)      ← 被夹，看得见
```

这个打印是**判据**：它告诉你"限位在哪里把命令拦住了"。
对比 `L 2 77.8 275.9` 与 `L 2 2.0 358.9` 两次探测的输出，能直观看出放宽了多少。

⚠ 注意区分：**`a` / `L` 这条路径夹住会打印**，
而 **流式跟随（`sp`/`mf` → `cmdStreamJoints`）夹住是静默的**
（`clamp_raw()` 后直接下发、返回成功、不打印）—— 这就是历轮把"J5 被夹住"误判成
"J5 舵机慢"的根源。**别用流式跟随做试探**，用 `a`。

### 5.2 小步试探（**逐 5° 递增，看着舵机走**）

```
V 500                 ← 低速（低速能显著减小撞击冲量）
L 2 2.0 358.9         ← 放宽 J3 到"手推值"（RAM）
t 2 1                 ← 确保上力
a 2 90                ← 从已确认安全的角度起手
a 2 95  →  a 2 100  →  a 2 105 ...   ← 每次只加 5°，往原禁入区方向探
```

**中止条件（出现任一条立刻停）**

- 舵机**红灯 / 过载报警**
- 出现**堵转声**（电流声变粗、咔哒）
- `p 2` 读数**不动了但我还在加大目标** ⇒ 已顶死
- 机械结构有**变形/异响**

**中止动作**：立刻 `t 2 0` 松力 → 手托住 → **断电重启**（限位自动回内置）。
或者直接拔电（松力更快，但要托住臂，防止重力下垂砸桌）。

### 5.3 J5 只能用"通电驱动"验证

J5 的卡区性质是**通电才堵转**（断电手推能硬过去、不报警）——
所以 §4 的"手推能过"**不能**作为 J5 可以放宽的证据。J5 的判据只能是**低速通电试探**
（`V 500` + `a 4 <5°递增>` + 盯红灯）。
⚠ 这也意味着 **J5 的试验风险高于 J3**，建议**放在最后做**，且一次只动一个轴。

## 6. 回退

| 场景 | 回退方式 | 生效时间 |
|---|---|---|
| `L` 设的值不想要了 | **断电重启** | 上电即回内置保护带 |
| 想立刻回内置值（不想重启） | `L 2 77.8 275.9` / `L 4 89.2 249.2` | 当拍 |
| 被人误进了 `c` 并 `s` | `zr save` 复位零点（⚠ 会动 J2/J3/J4 的 IK 精度） | 当拍 |
| 宏已经改了、要回到旧行为 | 改回 `J3_LIMIT_OFF_*` / `J5_LIMIT_OFF_*` 重编重烧 | 一次烧录 |

⚠ **软件回退 100% 可行，硬件损伤不可回退。** "不行就改回来"这句对软件成立，
但撞挡块 / 堵转过载留下的是**舵机**（堵转烧线圈、齿轮磨损、结构变形）。所以：
**先做 §4 零风险判定，再决定要不要进 §5。**

## 7. 若试验通过 → 固化时要改的三处

（试验成功前不要动代码）

换成了内置偏移；`L` 显示出来的是**固件强加的保护带**。

（顺带验证了反向推导：把这对 J5 偏移代进**旧 zero = 3081**，得 raw 2048~3868 →
**180.0°~340.0°** —— 正是源码注释里写的"J5 强制锁安全区 **180~340**"。说明这对偏移
当年就是为旧零点量的，注释没说错，只是坐标系换了。）

### 判读 2 —— zero 健康，**不需要** `zr`

上面两组换算能精确复现显示值 ⇒ `calib_zero_raw = 2048` 完好无损。
⇒ **不要敲 `zr`**（它会复位六轴零点、伤了本来正常的 J2/J3/J4 的 IK 精度）。直接做 §4 判定。

### 判读 3 —— 当前姿态 = 停靠 / 收纳位

`J3 CUR = 270`，距上限 275° 只剩 5° —— 对应 `POSE_HOME_J` 的 J3
（rel-home `+90.29` → servo `270.29`）。
⚠ 臂现在停在收纳位，**这个位置不要松力**（重力下垂 / 压挡块）。

### 判读 4 —— ⚠ J5 窗口与"卡区"重叠 84.8°（**新发现，试验重点验证项**）

- 现役 J5 窗口：servo **89.2° ~ 249.2°**
- 源码注释记录的 J5 卡区：**77° ~ 174°**
- ⇒ **重叠 89.2° ~ 174.0°，共 84.8°**

**为什么会重叠**：窗口是"**相对 zero 的偏移**"，会跟着零点平移；卡区是**绝对物理位置**，
不跟着动。当年 zero = 3081 时这对偏移算出来是 180°~340°，正好在卡区上界（174°）之上、
留 6° 间隔；现在 zero = 2048 把窗口平移成 89°~249°，**就压进卡区了**。

**但这反而支持"可以试"**：09-15 实测从臂 J5 曾从 **208.35° 平滑走到 89.76°**
（穿过 174°~90° 整段），**全程没有堵转** ⇒ 至少从臂这只 J5 在当前状态下
**并不存在 77°~174° 卡区**。

⚠ 仍要留意：卡区可能是**姿态相关的自碰撞**（只在某些 J3/J4 姿态下才碰）。
所以试的时候要**换几个肘/腕姿态重复验证**，一次通过不算数。

### 判读 5 —— "手推记录"记录的是"你推过的范围"，不是"机械允许的范围"

J1 无机械挡块（可连续 360°），可手推只记到 63°~303°（240°）⇒ 说明手推值取决于
**当时推了多远**，而不是机械边界。
⇒ 所以"沿用手推值"本质上等于"沿用你当时推过的范围"。**要放宽就得重新量。**

### 取回你手推 J3/J5 的原始值（可选取证，零改动）

`L` 显示的已被覆盖，但 **`calib_min_raw / calib_max_raw` 里存的仍是你手推的原始 raw**：
进 `c` 模式 → 按 `n` 切到 **Phase 2** → 表格的 `MIN / POS / MAX` 就是它（单位 raw，0~4095）。

⚠ 两点注意：
1. 进 `c` 会**立刻释放全部扭矩** ⇒ 先托住臂（当前还在收纳位，会掉）；
2. **看完按 `q` 退出，不要按 `s`**（`s` 会把当前值写进 Flash）。
   —— 即便误按 `s` 也不会启用 J3/J5 的手推值（`apply_calib_limits()` 照样覆盖），
   但仍不建议，避免引入不必要的 Flash 写入。
