# 舵机总线改"开漏单总线"（去掉 74HC126D）— 方案与实测依据

> 版本：**ARM-NET-0924AY / ARM-BOTH-0924AY**（2026-11-02）
> 目标：省掉两片 74HC126D 的方向切换，舵机总线改为一根线；**不合并两条 UART**（保留并行度）。
> 结论：**可行**。1kΩ 上拉到 3.3V 是正确的现役配置，不需要改成 5V。

---

## 1. 为什么 CAN 不在选项里

| 项 | 事实 |
|---|---|
| STS3215 协议 | SCS / 飞特私有协议，**单端 TTL 异步串口**，1Mbps |
| CAN 物理层 | 差分 CANH/CANL + 收发器（TJA1050 等），帧格式完全不同 |
| 舵机内部 | **没有 CAN 控制器、没有收发器** |
| 结论 | CAN **不能直接接舵机**；74HC126 解决的是"全双工 UART → 单线半双工"，与 CAN 不在同一层 |

CAN 在本项目里只能放**板间**（上位机/主臂 ↔ 从臂 STM32），且受硬约束：
**PB13 = CAN2_TX = ETH_TXD1** ⇒ CAN 与网口物理互斥（BOTH 固件运行期二选一）。

---

## 2. 为什么开漏能替代 74HC126

74HC126D 存在的唯一理由是 **STM32 的 TX 是推挽输出**——推挽会主动输出高电平，与舵机应答对撞。开漏（AF_OD）后：

| 状态 | 推挽（旧） | 开漏（新） |
|---|---|---|
| 发 0 | 拉低 | 拉低 |
| 发 1 | **主动输出高** | **释放（高阻）**，靠上拉给高 |
| 舵机应答时 | 必须靠 126 断开 TX | MCU 本就处于释放态，**天然不冲突** |

方向控制从"GPIO 时序"变成"电气特性"，PA8/PA10 两根方向脚彻底退休。

---

## 3. 3.3V 上拉能不能驱动 STS3215

**能。** 三条依据：

1. 现役硬件一直是 **1kΩ 上拉到 3.3V**，通信正常 ⇒ 舵机输入阈值 ≤3.3V 已被现场证明
2. 本项目的 `outputs/sts3215_id_tool/sts3215_id_tool.ino`（ESP32，**3.3V GPIO** + 10kΩ 上拉）能正常扫描/改 ID ⇒ **3.3V 逻辑驱动 STS3215 有独立验证**
3. 飞特总线舵机信号为 TTL 兼容，STM32 引脚 PB10/PB11/PC12/PD2 在 F407ZGT6 上均为 **FT（5V 容忍）**，即使舵机回 5V 也不会损坏

⚠ **不要把上拉改到 5V**，除非确认舵机侧确实是 5V 逻辑。3.3V 是当前已验证的工作点。

---

## 4. 硬件改动（3 步）

| # | 动作 | 注意 |
|---|---|---|
| 1 | 拆掉两片 **74HC126D**（Bus A / Bus B 各一片） | 拆前断电；拆后 PA8/PA10 悬空，代码里保留初始化也无害 |
| 2 | **TX 与 RX 短接成一根线** | Bus A：PB10 + PB11 并联；Bus B：PC12 + PD2 并联 |
| 3 | **保持 1kΩ 上拉到 3.3V**（每条总线各一个） | 不要改成 4.7k/10k：1Mbps 下 τ 会超过位宽 |

> ⚠ 两条总线**各自独立**，不合并：`JOINT_BUS` 保持 `{A,A,A,B,B,B}`（bus mode 0）。
> 合并成一条（bus mode 2）会把 6 轴串行化，采样率约减半，见 §6。

## 5. 代码改动（已落地）

| 文件 | 改动 |
|---|---|
| `Makefile` | 新增 `BUS_PP` 开关（默认 0 = 开漏）；`BUS_DEFS` 进 CFLAGS；`BUS_PP=1` 时 `BUILD_DIR` 加 `_pp` 后缀 |
| `Core/Src/usart.c` | `SERVO_BUS_TX_MODE`：默认 `AF_OD`，`BUS_PP=1` 时 `AF_PP`（原按 `ARM_MASTER_BUILD` 二分，现统一） |
| `Core/Src/servo_bus_hal.c` | `DXL_SetDirection()`：默认空实现；`BUS_PP=1` 时恢复 DIR 引脚切换 + 25µs 延时 |
| `Core/Src/main.c` | `h` 横幅 tag 升 **0924AY**，并追加 `bus=OD(1k->3V3)` / `bus=PP(74HC126)` 标记 |
| `Core/Src/arm_control_api.c` | GET_INFO tag 同步 AY（两处分支） |
| `tools/arm_preflight.py` | 白名单加 `ARM-NET-0924AY` / `ARM-BOTH-0924AY` |
| `tools/gen_arm_config_json.py` | tag 表 + 快照行刷新（已重新生成 `arm_config.json`，AX 残留 0 处） |

**保持不变（重要）**：

- `drain_echo()` 的"只排 len 个字节、不加等待窗口"逻辑**一行未改**——TX/RX 同线后回声依然存在，改这里会重演"0/6 全 MISSING"
- `GPIO_InitStruct.Pull = GPIO_NOPULL` 必须保持：开内部上拉会在舵机输出 5V 时往 VDD 灌电流
- `UART4`（主从链路）仍是推挽全双工，不受此宏影响

## 6. 性能影响

### 6.1 收益

| 项 | 变化 |
|---|---|
| 方向切换延时 | 每次事务原来两次切换 ≈ **50µs**，现在为 0（`for(i<150)` 那两段一并消失） |
| 接收路径 | **完全不变**（RX 是 UART 采样，与输出级无关） |
| 器件 | 省两片 74HC126 + 两根方向控制线 |

### 6.2 代价：上升沿变慢

```
τ = R × C = 1kΩ × ~240pF ≈ 0.24µs
  (1m 线 ~100pF + 6 个舵机输入 ~90pF + PCB 杂散 ~50pF)

3.3V 上拉，到 TTL 阈值 2.0V ：t = 0.93τ ≈ 0.22µs
1Mbps 位宽 1.0µs，采样点在位中央 0.5µs ⇒ 余量 0.28µs ✅
```

线长敏感度：

| 总线电容 | τ | 到 2.0V | 判定 |
|---|---|---|---|
| 240pF（1m，6 节点） | 0.24µs | 0.22µs | ✅ 余量足 |
| 400pF（1.5m） | 0.40µs | 0.37µs | ⚠ 余量 0.13µs |
| 500pF（2m+） | 0.50µs | 0.47µs | ❌ 降 500kbps |

### 6.3 ⚠ 最需要盯的风险：噪声容限减半

| 电平 | 高电平 | TTL 阈值 | 噪声容限 |
|---|---|---|---|
| 5V 推挽 | 5.0V | 2.0V | 3.0V |
| **3.3V 上拉** | **3.3V** | 2.0V | **1.3V** |

现役丢读率本来就 **25.5%**（J1/J2/J3 承重轴，总线层未修）。3.3V 下容限只剩 1.3V，**改造后丢读率有可能上升**。这是本方案唯一的实质技术风险，必须实测对比。

### 6.4 不合并两条总线的原因

| 配置 | 6 轴轮询 | 采样率 |
|---|---|---|
| 两条 UART 并行（本方案） | 3 轴的时间 | 基准 100% |
| 合并成一条（bus mode 2） | 6 轴串行 | **约 50%** |

现役 `GET_STATUS` 实测 4~6ms、采样 52Hz；合并后预计掉到 25~35Hz。RC 遥控够用，但轨迹/重力补偿不够。

## 7. 验证步骤

**烧前**：确认 126 已拆、TX/RX 已短接。**只改固件不拆 126 ⇒ DIR 默认低把总线关断 ⇒ 扫描 0/6**。

```
① 烧 0924AY → COM11 敲 h
   首行应为：fw-tag ARM-NET-0924AY ... bus=OD(1k->3V3)
② n            重新扫描，确认 6/6（Bus A: 3, Bus B: 3）
③ i            下发 PID，确认六轴都应答
④ s            六轴角度实时读，逐个看有无 MISSING
⑤ nx           crc err / tx err 应为 0
⑥ pv 100       连续刷新 10 分钟，统计丢读率，与改造前 25.5% 对比
```

若丢读率明显上升，按此顺序处置：

1. 上拉 1kΩ → **470Ω**（上升沿快一倍，灌电流 7mA 仍安全）
2. 波特率 1Mbps → **500kbps**
3. 缩短总线 / 减少节点

## 8. 回退方法

板上若把 126 焊回去，固件必须同步回退：

```
make BUS_PP=1 LINK=net      → build_net_pp/ArmControl_HAL.bin
```

- 输出目录自动带 `_pp` 后缀，**不会覆盖** `build_net/`
- `h` 首行会显示 `bus=PP(74HC126)`，现场可据此判断烧的是哪一版
- 回退版已验证可编译：266,792→265,820 text，md5 `92b12b1de1e28a1feb2db61c1c8edef3`
