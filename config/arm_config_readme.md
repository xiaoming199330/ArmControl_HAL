# 六轴机械臂 ArmControl_HAL — 接口与配置说明（上位机对接版）

> 硬件：STM32F407ZGT6（启明欣欣 V4.1）+ 飞特 STS3215 30KG ×6
> 固件：`Core/` 裸机 HAL + Makefile
> 本文档版本：2026-09-11
> 适用上位机：串口文本命令 + 二进制协议（0xAA 0x55）
> ⚠ 本文档**不含主从臂（Leader/Follower）相关内容** —— 主从臂链路（UART4）另行联调，接口暂不对外。

## 1. 上位机最小联调清单（先跑通这条）

```text
① 串口打开：115200 8N1，无流控（None），无硬件握手
② 行尾选择：CRLF（\r\n）—— 或 LF（\n）/ CR（\r）任一均可，详见 §2
③ 发 "h\r\n"        → 应收到帮助文本
④ 发 "s\r\n"        → 应收到 6 轴状态（raw / 角度 / 负载 / 温度 / 错误位）
⑤ 发 "f\r\n"        → 应收到末端位姿（FK）
⑥ 发 "LP\r\n"       → 应收到全部算法参数 id/值/范围
⑦ 发 "n\r\n"        → 扫描总线，应报 6/6 舵机在线
```

只要 ③~⑦ 有回包，链路即通。**如果一条命令都没有响应，99% 是行尾问题**，见 §2。

## 2. ⚠ 行尾类型（Line Ending）—— 上位机最容易踩的坑

固件的命令行接收逻辑在 `Core/Src/main.c` 的 `Console_TryReadLine()`：

```c
if (ch == '\r' || ch == '\n') {     /* ← 关键：CR 和 LF 都当作"一行结束" */
    if (console_rx_len == 0) return 0;   /* 空行直接忽略 */
    console_rx[console_rx_len] = '\0';
    ...
    return len;                      /* 只有到这里，命令才会被执行 */
}
```

### 2.1 结论表（务必逐条确认）

| 行尾类型 | 字节 | 固件是否执行 | 说明 |
|---|---|---|---|
| **CRLF** | `0x0D 0x0A` | ✅ 执行 | **推荐**。绝大多数串口助手/上位机默认值 |
| **LF** | `0x0A` | ✅ 执行 | 合法，嵌入式/Linux 习惯 |
| **CR** | `0x0D` | ✅ 执行 | 合法，旧 Mac 习惯 |
| **无行尾** | — | ❌ **永不执行** | 命令会一直躺在缓冲区里，**表现为"下发了没响应"** |
| 只有空白/空行 | — | ❌ 忽略 | 空行不触发命令，也不会报错 |
| `\r\n` 连发 | 2 字节 | ✅ 只执行 1 次 | `\r` 结束当前行，紧跟的 `\n` 视为空行被丢弃。**不会重复执行** |

> **上位机开发铁律**：发任何命令，**必须**在命令末尾追加 `\r`、`\n` 或 `\r\n`。
> 最保险：**统一用 `\r\n`**（与本项目控制台实测一致）。
> 若你的上位机用 `Write()` 直接写字符串，请确认字符串里带了行尾（如 `"s\r\n"`，而不是 `"s"`）。

### 2.2 回显与提示符（解析返回时要跳过）

- 固件对收到的**每个字符都会原样回显**（`HAL_UART_Transmit` 单字节）。
- 一行结束时固件先回 `\r\n`，执行命令，再打印提示符 `> `（注意 `>` 后有一个空格）。
- 因此上位机解析返回时必须**容忍**：命令回显、`\r\n`、`> `、以及 `[RUN]` 开头的日志行。
- 不建议用"读到固定字节数"的方式解析文本命令返回；建议**按行读 + 关键词匹配**，并设置**整体超时**（见 §11）。

### 2.3 其它编码/解析规则

| 规则 | 说明 |
|---|---|
| 字符集 | **ASCII**。中文/全角字符不被识别 |
| 单行最大长度 | **127 字符**（缓冲区 128，含结尾 `\0`）。超出部分被丢弃 |
| 分词 | 仅按**空格 / Tab (0x09)** 分隔；**不认逗号、分号** |
| 参数个数 | 最多 **16 个 token**；多余被忽略 |
| 大小写 | **严格区分大小写**！`m`≠`M`、`p`≠`P`、`s`≠`S`、`t`≠`T`、`b`≠`B`… |
| 退格 | 支持 `0x08`(BS) 与 `0x7F`(DEL)，仅本地回显用；上位机一般不需要发 |
| 数字类型 | 角度/坐标用 `atof`（支持小数）；关节号/枚举用 `atoi`（整数） |
| 不支持 | ANSI 转义序列（颜色/光标）、引号包裹、注释、Tab 补全 |
| 二进制分流 | 控制台与二进制协议共用本串口。`0xAA 0x55` 开头的字节被协议状态机消费，其余交给文本控制台 |

### 2.4 常见"下发了没响应"排查顺序

1. **确认行尾**：命令末尾是否真的有 `\r` / `\n`？（最常见）
2. **确认大小写**：例如把 `P 0` 写成 `p 0`（`p` 是读角度，不是执行位姿）。
3. **确认参数个数**：如 `m` 需要 6 个角度，少于 6 个会打印 `Usage:` 而不动作。
4. **确认波特率**：115200 8N1；波特率错会收到乱码或 0 字节。
5. **确认是否处于特殊模式**：`teach` 录制中、`W` 挥动中、急停（E-STOP）激活时，多数命令被拦截或顶退（见 §4 备注）。
6. **确认是否是"只读诊断命令"**：`lk` 需连敲两次才出 `rate:` 行；`c` 校准是**交互式阻塞**模式，需按 `q` 退出。

## 3. 串口与总线参数

| 通道 | 外设 | 引脚 | 波特率 | 帧格式 | 用途 |
|---|---|---|---|---|---|
| **控制台** | USART6 | PC6(TX) / PC7(RX) | **115200** | 8N1 | **上位机主通道**：文本命令 + 二进制协议 |
| 舵机总线 A | USART3 | PB10(TX) / PB11(RX) | 1,000,000 | 8N1 | J1~J3，方向控制 PE8（74HC126） |
| 舵机总线 B | UART5 | PC12(TX) / PD2(RX) | 1,000,000 | 8N1 | J4~J6，方向控制 PE10 |
| （主从链路） | UART4 | PA0/PA1 | 115200 | 8N1 | **本次不对外，见文首说明** |

- **无硬件流控、无软件流控**。
- 控制台 TX 是**阻塞发送**（`cprint` → `HAL_UART_Transmit`），115200 下约 **87 µs/字符**，一行 100 字符 ≈ **9 ms**。
  - 影响：高频打印（`pv` / `pf` / `tm` / 轨迹日志）会占用主循环时间；上位机**不要把轮询周期设得过小**。
  - `tm`（遥测）与 `pv`/`pf` 已做"只读缓存、与总线解耦"，运动中也安全；仍建议 `tm` 周期 **≥100 ms**。

## 4. 文本命令总表（含行尾 / 大小写 / 参数）

> 本表 = `cmd_registry[]` + `ProcessCommand` 实际分发。**所有命令末尾都必须带 `\r`/`\n`/`\r\n`**（表中不再重复）。
> 关节号 **J 的取值随命令不同**，务必看备注：
> - 单轴命令（`t/a/r/p/z/w`）用 **0~5** 表示 J1~J6；
> - PID/自适应命令（`K/I/D/N/A g/Y`）用 **1~6** 表示 J1~J6。

### 4.1 扫描与配置

| 命令 | 参数 | 作用 | 备注（默认/范围/坑） |
|---|---|---|---|

## 5. ⚠ PID 调参指南（何时增大、何时减小）

> 适用命令：`K`(P) / `I`(I) / `D`(D) / `N`(P I D) —— 关节号 **1~6**。
> 生效链：**改 → 写舵机 RAM（立即生效）→ `Y J` 烧舵机 EEPROM（舵机掉电保留）→ `F` 存 STM32 Flash（固件开机自动下发）**。

### 5.1 固件默认 PID（= 调参基线，务必先记录）

| 关节 | P | I | D | 说明 |
|---|---|---|---|---|
| J1（底座旋转） | 16 | 4 | 12 | 无重力矩 |
| **J2（肩）** | **32** | 4 | 12 | **重力负载最大，P 单独翻倍** |
| J3（肘） | 16 | 4 | 12 | 减速箱有齿隙（9-01 撞击），**D 敏感** |
| J4（腕俯仰） | 16 | 4 | 12 | |
| J5（腕滚转） | 16 | 4 | 12 | |
| J6（夹爪） | 16 | 4 | 12 | |

- 取值范围 **0~254**（STS3215 RAM 增益范围）。
- 查看命令：`N J` 会同时显示 **STM32 缓存值 vs 舵机 EEPROM 值**，不一致会提示 `(不一致! 需 Y 烧写)`。

### 5.2 三个增益分别"管什么"

| 增益 | 增大时 | 减小时 | 典型症状 → 调整方向 |
|---|---|---|---|
| **P（Kp 位置刚度）** | 响应更快、更"硬"、抗重力下垂更强、稳态误差更小 | 更柔、噪声更小，但**稳态误差变大 / 会下沉** | 到点软、负重下沉 → **加大**；高频抖动、嗡鸣、噪声放大 → **减小** |
| **I（Ki 积分）** | 消除稳态误差（缓慢重力下沉），到位更准 | 消除慢速振荡/超调；太小则**永远补不掉静态误差** | 到位后慢慢下沉、反复微调 → **加大**；低频来回晃、积分饱和 → **减小** |
| **D（Kd 微分/阻尼）** | 阻尼增强、抑制过冲与振荡、到位更利落 | 噪声不被放大；**齿隙关节（J3）必须保持小 D** | 到点来回荡 → **加大**；**高频剧烈抖动/打摆 → 减小** |

### 5.3 具体到本机（血泪结论）

1. **`D` 对齿隙大的关节最敏感，不要盲目加大。**
   - 2026-09-10 曾把 J3 烧成 `P50 / I2 / D30`，**回折叠位到点剧烈颤抖**；恢复默认（P16/I4/D12）后立即消失。
   - 原因：J3 减速箱有损伤齿隙，D 由 12→30（×2.5）把齿隙噪声放大成高频自激。
2. **`I` 不是越小越好。** J3 的 `I` 从 16 压到 2 后，重力位姿稳态下沉、位置环反复拉扯；本机 J3 实际需要比"教科书"更大的 I。
3. **改 PID 之前先记录基线**：`N 1`~`N 6`（或 `LP`）把当前值抄下来；**一次只改一个关节、一个量**，改完做一次到位动作验证。
4. **J2 的 P 默认 32**（其它轴 16）：因为肩部承担整臂重力，P 小会明显下沉。只有在 J2 出现高频抖动时才考虑回调。
5. **验证抖动/顿挫时，先排除"不是 PID"的可能**：本机曾把"到点顿两下"误判为 PID，实际是**尾段流式微步**与舵机内部 planner 的交互（收尾降速 `SP 42` / 尾段交接 `SP 45`），与 D 无关。
6. **改完务必存两处**：
   - `Y J` → 烧舵机 EEPROM（否则**舵机断电重启会从 EEPROM 回载旧值**，坏 PID 复活）；
   - `F` → 存 STM32 Flash（否则**固件重启会用旧缓存**）。
   - `X` 只把 **RAM + 舵机 RAM** 恢复成固件默认，**两处持久化都不动**，所以 `X` 之后若想永久生效仍需 `Y J` + `F`。

### 5.4 推荐调参流程（上位机可实现为向导）

```text
1) N J                 ← 记录基线（P/I/D + 是否与 EEPROM 一致）
2) P 偏小导致下沉   →  K J <P+>          每次 +4 ~ +8
   D 过大导致抖动   →  D J <D->          每次 −4（J3 优先）
   I 不足导致慢漂   →  I J <I+>          每次 +2
3) 单关节动作验证（a J deg / m ...）
4) 满意 →  Y J   （烧舵机 EEPROM）
5) 全部满意 →  F （存 STM32 Flash）
6) 若变坏 →  X 恢复默认，回到基线重新来
```

## 10. 二进制协议（可选，控制台同口）

帧格式（小端，逐字节流）：

```
[0]=0xAA  [1]=0x55  [2]=SEQ  [3]=CMD  [4]=LEN  [5..]=PAYLOAD  [..]=CRC16(2B, 低字节在前)
CRC 范围 = SEQ..PAYLOAD；CRC-16/CCITT-FALSE (poly 0x1021, init 0xFFFF)
最大帧 = 5 + 64 + 2 = 71 字节
```

定点编码（避免 float 序列化歧义）：

| 量 | 类型 | 比例 |
|---|---|---|
| 角度 | int16 | 0.1 deg |
| 位置 | int16 | 0.1 mm |
| 速度 | uint16 | 0.1 deg/s |
| 加速度 | uint16 | 0.1 deg/s² |
| 增益 K | int16 | 0.001 deg/mm |
| 参数值 | int32 | 0.001 |

命令码（节选）：

| CMD | 名称 | 负载 → 响应 |
|---|---|---|
| 0x01 | PING | → 0x81: u8 ver, u8 run_id |
| 0x02 | GET_STATUS | → 0x82: 定点状态快照 |
| 0x03 | LOG_SET_LEVEL | u8 level → ACK |
| 0x10 | MOVE_JOINTS | 6×i16 角度 + u16 v + u16 a → ACK |
| 0x11 | STOP | → ACK |
| 0x12 | SET_TORQUE | u8 joint(0~5,0xFF=全) + u8 en → ACK |
| 0x13 | STREAM_JOINTS | 6×i16 逻辑角×10 → ACK（主从直写，**本接口暂不对外**） |
| 0x20 | MOVE_CART | i16 x,y,z + i16 pitch + u16 v + u16 a → ACK |
| 0x21 | FK_QUERY | → 0xA1: 位姿 + 六关节角 |
| 0x30 | SET_GRAVITY | i16 K(0.001 deg/mm) → ACK |
| 0x31 | SET_CORRECTION | u8 en, u16 thr(0.01 deg), u8 rounds → ACK |
| 0x40 | PARAM_READ | u8 id → 0xC0: u8 id, i32 val×1000 |
| 0x41 | PARAM_WRITE | u8 id, i32 val×1000 → ACK |
| 0x42 | PARAM_COUNT | → 0xC2: u8 count |
| 0x7F | ACK | u8 orig_cmd, u8 err(=0) |
| 0x7E | NACK | u8 orig_cmd, u8 err(ARM_API_ERR_*) |

> 响应规则：查询类响应 CMD = 请求 CMD | 0x80；控制类成功 ACK(0x7F)，失败 NACK(0x7E)+错误码。
> ⚠ 上位机若同时收文本**和**二进制，务必以 `0xAA 0x55` 作为二进制帧起始判据（文本控制台不会输出 `0xAA`）。
