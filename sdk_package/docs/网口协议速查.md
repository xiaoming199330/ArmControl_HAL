## 0. 为什么优先用网口

| 链路 | p50 | p99 | max | 超时 | 实测 fps |
|---|---|---|---|---|---|
| **UDP 网口** | **1.61 ms** | 3.40 ms | 117.66 ms | 0 | 547 |
| CAN @500k | 2.72 ms | 6.60 ms | 179.94 ms | 4 | 341 |
| 串口 COM11 | 4.78 ms | 6.32 ms | 15.26 ms | 0 | 202 |

50 Hz 遥操在网口上有 **15× 余量**，且两臂之间一根线都不用接（PC 就是那根线）。

## 1. 逻辑包（三条链路完全一致）

```
SEQ(1) | CMD(1) | LEN(1) | PAYLOAD(LEN) | CRC16-LE(2)
```

| 字段 | 说明 |
|---|---|
| SEQ | 主机分配，自增 0~255 回绕。**固件只回显，不校验、不去重、不排序** |
| CMD | 见 §3。`>=0x80` 是响应码 |
| LEN | 0~64 |
| CRC | CRC-16/CCITT-FALSE：poly 0x1021 / init 0xFFFF / 不反转；**范围 = SEQ..PAYLOAD**（不含帧头） |

CRC 自检向量：`crc16(b"123456789") == 0x29B1`

### 三条承载的"外壳"

| 承载 | 线上形态 | 最大 |
|---|---|---|
| **UDP** | **无外壳**，一个数据报 = 一个逻辑包 | 69 B |
| 串口 | `AA 55` + 逻辑包，与文本控制台同口 | 71 B |
| CAN | 逻辑包按 8 B 切分；首帧 `data[0] = 0x80|N`，后续 `data[0]=序号` | 10 帧 |

> CAN 必须重组：bxCAN 有 3 个 mailbox，**分片可能乱序到达**。
> 参考实现 `arm_sdk.protocol.CanReassembler`（按帧号缓冲）。

> 串口必须把文本行与二进制帧分开：`0xAA` 不会出现在固件文本输出里，所以 `AA 55` 就是帧头。
> 参考实现 `arm_sdk.protocol.FrameStreamParser`。

## 2. 最小可跑客户端（纯标准库，30 行）

```python
import socket, struct

def crc16(b):
    c = 0xFFFF
    for x in b:
        c ^= x << 8
        for _ in range(8):
            c = ((c << 1) ^ 0x1021) & 0xFFFF if c & 0x8000 else (c << 1) & 0xFFFF
    return c

def pack(seq, cmd, payload=b""):
    body = bytes([seq, cmd, len(payload)]) + payload
    return body + struct.pack("<H", crc16(body))     # UDP：不带 AA55

s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
s.settimeout(0.3)
s.sendto(pack(0x31, 0x01), ("192.168.7.120", 5000))   # PING
print(s.recvfrom(256)[0].hex(" "))                    # 31 81 02 01 xx CRC
```

或者直接用 SDK：

```bash
armctl --uri net://192.168.7.120:5000 ping
```
```python
from arm_sdk import open_arm
with open_arm("net://192.168.7.120:5000") as arm:
    print(arm.ping()); print(arm.get_status().joints)
```

## 3. 基础 14 条命令（字段级）

`dir`：**Q** = 查询（响应 `CMD|0x80`）；**C** = 控制（响应 ACK 0x7F / NACK 0x7E）

| CMD | 名称 | 方向 | 请求负载 | 响应 |
|---|---|---|---|---|
| 0x01 | PING | Q | — | `0x81`: u8 proto_ver(=1), u8 **run_id** |
| 0x02 | GET_STATUS | Q | — | `0x82` 21 B：6×i16 关节 | i16 X/Y/Z/Pitch | u8 flags |
| 0x03 | LOG_SET_LEVEL | C | u8 level(0~3) | ACK |
| 0x10 | MOVE_JOINTS | C | 6×i16 角(舵机度×10) + u16 v(×10) + u16 a(×10) | ACK |
| 0x11 | STOP | C | — | ACK（总是成功） |
| 0x12 | SET_TORQUE | C | u8 joint(0~5 / **0xFF**) + u8 en | ACK |
| 0x13 | STREAM_JOINTS | C | 6×i16 **逻辑角**×10 | ACK |
| 0x20 | MOVE_CART | C | i16 X,Y,Z(mm×10) + i16 pitch(deg×10) + u16 v + u16 a | ACK |
| 0x21 | FK_QUERY | Q | — | `0xA1` 21 B：i16 X/Y/Z/Pitch | 6×i16 关节 | u8 read_ok |
| 0x30 | SET_GRAVITY | C | i16 K(×1000 deg/mm) | ACK |
| 0x31 | SET_CORRECTION | C | u8 en + u16 thr(×100) + u8 rounds | ACK |
| 0x40 | PARAM_READ | Q | u8 id | `0xC0` 5 B：u8 id 回显 + i32 val(×1000) |
| 0x41 | PARAM_WRITE | C | u8 id + i32 val(×1000) | ACK |
| 0x42 | PARAM_COUNT | Q | — | `0xC2` 1 B：u8 count |

### 响应负载布局（⚠ 两条顺序**相反**）

```
0x82 GET_STATUS (21B)          0xA1 FK_QUERY (21B)
[0..11]  6 × i16 关节(舵机度)    [0..7]   i16 X/Y/Z/Pitch
[12..17] i16 X/Y/Z              [8..19]  6 × i16 关节(舵机度)
[18]     i16 Pitch              [20]     u8 read_ok  ← 裸 0/1
[20]     u8 flags (位域)                    ↑ 不是位域！
   bit0 estop  bit1 traj
   bit2 corr   bit3 read_ok
```

**别复用同一个解码器。** 参考实现：`decode_status()` / `decode_fk()`。

### 已验证的 hex 例子

| 请求 | 字节 |
|---|---|
| PING, seq=0x31 | `31 01 00 38 0D` |
| PARAM_COUNT, seq=0x43 | `43 42 00 CF E3` |
| STREAM_JOINTS `[0,10,20,30,40,50]` | `00 00 64 00 C8 00 2C 01 90 01 F4 01` |

（`arm_sdk.protocol._selftest()` 会逐字节核对这三条。）

## 3.5 扩展 24 条（2026-09-23 全指令覆盖）

### 3.5.0 ⭐ 一句话架构：`TEXT_EXEC` 把整个控制台搬到了网口

控制台有 **124 条**命令，网口原来只有 14 条。逐条加 opcode 追不上新增、
而且会造成"两份实现迟早分叉"。所以：**热路径留类型化 opcode，长尾走一条
`TEXT_EXEC`** —— 它执行的就是 COM11 上**同一条** `ProcessCommand`，
语义零漂移，11 条抢引脚命令的安全拦截也天然继承。

| 码 | 名称 | 方向 | 请求负载 | 响应 |
|---|---|---|---|---|
| 0x04 | GET_JOINT_DETAIL | Q | u8 joint(0~5 / 0xFF=全) | `0x84`: u8 n + u8 joint0 + n×**10 B** |
| 0x05 | GET_LIMITS | Q | — | `0x85`: 6×8 B = 48 B |
| 0x07 | GET_INFO | Q | — | `0x87`: u8 tag_len + char[16] + u8 build + u8 link + u8 nsrv = 20 B |
| 0x0A | GET_FLAGS | Q | — | `0x8A`: u8 flags + u8 run_id = 2 B |
| **0x0B** | **TEXT_EXEC** | C | **u32 magic + char text[]**(NUL 结尾, ≤58) | `0x8B`: 分页 |
| **0x0C** | **TEXT_FETCH** | Q | u16 off + u8 n(1~58) | `0x8C`: 分页 |
| 0x14 | MOVE_JOINT_ONE | C | u8 joint + i16 deg×10 + u16 v×10 + u16 a×10 = 7 B | ACK |
| 0x17 | SET_BUS_MODE | C | u8 mode(0/1/2) | ACK |
| 0x18 | SERVO_INIT | C | u8 joint(0~5 / 0xFF) | ACK |
| 0x22 | IK_QUERY | Q | i16 x,y,z(mm×10) + i16 pitch×10 = 8 B | `0xA2`: 6×i16 舵机度×10 |
| 0x32 | GET_GRAVITY | Q | — | `0xB2`: i16 K(×1000 deg/mm) |
| 0x33 | GET_CORRECTION | Q | — | `0xB3`: u8 en + u16 thr×100 + u8 rounds + u8 pending = 5 B |
| 0x36 | GET_PID | Q | u8 joint(0~5) | `0xB6`: u8 p + u8 i + u8 d + u8 from_eeprom = 4 B |
| 0x43 | PARAM_SAVE | C | **u32 magic** | ACK（= 文本 `F`） |
| 0x44 | PARAM_LIST | Q | u8 offset | `0xC4`: u8 total + u8 n + n×**10 B** |
| 0x50 | TEACH_LIST | Q | u8 idx | `0xD0`: 19 B |
| 0x51 | TEACH_READ | Q | u8 idx + u16 off + u8 n(1~5) | `0xD1`: u8 n + n×12 B |
| 0x53 | TEACH_DELETE | C | u8 idx | ACK（写 tombstone） |
| 0x54 | TEACH_COMPACT | C | — | ACK |
| 0x55 | TEACH_TOTAL | Q | — | `0xD5`: u8 nfiles + u8 capacity + u32 total + u32 free = 10 B |
| 0x70 | CENTER_CALIB | C | **u32 magic** | ACK（= 文本 `M a`）⚠ |
| 0x71 | CALIB_ENTER | C | **u32 magic** | ⚠ **一律 NACK(err=1)** |
| 0x72 | ZERO_RESET | C | **u8 flags(bit0=落盘) + u32 magic** | ACK（= `zr` / `zr save`）⚠ |
| 0x73 | SYS_RESET | C | **u32 magic** | ACK **之后** 150 ms 才复位 ⚠ |

`magic = 0x5A5A5A5A`。**`TEXT_EXEC` 无条件要求 magic**（它能做的事等于整个控制台）。

### 3.5.1 逐条载荷布局

```
0x84 GET_JOINT_DETAIL           每轴 10 B（6 轴 = 2 + 60 = 62 ≤ 64）
  u16 pos_raw(0~4095)
  i16 speed(step/s)
  i16 load(有符号)
  u8  volt(0.1V)
  u8  temp(°C)     0xFF = 这一拍丢读
  u8  err(硬件错误位) 0xFF = 读失败
  u8  ok(1=本轴读成功)
  ⚠ 总线**逐字段瞬时丢读**(Angle≈5% / Temp≈20%, 各自独立)
    ⇒ temp=0xFF / err=0xFF 是"没读到"，不是"0 度"、也不是"硬件报错"。

0x85 GET_LIMITS                 6 × 8 B = 48 B
  每轴 u16 min_raw, pos_raw, max_raw, zero_raw
  ⚠ 这是 **Flash 校准记录**，不是运行时限位(J1 63~303 那套没进协议)。
  ⚠ zero_raw == 0 ⇒ 该轴未做 Home 零点校准，固件回落 180°/raw 2048。

0x87 GET_INFO                   20 B
  u8 tag_len + char fw_tag[16] + u8 build + u8 link + u8 nsrv
  build: 0=net 1=can 2=both 3=uart 4=off
  ⚠ link 是 LinkCfg_ActiveMode() 的**启动冻结值**，不是 Flash 偏好 ——
    「改了偏好还没 RESET」时两者分叉。

0x8A GET_FLAGS                  2 B
  u8 flags: bit0=E-Stop bit1=轨迹 bit2=流模式 bit3=修正
            bit4=示教录制 bit5=示教回放
  u8 run_id
  ⚠ 只读变量、不碰总线 ⇒ 可 10~50 Hz 轮询做 UI 状态灯(GET_STATUS 要读 6 轴)。

0x8B / 0x8C 文本透传分页
  u16 total | u8 flags | u16 off | u8 n | char text[n]
  flags bit0 = 输出被 ARM_TEXT_BUF_SZ(2048) 截断
  flags bit1 = 被安全闸门拒绝（正文是**原因说明**，不是命令输出）
  ⚠ total / off 都是**字节**数。中文提示是 UTF-8 字节 ⇒
    PC 侧必须**按字节拼接、最后统一 decode 一次**；
    逐页 decode 会在分页缝上拼出坏字符（一页 58 B 很容易切在 3 字节汉字中间）。
  ⚠ 每页正文上限 58 B（6 B 头 + 58 = 64）。

0xA2 IK_QUERY                   6 × i16 舵机度×10 = 12 B
  **只解不算**：解算 + 限位检查 + FK 回代，不启动运动。
  失败：err=3 不可达 / err=4 超关节限位 / err=6 回代超差。

0xB2 GET_GRAVITY                i16 K(×1000 deg/mm) = 2 B
0xB3 GET_CORRECTION             5 B: u8 en + u16 thr×100 + u8 rounds + u8 pending
0xB6 GET_PID                    4 B: u8 p + u8 i + u8 d + u8 from_eeprom
  ⚠ 顺序就是 p/i/d。固件底层 SERVO_ReadPidEeprom 形参是 (p,d,i)，
    API 层已换算 —— **不要再换一次**。
  ⚠ from_eeprom=0 ⇒ **读失败**，p/i/d 不可信。

0xC4 PARAM_LIST                 2 + n×10 B，n ≤ 6（62 ≤ 64）
  每条: u8 id + u8 type + i32 vmin×1000 + i32 vmax×1000
  ⚠ 必须是 i32：范围里有超过 i16 的值(traj.approach_speed 上限 4095)，
    压成 i16 会**静默截断**。
  ⚠ 值不在这一包里 —— 带上会超 64 B，用 PARAM_READ 单取。
  翻页终止: n == 0 或 offset + n >= total。

0xD0 TEACH_LIST                 19 B
  u8 total + u8 idx + u8 valid + char name[12] + u32 samples
  valid=0 ⇒ 该槽位是 tombstone(已删未回收)。

0xD1 TEACH_READ                 u8 n + n×12 B(6×u16 raw)
  12×5 = 60 ≤ 64。1000 点轨迹 = 200 次请求 ≈ 0.3 s @p50 1.61 ms。
  ⚠ off 越界 ⇒ n=0，那是"**正常读完**"，不是错误。

0xD5 TEACH_TOTAL                10 B
  u8 nfiles + u8 capacity + u32 total_samples + u32 free_bytes
```

### 3.5.2 危险操作的三条注意

1. **`ZERO_RESET` 没有关节号** —— 文本 `zr` 根本没有单轴变体（一次复位全部
   六轴）⇒ 协议也不给，不猜。`flags.bit0=1` 等价 `zr save`（写 Flash）。
2. **`CALIB_ENTER` 一律 NACK 是设计而非漏项** —— `cmdCalibrate()` 里是
   `for(;;)` 等人在**本机串口**敲键；从网口进 = 主循环永不返回，而本工程
   **没有看门狗** ⇒ 板子彻底失联但 USB 还在枚举。保留码位是为了让"不可用"
   在协议层面**显式可见**。
3. **`SYS_RESET` 先回 ACK、150 ms 后才复位** —— 顺序反了上位机只会看到超时，
   分不清"复位成功"和"包丢了"。远程切链路完整序列：
   `TEXT_EXEC("link can")` → `TEXT_EXEC("link save")` → `SYS_RESET`。

### 3.5.3 `TEXT_EXEC` 的边界（务必知道）

| 情况 | 表现 |
|---|---|
| 124 条里的 **113 条** | 正常执行，输出自动翻页取回 |
| 11 条抢 ETH 引脚的（`cx cp cy cz cw ps can mg mp mo ml`） | 固件**接住并把原因当输出回给你**（`flags.bit1 = 0` —— **不算闸门拒绝**） |
| `c`（校准向导） | 闸门拒绝，`flags.bit1 = 1`，正文是原因 |
| 急停中 | 只放行 `s` / `h` |
| 命令 > 58 字符 | **客户端就该拒**（固件会钳断，而半条命令往往是**另一条命令**） |
| 输出 > 2048 B | 截断并置 `flags.bit0`（`h` 帮助表 5406 B 就是这种） |

⚠ 闸门**刻意不重复列那 11 条抢引脚命令**（那判断在 `ProcessCommand` 开头）。
PC 侧要能区分"被策略拒"(`gated=true`) 与"这条命令在当前链路物理上不可用"
(`gated=false` + 正文是引脚解释)。

## 5. ★ 六种"一个字节都不回"的情况

只看"超时"是分不清的，必须逐条排查：

1. `LEN` 与数据报实际长度不符（`5 + LEN != len(datagram)`）→ **静默丢弃**
2. 目的端口不是 **5000**
3. 目的 IP 不是本板
4. 入站 `CMD >= 0x80` —— **刻意不回**（防双方互相回包死锁）
5. CRC 错 —— **唯一会回包的坏包**：回 NACK err=2
6. 当前构建没开网口（`link` 偏好未落盘/未 RESET，或本构建是 `LINK=can`）

> 6 的排查：串口敲 `h`，看首行 `active=`；或 `link`。

## 6. 哨兵与"读失败"

| 项 | 值 |
|---|---|
| 原始读失败哨兵 | `-32768`（`0x8000`） |
| GET_STATUS flags.bit3 | `read_ok` |
| FK_QUERY offset 20 | `read_ok`，**裸 0/1** |

**铁律：`read_ok=0` 或某轴 = `None` 时，绝不填 0 / 绝不填上次值。** 如实上报，让上位机自己决定。

舵机总线还会**逐字段瞬时丢读**（不是某轴坏）：Angle≈5% / Temp≈20% / Moving≈33%，各自独立随机。单次读数不可全信，上位机应做滑窗健壮化。

## 7. ★ 两套角度体系（头号 bug 源）

| 体系 | 范围 | 谁用 |
|---|---|---|
| **舵机度** servo_deg | 0~360（wrap） | GET_STATUS / FK_QUERY / MOVE_JOINTS / MOVE_CART |
| **逻辑角** logical_deg | 相对本臂 Home，归一到 (-180,180] | **STREAM_JOINTS (0x13) / `#P`（遥操）** |

```
舵机度 = (offset[j] + dir[j] * 逻辑角) mod 360
逻辑角 = wrap180(dir[j] * (舵机度 - offset[j]))

JOINT_DIR = [-1, +1, +1, +1, +1, +1]      # 只有 J1 反向
offset 默认 180.0（未校准）；真值用串口 `zi` 读 calib_zero_raw
```

参考实现：`arm_sdk.protocol.JointCalib`；从 `zi` 文本解析：`parse_servo_offset_from_zi()`。

> 两臂都校准到**同一物理基准**，逻辑角才可比。否则遥操一开就从臂猛冲。

## 8. STREAM_JOINTS 硬约束

| 约束 | 值 | 后果 |
|---|---|---|
| 断流看门狗 | **500 ms** | 从臂自动退出流模式并**原地自锁** ⇒ 频率必须 >2 Hz，建议 20~50 Hz |
| 单帧单轴跳变 | **>25°** | **整帧拒收** err=4，**且不更新跳变基准** ⇒ 同一目标反复发会一直拒（**自锁冻结**） |
| 单帧字节 | 12 B | 装得下（LEN ≤ 64） |
| 门闩 | 从臂 `sf 0/1` | `sf 0` 时忽略所有流帧（0x13 与 `#P` 都受影响） |

**对策**：发送端限速（`TeleopSession` 默认 240°/s = 4.8°/帧 @50Hz，离 25° 有 5× 余量），
而不是依赖固件拒帧 —— 拒帧会自锁。

## 9. 三个"静默钳制"陷阱（err=0 但值被改了）

| 命令 | 行为 |
|---|---|
| `MOVE_JOINTS` 目标角 | 超限静默钳制，仍回 err=0（只在串口打 WARNING） |
| `PARAM_WRITE` 值 | 超范围静默钳制，仍回 err=0 ⇒ **必须回读确认** |
| `STREAM_JOINTS` 单轴 | 被限位夹住时照常成功，不打日志（`lk` 里有逐轴 clamp 计数） |

另外：`MOVE_JOINTS` 的 **err=0 只代表"命令被收下"** —— 读起点失败时固件也回 ACK 但轨迹没起步。
判断"动没动"必须再 `GET_STATUS` 看角度是否真的变了。

参考实现：`ArmClient.move_joints()` 的 docstring、`param_write_verified()`。

## 10. 运行时参数（PARAM_READ/WRITE）

`PARAM_COUNT` 现役 24 项（`LP` 表长 46，**不连续是正常的**）。

| id | 名 | 单位 | 范围 | 默认 |
|---|---|---|---|---|

## 11. 已知缺口

### 11.1 已被 2026-09-23 扩展**关闭**的

| 原缺口 | 现在怎么读 |
|---|---|
| 关节遥测（温度/负载/电压/硬件错误）只能串口 | `GET_JOINT_DETAIL(0x04)` |
| Flash 限位与 Home 零点只能 `zi` | `GET_LIMITS(0x05)` |
| 固件 tag / 构建 / 运行链路只能 `h` 首行 | `GET_INFO(0x07)` |
| 状态位只能 `ms` | `GET_FLAGS(0x0A)` |
| 参数**元数据**（范围）只能 `LP` | `PARAM_LIST(0x44)` |
| 参数落盘只能 `F` | `PARAM_SAVE(0x43)` |
| 示教文件列表/内容只能 `list`/串口 | `TEACH_LIST/READ/TOTAL(0x50/51/55)` |
| 补偿/PID 的**读**侧缺失 | `GET_GRAVITY/GET_CORRECTION/GET_PID(0x32/33/36)` |
| "这条轨迹能不能到"要先发再撞 | `IK_QUERY(0x22)` 只解不算 |
| 长尾 113 条命令无法网口下发 | ⭐ `TEXT_EXEC(0x0B)` |

### 11.2 仍然存在

1. **运行时关节限位** `L`（舵机度 J1 63~303 / J2 75~284 / J3 76~271 /
   J4 71~284 / J5 12~351 / J6 138~266）**没进协议** —— 只能文本读
   （`TEXT_EXEC("L")`，输出 < 2048 B，装得下）。
2. 舵机逐字段瞬时丢读（见 §6），**无协议层去抖**。`GET_JOINT_DETAIL` 给了
   `temp`/`err` 的 `0xFF` 哨兵，但要去抖得上位机自己做滑窗。
3. `STREAM_JOINTS` 被拒时只在串口打限流日志；**网口查不到"当前跳变基准"**。
4. **没有统一错误计数器查询**（出错只能看串口）。
5. E-Stop 实时读 PE11 但**不自锁** ⇒ 人不要停在扫过区。
6. `GET_EVENTS(0x06)` 码位保留但**未实现**；用 `GET_FLAGS` 轮询代替。

> 第 3 条的缓解：`ArmClient.stats.stream_limit` 在主机侧累计 err=4 次数；
> `TeleopSession` 把 `slew_clamped` / `ack_limit` 都记进 stats。

## 12. 上板前的最小验证顺序

```
1. armctl preflight                        # PING + 6 轴全读到 + 无 E-Stop
2. armctl status                           # 看舵机度与位姿
3. armctl move --delta 0,+5,0,0,0,0 --v 5  # 单轴小步点动（★必须 --delta）
4. armctl stream --pose "0,0,0,0,0,0" --hz 50 --sec 2   # 验证流模式
5. armctl teleop --leader ... --follower ...            # 主从遥操
```

串口侧同步做（`armctl console --port COM11 --cmd h --cmd zi --cmd L`）：
`h` 看 fw-tag、`zi` 看零点是否被污染、`L` 看运行时限位。

### 12.1 新增命令的自检顺序（2026-09-23）

```
1. armctl text --cmd h          # 固件 tag / 构建 / 链路（也可 armctl-js diag）
2. armctl text --cmd zi         # Home 零点是否被污染（zero_raw 全 0 = 未校准）
3. armctl info 或 GET_INFO(0x07) # 确认 link 是 net
   GET_FLAGS(0x0A)              # estop=0 / traj=0 ⇒ 可以动
4. armctl text --cmd s          # 先读，再动
5. GET_JOINT_DETAIL(0x04)       # 任一轴 ok=0 ⇒ 总线有问题，别急着动
6. IK_QUERY(0x22)               # 想去的点在不在包线内（只解不算）
7. TELEOP / MOVE_JOINTS         # 才开始动
```

⚠ **`TEXT_EXEC` 敲不动 11 条抢引脚命令是正常的**（输出里会写原因），
不要以为网口坏了。
