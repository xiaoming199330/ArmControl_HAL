# 配置文件说明

本 SDK 里有 **两个** 配置文件，职责完全不同，**不要混用**：

| 文件 | 谁改 | 改什么 | 生效方式 | 性质 |
|---|---|---|---|---|
| `config/arm_config.json` | **你只读，不改** | —— | —— | **接口契约（真值源）** |
| `launchers/arm_link_config.json` | **你改** | 主/从臂地址、频率、限速、示教时长 | 下次启动启动器时读 | **部署配置** |

一句话：**`config/` 是"臂长什么样、能听什么话"，`launchers/` 是"我这台机器怎么连它"。**

---

## 一、`config/arm_config.json` —— 接口契约（只读真值源）

### 1.1 它是什么

一份 **113 KB / 40 章** 的 JSON，把固件的全部对外接口**机器可读地**镜像了一份。
它是"**参数不要硬编码**"这条规矩的落点：固件升级后你只要换这份 JSON，代码不用动。

> ⚠️ 它**不是运行时配置** —— STM32 固件启动时**不解析**这个文件（`_purpose` 字段里写明了）。
> 改它不会改变机械臂行为，只会改变**你的上位机读到的数**。要改真行为得用文本命令 / 网口命令
> （很多还要 `F` 存 Flash）。

### 1.2 顶层结构（`arm_config` 下 39 节）

| 节 | 内容 | 你什么时候要读它 |
|---|---|---|
| `_firmware_tag` | 三个构建的 fw-tag（`ARM-NET-…` / `ARM-CAN-…` / `ARM-BOTH-…`） | ★ 开机自检，对不上就别往下走 |
| `_control_policy` | 6 条控制铁律（链路判定 / 禁热切换 / 角度两套量纲 / 读失败不兜底） | ★ 写第一行代码之前 |
| `console_contract` | 14 条二进制命令的**串口契约**（帧头 AA55 等） | 走串口时 |
| `network_protocol` | ★ **网口协议全字段**：`transport` / `packet_layout` / `crc16` / `error_codes` / `commands`(38) | ★★ 走网口时**必读** |
| `extension_2026_09_23` | 24 条扩展命令的**叙述块**：架构、四条铁律、与提案的 7 处偏差、逐条 notes | 想知道"为什么这么设计" |
| `link_switch` | `link` / `link save` 命令语义、Flash 扇区 11 区 C、三构建指纹 | 网口不通时（第一嫌疑） |
| `carriers` | 三条承载（`udp` / `serial` / `can`）的**外壳字节、最大长度、丢包情形、实测延迟** | ★ 选链路时 |
| `binary_protocol_commands` | 16 条**串口**二进制命令码 | 走串口二进制时 |
| `commands` | ★ **114 条文本控制台命令**（每条含 `name` / `syntax` / `group` / `terminator` / `help` / `notes`） | ★★ 用 `TEXT_EXEC` 透传时 |
| `commands_meta` | 命令字字母含义表（`m`=move / `q`=queue / `QL`=queue+Loop …） | 读命令时查 |
| `mechanical` | DH 参数、连杆尺寸（`d1=58 / a2-4=54 / a5=64 / a6=0`）、底座高度 30 mm | 自己算 FK/IK、画 3D |
| `ik_solver` | IK 求解器配置（迭代上限、收敛阈值） | 校验 `IK_QUERY` 结果 |
| `world_offset` | 世界坐标偏移 `actual = model + offset`（`C dx dy dz` 设） | 基座不在原点时 |
| `joint_limits` | 各轴限位（**展示用度值**） | ⚠️ 见 §1.4 警告 |
| `servo_offsets` / `servo_config` / `servo_registers` / `servo_pid` | 舵机偏移、ID、量程、PID 寄存器映射 | 写标定工具时 |
| `pid_tuning_guide` | 调参指引 | 做 PID 面板时 |
| `gravity_compensation` / `adaptive_correction` / `teach_zero_force` | 重力补偿 K、自适应修正、示教零力 | 做补偿/示教功能时 |
| `predefined_poses` | `P0_HOME` ~ `P4_WAVE2` 五组预设姿态（**运动学关节角**，非舵机度） | 做"回原位"按钮 |
| `home_dock` | 折叠位白名单容差（`tol_deg=3.0` / `desk_margin_mm=3.0`） | 理解为什么某些点不报限位 |
| `trajectory` | 轨迹队列上限、插值方式 | 做轨迹编辑器 |
| `runtime_parameter_table` | ★ 运行时可调参数表（LP/SP 指针绑定的活变量） | 做参数面板 |
| `communication` | 串口波特率 / 超时建议 | 走串口 |
| `gpio` / `clock` | 引脚占用表、定时器占用表 | 排查"为什么这条命令动了网口" |
| `can_control` | CAN ID 三段（`0x100+node` / `0x180+node` / `0x280+node`） | 走 CAN |
| `leader_follower` | 主从遥操配置 | 做遥操 |
| `teleop_teach` | 示教录制/回放配置 | 做示教 |
| `host_sdk` | SDK 安装方式、分层说明 | 上手 |
| `host_integration_guide` | ★ 上位机对接建议：首选链路、超时建议、成功/失败关键词、开机自检清单 | ★★ 第一次对接 |

### 1.3 怎么读（Python / JS 都给了口子）

```python
import json
cfg = json.load(open("config/arm_config.json", encoding="utf-8"))["arm_config"]

tag   = cfg["_firmware_tag"]["net"]                       # "ARM-NET-0923B"
cmds  = cfg["network_protocol"]["commands"]               # 38 条
limits = {k: v for k, v in cfg["joint_limits"].items() if k.startswith("J")}
text  = {c["name"]: c for c in cfg["commands"]}           # 114 条，按命令字索引
```

SDK 自己也是这么读的（`arm_sdk/protocol.py` 启动时加载它），所以**不会出现"文档说 A、SDK 做 B"**。

JS 侧同理：`js/src/protocol.js` 读同一份 JSON；`npm test` 里有跨语言对拍。

### 1.4 ⚠️ 四个必须知道的坑

1. **`joint_limits` 里的度值只用于显示**。
   真值权威是**原始值空间** `JOINT_MIN_RAW/MAX_RAW`（0~4095，wrap-aware），由标定 `c` 和 `L` 命令
   重算。JSON 自己就写了 `_display_only: "never derive raw limits from these deg values"`。
   要活值就敲 `L`（或网口 `GET_LIMITS 0x05`）。

2. **两套角度量纲**（头号 bug 源）。
   `GET_STATUS` / `FK_QUERY` / `MOVE_JOINTS` / `MOVE_CART` 用**舵机度（0~360）**；
   `STREAM_JOINTS` / `#P` 用**逻辑角（相对 Home 零点）**。
   同一份 JSON 里两套并存，别串。

3. **`predefined_poses` 是"运动学关节角"**（0 = Home 位），不是舵机度。
   固件在运行期才转成舵机度（`main.c POSE_*_J`）。

4. **`_` 开头的键是注释**（JSON 不支持 `//`）。解析时跳过，
   但**别把它当成可写字段**。

### 1.5 这份 JSON 是怎么来的（以及为什么你不能手改它）

```
tools/net_ext_2026_09_23.py   ← 24 条扩展命令的叙述块 + 逐条 notes（手写在这）
tools/gen_arm_config_json.py  ← 读固件源码 + 上面那个块，生成 JSON
        │
        ├─→ config/arm_config.json                        （仓库真值）
        ├─→ sdk_package/arm_sdk/arm_config.json           （pip 装包后 import 读这份）
        ├─→ sdk_package/config/arm_config.json            （交付物里的"接口契约"）
        └─→ sdk_package/data/arm_config.json              （历史路径，保留兼容）
```

**四个落点由同一个脚本一次写出，字节完全一致。**
（2026-09-23 之前后两个是手工同步的旧副本 —— 结果漂移成 09-21 的内容：只有 14 条网口命令、
缺 24 条扩展。已修：现在四份由生成器统一写。）

于是：
- **你手改 `arm_config.json` 会被下次重生成抹掉** —— 要改就改 `tools/net_ext_2026_09_23.py`
  或 `tools/gen_arm_config_json.py`，然后重跑生成器。
- 生成后**必须**跑一致性闸门（三选一，建议全跑）：

```bash
python tools/check_arm_config.py    # JSON ↔ 固件源码交叉校验（注册表/白名单/命令码/CRC 向量）
python tools/check_proto_doc.py     # 文档里的 hex 报文 ↔ 协议实现
python tools/check_cprint_len.py    # 固件 cprint 单次 ≤255 字节（红线 4）
```

`check_arm_config.py` 会把"JSON 独有 / 固件独有"的差异**显式列出来**，
所以它既能防漏登记，也能当差异审阅工具用。

## 二、`launchers/arm_link_config.json` —— 部署配置（你要改的就是这个）

### 2.1 它管什么

主从遥操 / 遥操示教的**唯一**配置入口。两个启动器（`launch_teleop.py` / `launch_teach.py`）
启动时读它。**改这个文件不用改代码。**

### 2.2 字段全表

| 字段 | 默认 | 含义 / 怎么填 |
|---|---|---|
| `leader` | `net://192.168.7.121:5000` | 主臂地址。**手扳的那台** |
| `follower` | `net://192.168.7.120:5000` | 从臂地址。**跟着动的那台** |
| `timeout_s` | `0.3` | 单次请求超时。网口实测 p50 1.61 ms ⇒ 0.3 s 有 190× 余量 |
| `hz` | `50.0` | 遥操帧率。**必须 >2 Hz**（断流 >500 ms 从臂退出流模式并原地自锁） |
| `slew_deg_per_s` | `240.0` | 限速（逻辑角）。**别超 400**：固件单帧单轴跳变 >25° 会整帧拒收 + 不更新基准 ⇒ 连续几次自锁冻结。240°/s @50 Hz = 4.8°/帧，留 5× 余量 |
| `gain` | `1.0` | 主→从比例。`0.5` = 从臂只走一半（更安全，适合第一遍） |
| `sync` | `"hold"` | 起遥操前是否先对齐：`hold`=把从臂拉到主臂当前位姿；`none`=不齐 |
| `reverse` | 6×`false` | 反向。可写 `true`（全轴反）或 6 个布尔（`true` = 该轴反）。**镜像安装的从臂通常 J1/J4/J5/J6 要反** |
| `soft_limits_deg` | `null` | 软限位，6 组 `[min,max]`（**逻辑角**）。`null`=不限。收紧写 `[[-20,20],[-20,20],[-20,20],[-20,20],[-70,70],[-33,33]]` |
| `enable_torque` | `true` | 启动时是否使能力矩。调试接近开关时可关 |
| `serial.leader_port` / `follower_port` / `baud` | `COM9`/`COM11`/`115200` | 只有走**串口路线**才用。COM 号会漂移，插拔后在设备管理器确认 |
| `teach.out_dir` | `"trajectories"` | 示教文件输出目录（**相对本文件所在目录**） |
| `teach.name` | `"demo"` | 默认文件名（≤11 字符，`A-Za-z0-9_-`） |
| `teach.duration_s` | `30.0` | 默认录/放时长 |
| `teach.playback_speed` | `0.5` | 回放倍速。**第一遍先 0.5** |
| `teach.playback_loop` | `1` | 回放循环次数 |

> `_comment` / `_comment_addr` / `_comment_safety` / `_comment_reverse` /
> `_comment_soft_limits` / `_comment_serial` / `_comment_teach` 是注释，程序忽略。
> **所有字段都有内置默认值**，缺项自动取默认 —— 所以你可以只写要改的那几行。

### 2.3 地址写法（`--leader` / `--follower` 也接受同一套）

| 写法 | 链路 | 实测 |
|---|---|---|
| `net://192.168.7.120:5000` | 网口 UDP | ★ 首选，p50 **1.61 ms** / 547 帧·s⁻¹ / 零超时 |
| `serial://COM11` 或 `serial:///dev/ttyUSB0` | 串口（USART6 115200 8N1） | p50 4.78 ms |
| `can://` | CAN 2.0A 500 kbit/s | p50 2.72 ms |
| `sim://` | **内存假臂**，无需硬件 | 离线演练、CI |

现场没接线时用 `sim://` 先把两个启动器跑通，再换真地址。

### 2.4 软限位两种写法

```
"soft_limits_deg": [20,20,20,20,70,33]                    ← 对称，只要一半
"soft_limits_deg": [[-20,20],[-20,20],[-20,20],[-20,20],[-70,70],[-33,33]]   ← 完整
```

命令行覆盖：`--soft-limit "-20:20,-20:20,-20:20,-20:20,-70:70,-33:33"`。
建议按**运行时限位**（`L` 读到的）收紧，别贴边 —— 见 §2.5。

### 2.5 现场实测限位（填软限位时参考）

| 轴 | 限位（度，舵机度） |
|---|---|
| J1 | 63 ~ 303 |
| J2 | 75 ~ 284 |
| J3 | 76 ~ 271 |
| J4 | 71 ~ 284 |
| J5 | 12 ~ 351 |
| J6 | 138 ~ 266 |

六轴全动推荐包线（逻辑角）：**J1~J4 ±20° / J5 ±70° / J6 ±33°**。

### 2.6 改完怎么验

```bash
cd launchers
python launch_teleop.py --preflight-only          # 只预检，不动臂
python launch_teleop.py                           # 正式起（6 步打印）
```

预检会连着报：`PING` / `GET_STATUS` / 读失败轴 / E-Stop / `fw-tag` / `zi` 零点 / `L` 限位。
**只读，安全。**

## 三、还有哪些"配置"

除了上面两个 JSON，还有三类**不在 JSON 里**的配置，容易漏：

| 类型 | 在哪 | 怎么改 | 生效 |
|---|---|---|---|
| **板子链路偏好** | 固件 Flash 扇区 11 区 C（`0x080E2000`） | 串口敲 `link net` → `link save` | **必须按 RESET**（运行期挪不动引脚 AF） |
| **运行时参数** | 固件 RAM，指针绑定 `LP/SP`（见 `runtime_parameter_table`） | 文本命令 `LP n v` / 网口 `PARAM_WRITE(0x51)` | 立即；`F` 才存 Flash |
| **舵机 PID / 限位 / 中位** | 舵机 EEPROM | 文本 `Y J`（网口/串口） | 立即；`Y J` 存 EEPROM |

> ⚠️ **板子默认两条链路都关**，只留串口。所以"网口连不上"的第一嫌疑永远是
> `link net` → `link save` → **按 RESET** 没做。
> ⚠️ 改链路偏好是**冷启动**语义：不做热切换（工程红线 69）。
