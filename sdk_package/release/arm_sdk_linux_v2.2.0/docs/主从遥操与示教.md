# 主从遥操与示教（SDK 版）

> 固件侧长文档：`docs/主从臂联调步骤_2026-09-11.md`、`docs/遥操中录制示教轨迹_2026-09-16.md`
> 代码：`arm_sdk/teleop.py`（遥操）、`arm_sdk/teach.py`（示教/回放）

---

## 1. 三条路线，先选一条

| | A. 固件直连 | B. PC 中转（串口） | **C. 网口直写** ★ |
|---|---|---|---|
| 两臂之间接线 | PA0↔PA1 交叉 | **不需要** | **不需要** |
| PC 需要什么 | 1 根串口（发开关命令） | **2 根串口** | 1 个网口 |
| 延迟 | 板间 115200 | 串口往返 → 两条 | **p50 1.61 ms** |
| 优点 | 不占 PC | 不占网口 | 最快、可无损录制 |
| 风险 | **PA0/PA1 焊点不良**（现场踩过） | 两路各读一遍总线要 `mf 0` | 需网口可用 |
| SDK | `FirmwareLink` | `PcRelay` (+`tools/pc_relay.py`) | **`TeleopSession`** |

数据流三条**最终都汇到 `ArmApi_StreamJoints()`** 这一条通路，所以行为（限位/跳变/门闩）一致。

## 2. 路线 C：网口遥操（推荐）

```python
from arm_sdk import open_arm, TeleopSession, TeleopConfig, JointCalib

lead = open_arm("net://192.168.7.121:5000")     # 主臂
foll = open_arm("net://192.168.7.120:5000")     # 从臂

cfg = TeleopConfig(hz=50.0, slew_deg_per_s=240.0, sync="hold")
with TeleopSession(lead, foll, cfg=cfg) as tp:
    tp.run()                    # 拖主臂 → 从臂跟随；Ctrl-C 停
print(tp.stats.summary())
```

命令行等价：

```bash
armctl teleop --leader net://192.168.7.121:5000 --follower net://192.168.7.120:5000 --sec 30
```

### 2.1 核心公式

```
target[j] = foll_ref[j] + gain * sign[j] * (lead[j] - lead_ref[j])
```

* `lead_ref` / `foll_ref` 是**启动那一刻**两臂的各自姿态
* 所以**两臂起始姿态不同也安全** —— 从臂按"位移增量"跟随，不会被硬拉到主臂姿态

`sync` 两种模式：

| 模式 | 行为 | 用在哪 |
|---|---|---|
| `hold`（默认） | 不动从臂，直接开始按增量跟随 | 常规；从臂已在安全区域 |
| `align` | 先 `MOVE_JOINTS` 把从臂对齐到主臂当前姿态，再跟随 | 想让两臂姿态严格一致；**要求 Home 基准一致** |

### 2.2 为什么必须限速（`slew_deg_per_s`）

固件规则：**单帧单轴跳变 > 25° ⇒ 整帧拒收 err=4，且被拒时不更新跳变基准** ⇒ 会一直拒（自锁冻结）。

所以不能靠"固件会拒"来兜底，必须由发送端限速：

```
240 °/s @ 50 Hz = 4.8 °/帧      离 25° 门限有 5× 余量
```

`TeleopSession` 还会把每次削峰记进 `stats.slew_clamped`，`ack_limit` 记固件的拒帧次数 ——
**`ack_limit` 应该恒为 0**，一旦增长说明限速不够或起点太远。

### 2.3 存活与安全

| 情况 | 行为 |
|---|---|
| 主臂某轴读失败 | **hold** 上一有效目标继续发（保住流，避免 500 ms 自锁）；计入 `stats.held` |
| 连续读失败 > `link_loss_timeout_s`（默认 1 s） | 抛 `TeleopLinkLost` + `STOP` 从臂 |
| 主臂 flags.bit0 = E-Stop | `estop_trips=True` ⇒ `STOP` 从臂 + 抛 `TeleopAbort` |
| `hz < 3` | 直接拒绝启动（会掉流） |
| `STREAM_JOINTS` 丢帧 | **不重发**（非幂等命令，重发会重复规划） |

### 2.4 `reverse` / `gain`

```python
TeleopConfig(gain=1.0, reverse=False)          # 全轴同向（默认）
TeleopConfig(reverse=True)                     # 全轴反向
TeleopConfig(reverse=[0,0,1,0,0,0])            # ★只反 J3（该位为真 = 这一轴反向）
```

镜像安装的从臂一般 J1/J4/J5/J6 需要反 —— 但**先确认是不是校准基准不一致**，别用 reverse 去凑。

## 3. 路线 B：PC 中转（串口）

```python
from arm_sdk import ArmSDK, SerialTransport, PcRelay

lead = ArmSDK(SerialTransport("COM9", 115200), response_timeout=2.0)
foll = ArmSDK(SerialTransport("COM11", 115200), response_timeout=2.0)
with lead, foll:
    with PcRelay(lead, foll, hz=30) as rel:     # auto_gate=True 自动做前置
        rel.run(duration=30)
    print(rel.stats.summary())
```

`auto_gate=True` 会自动做三件前置（**顺序不能反**）：

1. 主臂 `mf 0` —— 静默固件直连链路。**不做的话两路各读一遍舵机，总线负载翻倍**
2. 从臂 `sf 1` —— 允许跟随
3. 从臂 `ma 0` —— 主臂保持手拖

另外强烈建议从臂 `ec 0`（关回显）：逐字符回显会白占发送线并挤掉收帧时间。

原理：主臂 `sp 30` 在控制台吐 `#P a1..a6`（逻辑角×10），PC 原样转发给从臂，从臂走同一条
`ArmApi_StreamJoints()`。**PC 就是那根线。**

### 编码要求（`#P` 与 0x13 同编码）

```
#P 12 -34 200 0 15 330      ← 每个值是 逻辑角×10 的四舍五入整数
```

`PcRelay` 用"round half away from zero"（不是 Python 的银行家舍入）。

## 4. 路线 A：固件直连（UART4 PA0/PA1）

```python
from arm_sdk import FirmwareLink
L, F = FirmwareLink(lead_console), FirmwareLink(foll_console)
print(L.link_status().text())    # lk：字节/帧/CRC 错/uart 硬件错
L.forwarding(True)               # mf 1
F.follow(True)                   # sf 1
```

### ★ 判"线到底通不通"只有一个判据

**命令不回错 ≠ 线是通的。** 必须看 `lk` 的字节数/帧数，或者主动自检：

| 命令 | 作用 | 需要跳线 |
|---|---|---|
| `ml 200` | 主臂自环发 200 帧，看 CRC 正确的回环帧数 | 不需要（内部回环），舵机断电也能跑 |
| `mg` | GPIO 级自环（PA0 当输出、PA1 当输入，连采 8 次打位图） | **需要**，且要拔链路 |
| `mp` | 引脚直流探测（内部上拉/下拉各采 8 次 + 推挽自检） | 不需要 |
| `mo A 1 0/1` | 把某脚输出并保持，用万用表找脚 | 不需要 |

> 现场教训（`主从臂联调步骤` §13）：PA0/PA1 **焊点不良**导致长期不通，而"敲命令没报错"。
> 所以这条路线的状态判定必须落在 `lk` / `ml` 上。

## 5. 遥操示教

### 5.1 PC 侧（推荐，无长度上限）

```python
from arm_sdk import TeleopTeachSession, Trajectory, PlaybackSession

with TeleopTeachSession(lead, foll, out="demo1.json", hz=50.0) as ts:
    ts.record(duration=60)                  # 一边遥操一边录
    # 真人遥操就 ts.record(duration=None) 然后 Ctrl-C
```

产物 `Trajectory`：

| 格式 | 用途 |
|---|---|
| `.json` | 单文件带元数据（SDK 首选） |
| `.jsonl` | 一行一帧，超大轨迹不占内存峰值 |
| `.csv` | `t,J1..J6` 表头，Excel/MATLAB 直接开 |
| `.npz` | numpy / LeRobot 数据集（需 numpy） |

**单位一律逻辑角（rel-home，度）**，与 `STREAM_JOINTS` / `#P` 同量纲。

变换/检查：

```python
t = Trajectory.load("demo1.json")
t.validate()                    # 点数/时长/采样率/单帧跳变/软限位
t.resample(50.0)                # 统一节拍
t.smooth(5)                     # 移动平均（首尾保留）
t.slice(1.0, 3.0)               # 裁段
t.scale_time(0.5)               # 加速 2×
t.save("demo1.csv")             # 按扩展名自动分派
```

### 5.2 回放

```python
with open_arm("net://192.168.7.120:5000") as arm:
    pb = PlaybackSession(arm, cfg=TeleopConfig(hz=50.0))
    pb.play(traj, speed=0.5, loop=3)
```

**`PlaybackSession` 会先做"接近段"**（`approach=True`）：
先 `MOVE_JOINTS` 走到轨迹起点，再开始流。

为什么必须做：如果当前姿态离轨迹起点很远，第一帧就是 >25° 跳变 ⇒
**每一帧都被拒**（表现为"回放跑完了但臂一动不动，`ack_limit` 一大堆"）。

其他安全项：

* 单帧步长硬限 `25° × 0.8 = 20°`，超了自动削（绝不触发拒帧）
* 每 `estop_check_s`（默认 0.5 s）查一次 E-Stop
* 回放前 `validate()` 有警告就提示（`armctl play` 要 `--force` 才继续）
* `warmup=3` 帧预热，保证从臂进入流模式

### 5.3 固件侧（独立演示用）

```python
from arm_sdk import FirmwareTeach
T = FirmwareTeach(foll_console)
T.enter_rec()               # teach rec：只读跟录，不碰舵机、不松力矩 ★PC 中转时用
# …拖主臂…
print(T.rec_list().text())  # ★存盘前必须核对点数
T.save("demo1")             # 阻塞 1~3 s
T.play("demo1", loop=False)
```

限制与坑：

| 项 | 值 |
|---|---|
| 容量 | 50 Hz × 4000 点 ≈ **80 s** |
| `save` | **阻塞 1~3 s**（CPU 冻结可接受） |
| 名字 | ≤11 字符 `A-Z a-z 0-9 _ -` |
| **丢录音的三种方式** | `rec clear` / 直接断电 / **再进一次 `teach`** |
| ⚠ `teach`（无参数） | **会松力矩**进手拖模式，臂会下沉 —— 要先托住 |

## 6. 排查表

| 症状 | 最可能的原因 | 怎么确认 |
|---|---|---|
| 从臂完全不动，`ack_limit` 一直涨 | 起点离轨迹太远（回放）/ `slew` 太大 | 看 `stats.ack_limit`；开 `approach`；调小 `slew_deg_per_s` |
| 从臂动一下就"冻住"，之后一直不动 | **25° 拒帧自锁**（基准没更新） | `lk` 看 `reject streak / max`；`stream_reject_max ≥ 20` = 自锁 |
| 从臂完全不接流帧 | `sf 0` 关过跟随 | `lk` 看 `follow: OFF`；发 `sf 1` |
| 从臂偶尔停一下 | 断流 >500 ms（PC 卡顿 / 频率太低） | `lk` 看 `watchdog(500ms)` 计数 |
| 一开遥操就从臂猛冲 | 两臂 **Home 基准不一致**（没校准或零点被污染） | 两边各敲 `ms` 对比；`zi` 看 calib_zero_raw 是否接近 2048×6 |
| 某个轴总是比别的轴慢 | 该轴被**限位夹住**（`clamp_raw()` 静默成功不打日志） | `lk` 的 `clamp(limit): frames N` + 逐轴报告 |
| PC 中转时命令响应里混进几百行 `#P` | 位置行没走异步通道 | 2026-09-22 已修（`ConsoleClient.on_position`） |
| 主臂 `sp` 开着但 PC 收不到位置行 | `sp` 没开 / 主臂在 teach 模式 | `ms` 看 `lines/skipped` 计数 |
| 丢控后从臂乱跑（RC 路线） | 接收机**继续输出预设行程**，旧"新鲜度"判据失效 | X/Y/Z 的 F/S 必须设中位 |
| 板子复位后臂下沉 | **复位必丢力矩** | 上运动测试前先 `m 180 180 180 180 180 180 15` |

## 7. 安全清单（上臂之前逐条打勾）

- [ ] 两臂 `h` 的 fw-tag 是**预期版本**（新版做了三区化，同 tag 也可能 md5 不同）
- [ ] `zi` 的 calib_zero_raw 接近 2048×6（不是全 0 = 已校准；不是被示教误触变小）
- [ ] `L` 的运行时限位与预期一致
- [ ] 两臂 `ms` 摆同一姿态，6 轴逻辑角接近（校准一致性）
- [ ] 从臂 `sf 1`
- [ ] 从臂 **E-Stop 在手上**（注意：**E-Stop 不自锁**，人不能停在扫过区）
- [ ] 运动前先回中位 `m 180 180 180 180 180 180 15`
- [ ] ⚠ **绝不能用 `M a`**（那是 `cmdCenterCalib()` 标定，会废掉量纲基准）
- [ ] `slew_deg_per_s` ≤ 240（50 Hz 下 4.8°/帧）
- [ ] 先小范围（±20°）跑一遍，再加幅度
