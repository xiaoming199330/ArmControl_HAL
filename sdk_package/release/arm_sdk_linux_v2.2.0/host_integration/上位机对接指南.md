## 0. 30 秒速览

```
你的上位机 ──UDP──▶ <臂的IP>:5000
   一个数据报 = 一个逻辑包，无帧头、无分包、无重传
   实测往返 p50 1.61 ms（CAN 2.72 / 串口 4.78）⇒ 50 Hz 有 15× 余量
```

```
┌─────┬─────┬──────┬────────────────┬──────────────┐
│ SEQ │ CMD │ LEN  │ PAYLOAD (LEN)  │  CRC_LO CRC_HI│
│ 1B  │ 1B  │ 1B   │ LEN ≤ 64       │  2B 小端      │
└─────┴─────┴──────┴────────────────┴──────────────┘
CRC-16/CCITT-FALSE(poly=0x1021, init=0xFFFF, 非反射, 无最终异或)
校验范围 = 前 (3+LEN) 字节
```

**动手前先做这一件事**：把 CRC 算对。

```c
arm_crc16("123456789", 9) == 0x29B1     // ← 不对就别往下写
```

三份参考实现都已经过了这套自检（C 用 `arm-none-eabi-gcc -Wall -Wextra` 语法检查通过；
Python 端 933 项随机对拍与 SDK 逐字节一致）。**直接抄它们的 CRC 函数**是最省事的路。

## 2. 一条命令的完整生命周期

### 2.1 发

```csharp
byte seq = ++mySeq;                       // 0~255 自增
byte[] pkt = Pack(seq, cmd, payload);     // 见 §0 格式
udp.Send(pkt, pkt.Length, new IPEndPoint(IPAddress.Parse(armIp), 5000));
```

### 2.2 收

必须做**四件事**，少一件都会在真机上出玄学问题：

| # | 检查 | 不做会怎样 |
|---|---|---|
| 1 | 长度 == `3+LEN+2` | 把截断的包当有效包解 |
| 2 | CRC 正确 | 解出垃圾数据且**看不出来** |
| 3 | `CMD < 0x80` 之外**按 SEQ 匹配** | UDP 乱序 ⇒ 把上一条的回答安到下一条上 |
| 4 | NACK 要取 `payload[1]` 当错误码 | 把"越限"当"成功" |

> **第 3 条最容易被忽略**。同一个 socket 上并发发 3 条命令，回包顺序不保证。
> 参考实现都用"**一把锁 + seq 匹配**"把请求串行化（和固件的单线程主循环同构）。
> 50 Hz 流控是唯一的例外 —— 那条**只发不等**。

### 2.3 超时与重试

| 场景 | 建议超时 | 说明 |
|---|---|---|
| 网口查询类 | **300 ms** | 实测 p50 1.61 ms，300 ms 已是 100× 余量 |
| 危险操作（落 Flash / 复位） | **2 s** | 扇区擦写本身就要时间 |
| TEXT_EXEC | **2.5 s** | 命令本身可能慢（如 `n` 扫总线几十秒） |
| 50 Hz 流控 | **不等** | 只发不等；用 ACK 统计做质量观测 |

**重试策略**：查询类可以重试 1~2 次；**运动类和危险类绝不要自动重试**
（重试 = 又动一次 / 又擦一次 Flash）。运动类失败就该停下来报给用户。

### 2.4 六个最常见的实现错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| `LEN` 写成 2 字节 | 固件**静默丢弃**，只表现为"超时"，查一天 | `LEN` 是 **1 字节** |
| `CRC` 大端存放 | 全部包被丢弃 | CRC **小端**存（低字节在前） |
| `MOVE_JOINTS` 的 v/a 不 ×10 或不按 u16 | 传 `v=20` 写 2（几乎不动）或 2000（满速冲），**且不报错** | v/a 是 **u16 且 ×10** |
| 把 `-32768` 当角度 0 | 腿读到"读失败"却显示 0°，操作员以为臂在那里 | 哨兵必须原样上报 → §5 |
| 每收一条就解码一条 TEXT 页 | 中文乱码（页边界切断 3 字节字符） | 按**字节**拼接，最后统一 UTF-8 解码 |
| **只取 TEXT 第一页就当读完了** | 长输出被**静默截断**，正则永远匹配不到 → 功能看起来"没实现" | **循环 `TEXT_FETCH` 到 `total`** → §4.9 |

> ⚠ 最后一条是**真机上真实踩过**的坑（2026-09-24）：`nx` 全文 1050~1311 B，
> 只取首页拿到 63 个字符，`udp cmd=` 字段在**第 20 页**里 ——
> 于是"读板侧计数"这个功能静默失效，还因为 `except: return None`
> 把原因也吞了，现象看起来像"板子不支持"。
> **凡是可能超过 58 字符回显的命令，一律要翻页**（`nx` / `h` / `i` / `L` / `s`）。

## 3. ★ 场景 → 发哪条指令（决策表）

`风险`列的含义：**read** 无副作用可随时发 ｜ **motion** 会动电机 ｜
**write** 改配置（建议二次确认）｜ **danger** 不可逆（**必须带 MAGIC** + 红字确认）

### 3.1 连接与自检

| 我要… | 发哪条 | 载荷 | 风险 | 判据 |
|---|---|---|---|---|
| 确认臂活着 | `0x01 PING` | 空 | read | 收到 `0x81`；`payload=[proto_ver, run_id]` |
| 看固件版本/构建/链路 | `0x07 GET_INFO` | 空 | read | `0x87`，20 B：`fw_tag`+build+link+参数数 |
| 首次上电自检 | 依次 `0x01 → 0x02 → 0x21` | — | read | 见 §4.1 |
| **做心跳（不打扰舵机）** | `0x0A GET_FLAGS` | 空 | read | `0x8A`，2 B。**只读变量、不碰总线** ⇒ 10~50 Hz 轮询都安全 |

> ⭐ **心跳请用 `GET_FLAGS(0x0A)`，不要用 `GET_STATUS(0x02)`**。
> 后者每次都真的去读 6 个舵机，会占掉总线时间片；前者只读几个标志位。

### 3.2 状态与显示

| 我要… | 发哪条 | 载荷 | 风险 | 说明 |
|---|---|---|---|---|
| 关节角度（做面板/曲线） | `0x02 GET_STATUS` | 空 | read | 21 B：6×i16 舵机度(0.1°) + X/Y/Z/pitch + flags |
| 温度/电压/电流/负载 | `0x04 GET_JOINT_DETAIL` | `u8 joint`（`0xFF`=全部 6 轴） | read | 62 B 一帧装得下；**温度有 0xFF 丢读哨兵** |
| 限位（画安全区/做校验） | `0x05 GET_LIMITS` | 空 | read | 48 B = 6×8B `min,pos,max,zero`（u16 raw） |
| 正解位姿（3D 显示） | `0x21 FK_QUERY` | 空 | read | `0xA1`：X/Y/Z/pitch + 六轴 + `read_ok` |
| 逆解预校验（**动之前先问**） | `0x22 IK_QUERY` | `i16 x,y,z ×10` + `i16 pitch ×10` | read | `0xA2`；无解回 `ERR_UNREACH(3)`，位姿不符回 `ERR_FK_VERIFY(6)` |
| 状态位图（E-Stop/轨迹/补偿） | `0x0A GET_FLAGS` | 空 | read | bit0 estop / bit1 traj / bit2 stream / bit3 corr / bit4 teach_rec / bit5 teach_play |
| 读一个参数 | `0x40 PARAM_READ` | `u8 id` | read | `0xC0`：`u8 id + i32 值(×1000)` |
| 枚举参数表 | `0x44 PARAM_LIST` | `u8 offset` | read | `0xC4`，每页 ≤6 条 ×**10 B**（`id,type,i32 vmin,i32 vmax`） |
| 参数个数 | `0x42 PARAM_COUNT` | 空 | read | 现役 **24** |

> ⚠ **`PARAM_LIST` 的范围字段是 i32 不是 i16** —— 有参数上限超过 32767
> （如 `traj.approach_speed` 上限 4095 但另一个参数到 60000+），
> 压成 i16 会**静默截断**，界面上就显示错范围了。

### 3.3 运动控制

| 我要… | 发哪条 | 载荷 | 风险 | 关键提醒 |
|---|---|---|---|---|
| **点动（按住不放）** | `0x13 STREAM_JOINTS` 循环发 | 6×i16 **逻辑角增量** ×10 | motion | ★ **别用 MOVE_JOINTS 做点动**：每次绝对角都会重新规划、且有 25°/帧门限 |
| 走到绝对角度 | `0x10 MOVE_JOINTS` | 6×i16 **舵机度** ×10 + u16 v×10 + u16 a×10 = 16 B | motion | ⚠ **舵机度不是逻辑角**；v/a 乘 10 |
| 只动一个轴 | `0x14 MOVE_JOINT_ONE` | 见速查 | motion | 任一轴丢读 ⇒ `ERR_READ(7)`，不兜底 |
| 走笛卡尔位姿 | `0x20 MOVE_CART` | i16 x,y,z(mm×10)+pitch(deg×10)+u16 v×10+u16 a×10 = 12 B | motion | ⚠ **会归零 J5/J6**（丢夹爪开合）；坐标原点是**夹爪中心 TCP** |
| **50 Hz 遥操/回放** | `0x13 STREAM_JOINTS` | 6×i16 逻辑角增量 ×10 | motion | ★ 必须**限速**：单帧单轴 >25° ⇒ **整帧拒收且不更新基准**，连续几次自锁冻结。50 Hz 下 240°/s = 4.8°/帧 |
| 停 | `0x11 STOP` | 空 | motion | 随时可发，**含 E-Stop 期间** |
| 上/卸力矩 | `0x12 SET_TORQUE` | `u8 joint`（0~5 或 `0xFF`）+ `u8 enable` | motion | 掉力矩的臂必须先上力；**卸力矩后臂会下沉** |

> ⚠ **`MOVE_CART` 会归零 J5/J6** —— 这是固件行为，不是 bug。想保住夹爪开合，
> 用 `MOVE_JOINTS` / `STREAM_JOINTS`。遥操一律用 `STREAM_JOINTS`。

### 3.4 参数与整定

| 我要… | 发哪条 | 载荷 | 风险 |
|---|---|---|---|
| 读 PID | `0x36 GET_PID` | `u8 joint` | read |
| 改运行时参数 | `0x41 PARAM_WRITE` | `u8 id + i32 值(×1000)` | write |
| **把参数落 Flash** | `0x43 PARAM_SAVE` | **magic(4B)** | write |
| 读重力补偿 K | `0x32 GET_GRAVITY` | 空 | read |
| 设重力补偿 K | `0x30 SET_GRAVITY` | `i16 K(×1000)` | write |
| 读/设补偿开关 | `0x33` / `0x31` | 见速查 | read/write |
| 日志级别（调试用） | `0x03 LOG_SET_LEVEL` | `u8 0~4` | write | 越大越啰嗦，**会占网口带宽**，调完记得调回 1 |

### 3.5 示教文件（固件侧存储）

| 我要… | 发哪条 | 说明 |
|---|---|---|
| 列出文件 | `0x50 TEACH_LIST` | `u8 idx`；**有 tombstone 语义**（删过但没压实的位置仍在） |
| 读采样点 | `0x51 TEACH_READ` | `u8 idx + u16 off + u8 n`（**n ≤ 5**，每点 12 B） |
| 删一个文件 | `0x53 TEACH_DELETE` | write |
| 压实（回收空间） | `0x54 TEACH_COMPACT` | write |
| 容量统计 | `0x55 TEACH_TOTAL` | read |

> 上位机自己做示教/回放（**推荐**）不需要走这里 —— 用 SDK 的
> `Trajectory` + `PlaybackSession`，**PC 侧没有固件那 80 秒上限**。
> 这一组命令是给"要读固件里已有的示教文件"或"不跑 PC 端"的场景。

### 3.6 ⚠ 危险操作（**必须带 MAGIC**，缺了回 `ERR_MAGIC(8)`）

| 操作 | 发哪条 | 载荷 | 后果 |
|---|---|---|---|
| 六轴中位标定 | `0x70 CENTER_CALIB` | magic | **废掉量纲基准** ⇒ 之后所有角度都不可信 |
| 交互式校准向导 | `0x71 CALIB_ENTER` | magic | ⛔ **从网口一律 NACK**，见下方说明 |
| 清 Home 零点 | `0x72 ZERO_RESET` | `u8 flags(bit0=落盘) + magic` | 量纲基准回到出厂中位。⚠ **没有关节号**（一次全六轴） |
| 软复位 | `0x73 SYS_RESET` | magic | 固件**延后到回包之后**执行，所以能收到 ACK |

> **`CALIB_ENTER` 为什么一律 NACK**：`cmdCalibrate()` 是 `for(;;)` 等人在**本机串口**
> 敲键的交互式流程。从网口进去 = 主循环永远不返回，而本工程**没有看门狗** ⇒ 臂彻底失联。
> **上位机的正确做法**：不要实现它。在 UI 上引导用户"插 USB 串口，用串口终端敲 `c`"，
> 或者用 §4.9 的 `TEXT_EXEC` 明确提示这条不支持。

MAGIC 前缀写法：**小端 4 字节 `0x5A5A5A5A`** → `5A 5A 5A 5A`。

### 3.7 ⭐ 不在上面任何一条里的功能

**先想到 `0x0B TEXT_EXEC`（见 §4.9）**。它把**整条控制台**搬到了网口上 ——
124 条文本命令里 **113 条**都能这样下发，而你只需要写一次字符串编码。
11 条发不了的是抢 ETH 引脚的（见 §4.9 表）。

## 4. 高频功能的完整调用序列

### 4.1 上电自检（进主界面之前跑）

```
1. PING(0x01)            → 不通就别往下走。查：固件是 NET/BOTH 吗？`link` 偏好是 net 吗？
                          端口 5000？防火墙？IP？
2. GET_INFO(0x07)        → 显示/记录 fw_tag（**判版本就靠它**）
3. GET_STATUS(0x02)      → 6 轴舵机度；任一轴读失败 ⇒ 状态栏黄灯
                           flags.estop ⇒ 整个运动区红灯禁掉
                           flags.read_ok=0 ⇒ 位姿字段无效，**别当真值显示**
4. PARAM_COUNT(0x42)     → 应等于 24（不等说明固件版本不对）
5. GET_FLAGS(0x0A)       → 起 10 Hz 心跳轮询
```

### 4.2 状态轮询（面板刷新）

```
心跳          GET_FLAGS(0x0A)      10~50 Hz    不碰总线
关节曲线      GET_STATUS(0x02)     5~10 Hz     碰总线，别超过 10 Hz
温度/电压     GET_JOINT_DETAIL(0x04) 1~2 Hz     6 轴一次 62 B 装得下
```

> ⚠ **别把这三个都设成 50 Hz**。`GET_STATUS` 和 `GET_JOINT_DETAIL` 要跟舵机总线
> 来回，加在一起会把总线时间片吃光，表现为"遥操时抖动/丢读"。

### 4.3 点动（JOG，按住不放）

```
按下： 进入点动模式 → 以 20~50 Hz 循环发 STREAM_JOINTS(0x13)
       每帧增量 = 速度(°/s) / 帧率，例：30°/s @ 20 Hz → 1.5°/帧
       只改要动的那个轴，其余轴填 0
松开： 立刻停止发送 → 再发一条 STOP(0x11) 兜底
       （不发 STOP 也不会继续动：流模式 1 s 无帧就自动退出）
```

**必须限速**：单帧单轴 >25° ⇒ 固件**整帧拒收且不更新基准**。20 Hz 下 500°/s 就会踩到。

### 4.4 单轴点动 / 绝对角

```
绝对角：MOVE_JOINTS(0x10)  舵机度，一次给全 6 轴（不想动的轴填当前角）
        先 GET_STATUS 读到当前角，改要动的那一个 ⇒ 这叫"原地回写"，最安全
```

> ⚠ 量纲：`MOVE_JOINTS` 吃**舵机度**（0~360），`STREAM_JOINTS` 吃**逻辑角**
> （相对 Home 零点、带符号）。**两者不能混用**。逻辑角要经本臂的 `calib(zero/offset/dir)`
> 换算。**别自己猜** —— SDK 的 `JointCalib` 就是干这个的。

### 4.5 笛卡尔运动

```
1. FK_QUERY(0x21)        读当前 X/Y/Z/pitch，作为增量起点
2. IK_QUERY(0x22)        新人机目标先问一遍能不能解 —— **这一步能省掉一次瞎动**
   无解 ⇒ ERR_UNREACH(3)，UI 提示"超出工作空间"，别发 MOVE_CART
3. MOVE_CART(0x20)       走
4. GET_STATUS(0x02)      确认到位（或看 flags.traj 位从 1 变 0）
```

### 4.6 50 Hz 流控遥操（主从 / 回放）

```
循环（50 Hz，只发不等）：
   从主臂读姿态          GET_STATUS(0x02) 或者 PC 侧已有的缓存
   算逻辑角 → 限速 →    slew: 240°/s @50Hz = 4.8°/帧（离 25° 门限 5× 余量）
   STREAM_JOINTS(0x13)  直接 send，不等 ACK
   异步统计 ACK          ok / limit(=4) / estop(=5) 的计数
退出：
   一帧 STOP(0x11)
```

⚠ **不要再叠加第二路写操作**（比如同时发 `MOVE_JOINTS`）。
固件对"流"和"绝对角"没有互斥锁，两路一起发会乒乓互踢。

### 4.7 急停与恢复

```
监测：GET_FLAGS(0x0A).estop 或 GET_STATUS(0x02).flags.bit0
E-Stop 生效时：
   · 所有运动命令回 ERR_ESTOP(5) —— UI 上把运动按钮全禁掉 + 红字"急停中"
   · STOP(0x11) 仍然可以发
恢复：E-Stop 是硬件电平（PE11 实时读），**不自锁** ⇒ 松开就恢复。
      但**人别停在臂会扫过的区域**。
```

### 4.8 参数面板

```
进面板：  PARAM_COUNT(0x42) → 24
          循环 PARAM_LIST(0x44, offset)  每页 ≤6 条 ×10B，offset 递增直到 offset+n ≥ total
          参数详情用 PARAM_READ(0x40, id) 单取（带 i32 值会超 64 B 上限，所以分开）
改一个：  PARAM_WRITE(0x41, id, value)
          成功后**不落盘**（掉电丢）
要保留：  PARAM_SAVE(0x43) + magic     ← 会写 Flash，UI 上二次确认
```

> ⚠ **参数 id 不要硬编码到代码里**。从 `config/arm_config.json` 读，
> 或用 `PARAM_LIST` 在运行期枚举 —— 固件加参数时你的界面不用改。

### 4.9 ⭐ TEXT_EXEC：一条通道用上全部 113 条控制台命令

不在 §3 表里的功能，**九成都能这样解决**，不用为每条命令写编码。

```
TEXT_EXEC(0x0B)：u32 magic(小端 0x5A5A5A5A) + 正文(**ASCII**) + u8 NUL(0x00)
   正文 ≤ 58 **字符**；超长要报错，**不能静默截断**
   （截断后可能变成另一条命令：`sf 1` 被截成 `sf` 就是完全不同的行为）

回包 0x8B / 0x8C：
   u16 total(小端, **字节数**)  u8 flags  u16 off  u8 n  + n 字节 UTF-8 正文
   total > n ⇒ 用 TEXT_FETCH(0x0C, off+n, n) 续取，直到取满 total
```

**必须遵守的两条**：

1. **按字节拼接，最后统一 UTF-8 解码**。中文一个字 3 字节，页边界会把它切开 ——
   逐页解码必然乱码。
2. **`flags` 要如实反映到 UI**：
   * `bit0 = 1` ⇒ 输出超过 2048 B 被**截断**（要告诉用户"只看到前 2 KB"）
   * `bit1 = 1` ⇒ 被**安全闸门拒绝**，正文就是原因（例如"急停中只放行 `s`/`h`"）

**别只取第一页**（真机踩过，见 §2.4 最后一行）：

| 命令回显长度（真机实测） | 只取第一页会怎样 |
|---|---|
| `nx` 网口状态 **1050 ~ 1311 B**（≈23 页） | 只拿到 63 字符，`udp cmd=` / `crc err=` 全看不到 |
| `h` 帮助表 **5406 B**（超 2048 ⇒ 触发 `flags.bit0`） | 只拿到第一页且不知道被截断 |
| `L` 限位 / `s` 舵机表 | 通常一页够，但**别假设** |

判定办法很简单：**回包的 `total` > `n` 就必须继续 `TEXT_FETCH`**，
循环到 `off` 累加到 `total` 为止（SDK 的 `text_exec()` / C# 的 `Text()` 已内置）。
只调一次 `TEXT_EXEC` 就收工 = 一定有 bug，只是在短回显上看不出来。

**能被拦下的命令（固件主动拦，不是你写错）**：

| 类 | 命令 | 原因 |
|---|---|---|
| 抢 ETH 引脚 | `cx` `cp` `cy` `cz` `cw` `ps` `can` `mg` `mp` `mo` `ml` | 重配 PB12/PB13 或写 PA0/PA1 —— 而 PB13=ETH_TXD1、PA1=ETH_RMII_REF_CLK ⇒ **一敲网口就死** |
| 交互阻塞 | 单独的 `c`（校准向导） | 死等本机键盘，**无看门狗** ⇒ 主循环回不来 |
| 闸门（急停中） | 除 `s` / `h` 以外全部 | 安全设计 |

**⚠ 但"能发"不等于"该发" —— 固件不拦的才真有风险**

下面这些 **不会被拦住**，但它们是真动硬件 / 改基准的：

| 命令 | 副作用 | 能不能做按钮 |
|---|---|---|
| `i` | `SERVO_InitAll()`：**Torque ON 抱闸**、全部舵机重设 joint mode | 不要。只做"上电初始化"内部调用 |
| `t J 0` | **松掉 J 轴力矩**（0-based？**不是** —— 这里按 1-based 习惯传，见控制台帮助） | 不要。松了臂会掉下来 |
| `m 180 180 180 180 180 180 15` | 让臂**真运动**回中位 | 可以，但要二次确认 |
| `zr` | **零位复位 —— 废掉量纲基准** | **绝对不要** |
| `M a` | **标定 —— 废掉量纲基准** | **绝对不要**（要 MAGIC 才能发，别提供入口） |

> 现场教训（2026-09-24）：调试时顺手发了一条 `i` 想看输出，结果它是
> **初始化舵机 = Torque ON 抱闸**，不是无害的 info。
> 幸好当时臂已在抱闸状态、六轴读数与记录值只差 1~2°，未造成位移。

**给上位机的纪律**：`TEXT_EXEC` 只留给**只读**命令 ——
`h`（帮助）/ `s`（舵机表）/ `L`（限位）/ `nx`（网口状态）/ `pv`（实时反馈）/
`zi`（查零点）。凡是带副作用的，一律走**结构化命令**：
它自带 MAGIC、有明确错误码、能回读校验。

**好用的几条**（直接抄）：

| 目的 | 发什么文本 |
|---|---|
| 打印所有轴状态 | `s` |
| 零点是否被污染 | `zi` |
| 运行时限位 | `L` |
| 链路偏好（can/net/off） | `link` |
| 从臂跟随开关 | `sf 1` / `sf 0` |
| 主臂直连转发 | `mf 1` / `mf 0` |
| 主从链路诊断（字节数/帧数/CRC 错） | `lk` |
| 保存参数到 Flash | `F` |
| 帮助（控制台命令一览） | `h` |

> ⚠ 这些文本命令是**完整一行**，**不要**自己加 `\r` —— 固件会剥掉 CR/LF。

### 4.10 查看当前"已录示教"和上位机自己录的区别

## 5. 错误码 → UI 该怎么显示

**核心原则（工程红线）：读失败**绝不**兜底成 0。** 宁可显示 `--` 并给黄灯。

| err | 名字 | UI 该显示 | 用户该做什么 | 能重试吗 |
|---|---|---|---|---|
| 0 | OK | 正常 | — | — |
| 1 | PARAM | 🟡 "参数不被接受" | 检查量纲/范围（舵机度 vs 逻辑角） | 改参数后重发 |
| 2 | CRC | 🔴 "通讯数据损坏" | 检查自己的组包（LEN 1 字节 / CRC 小端） | 可以重试 1 次 |
| 3 | UNREACH | 🟡 "目标超出工作空间" | 换个目标（`IK_QUERY` 先验） | 换目标 |
| 4 | LIMIT | 🟡 "超出限位 / 单帧跳变过大" | 查限位表；流控降速 | 降速后重发 |
| 5 | ESTOP | 🔴 **急停中**：运动功能全部禁掉 | 排除原因后松开 E-Stop | 解除后 |
| 6 | FK_VERIFY | 🔴 "位姿核对不符，已拒动" | **别重试**，先查臂是否被卡/读失败 | ❌ |
| 7 | READ | 🟡 "读取失败"（**含义按命令不同，见 §5.1**） | 见 §5.1 | 多数可重试 |
| 8 | MAGIC | 🟡 "危险操作缺确认" | 补 4 字节 magic | 补后重发 |
| 9 | BUSY | 🟡 "轨迹/示教/回放进行中" | 等当前动作结束 | 稍后 |
| 10 | NOTCAL | 🟡 "未校准" | 用串口按 `c` 走校准向导 | ❌ 先校准 |

### 5.1 ⚠ 错误码 7（READ）是**多命令复用**的 —— 同一个数字，含义不同

固件把 `ARM_API_ERR_READ` 用在了多处，**含义取决于你发的是哪条命令**。
上位机**不要**把 7 一律提示成"检查线缆" —— 参数类命令报 7 通常**跟线缆无关**。

| 你发的命令 | 报 7 的真实含义 | 怎么查 |
|---|---|---|
| `GET_STATUS(0x02)` / `GET_JOINT_DETAIL(0x04)` | 舵机**总线**读失败 | 查总线接线 / 共地 / 舵机 ID 冲突 / 供电 |
| `GET_LIMITS(0x05)`、`GET_PID(0x36)` 等**参数类** | 读 **Flash 参数区（扇区 11）失败** | **先怀疑"从未写过参数"**（`PID_FlashLoad` 返回非 OK），**不是线缆** |
| `FK_QUERY(0x08)` 等解算类 | 读关节角失败（解算输入没拿到） | 同总线那一条 |

> **现场实测（2026-09-24，真机 `192.168.7.120`）**：`GET_LIMITS(0x05)` 连续 3 次
> **全部**报 7，根因是固件 `ArmApi_GetLimits()` 里 `PID_FlashLoad()` 返回非 OK
> ⇒ **flash 里的 PID/限位参数区没写过**（未标定，或标定后没落盘）。
> 注意：**这不影响文本 `L`** —— `L` 读的是**内存里当前生效**的限位数组，
> 所以会出现「`L` 一切正常、`GET_LIMITS` 一直失败」这种组合，这是**合理的**，别当成"臂坏了"。

### 5.2 ⚠ `flags` 字节有**两套语义** —— 别把两条命令的 flags 混用

同一个"flags"概念，在两条命令里**位定义完全不同**，而且都是 1 字节。这是最容易写错的地方之一。

| 命令 | bit0 | bit1 | bit2 | bit3 | bit4 | bit5 |
|---|---|---|---|---|---|---|
| `GET_STATUS(0x02)` → 回 `0x82` | ESTOP | TRAJ | **CORR** | **READ_OK** | — | — |
| `GET_FLAGS(0x0A)` → 回 `0x8A` | ESTOP | TRAJ | **STREAM** | **CORR** | TEACH_REC | TEACH_PLAY |

- `GET_STATUS` 的 **bit3 = `read_ok`**：本拍 6 轴是否**全部**读到。为 0 时角度字段可能含 `-32768`。
- `GET_FLAGS` 的 **bit2 = `stream`**（主从直写流模式激活）、**bit3 = `corr`**（自适应修正进行中）。
- ⚠ **不要**拿 `GET_FLAGS` 的位图去解释 `GET_STATUS` 的 flags（反之亦然）—— 会把
  "读到了没" 误判成 "修正进行中"。

> **现场实测（2026-09-24）**：`GET_STATUS` 返回 `flags=0x08` 时六轴全部读到（`read_ok=1`）；
> `flags=0x00` 那几拍恰有轴返回 `None`。两套编码各自自洽 —— 错的是把它们混着读。

**读失败的哨兵**（必须原样上报，不要做数字运算）：

| 位置 | 哨兵 | 含义 |
|---|---|---|
| `GET_STATUS` 某轴角度 | `-32768` (0x8000) | 该轴舵机读失败 |
| `GET_JOINT_DETAIL.temp` | `0xFF` (255) | 温度**这一拍**丢读（≈20% 的拍，不是故障） |
| `GET_JOINT_DETAIL.hw_err` | `0xFF` (255) | 硬件错寄存器**读失败**（≠ 硬件真的报错） |

> 舵机总线是**逐字段瞬时丢读**的：角度约 5% / 温度约 20% / 移动位约 33% 的拍会丢。
> 所以某一拍读到 `0xFF` 是**正常的**，下一帧可能就有。UI 上显示成 `--` 或保留上一帧，
> 但**不要**显示成 `0℃` / `0V` —— 那是在撒谎。

### 7.1 ⭐ 第四种选择：连这些都不用抄 —— 直接用 HTTP 边车

如果你不想自己处理 CRC-16、SEQ 配对、分页 UTF-8 拼接，可以**不写协议代码**，
改用一个现成的 HTTP 边车（板子上没有 TCP，所以边车跑在 PC 侧）：

```bash
# 终端 1：假臂（没有硬件时）
armctl mock --port 5000
# 终端 2：边车
armctl http-bridge --target 127.0.0.1:5000 --port 8080
# 终端 3：上位机侧，就是普通 HTTP
curl -X POST http://127.0.0.1:8080/api/raw  -d '{"cmd":1}'
curl         http://127.0.0.1:8080/api/status
curl -X POST http://127.0.0.1:8080/api/text -d '{"text":"s"}'
```

```python
import requests
s = requests.Session()                       # ★ 复用连接：省 51% 延迟（实测）
print(s.get("http://127.0.0.1:8080/api/status").json())
print("链路 RTT =", s.get("http://127.0.0.1:8080/api/health").headers["X-Arm-Rtt-Ms"], "ms")
```

**关键性质**：边车**不改协议、不加语义** —— 错误码、丢读哨兵（`None` / `-32768`）、
静默钳制行为与 UDP 直连**完全一致**。所以本指南 §3 ~ §6 的所有结论照样适用。

| 什么时候用边车 | 什么时候**不要**用 |
|---|---|
| Web / Electron / 脚本 / 快速原型 | **50 Hz 遥操流** —— 每帧等应答会把帧率锁死在 RTT 上 |
| 配置、查询、写参数（要 TCP 的送达保证） | **急停** —— 少一跳就少一个故障点，别让 TCP 重传挡在中间 |
| 想用 `requests` / `HttpClient` / Postman 直接调 | 需要极致低延迟的实时闭环 |

⚠ 边车**没有鉴权**，默认只绑 `127.0.0.1`，**不要改成 `0.0.0.0`**。
详细的延迟/吞吐对照数据见 `docs/UDP_vs_HTTP_实测.md`。

### 7.1 ⭐ 没有真机也能把协议调通

## 9. 网口侧的红线（最容易踩的 8 条）

1. **目的端口必须 5000**，报文长度必须恰好 `3+LEN+2`，否则**静默丢弃**。
2. **`CMD ≥ 0x80` 的包固件不回**（回包号段）。
3. **`LEN` 是 1 字节**。
4. **危险命令必须带 MAGIC**（小端 `5A 5A 5A 5A`），缺了回 `ERR_MAGIC`。
5. **单帧单轴跳变 >25° ⇒ 整帧拒收且不更新基准**，连续几次自锁冻结 ⇒ 上游必须限速。
6. **`GET_STATUS` 读失败是 `-32768`，不是 0**；`temp`/`hw_err` 丢读是 `0xFF`。
7. **`MOVE_JOINTS` 是舵机度、`STREAM_JOINTS` 是逻辑角**；`MOVE_JOINTS` 的 v/a 是 **u16×10**。
8. **`CALIB_ENTER` 从网口一律 NACK** —— 别实现它，引导用户去串口。

> 完整 13 条见 `docs/网口指令大全.md`。真机上任何"玄学超时"，
> 先怀疑第 1、3 条 —— 它们**不报错**，只表现为超时。

## 10. 卡住了看哪

| 现象 | 先查 |
|---|---|
| 全部命令超时、PING 也不回 | ① 固件是 NET/BOTH 吗 ② `link` 偏好是 net 吗（改完要 `link save` + **RESET**）③ 端口 5000 ④ 防火墙 ⑤ IP/网线 |
| 只有个别命令超时 | 那条命令的 `payload` 长度/格式（§2.4） |
| 命令都通但臂不动 | `GET_FLAGS.estop`？`GET_FLAGS.traj`（说明在跑轨迹）？从臂 `sf 0`？力矩掉了？ |
| 动一下就冻住 | 限速太大（§4.3），看有没有 `ERR_LIMIT(4)` 连续发生 |
