# 启动步骤（主从遥操 / 遥操示教）

> 面向"拿到包就要把两臂跑起来"的人。**照顺序做，不要跳步。**
> 所有可调的东西都在 `arm_link_config.json` 里 —— **改配置，不改代码**。

---

## 0. 30 秒总览

```
                      ┌── UDP :5000 ──┐
   [主臂 192.168.7.121]                [本机 PC]                [从臂 192.168.7.120]
        ↑ 人拖它                      ↑ 读主臂 → 限速 → 写从臂         ↑ 跟随它
```

* 走 **网口 UDP**：实测往返 **p50 1.61 ms**（CAN 2.72 / 串口 4.78），50 Hz 有 **15× 余量**。
* **两臂之间一根线都不用接**，PC 就是那根线（两臂各开一个网口，PC 也接同一交换机）。
* 本机不需要装任何第三方库（串口路线才需要 `pyserial`）。

## 2. 改配置（唯一入口）

打开 `launchers/arm_link_config.json`，至少确认这三行：

```json
"leader":   "net://192.168.7.121:5000",     ← 主臂（人拖的那台）
"follower": "net://192.168.7.120:5000",     ← 从臂（跟随的那台）
"slew_deg_per_s": 240.0                     ← 每轴限速，别超 400
```

| 字段 | 说明 | 常见错误 |
|---|---|---|
| `leader` / `follower` | `net://IP:5000`；也可 `serial://COM11`、`sim://` | **端口必须 5000** |
| `hz` | 流频率，默认 50 | 不要低于 2（固件要求 >2 Hz） |
| `slew_deg_per_s` | 每轴限速 deg/s | **调 >400 会自锁**：单帧跳变 >25° 时固件整帧拒收，连续几次就冻结 |
| `gain` | 跟随增益，默认 1.0 | 想"小幅度微调"可设 0.5 |
| `sync` | `hold`（默认可不动从臂）/ `align`（先把从臂走到主臂姿态） | 首次一定用 `hold` |
| `reverse` | `false` 全同向；`true` 全反向；或 6 个布尔值逐轴反 | **镜像安装**的从臂一般 J1/J4/J5/J6 要反 |
| `soft_limits_deg` | 6 组 `[min,max]` 逻辑角软限位；`null` 不限 | 填错会"看起来不动"（被软限位削平） |

## 3. 空跑一次（**不需要任何硬件**）

先确认"流程、参数、显示"都对，再上真机：

**Windows**：`start_teleop.bat --leader sim:// --follower sim:// --sec 8 --yes --allow-uncalibrated`
**任意平台**：
```bash
cd launchers
python launch_teleop.py --leader sim:// --follower sim:// --sec 8 --yes --allow-uncalibrated
```

期望看到 `发送 400 帧 / 8.0s (50.0 Hz) | ACK ok=399`。

> `--allow-uncalibrated` 是给仿真用的：仿真臂的 Home 零点默认没校（`zero_raw = 0`），
> 预检会**正确地**报"零点未校准"。真机上不该加这个参数。

## 4. 上真机前的四项检查（**别跳**）

### 4.1 网络
* PC 与两臂在同一网段，静态 IP（例：PC `192.168.7.100/24`）。
* 关掉 Windows 防火墙对 UDP 5000 的拦截，或放行 python.exe。
* 两臂烧的必须是 **NET 或 BOTH 构建**（`link` 偏好 = net，改完要 `link save` + **RESET**）。
* 排查顺序：`ping <IP>` → 下面的 `--preflight-only` → 都不通再看串口 `link`。

### 4.2 只验连通，不动臂（**强烈建议先跑这一条**）

```bash
python launch_teleop.py --preflight-only
```

它会打印 6 步里的前 4 步并停下：PING / 舵机度 / 读失败轴 / E-Stop / **fw-tag** / **`zi` 零点是否被污染** / 运行时限位 `L`。
**任何一项 ✗ 都先修，别急着动臂。**

### 4.3 两臂姿态与零点
* 两臂都要在各自主板上用串口敲过 `c` 做校准，且 **Home 零点对应同一物理姿态**。
* 主臂必须处于**能被人拖动的状态**（松力矩）；从臂**上力矩**（启动器会自动给）。

### 4.4 安全
* 工作空间清空、没人。
* E-Stop 在手边（从臂本机 / 网络 STOP / 断电，三选一）。
* 首次上真机建议先把 `sync` 保持 `hold`、`--sec 5` 跑一小段。

## 5. 正式启动

```bash
# 方式 A：双击
start_teleop.bat            # Windows
# 方式 B：命令行（推荐，参数好改）
python launch_teleop.py
python launch_teleop.py --sec 30                    # 跑 30 秒
python launch_teleop.py --soft-limit 20,20,20,20,70,33   # 各轴 ±(逻辑角)
python launch_teleop.py --sync align                # 先把从臂走到主臂姿态再跟随
```

启动器会依次走 6 步，并在第 4 步**停下来要你人工确认 4 条安全项**（输入 `y` 才继续）：

```
[1/6] 读配置        → 打印实际生效的地址与参数
[2/6] 连主臂并预检   → PING / 状态 / fw-tag / zi / L
[3/6] 连从臂并预检
[4/6] 安全确认      → 人工输入 y（CI 里可用 --yes 跳过）
[5/6] 开始遥操      → 拖主臂，从臂跟随
[6/6] 收尾          → 自动停从臂，打印统计
```

**停机**：`Ctrl-C` —— 会自动给从臂发 STOP，不是"甩手不管"。

退出码：`0` 正常 ｜ `2` 配置/连接/预检不过 ｜ `3` 链路丢失 ｜ `4` 急停中止 ｜ `5` 未确认安全

## 6. 遥操示教（录制 / 检查 / 回放）

**四种模式**：

```bash
python launch_teach.py --mode record --sec 30 --name demo1   # 边遥操边录
python launch_teach.py --mode list                           # 看录过哪些
python launch_teach.py --mode info trajectories/demo1.json    # 检查（会不会被拒帧）
python launch_teach.py --mode play trajectories/demo1.json --speed 0.5
```

**推荐顺序（照着做）**：

1. **录**：`--mode record --sec 30`。拖主臂即录，**PC 侧没有固件那 80 秒上限**。
   中途 Ctrl-C 也会把已录的部分存下来。
2. **查**：`--mode info <file>`。重点看 **单帧最大跳变**。固件硬门限是 **25°/帧**，
   超了会被**整段拒收**。`info` 会直接告诉你 `校验通过` 还是 `有警告`。
   顺便可以 `--convert csv` 导一份给 Excel / LeRobot 看。
3. **放**：第一遍**一定先 `--speed 0.5`**。回放默认会先做"接近段"（走到轨迹起点），
   避免第一帧大跳变被拒。**不要**随手加 `--no-approach`。

轨迹格式按扩展名：`.json`（默认，可读）/ `.jsonl`（流式）/ `.csv`（Excel、LeRobot）/ `.npz`（numpy）。

**回放期间的判据**：结束时会打印 `ACK limit=N`。`N > 0` 表示有帧被固件拒收，常见原因：
单帧跳变 >25° / 从臂 `sf 0` / 起点没接近到位。

## 7. 三条路线怎么选

| 路线 | 何时用 | 命令 |
|---|---|---|
| **网口 UDP** ★ | 默认，两臂各有网口 | `launch_teleop.py`（配置里写 `net://`） |
| PC 中转串口 | 两臂只有串口 | `armctl relay --leader-port COM9 --follower-port COM11` |
| 固件直连 | 两臂 PA0/PA1 已焊通 | 见 `docs/主从遥操与示教.md` §4 |

⚠ **固件直连**判"线到底通不通"只有一个判据：`lk` 的字节数/帧数/CRC 错。
命令不回错 **≠** 线是通的。

## 8. 排错表

| 现象 | 最可能的原因 | 怎么办 |
|---|---|---|
| `PING 无响应` | ① `link` 偏好不是 net ② 固件不是 NET/BOTH 构建 ③ 端口不是 5000 ④ 防火墙 | 串口敲 `link` 看偏好；`link net` → `link save` → **RESET** |
| `零点未校准`（`zi` 报有轴为 0） | 没做过 `c` 校准，或 Flash 被污染 | 串口按 `c` 走校准向导；**别用 `M a`** |
| 从臂不动 | `sf 0`（跟随关了）/ 力矩掉了 | 串口敲 `sf 1`；启动器会自动上力矩（`enable_torque`） |
| 动一下就自锁冻结 | 限速太大，单帧跳变 >25° 被整帧拒收 | 把 `slew_deg_per_s` 降到 240 或更低 |
| 从臂动作方向反了 | 镜像安装 | 配置 `reverse` 填该轴为 `true` |
| 遥操一段时间后报 `链路丢失` | 主臂读失败超 1 s（总线丢读 / 网线） | 看 `[FAULT]/[STALL]`；降 `hz`；查总线 |
| 回放报 `ACK limit>0` | 轨迹有 >25°/帧 的跳变 | `--mode info` 看哪一轴；降 `--speed` 重录 |
| 双击 `.bat` 一闪而过 / 中文乱码 | 控制台编码 | 脚本已自带 UTF-8 处理；仍异常就直接用 `python launch_teleop.py` |
| 端口被占（`WinError 10048`） | 上一次的 `armctl mock` 没退 | 关掉那个窗口，或 `--port` 换一个 |

## 9. 没有真机也想开发？

**有一台"假臂"可以直接连着调**（报文与真机逐字节一致）：

```bash
armctl mock --port 5000 --verbose      # 起假臂服务
armctl mock --loss 0.2                 # 20% 丢包，测你的重试逻辑
armctl mock --estop                    # 上电即 E-Stop，测你的安全流程
armctl mock --fail-joints 2            # J3 恒读失败，测"读失败要如实上报"
armctl mock --latency-ms 30            # 卡顿容忍度
```

然后把上位机的地址指向 `127.0.0.1:5000` 即可。
**这是给 C# / C++ / Node / 组态软件工程师准备的** —— 不用等真机就能把协议调通。

⚠ 它是**协议级**假臂：报文格式/错误码/分页/闸门与真机一致，但**没有物理仿真**，
轨迹和时序只能验"协议对不对"，不能验"效果好不好"。
