## 1. 机械臂是什么

| 项 | 值 |
|---|---|
| 构型 | SO-ARM101 风格的 **6 自由度串联机械臂**（轴心距经实测交叉验证） |
| 执行器 | 6 × Feetech **STS3215**（12V 30KG），SCS 半双工串行总线 |
| 关节命名（官方） | `shoulder_pan` / `shoulder_lift` / `elbow_flex` / `wrist_flex` / `wrist_roll` / `gripper` |
| 关节命名（固件） | **J1** / **J2** / **J3** / **J4** / **J5** / **J6** |
| 中文 | 底座旋转 / 肩 / 肘 / 腕俯仰 / 腕自转 / 夹爪 |

### 关节功能（决定 3D 模型怎么动）

| 关节 | 类型 | 旋转轴 | 是否改变末端位置 | 说明 |
|---|---|---|---|---|
| **J1** | Yaw | **竖直 Z** | ✅ | 0 = 朝 +X（前）；正向 = 朝 +Y（左/俯视逆时针） |
| **J2** | Pitch | **水平 Y** | ✅ | 正向 = 上臂向前倾 |
| **J3** | Pitch | **水平 Y** | ✅ | 正向 = 前臂向前倾 |
| **J4** | Pitch | **水平 Y** | ✅ | 正向 = 工具下沉 |
| **J5** | Roll | **工具轴**（零位时 87.79° 方向） | ❌ | 绕夹爪轴自转，只改工具朝向 |
| **J6** | 开合 | 近似水平 Y | ❌ | 夹爪张开/闭合 |

> ⚠ **J2/J3/J4 的旋转轴平行（都绕 Y）**，所以臂始终在一个平面内（臂平面），该平面随 J1 旋转。
> **J5/J6 不改变 TCP 位置** —— 做正运动学时只算 J1~J4 即可。

## 2. 坐标系约定（**先记住这个，否则模型方向会反**）

```
世界坐标系（右手系）：
  原点 = 桌面上的 J1 轴心（即 z=0 在桌面）
  X = 前（forward）
  Y = 左（left）
  Z = 上（up）
  单位 = mm（URDF 用 m）

关节角零点 = "官方 Home" 姿态：
  上臂自竖直方向前倾 13.97°
  前臂水平（自竖直算 87.79°）
  此时所有舵机 raw = 2048（出厂中位），固件 SERVO_OFFSET 默认 = 180°

工具俯仰 pitch（FK 输出的 yaw）：
  0°   = 工具轴竖直向上
  90°  = 工具轴水平向前
  180° = 工具轴竖直向下
  注意：**零位（关节角全 0）时工具是水平的，pitch = 87.79°**，不是 0°
```

## 4. 轴心坐标表（零位姿态 = 关节角全 0，臂平面内 rho-z）

> `rho` = 到 J1 轴的**水平距离**（= √(x²+y²)），`z` = 高度。
> 零位时 J1 = 0，所有轴心都在 X 轴上（y = 0）。

| 轴 | rho (mm) | z (mm) | 完整坐标 (x, y, z) | 相对上一轴 | 方向角 |
|---|---|---|---|---|---|
| **J1 轴** | 0.00 | **65.30** | (0.00, 0, 65.30) | — | — |
| **J2 轴** | 31.32 | **120.10** | (31.32, 0, 120.10) | Δ 前 31.32 / 上 54.80 | — |
| **J3 轴** | 59.32 | **232.67** | (59.32, 0, 232.67) | 116.00 | **+13.97°** |
| **J4 轴** | 194.22 | **237.87** | (194.22, 0, 237.87) | 135.00 | **+87.79°** |
| **J5 轴** | 256.67 | **240.28** | (256.67, 0, 240.28) | 62.50 | **+87.79°** |
| **TCP** | 361.90 | **244.33** | (361.90, 0, 244.33) | 105.30 | **+87.79°** |

> 若 J1 ≠ 0，把上表的 (rho, z) 绕 Z 轴旋转 J1 角即可：

## 5. 正运动学（FK）——**这就是让模型动起来的公式**

固件实现（`kinematics.c` `FK_Solve` + `planar_fk`），**务必按此实现，不要用 DH 参数自己推导**：

```python
# 常量（mm / rad）
L    = [116.00, 135.00, 167.80]          # 上臂 / 前臂 / (腕+工具)
BASE = [0.243787, 1.532268, 1.532268]    # psi0: 上臂 / 前臂 / 工具
J2Y, J2Z, BASE_H = 31.32, 54.80, 65.30

def fk(joint_deg):                        # joint_deg = [J1..J6] 关节角(相对 Home)
    t1  = radians(joint_deg[0])
    ang = [radians(joint_deg[1]), radians(joint_deg[2]), radians(joint_deg[3])]

    s = y = z = 0.0
    for i in range(3):
        s += ang[i]
        y += L[i] * sin(BASE[i] + s)      # 前向分量
        z += L[i] * cos(BASE[i] + s)      # 向上分量
    y += J2Y
    z += BASE_H + J2Z

    x = y * cos(t1)                       # 绕 J1 旋转
    wy = y * sin(t1)
    pitch = degrees(1.532268 + ang[0] + ang[1] + ang[2])   # 工具轴俯仰
    return x, wy, z, pitch

# 说明：J5/J6 不影响位置。J4 之后的 167.80mm 工具段方向 = 前臂方向 + J4 角，
#      即 psi_tool = PSI_FORE0 + J2 + J3 + J4。
```

**工具方向（供 3D 模型旋转夹爪）**：
```
工具轴方向角 psi_tool = 87.79° + J2 + J3 + J4      （自竖直向上的前倾角）
工具轴单位向量 (臂平面内) = (sin psi_tool, 0, cos psi_tool)  再绕 Z 转 J1
```

## 6. ⚠ 与官方 SO-ARM100/101 URDF 的差异（**必须知道**）

官方 `so101_new_calib.urdf` 的**中性位连杆方向与长度与固件完全一致**（上部 13.97°、前臂 87.79°、
上臂 116.00、前臂 135.00 —— 已核对，逐位相符），但有三处差异：

| 项 | 固件模型 | 官方 URDF | 影响 |
|---|---|---|---|
| **J1→J2 偏移** | 前 31.32 / 上 54.80（平面内） | 前 30.39 / 侧 −18.28 / 上 54.20 | 官方有 **18.28mm 侧向偏移**，固件模型是**纯平面** |
| **J4→TCP** | **167.80** | 162.17（63.72 + 98.45） | 差 **≈5.6 mm** |
| **TCP 定义** | 夹爪末端（含模型累积偏差，偏保守 ~6mm） | `gripper_frame_link` | 数值不完全等价 |

**决策（重要）**：
> **上位机的 3D 模型必须与固件 FK 数值一致**（因为机械臂上报的 XYZ 就是固件 FK 的输出）。
> 因此：**优先使用本包提供的 `model/arm_model.urdf`（与固件逐位一致）**。
> 官方 URDF 只作为"照片级外观"可选参考（`model/official/`），**不要**用它来换算 XYZ。

## 7. 关节限位（**权威在 raw 空间，不在角度空间**）

### 7.1 为什么必须用 raw

0~360° 在 0/360 处**不连续**，而限位可能跨越该边界（如 J3 的合法区是 `servo 177°→360°→0°→10°` 的**包裹弧**）。
所以固件在 **raw 空间（0~4095）** 做限位判定，角度版 `JOINT_MIN/MAX` **仅供显示**。

### 7.2 权威限位来源（`main.c`）

| 关节 | 限位来源 | 说明 |
|---|---|---|
| J1 / J2 / J4 / J6 | **`c` 校准 Phase 2 实测极值** | 静态不可知，**必须运行时读取** |
| **J3** | **写死偏移**（相对 `calib_zero_raw[2]`）：后 `−1163` / 前 `+1090` | *"Phase2 极值对 J3 无效"* |
| **J5** | **写死偏移**（相对 `calib_zero_raw[4]`）：`−1033` / `+787` | 同 J3 |

由写死偏移换算出的**关节角限位**（= 偏移 raw × 360/4095）：

| 关节 | 关节角下限 | 关节角上限 |
|---|---|---|
| **J3** | **−102.24°** | **+95.82°** |
| **J5** | **−90.81°** | **+69.19°** |

### 7.3 角度版显示限位（`main.c`，**仅显示/未校准时兜底，不要当权威**）

```c
JOINT_MIN[6] = {   0,  58,  10,  83, 180,   0 };   /* 舵机度，仅显示 */
JOINT_MAX[6] = { 360, 264, 177, 289, 340, 360 };   /* 舵机度，仅显示 */
```

换算成关节角（默认 zero=180°、`JOINT_DIR = [−1, +1, +1, +1, +1, +1]`）：

| 关节 | 关节角下限 | 关节角上限 | 备注 |
|---|---|---|---|
| J1 | −180° | +180° | 连续旋转，无机械挡块 |
| J2 | −122° | +84° | 肩 |
| J3 | −102.24° | +95.82° | **用 §7.2 的权威值** |
| J4 | −97° | +109° | 腕俯仰 |
| J5 | −90.81° | +69.19° | **用 §7.2 的权威值** |
| J6 | −180° | +180° | 夹爪 |

> **J5 卡区**：舵机度 **77°~174°** 是机械卡死区，固件**无条件**把 J5 限制在 **180°~340°**，
> 任何情况下都不让 IK 进入卡区。
>
> **上位机建议**：启动时用 `L` 命令读取实时限位（servo 度）并覆盖模型里的默认值；
> 用 `p J` / `s` 读取 raw 做精确校验。**不要把上表硬编码成唯一真值。**

### 7.4 角度换算公式（实现 IK/限位时必须用）

```
关节角(rad)  = JOINT_DIR[j] × (舵机度 − SERVO_OFFSET[j]) × π/180
舵机度      = SERVO_OFFSET[j] + JOINT_DIR[j] × 关节角(rad) × 180/π
raw         = round(舵机度 / 360 × 4095)
舵机度       = raw / 4095 × 360
JOINT_DIR   = [−1, +1, +1, +1, +1, +1]
SERVO_OFFSET 默认 = [180,180,180,180,180,180]（现场校准后为该臂实测 raw 换算值）
```

## 8. 零位与标定（**为什么不能写死舵机度**）

| 项 | 说明 |
|---|---|
| 出厂默认零位 | 所有关节 raw = **2048** → `SERVO_OFFSET = 180.0°` |
| 现场标定 | 用 `c` 命令 Phase 1：把整臂摆成官方 Home（上臂竖直/前臂水平/工具朝前），按 `0` 记录各关节 raw 作为运动学零点 |
| **实际漂移量** | 现场某臂 Phase1 实测 zero raw = `692 / 1849 / 3221 / 2160 / 3081 / 2118` —— 与 2048 相差可达 **±1000 raw ≈ ±88°**！ |
| 结论 | **任何位姿/路点都必须用"关节角"或"XYZ"表达，绝不能写死舵机度**（写死必然随标定漂移而失效，甚至撞挡块） |

**上位机要求**：3D 模型显示用**关节角**驱动即可；若要把"实际舵机度"转成关节角，
必须使用**设备当前的真实 `SERVO_OFFSET`**（可由校准流程/固件读出），不要假设 180。

## 12. 做 3D 模型的三种做法（按推荐度）

### 方案 A（推荐）：直接加载本包 URDF
```
model/arm_model.urdf
```
- 与固件 FK **逐位一致**（已验证 0.001 mm）
- 纯 primitive 几何（cylinder/box），**无需外部网格文件**，任何 URDF 加载器都能开
- 关节名与官方一致（`shoulder_pan` … `gripper`），便于与 LeRobot 生态互操作
- 用法：按 `joint_deg` → 设 URDF 关节角（rad = deg×π/180）→ 渲染

不同语言/框架：Three.js（`urdf-loader`）、ROS `robot_state_publisher`、
Python（`yourdfpy` / `urdfpy` / `pybullet`）、Unity/Unreal（导入工具）均可。

### 方案 B：自研渲染（不依赖 URDF 解析器）
消费 `model/link_geometry.json`：
- `joints[]`：每个关节的 `axis_world` + `axis_origin_mm` + `limits_deg`
- `axis_chain_zero_pose_mm`：零位轴心坐标（直接放连杆）
- `link_lengths_mm`：连杆长度
- 或直接照 §5 的 FK 公式自己算

### 方案 C：照片级外观（可选）
```
model/official/so101_new_calib.urdf  +  model/official/meshes/*.stl
```
- 外观是真实 3D 打印件
- ⚠ 但 TCP 与固件差 ~5.6mm，且有 18.28mm 侧向偏移 —— **只用来"看"，不要用来算 XYZ**
