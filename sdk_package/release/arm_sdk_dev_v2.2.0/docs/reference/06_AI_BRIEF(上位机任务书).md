## 1. 你的交付物

一个**上位机软件**（PC 桌面或 Web 均可），通过**串口**控制这台六轴机械臂。必须具备：

| 模块 | 要求 |
|---|---|
| 连接管理 | 串口枚举、打开/关闭、115200 8N1 无流控；打开后清空收发缓冲 |
| 命令终端 | 所有文本命令可下发（**自动追加 `\r\n`**）；另提供"原始命令"透传输入框 |
| 回包解析 | 按行读取；过滤**回显行**、**`> ` 提示符**、**`[RUN]` 日志行**；按关键词判定成功/失败 |
| 状态面板 | 6 轴：舵机度 / raw / 负载 / 温度 / 错误位；末端位姿 XYZ + pitch |
| 3D 模型 | 用 `model/arm_model.urdf`（或 `model/link_geometry.json`）实时显示机械臂姿态，**与固件 FK 数值一致** |
| 运动控制 | 关节空间运动、笛卡尔运动（IK）、预设位姿、急停/停止 |
| PID 调参 | 读缓存值 vs 舵机 EEPROM 值、改值、烧写 EEPROM、存 Flash、恢复默认；**带调参方向提示** |
| 参数表面板 | `LP` 解析成表格，`SP` 写回 |
| 遥测曲线 | `tm` 数据成图（角度/电流/温度/负载） |
| 日志 | 带时间戳的原始收发日志，可导出 |

**明确不做**（这一版不要实现）：主从臂（Leader/Follower，UART4 链路）、ROS2 接入、微秒级时间同步。

## 2. 四条铁律（违反必然出 bug）

### 铁律 1：命令必须以 `\r\n` 结尾

固件判行逻辑（`main.c` → `Console_TryReadLine()`）：

```c
if (ch == '\r' || ch == '\n') {        /* CR 或 LF 都算"一行结束" */
    if (console_rx_len == 0) return 0; /* 空行忽略 */
    console_rx[console_rx_len] = '\0'; /* 到这里才会执行命令 */
    ...
}
```

- 正确：`"m 10 20 30 40 50 60\r\n"`
- 错误：`"m 10 20 30 40 50 60"` ← **永不执行**，现象就是"下发了没响应"
- `\r\n` 连发不会重复执行（`\r` 结束一行，`\n` 被当空行丢弃）

**实现要求**：把"补行尾"封装进 SDK 的 `send_command()`，业务层**不可能**漏掉。
**禁止**让业务代码自己拼字符串。

### 铁律 2：绝不臆造数值——所有尺寸/限位/角度以本包文档为准

- `02_MECHANICAL.md` 里的运动学常量已**与实机实测对拍**（误差 < 0.01 mm），直接用，**不要自己"估算"**。
- `03_INTERFACE.md` 的命令表**逐条从固件源码核实**（包括行号），没有的命令不要写。
- 不要从网上抄 SO-ARM100 的 URDF 数值来替代——本臂的固件用的是**简化平面模型**，
  与官方 URDF 有 ~5.6 mm 差异（见 `02_MECHANICAL.md` §6）。**以上位机显示与机械臂 FK 一致为最高优先级**。

### 铁律 3："读失败"必须如实上报，禁止用期望值兜底

固件里"读舵机位置做安全判定"的逻辑是：**任一轴读不到就整组重试，仍失败则拒绝运动**（不兜底）。
上位机必须一致：

- `GET_STATUS` / `s` / `p J` 返回读取失败 → **UI 显示"读取失败"**，**不要**用上一次的值或目标值填充。
- 若你的 3D 模型在"读失败"时仍按旧值渲染，用户会以为臂在那里——**这会掩盖真故障**。

### 铁律 4：结果必须分**三态**——成功 / 被钳制 / 被拒绝

固件有两类"看起来成功、其实不是"的回包，**只判断"有没有报错"必然误报**：

| 态 | 判据 | UI |
|---|---|---|
| 🟢 成功 | `ok=true` 且 `clamps()` 为空 | 绿色 / 无提示 |
| 🟡 **被钳制** | `clamps()` 非空（`a`/`q`/`B` 的 `J3: 320 -> 300 deg` 行） | 黄色 + "已限位钳制，实际执行 x°" |
| 🔴 被拒绝 | `kind ∈ {fail, safety, estop}` | 红色 + 固件原文 |

**反面教材（已被 SDK 修掉，但你移植时不要重犯）**：固件未知命令回
`Unknown command 'x'. Type 'h' for help.`，此前 SDK 关键词表没收录它，
掉进"有输出即成功"的兜底 ⇒ **命令压根没执行，UI 却打绿灯**。
Python/JS 两套 SDK 的 `classify()` 已修复并有回归测试，移植时照抄关键词表。

`m`（6 轴同时运动）还有一个**连打印都没有**的钳制：每轴数值被硬钳到 `0~300`。
所以 UI 里所有关节运动都必须走 SDK 的 `move_joints()`（Python）/ `moveJoints()`（JS），
**不要**自己拼 `"m " + 数字`——SDK 会在发送前抛错拦住越界值。

## 3. 十二个必踩的坑（已替你踩过，照做即可）

| # | 坑 | 正确做法 |
|---|---|---|
| 1 | 行尾缺失 → 没响应 | 一律 `\r\n`（铁律 1） |
| 2 | 把回显当成结果解析 | 固件**逐字符回显**你发的命令；解析前必须丢掉回显行，并按**关键词**判定（见 `03_INTERFACE.md` §1.4） |
| 3 | **关节号两套**混用 | 单轴命令 `t/a/r/p/z/w/L/M/T/O/E` 用 **0~5**；PID 命令 `K/I/D/N/Y` 用 **1~6**。差 1 就会动错轴 |
| 4 | **角度两套**混用 | **输入侧**：`a J deg`、`m`、`B`、`q`、`L` 收的都是**舵机度**（0~360，其中 `m` 硬钳到 **300**）。**输出侧/姿态侧**才是关节角 rel-home（可负）：`f`/`p` 的 relhome 行、内部 IK、`g`/`BG`/`qg` 的 `pitch`。见 `03_INTERFACE.md` §2.2 |
| 5 | 以为 `K/I/D` 改完就生效 | `K/I/D/N` **只改 STM32 缓存**！必须 `Y J` 才烧入舵机 EEPROM，`F` 才存 STM32 Flash。见 `04_SDK_SPEC.md` §PID |
| 6 | 以为 `SP` 存盘了 | `SP` **只改 RAM**，要 `F` 才持久化 |
| 7 | `Y` 烧写时臂失力 → **砸臂** | `Y` 会让该关节**失力约 0.6 s**。UI 必须**弹窗要求用户托住机械臂**再执行 |
| 8 | 用 `P 0` 时不检查当前姿态 | `P`/`m`/`g` 会做路径安全检查（桌面/立柱/限位），**可能被拒**。被拒后在 UI 上提示"路径不安全"，**不要静默失败** |
| 9 | 认为"到点顿两下"是 PID 问题 | 其根因是**轨迹尾段流式微步**（参数 `#42 traj.approach_speed` / `#45 traj.handoff_deg`），不是 PID |
| 10 | 二进制协议与文本混在同一串口 | 二者**共用 USART6**。解析时以 `0xAA 0x55` 作为二进制帧起始判据；文本行以 `\r\n` 切分 |
| 11 | **把"假成功"当真成功** | 固件未知命令打印 `Unknown command 'x'. Type 'h' for help.`。若关键词表没收录它，会掉进"有输出即成功"的兜底 ⇒ **命令没执行，UI 显示成功**。必须把 `Unknown command`/`Unknown pose`/`must be`/`Cannot `/`Error:` 收进失败表 |
| 12 | **把"静默改值"当正常成功** | `a`/`q`/`B` 被限位钳制时固件打印 `J3: 320 -> 300 deg (raw 4096 -> 4095 limit)` 但**仍算成功**；`m` 的 0~300 钳制**连打印都没有**。UI 必须：钳制=黄、拒绝=红、读失败=灰，三态分开 |

## 4. 关键技术约定速查

```
串口      : 115200 8N1, 无流控, ASCII
行尾      : \r\n  (强制)
单行最长  : 127 字符（超出丢弃）
分词      : 空格 / Tab；最多 16 个 token；不支持逗号/分号/引号
大小写    : 严格区分（m≠M, p≠P, s≠S, t≠T, b≠B, c≠C, d≠D, q≠Q）
回包形态  : <回显> <命令输出...> "> "   （每行以 \r\n 结束）
```
```
坐标系    : X=前, Y=左, Z=上, 原点=桌面上的 J1 轴心, 单位 mm
关节角    : 0 = 官方 Home（上臂+13.97°, 前臂水平 87.79°）; J1 正向=朝 +Y
工具俯仰  : pitch 0°=竖直向上, 90°=水平向前, 180°=竖直向下
可达半径  : J2 平面臂展最大 418.80 mm
```
