## 0. 一页速查

| 项 | 值 |
|---|---|
| 臂 IP / 端口 | `192.168.7.120` / **UDP 5000** |
| 臂 MAC | `02:4E:45:54:00:01` |
| PC 网卡 | `192.168.7.1/24`（本机「以太网 5」） |
| 承载 | 一个 UDP 数据报 = **一个逻辑包**，无分包、无重传、无连接 |
| 逻辑包 | `[SEQ(1) \| CMD(1) \| LEN(1) \| PAYLOAD(LEN) \| CRC16-LE(2)]` |

| 字节序 | 全部**小端** |

| 臂是否主动上报 | **否**。纯请求-应答，只能靠轮询 `GET_STATUS` |

## 2. 报文格式（线格式）

### 2.1 帧结构

```
偏移  字段      长度   说明
 0    SEQ        1    请求序号，0~255。臂**原样回显**，用于请求-应答配对
 1    CMD        1    命令码（见 §4）
 2    LEN        1    PAYLOAD 长度 0~64
 3    PAYLOAD   LEN   定点编码负载（见各命令）
3+LEN CRC_LO     1    CRC16 低字节
4+LEN CRC_HI     1    CRC16 高字节
```

- 报文总长**必须**恰好 `5 + LEN`。不等 ⇒ 臂**静默丢弃，不回包**（见 §3）。
- 请求与响应**同构**：响应也是一个这样的包，`SEQ` 回显请求的 `SEQ`。

### 2.2 CRC

**CRC-16/CCITT-FALSE**：`poly=0x1021`、`init=0xFFFF`、**非反射**、无最终异或。
计算范围 = 从 `SEQ` 到 `PAYLOAD` 末尾，即 `SEQ, CMD, LEN, PAYLOAD...` 共 `3 + LEN` 字节。
结果按**小端**放进报文末两字节（先低后高）。

```c
uint16_t crc = 0xFFFF;
for (i = 0; i < 3 + len; i++) {
    crc ^= (uint16_t)data[i] << 8;
    for (b = 0; b < 8; b++)
        crc = (crc & 0x8000) ? (crc << 1) ^ 0x1021 : (crc << 1);
}
```

**已知向量**：`crc16("123456789") == 0x29B1`。一开始对不上就先验这个。

### 2.3 字节序与定点编码

全部整数**小端**。角度/位置类**没有浮点**，一律定点：

| 量 | 类型 | 比例 | 例 |
|---|---|---|---|
| 关节角 / 位置 | `int16` | **×10**（0.1° / 0.1 mm） | 182.3° → `0x071F` |
| 速度 / 加速度 | `uint16` | **×10**（0.1 deg/s、0.1 deg/s²） | 10.0 → `0x0064` |
| 重力 K | `int16` | **×1000** deg/mm | 0.05 → `50` |
| 修正阈值 | `uint16` | **×100** deg | 2.00° → `200` |
| 参数值 | `int32` | **×1000** | 0.025 → `25` |

⚠ **四舍五入的边界**：固件编码用 `(int16_t)(deg*10 + (deg>=0?0.5:-0.5))`（向零取整方向的四舍五入）。
上位机侧请用同样规则（Python 的 `round()` 是**银行家舍入**，`round(0.5)=0`，会和固件差 1 个 LSB）。

### 2.4 长度上限

| 项 | 值 |
|---|---|
| `APROTO_MAX_PAYLOAD` | **64** 字节 |
| `APROTO_MAX_FRAME` | **71** 字节（5 + 64 + 2） |
| 最长请求负载 | `MOVE_JOINTS` = 16 B；`MOVE_CART`/`STREAM_JOINTS` = 12 B |
| 最长响应负载 | `GET_STATUS`/`FK_QUERY` = 21 B（报文 26 B） |

LEN > 64 ⇒ 臂丢弃该包（不回包）。UDP 本身能承载更大，但协议不吃。

### 2.5 与串口帧的区别（**别把两种帧混了**）

| | 串口 / CAN 逻辑帧 | **网口 UDP 数据报** |
|---|---|---|
| 帧头 | 串口有 `0xAA 0x55` | **没有帧头**，`SEQ` 直接在偏移 0 |
| 分包 | 串口逐字节、CAN 需 7 字节/帧重组 | **不需要**，一个数据报就是一个逻辑包 |
| CRC 范围 | `SEQ..PAYLOAD` | 同 |
| 负载/命令码/错误码 | — | **完全相同** |
| 事件帧 / 周期状态帧 | CAN 有（`0x280+node`） | **没有**（网口无主动上报） |

> 结论：上位机的**编解码函数可以复用**，只是"怎么把逻辑包送上线"这一步不同。
> 参考 `tools/can_host.py`（编解码）与 `tools/arm_net_host.py`（UDP 承载）。

## 3. 应答规则与"不回包"的六种情况

### 3.1 应答规则

| 请求类型 | 响应 CMD | 负载 |
|---|---|---|
| **查询类** `PING/GET_STATUS/FK_QUERY/PARAM_READ/PARAM_COUNT` | `请求CMD \| 0x80` → `0x81/0x82/0xA1/0xC0/0xC2` | 数据本体 |
| **控制类** `LOG_SET_LEVEL/MOVE_JOINTS/STOP/SET_TORQUE/STREAM_JOINTS/MOVE_CART/SET_GRAVITY/SET_CORRECTION/PARAM_WRITE` | 成功 `0x7F`(ACK) / 失败 `0x7E`(NACK) | `{原CMD, 错误码}` 固定 2 字节 |

⚠ **`PING` 的应答不是 ACK**：它回 `0x81`，负载 2 字节 `{proto_ver, run_id}`。
**第 2 字节是 `run_id`（本次上电随机），不是错误码** —— 别当 `err` 打印，否则会看到"随机错误码"。

### 3.2 六种"完全没有回包"的情况（现象都是**超时**）

| # | 条件 | 会不会回包 | 怎么区分 |
|---|---|---|---|
| 1 | 数据报 < 5 字节 | ❌ 静默丢弃 | `nx` 的 `rx` 计数会涨，但 `udp cmd` 不涨 |
| 2 | `5 + LEN ≠ 实际长度` | ❌ 静默丢弃 | 同上（会让 `crc err` 计数涨） |
| 3 | UDP 目的端口 ≠ 5000 | ❌ | `udp cmd` 不涨 |
| 4 | IPv4 目的 IP ≠ 臂 IP / 头校验和错 | ❌ | `rx` 甚至不涨（被网卡/协议栈挡掉） |
| 5 | `CMD ≥ 0x80`，或 `CMD = 0x7E/0x7F` | ❌ **故意不回** | **防死循环**：两端若把响应当请求会互回 NACK 打成死循环（见 `arm_control_protocol.c` 注释） |
| 6 | **CRC 错** | ✅ **回 NACK** | 这是唯一"坏包也回"的情况：回 `0x7E` + `{原CMD, err=2(CRC)}` |

> ⚠ 第 2 条最阴：CRC 错会回 NACK，但**长度写错连 NACK 都没有** ⇒ 只表现为超时。
> 排查"一直超时"时，先手算一遍 `5 + LEN` 是否等于你发的字节数。

### 3.3 序号与重发

- 臂**不对 SEQ 做任何校验**，只回显。所以：
  - 上位机**必须自己**用 `SEQ` 过滤回包（否则串话）；
  - 建议每次请求 `SEQ = (SEQ + 1) & 0xFF`，走一整个 0~255 循环。
- 建议超时 **≥ 300 ms**（`MOVE_JOINTS`/`MOVE_CART` 内部可能触发舵机总线读写，偶尔偏慢）；
  超时后**重发同一条**（幂等性：`GET_STATUS`/`PING`/`PARAM_*` 可随意重发；
  `MOVE_JOINTS` 重发 = 再规划一次同目标轨迹，通常无害但不推荐高频）。
- 实测基线：30 次 `GET_STATUS` 全部成功，平均往返 **11.8 ms**。

### 3.4 速率建议

| 场景 | 建议频率 | 理由 |
|---|---|---|
| 状态轮询 `GET_STATUS` | ≤ 30~50 Hz | 每次都要读 6 颗舵机总线，主循环同步处理 |
| 主从跟随 `STREAM_JOINTS` | **20~50 Hz** | 固件建议值；断流 **500 ms** 看门狗自动退出流模式 |
| 轨迹命令 `MOVE_JOINTS` | 按需 | 一次一条，等 ACK 再发下一条 |

## 5. 逐条命令详解

> 所有 hex 示例都由 `tools/can_host.py` 的真实 codec + 真实 CRC 生成，可直接复制发出去。
> 示例统一 `SEQ` 递增（`0x31` 起），你可以用任何值。

---

### 5.1 `0x01` PING → `0x81`

**用途**：探活 + 取协议版本 + 取本次上电的会话 ID。**不发运动命令也能用**，是最安全的握手。

| 请求负载 | 长度 |
|---|---|
| （无） | 0 |

**回传负载（2 字节）**——这是"详细注释"部分：

| 偏移 | 类型 | 字段 | 含义与判读 |
|---|---|---|---|
| 0 | u8 | `proto_ver` | 协议版本，期望 **`0x01`**。≠1 ⇒ 上位机按协议版本分支 |
| 1 | u8 | `run_id` | **本次上电随机生成的会话 ID**。⚠ **不是错误码**。用途：两次读到不同 `run_id` ⇒ 臂**重启过**（掉电/看门狗复位），上位机应重置内部状态 |

**行为**：无副作用、不动机器人、不限速率。**建议作为所有会话的第一条命令**。

**示例**（`SEQ=0x31`）：
```
请求:  31 01 00 38 0D
应答:  31 81 02 01 5A D1 BA        ← proto_ver=0x01, run_id=0x5A
```

---

### 5.2 `0x02` GET_STATUS → `0x82`（**21 字节**）

**用途**：读六轴实际角度 + FK 末端位姿 + 状态位。**唯一的常规状态来源**（网口没有周期上报）。

| 请求负载 | 长度 |
|---|---|
| （无） | 0 |

**回传负载（21 字节）**：

| 偏移 | 类型 | 字段 | 含义与判读 |
|---|---|---|---|
| 0,2,4,6,8,10 | 6×`int16` | `J1..J6` | **舵机度 ×10**（0~360 全圈量纲，**不是**逻辑角）。`0x8000` = 该轴读失败（见下） |
| 12 | `int16` | `X` | 末端 X，mm ×10 |
| 14 | `int16` | `Y` | 末端 Y，mm ×10 |
| 16 | `int16` | `Z` | 末端 Z，mm ×10 |
| 18 | `int16` | `Pitch` | 末端俯仰，deg ×10 |
| 20 | u8 **位域** | `flags` | bit0=E-Stop 激活，bit1=轨迹执行中，bit2=自适应修正中，bit3=**read_ok**（6 轴读数+F K 全成功）。未用位恒 0 |

**回传语义（关键）**：

- ⚠ **读数无效哨兵 = `-32768`（`0x8000`，字节序 `00 80`）**。某关节读不到时该字段置此值。
  上位机**必须**判它，不能当角度用（`-3276.8°` 会把任何计算带飞）。此时对应位 `read_ok=0`。
- `read_ok=0` 时 **X/Y/Z/Pitch 是 0（不是有效位姿）** —— 固件在 `read_ok=0` 时提前返回，没做 FK。
- 该命令**永远回 `0x82`**，即使读角失败也是（读失败通过位域和哨兵表达，**不会**回 NACK）。
  所以别用"有没有回包"判读角成功，要看 `flags` 的 bit3。
- `E-Stop` 位是**实时电平**（PE11，低有效），**不自锁**：松开立即变 0。

**示例**（正常）：
```
请求:  32 02 00 3B 01
应答:  32 82 15  08 07  B5 04  C2 01  D0 07  84 03  0F 0E  DC 05  E2 FF  68 10  70 03  0A  2A 84
       │  │  │   └J1    └J2    └J3     └J4    └J5    └J6    └X     └Y     └Z     └Pitch └flags
       │  │  └ LEN=0x15=21
       │  └ CMD=0x82
       └ SEQ 回显
       J1=180.0 J2=120.5 J3=45.0 J4=200.0 J5=90.0 J6=359.9
       X=150.0mm Y=-3.0mm Z=420.0mm Pitch=88.0°
       flags=0x0A = 0b1010 ⇒ estop=0, traj=1, corr=0, read_ok=1
       末尾 2A 84 = CRC16 低/高
```
⚠ 位域判读要按位来：`0x0A` = bit1|bit3 ⇒ **estop 是 0**。
写成 `0x0B` 就变成"急停激活"了（bit0=1）—— 别凭"0x0A/0x0B 差不多"想当然。

**示例**（J3 读失败 —— 演示哨兵）：
```
请求:  33 02 00 0B 36
应答:  33 82 15  08 07  B5 04  00 80  D0 07  84 03  0F 0E  00 00  00 00  00 00  00 00  00  77 F4
                              ^^^^^  J3 = 00 80 = -32768 ⇒ 该轴读失败
                                                      X/Y/Z/Pitch 全 0 ⇒ 位姿无效(固件提前返回)
                                                                   flags=0x00 ⇒ read_ok=0
        ⇒ 读失败时"读不到的轴"置哨兵, 而**位姿整体置 0**(不是保留上次值)。两种都要判。
```
⚠ `flags` 判读要**按位**：`0x08`（bit3）是 **read_ok=1**，即"读成功"。
读失败时 bit3 是 **0** ⇒ 一个空闲、未急停、读失败的臂，`flags` 就是 **`0x00`**。

**读失败时固件的确切行为**（`ArmApi_GetStatus`）：
先 `memset` 清零整个快照 → 逐轴读；读失败的轴 `joint_deg` 停在 `-1.0` ⇒ 协议层转成 `-32768`；
只要**任一**轴失败就**跳过 FK** ⇒ `X/Y/Z/Pitch` 保持 **0**，`read_ok=0`。

### 5.3 `0x03` LOG_SET_LEVEL，1 字节

**用途**：设臂侧**运行日志**（`RLOG`，走 COM11 控制台）的等级。调试用，不影响运动。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | u8 | `level` | 0=NONE 1=ERROR 2=WARN 3=INFO 4=DEBUG。**>4 按 4 处理**（不报错） |

**回传**：`ACK` `{0x03, 0}` / `NACK` `{0x03, 1(PARAM)}`（负载长度 < 1 时）。

**行为**：只影响 `[RUN][..]` 那类日志行的输出量。
⚠ 日志是**阻塞写串口**（~7 ms/行 @115200），`DEBUG` 会明显拖慢主循环 ⇒ 测运动时别开 4。

**示例**（`SEQ=0x34`，level=3）：
```
请求:  34 03 01 03 DA 38
应答:  34 7F 02 03 00 4C 39
```

### 5.4 `0x10` MOVE_JOINTS，**16 字节** —— 最常用

**用途**：六关节**关节空间** S 曲线（七段 jerk 限制）运动。**会自动上力矩**。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0,2,4,6,8,10 | 6×`int16` | `J1..J6` | 目标角，**舵机度 ×10**（0~360） |
| 12 | `uint16` | `v_max` | 最大速度 deg/s ×10。**0 = 用臂内默认**（`sc.def_vmax` = 25.0） |
| 14 | `uint16` | `a` | 加速度 deg/s² ×10。**0 = 用 `v × sc.accel_factor`**（×2.0） |

**回传**：`ACK {0x10, 0}` / `NACK {0x10, err}`。

| err | 何时 | 说明 |
|---|---|---|
| 0 | 命令被接受 | ⚠ **"被接受"≠"已动起来"，见下** |
| 1 `PARAM` | 负载 < 16 | |
| 5 `ESTOP` | 急停激活 | 唯一会被固件**明确拒绝**的运动条件 |

**固件内部处理链（`ArmApi_MoveJoints` → `cmdMove`）**：

1. `IsEStop()` → 真则 `err=5` 返回；
2. 速度/加速度**钳制**：`v ≤ 0` → 25；`v < 5` → 5；`v > 300` → 300；`a ≤ 0` → `v×2`；`a < 1` → 1；
3. **目标角静默钳制**（`clamp_all_angles`，按**校准后的 raw 限位**）→ 超限**不报错**，只打一行 WARNING 到 COM11；
4. 读起点（多次采样多数表决）；**读失败 ⇒ 轨迹不启动，直接返回，但 ACK 已发 `err=0`**；
5. 全部上力矩；规划 S 曲线；主循环 200 Hz 插补；结束后做自适应修正。

> ⚠⚠ **三条最要命的语义**（本项目真实踩过）：
> 1. **`err=0` 只代表"命令被收下"**。步骤 4 读起点失败时轨迹根本没起步，但 `ArmApi_MoveJoints` 仍返回 OK。
>    ⇒ **不要用 ACK 判"动没动"，要用 `GET_STATUS` 看角度是否真的变了**。
> 2. **超限是静默钳制**（步骤 3）。目标 400° 会被夹到上限并照常执行 ——
>    `err=0` 但到的位置不是你想要的。**绝对角必须先 `GET_STATUS` 核对当前角**。
> 3. **未校准 ⇒ 限位为空 ⇒ 完全不拦**（`JOINT_MIN_RAW/MAX_RAW` 全 0 时 `clamp_all_angles` 直接 `continue`）。
>    ⇒ 校零前不要用绝对角命令。

**单位警告**：这里的角度是 **舵机度（0~360 全圈）**，与 `GET_STATUS` 返回的**同一量纲**（可直接回填）。
但它**不等于** `STREAM_JOINTS` 的逻辑角 —— 见 §9。

**示例**（`SEQ=0x35`，目标 180°×6，v=10，a=20）：
```
请求:  35 10 10  08 07 08 07 08 07 08 07 08 07 08 07  64 00  C8 00  2A 79
       │  │  │   └ J1..J6 (180.0 = 1800 = 0x0708, 小端 = 08 07)
       │  │  └ LEN=16
       │  └ CMD=0x10
       └ SEQ
       v=10.0 → 100  (0x0064)    a=20.0 → 200 (0x00C8)
应答:  35 7F 02 10 00 3D C5          ← ACK, err=0
NACK:  35 7E 02 10 05 2C E3          ← 若急停激活: err=5 (ESTOP)
```

相对微动（读当前角 → 只改 J6 +2°，v=5）：
```
请求:  36 10 10  08 07 08 07 08 07 08 07 08 07 1C 07  32 00  00 00  50 DA
                                                    └ J6=182.0 (1820=0x071C)
```
（`py -3 tools/arm_net_host.py --delta 0 0 0 0 0 2 --speed 5` 就是自动做这件事）

### 5.5 `0x11` STOP

**用途**：立即停止当前轨迹。

| 请求负载 | 长度 |
|---|---|
| （无） | 0 |

**回传**：`ACK {0x11, 0}` —— **总是成功**，没有失败分支（`ArmApi_Stop` 返回 void）。

**行为**：调 `Trajectory_Stop()`，**平滑减速**停止，不是急停断电。
- 不会取消 `sf` 主从跟随、不会清 E-Stop、不会下力矩。
- 急停链另有其人：物理急停是**硬件电平**（PE11），`IsEStop()` 只在**入口**判 —— 运动中按下急停，
  截断由主循环的急停检查执行（`Trajectory_Stop()`），**松开立即恢复**（无自锁）。

**示例**：
```
请求:  37 11 00 EB BC
应答:  37 7F 02 11 00 8F B2
```

### 5.6 `0x12` SET_TORQUE，2 字节

**用途**：手动抱闸/松闸（上/下力矩）。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | u8 | `joint` | **0~5** = 单关节（0 基，J1=0…J6=5）；**`0xFF` = 全部六轴** |
| 1 | u8 | `enable` | 0 = 下力矩（松）；1 = 上力矩（抱） |

**回传**：`ACK {0x12, 0}` / `NACK {0x12, err}`。

| err | 何时 |
|---|---|
| 0 | 已执行（`enable` 非 0/1 也当非 0，不校验） |
| 1 `PARAM` | 负载 < 2，或 `joint` 在 6~0xFE 之间（非法关节号） |

**行为要点**：

- `MOVE_JOINTS`/`MOVE_CART` **会自动上力矩**，但**不会自动下力矩** ——
  松臂必须显式发本命令（或 `STREAM` 退出后仍在位置模式自锁保温）。
- **主臂构建下无实际作用**：主臂默认只读（`ma 0`）并每秒重申 Torque OFF。
- ⚠ `joint = 0xFF` 是"全部"；`joint = 6` 是**非法**（返回 err=1），别混淆。

**示例**：
```
全部上力矩 (SEQ=0x38):  38 12 02 FF 01 BE 94
应答:                   38 7F 02 12 00 25 82
J3 下力矩  (SEQ=0x39):  39 12 02 02 00 53 4B
应答:                   39 7F 02 12 00 74 28
```

### 5.7 `0x13` STREAM_JOINTS，**12 字节** —— 主从实时跟随

**用途**：20~50 Hz 连续下发六轴目标，**不做轨迹规划/不读起点/不 settle**，专供遥操作跟随。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0,2,4,6,8,10 | 6×`int16` | `J1..J6` | **逻辑关节角 ×10**（相对本臂 Home 零点，带符号） |

**回传**：`ACK {0x13, 0}` / `NACK {0x13, err}`。

| err | 对应固件返回 | 何时 |
|---|---|---|
| 0 | `rc=0` | 本帧已下发。**`sf 0` 暂停跟随时也回 0**（帧被忽略但不算错） |
| 4 `LIMIT` | `rc=1` | 单帧单轴**跳变 > 25°**、或落点过桌面/撞立柱、或舵机总线写失败 |
| 4 `LIMIT` | `rc=3` | **主臂构建**（本臂是主臂 ⇒ 拒绝直写）。⚠ 语义不准，实为主从角色问题 |
| 5 `ESTOP` | `rc=2` | 急停激活 |

**行为要点（全部来自 `cmdStreamJoints`）**：

- **看门狗**：**500 ms** 无成功下发 ⇒ 自动退出流模式，臂**保持当前位置自锁**。所以频率**必须 > 2 Hz**，
  建议 20~50 Hz。
- **限位是静默钳制**：逐轴夹到 `JOINT_MIN_RAW/MAX_RAW`，**整帧照旧下发、不回错**，
  只累计 `stream_clamp_cnt[]` 和 `stream_clamp_frames`（COM11 可查）。
  ⇒ 跟随"到不了位"时先怀疑这里，而不是网络。
- **跳变限制 25°**（`STREAM_MAX_JUMP_DEG`，按**实际下发角**判，避免被 clamp 的帧误判）：
  超了**整帧丢弃**并回 err=4。所以初始对齐要避免大跨度跳变。
- **与轨迹互斥**：任何 `MOVE_JOINTS`/`MOVE_CART` 会先**退出流模式**（`cmdStreamExit`），
  避免流目标与插补目标抢总线（表现为抖动/顿挫）。
- **`sf 0`（文本命令）**：暂停跟随 —— 忽略流帧、立即退出流模式，且**回 err=0**（不算拒绝）。
  ⇒ 上位机从 err 上看不出被忽略了，要另查 `lk` 的 `ignored` 计数。
- ⚠⚠ **量纲**：这里是**逻辑角**（相对 Home），**不是** `GET_STATUS` 返回的舵机度。
  两者差一个 `SERVO_OFFSET`/`JOINT_DIR` 变换 —— **详见 §9，这是本协议最容易搞错的地方**。

**示例**（`SEQ=0x3A`，逻辑角 0,10,20,30,40,50）：
```
请求:  3A 13 0C  00 00  64 00  C8 00  2C 01  90 01  F4 01  FA EB
                 └0.0   └10.0  └20.0  └30.0  └40.0  └50.0
应答:  3A 7F 02 13 00 97 F5          ← ACK
NACK:  3A 7E 02 13 04 A7 C3          ← 跳变>25° 或被拒: err=4 (LIMIT)
```

### 5.8 `0x20` MOVE_CART，**12 字节** —— 笛卡尔运动

**用途**：给定末端 X/Y/Z/Pitch，固件做 IK-CCD 解算 → 限位检查 → FK 回代验证 → 走 S 曲线。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | `int16` | `X` | mm ×10 |
| 2 | `int16` | `Y` | mm ×10 |
| 4 | `int16` | `Z` | mm ×10 |
| 6 | `int16` | `pitch` | 末端俯仰 deg ×10（**相对竖直**，非绝对水平） |
| 8 | `uint16` | `v_max` | deg/s ×10（0=默认） |
| 10 | `uint16` | `a` | deg/s² ×10（0=默认） |

**回传**：`ACK {0x20, 0}` / `NACK {0x20, err}`。

| err | 名称 | 触发 |
|---|---|---|
| 1 | `PARAM` | 负载 < 12 |
| 3 | **`UNREACH`** | **IK 不收敛**（目标太远/姿态无解） |
| 4 | `LIMIT` | 解算出的关节角超**标称限位表** |
| 5 | `ESTOP` | 急停 |
| 6 | **`FK_VERIFY`** | 解算角做 FK 回代，位置误差 > `ik.fk_verify_mm`（默认 5.0 mm）⇒ 认为解不可信，拒绝执行 |

**行为要点**：

- 这是**四类失败码最全**的命令，也是唯一会主动做"解的合理性验证"的。
- 限位检查用的是**标称限位表** `JOINT_MIN/MAX`，**不是**校准 raw 限位（与 `MOVE_JOINTS` 不同）；
  通过后再进 `MOVE_JOINTS` 的 `cmdMove`，那里会**再按校准限位钳一次**（静默）。
- `pitch` 是**相对竖直**的俯仰角；`IK` 里转成 `yaw` 弧度。
- 适合"末端走直线/定高度"类需求；但对**不熟悉工作空间**的第一次联调，建议仍从 `MOVE_JOINTS` 起。

**示例**（`SEQ=0x3B`，X=200, Y=0, Z=300, pitch=90, v=10, a=20）：
```
请求:  3B 20 0C  D0 07  00 00  B8 0B  84 03  64 00  C8 00  2C 7D
                 └200.0 └0.0   └300.0 └90.0
应答:  3B 7F 02 20 00 00 0F      (ACK)
或:    3B 7E 02 20 03 D7 49      (NACK err=3 UNREACH — IK 不可达)
或:    3B 7E 02 20 06 72 19      (NACK err=6 FK_VERIFY — FK 回代超差)
```

### 5.9 `0x21` FK_QUERY → `0xA1`（**21 字节**）

**用途**：查末端位姿 + 六轴角。与 `GET_STATUS` 的**数据源相同**，但**排列顺序不同**。

| 请求负载 | 长度 |
|---|---|
| （无） | 0 |

**回传负载（21 字节）**：

| 偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | `int16` | `X` | mm ×10 |
| 2 | `int16` | `Y` | mm ×10 |
| 4 | `int16` | `Z` | mm ×10 |
| 6 | `int16` | `Pitch` | deg ×10 |
| 8,10,12,14,16,18 | 6×`int16` | `J1..J6` | **舵机度 ×10**，`0x8000` = 该轴读失败 |
| 20 | u8 | `read_ok` | **原始值 0 或 1**（⚠ **不是位域！**） |

> ⚠⚠ **两个和 `GET_STATUS` 极易混淆的点**：
> 1. **顺序相反**：这里是"先位姿后关节"，`GET_STATUS` 是"先关节后位姿"。
> 2. **偏移 20 的含义不同**：这里是 `read_ok` 裸值（0/1）；`GET_STATUS` 那里是**位域**（bit3 才是 read_ok）。
>    ⇒ **共用一个解析函数一定会出错。** 参考实现里是两个独立函数
>    （`decode_status_payload` / `decode_fk_payload`）。
>
> 与 `GET_STATUS` 一样：**永远回 `0xA1`**，读失败不 NACK，靠 `read_ok` 与 `-32768` 表达。

**示例**（`SEQ=0x3C`）：
```
请求:  3C 21 00 8F 49
应答:  3C A1 15  DC 05  E2 FF  68 10  70 03  08 07  B5 04  C2 01  D0 07  84 03  0F 0E  01  0E D5
                └X=150.0 └Y=-3.0 └Z=420.0 └P=88.0 └J1=180.0 …                 └J6=359.9 └read_ok=1
       ⚠ 对照上面的 GET_STATUS: 这里**先位姿(0~7)后关节(8~19)**, 且偏移 20 是**裸 read_ok**(不是位域)
```

### 5.10 `0x30` SET_GRAVITY，2 字节

**用途**：设 J2 重力前馈系数 K（等价于写参数表 **#32 `gc.k`**）。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | `int16` | `K` | deg/mm **×1000**。例：0.05 → `50`；0 → 关闭 |

**行为**：内部走 `ArmParams_Set(AP_GC_K, K/1000)` ⇒ **范围钳制 0~0.5，超范围不回错**。

**示例**（`SEQ=0x3D`，K=0.05）：

```
应答:  3D 7F 02 30 00 F6 C1
```

### 5.11 `0x31` SET_CORRECTION，4 字节

**用途**：配置**运动结束后的自适应修正**（用末端反馈微调关节角，消除重复定位误差）。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | u8 | `enable` | 0=关 1=开（写参数 **#33**） |
| 1~2 | `uint16` | `threshold` | 收敛阈值 deg **×100**（写 **#34**；例 2.00° → `200`） |
| 3 | u8 | `max_rounds` | 最大轮数（写 **#35**） |

**回传**：`ACK {0x31, 0}` / `NACK {0x31, 1}`（负载<4，或三个参数任一写失败）。

**行为**：**三个参数一次写全**（不是增量设置）。范围：`enable` 0~1、`threshold` 0.5~10°、`max_rounds` 1~20，
**超范围静默钳制、不回错**。修正进行中时 `GET_STATUS` 的 bit2 会置位。

**示例**（`SEQ=0x3E`，en=1, thr=2.00°, rounds=10）：
```
请求:  3E 31 04 01 C8 00 0A 49 21      ← 0x00C8 = 200 = 2.00° × 100
应答:  3E 7F 02 31 00 15 1C
```

### 5.12 `0x40` PARAM_READ，1 字节 → `0xC0`（5 字节）

**用途**：读参数表任意一项（见 §8）。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | u8 | `id` | 参数 ID（§8 表；⚠ **ID 46 是哨兵，不是参数**） |

**回传负载（5 字节）**：

| 偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | u8 | `id` | **回显**请求的 ID（配对校验用） |
| 1~4 | `int32` | `val` | 参数值 **×1000**，小端。实际值 = `val / 1000.0` |

**回传分支**：

| 情况 | 响应 | 说明 |
|---|---|---|
| 合法 ID | **`0xC0`** + 5 B | 查询响应 |
| 非法 ID | **`0x7E` NACK** `{0x40, 1}` | ⚠ 注意 `原CMD` 是 **`0x40`**（请求码），不是 `0xC0` |
| 负载 < 1 | `0x7E` NACK `{0x40, 1}` | |

**示例**（`SEQ=0x3F`，读 #17 `sc.def_vmax`，实际值 25.0 deg/s）：
```
请求:  3F 40 01 11 4B 50
应答:  3F C0 05 11 A8 61 00 00 D1 F6
                │  └ int32 = 0x000061A8 = 25000 ⇒ 25000 / 1000 = 25.0 deg/s ✔
                └ id 回显 = 0x11 = 17 ✔
```

**示例**（非法 ID —— 注意 NACK 里的"原CMD"是请求码 `0x40`）：
```
请求:  40 40 01 2E 6C 01          ← id=0x2E = 46 = 表长哨兵, 不是参数
应答:  40 7E 02 40 01 C6 93       ← NACK {原CMD=0x40, err=1(PARAM)}
                                  ⚠ 不是 0xC0! 查询失败时走 NACK 分支
```

> **×1000 的正确解读**：协议一律传 `值 × 1000`。
> 但参数的**量纲**不同 —— `sc.def_vmax` 的值 25.0 传成 `25000`；
> `ik.converge_mm` 的值 0.5 传成 `500`。
> ⇒ 解码统一 `val / 1000.0` 即可，**具体含义看 §8 表的"单位"列**，不要再除一次。

### 5.13 `0x41` PARAM_WRITE，5 字节

**用途**：写参数表任意一项。

| 请求偏移 | 类型 | 字段 | 含义 |
|---|---|---|---|
| 0 | u8 | `id` | 参数 ID |
| 1~4 | `int32` | `val` | 目标值 **×1000**，小端 |

**回传**：`ACK {0x41, 0}` / `NACK {0x41, 1(PARAM)}`。

| err | 何时 |
|---|---|
| 0 | 写入成功（**包括被范围钳制的情况**） |
| 1 | 负载 < 5、或 **ID 不存在** |

> ⚠⚠ **写超范围不会回 NACK，而是静默钳制后回 ACK err=0。**
> 例：给 #17（范围 5~300）写 `0.025` ⇒ 实际写入 `5.0`，但应答是 `err=0`。
> ⇒ **写完要 `PARAM_READ` 回读确认**，别信 ACK。
> （CAN 版规格书里"写超范围回 NACK PARAM"的表述是错误的，本文以源码为准。）

**持久化**：参数默认只存在 RAM。要落 Flash 需在 COM11 敲文本命令 `F`（会一并保存 PID/修正/速度）。
`PARAM_WRITE` 本身**不写 Flash**，重启即丢。

**示例**（`SEQ=0x41`，写 #17 = 25.0 deg/s —— 正常）：
```
请求:  41 41 05 11 A8 61 00 00 54 CB      ← id=0x11, val=25000 (=25.0×1000)
应答:  41 7F 02 41 00 33 6C               ← ACK err=0
回读:  3F C0 05 11 A8 61 00 00 D1 F6      ← 确认生效
```

**示例**（`SEQ=0x42`，写 #17 = 0.025 —— 会**被静默钳制**）：
```
请求:  42 41 05 11 19 00 00 00 1F 28      ← val=25 ⇒ 0.025, 但 #17 范围是 5~300
应答:  42 7F 02 41 00 E1 82               ← ⚠ 仍然是 ACK err=0!
回读:  值变成 5.0 (下限), 不是 0.025
```
⚠⚠ 这就是"**写超范围不报错**"的实证：**只有回读才能确认真正写进去的值**。

### 5.14 `0x42` PARAM_COUNT → `0xC2`（1 字节）

**用途**：读参数表项数。**同时也是"固件能力指纹"** —— 项数变了说明参数表被改过。

| 请求负载 | 长度 |
|---|---|
| （无） | 0 |

**回传负载（1 字节）**：`count` = 参数表项数，**现役 = 24**（`0x18`）。

**示例**：
```
请求:  43 42 00 CF E3
应答:  43 C2 01 18 1F 99      ← count=0x18=24
```

## 7. 错误码（NACK 负载第 2 字节）

| 值 | 名称 | 含义 | 实际触发点 |
|---|---|---|---|
| 0 | `OK` | 成功（ACK） | — |
| 1 | `PARAM` | 参数非法 | 负载长度不足；未知 CMD；非法参数 ID；非法关节号；未知命令 |
| 2 | `CRC` | 帧 CRC 校验失败 | **只有这一种坏包会回 NACK**（见 §3.2） |
| 3 | `UNREACH` | IK 不可达 | 只在 `MOVE_CART` |
| 4 | `LIMIT` | 超限/不安全 | `MOVE_CART` 解算超标称限位；`STREAM_JOINTS` 跳变>25°、撞桌面/立柱、总线写失败 |
| 5 | `ESTOP` | 急停激活 | `MOVE_JOINTS` / `MOVE_CART` / `STREAM_JOINTS` |
| 6 | `FK_VERIFY` | FK 回代验证超差 | 只在 `MOVE_CART` |
| 7 | `READ` | 舵机总线读失败 | ⚠ **协议层实际不会以 NACK 出现** —— `GET_STATUS` 读失败改用 `read_ok=0` + `-32768` 表达，命令本身仍回数据 |

| `8` | `MAGIC` | 危险命令的 `u32 magic` 不符（防误触发/串包） |
| `9` | `BUSY` | 轨迹/示教/回放进行中，当前操作不允许 |
| `10` | `NOTCAL` | 该轴未校准（`zero_raw == 0`） |

## 9. 关节坐标系（**本协议最容易错的地方**）

固件里有**两套**角度量纲，协议里各命令用的不是同一套：

| 量纲 | 定义 | 范围 | 用在哪 |
|---|---|---|---|
| **舵机度** | 舵机自己的绝对角度 | 0~360 全圈 | `GET_STATUS`(0x82)、`FK_QUERY`(0xA1)、`MOVE_JOINTS`(0x10)、`MOVE_CART` 内部 |
| **逻辑角** | 相对本臂 **Home 零点**的带符号关节角 | (-180, 180] | **`STREAM_JOINTS`(0x13)**、`MOVE_JOINTS` 的部分内部判定 |

转换关系（`kinematics.c` / `main.c`）：

```
舵机度 = (SERVO_OFFSET[j] + JOINT_DIR[j] × 逻辑角) mod 360
逻辑角 = JOINT_DIR[j] × (舵机度 - SERVO_OFFSET[j])，归一到 (-180, 180]

其中  JOINT_DIR   = { -1, +1, +1, +1, +1, +1 }        // 仅 J1 反向
      SERVO_OFFSET = { 180,180,180,180,180,180 }      // 出厂默认，但会被 Home 校零改写！
```

**两个实际后果**：

1. **`GET_STATUS` 的输出不能直接喂给 `STREAM_JOINTS`** —— 必须先做上面的变换。
   （`MOVE_JOINTS` 可以直接喂，因为同量纲。）
2. ⚠ **`SERVO_OFFSET` 会被 Home 校零（`zi` / `Kinematics_SetZeroRaw`）改写**，
   而**网口协议没有任何命令能读出它** ⇒ 走 `STREAM_JOINTS` 的上位机**拿不到这个偏移**。

**当前可行的做法**（按推荐度）：

| 做法 | 说明 |
|---|---|
| ✅ **两端都用同一套逻辑角** | 主从跟随的**正确用法**：主臂发出来的就是逻辑角，从臂直接吃，两端零点各自校准。协议头注释明确要求如此 |
| ✅ 用 COM11 敲 `zi` 读出偏移，端侧固化 | 标注"偏移变了要同步改" |
| ⚠ 假定 `SERVO_OFFSET = 180` | 只在**确认从未校零**时成立 |

## 11. 故障对照表（现象 → 先查什么）

| 现象 | 最可能的原因 | 怎么验 |
|---|---|---|
| 全部命令超时，`ping` 也丢 | 链路/PHY | `ping 192.168.7.120`；COM11 敲 `nx` 看 `link/phy found` |
| `ping` 通但所有 UDP 命令超时 | 端口/长度 | 目的端口必须 5000；手算 `5+LEN`；抓包看有没有回 |
| 只有 **CRC=错的**包有回包 | 正常！ | CRC 错会回 NACK err=2（§3.2） |
| 长度笔误 → 纯超时 | 正常！ | 长度不符臂**完全不回**（§3.2 第 2 条） |
| 发了 `0x82`/`0x7F` 没反应 | 正常！ | `CMD ≥ 0x80` 故意不回（防死循环） |
| `PING` 的"错误码"每次都不同 | **误把 `run_id` 当 err** | `0x81` 偏移 1 是 `run_id`（§5.1） |
| `GET_STATUS` 角度是 `-32768` | 该轴舵机读失败 | 查舵机总线/ID；看 `read_ok` |
| `MOVE_JOINTS` 回 err=0 但没动 | ①读起点失败（也回 ACK）②目标就是当前位姿 | `GET_STATUS` 对比角度；看 COM11 有没有 `current pose unreadable` |
| `MOVE_JOINTS` 到了但位置不对 | **超限被静默钳制** | 看 COM11 的 `WARNING: N joint(s) clamped`；先 `--status` 核对 |
| 未校零时绝对角命令"畅通无阻" | **限位为空，不拦** | COM11 敲 `zi` 确认已校准 |
| `MOVE_CART` 回 err=3 | IK 不可达（目标太远/姿态无解） | 缩小目标范围；改用 `MOVE_JOINTS` |
| `MOVE_CART` 回 err=6 | FK 回代超差 | 放宽 `ik.fk_verify_mm`(#4) 或换目标 |
| `STREAM_JOINTS` 回 err=4 且动不了 | ①单帧跳变>25° ②撞桌面/立柱 ③总线写失败 | 看 COM11 的 `Stream reject: Jn jump …` / `pose unsafe` |
| `STREAM` 跟随"到不了位"但没报错 | **限位静默钳制**（正常设计） | 查 `stream_clamp_cnt[]`（COM11） |
| `STREAM` 发了没反应，也不报错 | **`sf 0` 暂停跟随**（回 err=0） | COM11 敲 `sf` 看状态；`sf 1` 恢复 |
| `PARAM_WRITE` 回 err=0 但值没变 | **超范围被静默钳制** | `PARAM_READ` 回读；对照 §8 范围 |
| `PARAM_WRITE` 后重启就丢 | 参数默认只在 RAM | COM11 敲 `F` 落 Flash |
| 命令时好时坏 | 主循环被日志拖慢 / 频率太高 | `LOG_SET_LEVEL` 降到 1~2；降频 |

### 12.2 最小客户端（纯标准库，40 行，可直接改成你的语言）

```python
import socket, struct

ARM = ("192.168.7.120", 5000)

def crc16(data: bytes) -> int:
    crc = 0xFFFF
    for b in data:
        crc ^= b << 8
        for _ in range(8):
            crc = ((crc << 1) ^ 0x1021) & 0xFFFF if crc & 0x8000 else (crc << 1) & 0xFFFF
    return crc

def build(seq: int, cmd: int, payload: bytes = b"") -> bytes:
    body = bytes([seq & 0xFF, cmd & 0xFF, len(payload)]) + payload
    c = crc16(body)
    return body + bytes([c & 0xFF, c >> 8])

def parse(data: bytes):
    seq, cmd, ln = data[0], data[1], data[2]
    assert len(data) == 5 + ln, "长度不符"
    got = data[3 + ln] | (data[3 + ln + 1] << 8)
    assert got == crc16(data[:3 + ln]), "CRC 错"
    return seq, cmd, data[3:3 + ln]

sock = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
sock.settimeout(0.5)
seq = 0x30

def request(cmd: int, payload: bytes = b""):
    global seq
    seq = (seq + 1) & 0xFF
    sock.sendto(build(seq, cmd, payload), ARM)
    for _ in range(3):                     # 简单重发
        try:
            data, _ = sock.recvfrom(2048)
        except socket.timeout:
            continue
        rseq, rcmd, rpl = parse(data)
        if rseq == seq:                    # ★必须按 SEQ 配对
            return rcmd, rpl
    raise TimeoutError("cmd=0x%02X" % cmd)

# --- 用法 ---
rcmd, rpl = request(0x01)
print("PING proto_ver=%d run_id=%d" % (rpl[0], rpl[1]))

rcmd, rpl = request(0x02)
j = struct.unpack_from("<6h", rpl, 0)
print("关节(舵机度) =", [None if v == -32768 else v / 10.0 for v in j])
print("位姿 x=%.1f y=%.1f z=%.1f pitch=%.1f" %
      (struct.unpack_from("<h", rpl, 12)[0] / 10.0,
       struct.unpack_from("<h", rpl, 14)[0] / 10.0,
       struct.unpack_from("<h", rpl, 16)[0] / 10.0,
       struct.unpack_from("<h", rpl, 18)[0] / 10.0))
f = rpl[20]
print("estop=%d traj=%d corr=%d read_ok=%d" % (f & 1, (f >> 1) & 1, (f >> 2) & 1, (f >> 3) & 1))
```

## 13. 网口协议专用红线

1. **`5 + LEN` 必须等于报文长度** —— 不等臂**完全不回包**（连 NACK 都没有），只表现为超时。
   CRC 错反而会回 NACK。**别用"有没有回包"判 CRC。**
2. **`PING` 用的是 `0x81` + `{proto_ver, run_id}`，不是 ACK**。第 2 字节是会话 ID，不是错误码。
3. **`CMD ≥ 0x80`（含 `0x7E/0x7F`）故意不回包** —— 这是防两端互回 NACK 的死循环保护，不是故障。
4. **`GET_STATUS` 与 `FK_QUERY` 顺序相反、偏移 20 含义不同**（位域 vs 裸值）——
   共用解析函数必错。
5. **`err=0` ≠ "运动已启动"**：`MOVE_JOINTS` 在读起点失败时也回 ACK，只是没起步。
   判"动没动"只能靠 `GET_STATUS` 的角度变化。
6. **超限是静默钳制，不是报错**：`MOVE_JOINTS` 目标角超校准限位、`PARAM_WRITE` 值超范围、
   `STREAM_JOINTS` 逐轴超限 —— **三者都回 `err=0`**。一律**写完回读 / 看角度**验证。
7. **未校准 ⇒ 限位为空 ⇒ 绝对角不设防**（`JOINT_MIN_RAW/MAX_RAW` 全 0 时跳过钳制）。
   绝对角命令前先确认已校零（COM11 `zi`）。
8. **两套角度量纲不可混用**：`GET_STATUS`/`MOVE_JOINTS` 是**舵机度**，`STREAM_JOINTS` 是**逻辑角**，
   差一次 `SERVO_OFFSET/JOINT_DIR` 变换，且 `SERVO_OFFSET` **改过后网口读不到**（§9）。
9. **网口无主动上报**：没有周期状态帧、没有事件帧（那是 CAN 才有的）。
   急停/看门狗/限位都只能靠轮询 `flags` 发现。
10. **`SEQ` 臂不校验、只回显** ⇒ 上位机**必须自己**按 `SEQ` 过滤回包（UDP 无顺序保证）。
11. **单位 ×10/×1000 要按"参数单位"解读**，不能一律当"值/1000"（§8 末尾）。
12. **不要用 `--move`（绝对角）做第一次点动**，用 `--delta`（相对）——
    绝对角有静默钳制这个陷阱（红线 6）。

## 14. 2026-09-23 扩展：24 条新命令（字段级）

> 设计基准与取舍理由：`docs/网口指令扩展设计_2026-09-23.md`
> 固件出处：`Core/Inc/arm_control_protocol.h`（逐条注释）+
> `Core/Src/arm_control_protocol.c`（分发）+ `Core/Src/arm_main_exports.h`（文本透传导出）。

### 14.0 为什么是这 24 条（而不是提案里的 55 条）

提案原本要给每条控制台命令都加一个 opcode。实现阶段否掉了，理由三条：

1. **追不上**。控制台 124 条且在长；加 opcode = 每加一条控制台命令就要同步改
   头文件 / 分发 / API 层 / 两份 SDK —— 永远落后。
2. **会分叉**。`M a` / `zr` / `F` 在控制台早就实现好了（含全部副作用与提示文本）。
   再写第二份 = 两份实现迟早不一致，而**这几条的后果不可逆**。
3. **安全拦截天然继承**。11 条抢 ETH 引脚的命令，`ProcessCommand` 开头那段
   `#if ARM_LINK_NET` 会接住它们。走透传 = 自动继承。

所以最终形态是：**热路径留类型化 opcode，长尾走一条 `TEXT_EXEC`**（§15）。

### 14.1 诊断类

#### `0x04 GET_JOINT_DETAIL`

```
请求  u8 joint        0~5 单轴 / 0xFF 六轴
响应  0x84: u8 n, u8 joint0, n × 10 B
```

每轴 10 B：

| 偏移 | 类型 | 含义 |
|---|---|---|
| +0 | u16 | `pos_raw`（0~4095） |
| +2 | i16 | `speed`（step/s） |
| +4 | i16 | `load`（有符号） |
| +6 | u8 | `volt`（0.1 V） |
| +7 | u8 | `temp`（°C）—— **`0xFF` = 这一拍丢读** |
| +8 | u8 | `err`（硬件错误位）—— **`0xFF` = 读失败** |
| +9 | u8 | `ok`（1 = 本轴读成功） |

六轴 = `2 + 6×10 = 62 B` ≤ 64 ✅

⚠ **总线是逐字段瞬时丢读的**（实测 Angle≈5% / Temp≈20% / Moving≈33%，
各字段独立随机）⇒ `temp = 0xFF` 是"这一拍没读到"，**不是 0 度、也不是故障**。
单次读数不可全信，上位机应做滑窗/多数表决。

⚠ `ok = 0` 表示**本轴整组**读失败，此时`pos/speed/load` 都是 0（无意义），
只有 `temp`/`err` 的哨兵有意义。

#### `0x05 GET_LIMITS`

```
响应  0x85: 6 × 8 B = 48 B
      每轴 u16 min_raw, pos_raw, max_raw, zero_raw
```

⚠ 这 4 组 raw 取自 `PID_FlashLoad()` 的 `PID_JointLimits_t` —— 是
**Flash 校准记录**，**不是运行时限位**（运行时限位 `L` 是舵机度
J1 63~303 / J2 75~284 / J3 76~271 / J4 71~284 / J5 12~351 / J6 138~266，
那套没进协议，只能文本读）。

⚠ `zero_raw == 0` ⇒ 该轴没做过 Home 零点校准，固件回落 180° / raw 2048
⇒ **量纲基准是脆的**，别在上面做精度动作。

#### `0x07 GET_INFO`

```
响应  0x87: u8 tag_len, char fw_tag[16], u8 build, u8 link, u8 nsrv = 20 B
```

| 字段 | 说明 |
|---|---|
| `fw_tag` | 如 `ARM-NET-0921A`；`tag_len` 是有效长度，后面补 0 |
| `build` | `0=net 1=can 2=both 3=uart 4=off` |
| `link` | **`LinkCfg_ActiveMode()` 的启动冻结值**，⚠ **不是 Flash 偏好** |
| `nsrv` | 参数条目数（= `PARAM_COUNT` 的值，现役 24） |

🔴 **⚠⚠ 2026-09-24 定位的缺陷：`fw_tag` 字段是 `arm_control_api.c` 里
`GetInfo` 的硬编码字符串，从未随版本升级同步** ⇒ **响应里的 fw-tag 恒为
`ARM-NET-0921A`，与板上真实固件无关**。判版本**只能** `TEXT_EXEC "h"` 看首行
（§16 自检第 1 步本来就该发 `h` —— 把第 1 步的"也可 GET_INFO"当耳旁风）。
该缺陷在 §17.1 登记，修复需动 `GetInfo`（等下一次发版一并做）。

⚠ `link` 的"启动冻结"语义很关键：「改了偏好但还没 RESET」时，偏好已经变了
但 `link` 还是旧值 —— 这正是判断"**到底跑在哪条链路上**"的依据（红线 69）。

#### `0x0A GET_FLAGS`

```
响应  0x8A: u8 flags, u8 run_id = 2 B
```

| 位 | 含义 |
|---|---|
| bit0 | E-Stop 激活 |
| bit1 | 轨迹运动中 |
| bit2 | 流模式中 |
| bit3 | 自适应修正使能 |
| bit4 | 示教录制中 |
| bit5 | 示教回放中 |

⚠ 它**只读几个变量、不碰舵机总线** ⇒ 适合 10~50 Hz 轮询做 UI 状态灯。
对照 `GET_STATUS` 要读 6 轴舵机（约 4~6 ms）。

### 14.2 运动类

#### `0x14 MOVE_JOINT_ONE`

```
请求  u8 joint(0~5), i16 deg×10, u16 v×10, u16 a×10 = 7 B
响应  ACK / NACK
```

⚠ 角度是**舵机度**（与 `MOVE_JOINTS` 同量纲），**不是** `STREAM_JOINTS` 的逻辑角。

⚠ 固件先读**全场快照**、只改这一轴目标 ⇒ **任一轴丢读则整条回 `ERR_READ(7)`**。
这是有意设计：**拿不准位置时不动，比动错强**。
所以单轴点动前要保证六轴都能读（`GET_JOINT_DETAIL(0xFF)` 里 `ok` 全 1）。

`v` / `a` 传 0 ⇒ 用 `AP_SC_DEF_*` 默认值（与 `MOVE_JOINTS` 同规则）。

#### `0x17 SET_BUS_MODE` / `0x18 SERVO_INIT`

| 命令 | 请求 | 说明 |
|---|---|---|
| `0x17` | `u8 mode` | `0` = 正常 `A:AABBB` / `1` = 全 A / `2` = 全 B。调试用，别放进生产路径 |
| `0x18` | `u8 joint(0~5 / 0xFF)` | ⚠ **会重写该轴 PID / 限位 / 中位并 RESET**，副作用与文本 `i` 相同 |

### 14.3 运动学 / 补偿 / 参数

#### `0x22 IK_QUERY` —— **只解不算**

```
请求  i16 x, y, z (mm×10), i16 pitch(deg×10) = 8 B
响应  0xA2: 6 × i16 舵机度×10 = 12 B
失败  err = 3 不可达 / 4 超关节限位 / 6 FK 回代超差
```

做 IK 解算 + 限位检查 + FK 回代验证，**不启动任何运动**。
用途：「**先问能不能到，再决定动不动**」—— 比 `MOVE_CART` 发出去撞失败更省事，
而且不会因为"解算失败"留下半截状态。

#### `0x32 / 0x33 / 0x36` 读回侧

| 命令 | 响应 | 布局 |
|---|---|---|
| `0x32` | `0xB2` | `i16 K`（×1000 deg/mm）= 2 B |
| `0x33` | `0xB3` | `u8 en, u16 thr×100, u8 max_rounds, u8 pending` = 5 B |
| `0x36` | `0xB6` | `u8 p, u8 i, u8 d, u8 from_eeprom` = 4 B |

⚠ `GET_PID` 的字段顺序就是 **p/i/d**。固件底层 `SERVO_ReadPidEeprom()` 的形参
顺序是 `(p, d, i)`，API 层已经换算过 —— 到这里**不要再换一次**
（换两次等于没换，看见的值每轴都是错的）。

⚠ `from_eeprom = 0` 表示**读失败**，p/i/d 不可信（是那个轴的从机没答，
**不是"PID 就是 0"**）。

#### `0x44 PARAM_LIST`（元数据，6 条/页）

```
请求  u8 offset
响应  0xC4: u8 total, u8 n, n × 10 B
      每条: u8 id, u8 type, i32 vmin×1000, i32 vmax×1000
```

⚠ `vmin/vmax` **必须是 i32**：参数范围里有超过 `i16` 的值
（如 `traj.approach_speed` 上限 4095），压成 `i16` 会**静默截断**。
`2 + 6×10 = 62 B` ≤ 64 ✅

⚠ **值不在这一包里** —— 带上 i32 值会超 64 B，所以固件刻意把"元数据"和"值"
拆开；值用 `PARAM_READ(0x40)` 单取。

翻页终止：`n == 0` 或 `offset + n >= total`。

### 14.4 示教存储

| 命令 | 请求 | 响应 |
|---|---|---|
| `0x50` | `u8 idx` | `0xD0`：`u8 total, u8 idx, u8 valid, char name[12], u32 samples` = 19 B |
| `0x51` | `u8 idx, u16 off, u8 n(1~5)` | `0xD1`：`u8 n` + n×12 B（6×u16 raw） |
| `0x53` | `u8 idx` | ACK（写 tombstone） |
| `0x54` | — | ACK（回收 tombstone 空间） |
| `0x55` | — | `0xD5`：`u8 nfiles, u8 capacity, u32 total_samples, u32 free_bytes` = 10 B |

⭐ `TEACH_READ` 是**分页**读：`12 × 5 = 60 ≤ 64`。
1000 点轨迹 = 200 次请求；网口 p50 1.61 ms ⇒ 约 **0.3 s 取完**。

⚠ **`off` 越界 ⇒ `n = 0`，那是"正常读完"，不是错误**（PC 侧循环终止条件）。

⚠ `TEACH_LIST` 的 `valid = 0` 表示该槽位是 **tombstone**（已删、空间未回收）。
`TEACH_DELETE` 只写 tombstone；真回收空间要 `TEACH_COMPACT`（⚠ 会擦 Flash，耗时）。

### 14.5 危险操作（全部强制 MAGIC）

`MAGIC = 0x5A5A5A5A`。作用：无连接（UDP）/无重传通道上，这几条一旦误触发
**不可逆** —— `M a` 废掉量纲基准、`zr` 重置 Home 零点、软复位中断一切在跑的东西。
magic 让"扫描器误打 / 串包"无法命中，必须**显式构造**。

| 命令 | 请求 | 行为 |
|---|---|---|
| `0x70 CENTER_CALIB` | `u32 magic` | ACK，执行文本 `M a`（六轴推到 raw 2048） |
| `0x71 CALIB_ENTER` | `u32 magic` | ⚠ **一律 NACK(`ERR_PARAM`)** |
| `0x72 ZERO_RESET` | `u8 flags(bit0=落盘), u32 magic` | ACK，执行 `zr` / `zr save` |
| `0x73 SYS_RESET` | `u32 magic` | ACK **之后** 150 ms 才复位 |
| `0x43 PARAM_SAVE` | `u32 magic` | ACK，执行文本 `F` |

#### ⚠ `0x72 ZERO_RESET` 没有关节号

文本 `zr` **根本没有单轴变体**（一次复位全部六轴）⇒ 协议也不给关节号，不猜。
`flags.bit0 = 1` 等价 `zr save`（写 Flash，重启保持）；`0` 只本次运行有效。
传了非法 flags（> 1）一律回 `ERR_PARAM`。

#### ⚠ `0x71 CALIB_ENTER` 一律 NACK —— 这是**设计**，不是实现漏项

`cmdCalibrate()` 里是 `for(;;)` 等人在**本机串口**上敲 `'0'`/`'s'`/`'q'`。
从网口进 = **主循环永不返回**，而本工程**没有看门狗**（红线 5）⇒ 板子彻底失联，
但 USB 还在枚举 —— 最难查的一种死法。它本来就要求人手摆位，是控制台专属命令。

保留这个码位是为了让"**不可用**"在协议层面**显式可见**，
比让上位机收到一个没头没尾的参数错要好。**要校准请接 COM11。**

#### ⚠ `0x73 SYS_RESET` 先回 ACK，150 ms 后才复位

固件用 `ArmMain_RequestReset(150)` 登记时间戳，主循环 `ArmMain_ServicePendingReset()`
在 **UDP ACK 发完之后**才 `NVIC_SystemReset()`。
顺序反了上位机只会看到**超时**，分不清"复位成功"和"包丢了"。

复位后按 **Flash 里的链路偏好**重建 ⇒ 远程切链路的完整序列是：

```
TEXT_EXEC("link can")  →  TEXT_EXEC("link save")  →  SYS_RESET
```

⚠ 若偏好指向另一条链路，这台臂**就不会再在网口上回话**了。

## 15. `TEXT_EXEC` —— 把整个控制台搬上网口

> 这是"**所有指令都支持网口下发**"的答案。124 条控制台命令里 **113 条**可用，
> 而只需**一个** opcode。

### 15.1 为什么这样设计

```
TEXT_EXEC(0x0B)
   └→ ArmMain_TextGate()        安全闸门
        └→ ArmMain_ExecText()   把 con_sink 从 con_write_uart 切到 con_capture
             └→ ProcessCommand()  ← 与 COM11 上敲同一行**完全相同的路径**
                  └→ con_capture() 收进 g_text_buf[2048]
   ←── 切回 con_write_uart（不切回 ⇒ COM11 静默失声）
```

**语义零漂移**：连回显文本都与串口一字不差（含 `[FAULT]`/`WARNING`/中文提示）。

### 15.2 报文格式

```
请求 0x0B:  u32 magic(0x5A5A5A5A) | char text[]（NUL 结尾，有效长度 ≤ 58）
响应 0x8B:  u16 total | u8 flags | u16 off | u8 n | char text[n]
请求 0x0C:  u16 off | u8 n(1~58)        取上条的后续分页
响应 0x8C:  同 0x8B
```

| 项 | 值 | 出处 |
|---|---|---|
| 单条命令最长 | **58 字符** | `APROTO_TEXT_CHUNK` / `TEXT_EXEC_MAX` |
| 单页正文上限 | **58 B**（6 B 头 + 58 = 64） | 同上 |
| 单次捕获上限 | **2048 B** | `ARM_TEXT_BUF_SZ`（`main.c`） |
| `total` / `off` 单位 | ⚠ **字节**（不是字符） | 固件那边就是一块字节缓冲 |
| `magic` | **无条件要求** | 这条命令能做的事等于整个控制台 |

`flags`：

| 位 | 含义 |
|---|---|
| bit0 | 输出被 `ARM_TEXT_BUF_SZ(2048)` **截断**（半截，别当完整） |
| bit1 | 被**安全闸门拒绝**（正文是**原因说明**，不是命令输出） |

### 15.3 ⚠ 分页必须按「字节」拼接

控制台的中文提示是 **UTF-8 字节**。一页 58 B 很容易正好切在一个 3 字节汉字的
中间 ⇒ **逐页 decode 会在缝上拼出坏字符**（`U+FFFD`）。

正确做法：**按字节收集所有页 → 拼成一个 byte 串 → 最后统一 decode 一次**。

```python
parts, off = [first.raw], first.off + len(first.raw)
while off < first.total:
    page = client.text_out_raw(off, 58)      # 或直接发 0x0C
    if not page.raw: break
    parts.append(page.raw); off += len(page.raw)
text = b"".join(parts).decode("utf-8", "replace")
```

SDK 的 `text_exec()` 已经这么做（Python / JS 两边都是），直接用即可。

### 15.4 ⚠ 安全闸门 `ArmMain_TextGate()`

| 返回 | 条件 | 含义 |
|---|---|---|
| 0 | — | 放行 |
| 1 | 空行 / 以空格开头 / `#` / **单独 `c`** | **交互阻塞类**，拒绝 |
| 2 | **E-Stop 激活**且命令不是 `s` / `h` | 急停白名单 |

`c`（相位校准向导）被拒的理由见 §14.5。

⚠ 闸门**刻意不重复列那 11 条抢引脚命令** —— 那段判断就在 `ProcessCommand`
开头（`#if ARM_LINK_NET`），抄第二份迟早漂移。

### 15.5 `TEXT_EXEC` 的能力边界（**务必先读这张表**）

| 情况 | 表现 | `flags.bit1` |
|---|---|---|
| 124 条里的 **113 条** | 正常执行，输出自动翻页取回 | 0 |
| 11 条抢 ETH 引脚的（`cx cp cy cz cw ps can mg mp mo ml`） | 固件**接住并把原因当输出回给你**（含引脚解释与 `link can` 的正确做法） | **0** |
| `c`（校准向导） | 被闸门拒，正文是原因 | **1** |
| 急停中 | 只放行 `s` / `h` | 1（被拒的那些） |
| 命令 > 58 字符 | **客户端就该拒** —— 固件会钳断，而**半条命令往往是另一条命令**（`"zr save"` 被切成 `"zr"` 就是"只本次有效"变成"没执行"） | — |
| 输出 > 2048 B | 截断并置 bit0（`h` 帮助表 5406 B 就是这种） | 0 |

⚠ **PC 侧必须能区分"被策略拒"（`gated = 1`）与"这条命令在当前链路物理上
不可用"（`gated = 0` 且正文是引脚解释）** —— 这两件事的处置完全不同：
前者要人接串口，后者要改硬件方案。

### 15.6 手写最小示例（纯标准库）

```python
import socket, struct

def crc16(b):
    c = 0xFFFF
    for x in b:
        c ^= x << 8
        for _ in range(8):
            c = ((c << 1) ^ 0x1021) & 0xFFFF if c & 0x8000 else (c << 1) & 0xFFFF
    return c

def pack(seq, cmd, payload=b""):
    body = bytes([seq, cmd, len(payload)]) + payload
    return body + struct.pack("<H", crc16(body))          # UDP 不带 AA55

s = socket.socket(socket.AF_INET, socket.SOCK_DGRAM); s.settimeout(0.3)
ARM = ("192.168.7.120", 5000)
MAGIC = struct.pack("<I", 0x5A5A5A5A)

# TEXT_EXEC "s"（读六轴角度）
s.sendto(pack(0x31, 0x0B, MAGIC + b"s\x00"), ARM)
rsp = s.recvfrom(256)[0]
pl = rsp[3:-2]                                            # 去掉 SEQ/CMD/LEN 与 CRC
total, flags, off, n = struct.unpack_from("<HBHB", pl, 0)
print("total=%d flags=0x%02X off=%d n=%d" % (total, flags, off, n))
print(pl[6:6 + n].decode("utf-8", "replace"))

# 翻页（0x0C）
s.sendto(pack(0x32, 0x0C, struct.pack("<HB", 58, 58)), ARM)
```

或者直接用 SDK：

```bash
armctl --uri net://192.168.7.120:5000 text --cmd s --cmd zi --cmd "link net"
armctl-js --uri net://192.168.7.120:5000 diag --detail
```

### 15.7 一条命令的推荐替代写法

`TEXT_EXEC` 能做的事很多 —— 但**会改硬件基准 / 会松力矩 / 会改 Flash** 的，
请走**带 `danger` 后缀的类型化方法**，别随手拼字符串：

| 别这样 | 这样 |
|---|---|
| `text_exec("M a")` | `center_calib_danger()` —— MAGIC 自动填，方法名可见 |
| `text_exec("zr save")` | `zero_reset_danger(save=True)` |
| `text_exec("F")` | `param_save()` |
| `text_exec("i")` / `text_exec("Y")` | 暂未封装 —— 用前先确认副作用 |

命名约定：**会改硬件基准 / 会松力矩 / 会改 Flash 的，方法名带 `_danger` /
`Danger` 后缀** —— 让调用点在 code review 时一眼可见。

## 16. 上板前的自检顺序（2026-09-23 版）

```
1. TEXT_EXEC "h"            固件 tag / 构建 / 运行链路 —— ⭐ 唯一可信的判版本方式
                            （GET_INFO 0x07 的 fw-tag 硬编码，见 §17.1，别用它）
2. TEXT_EXEC "zi"           Home 零点是否被污染（zero_raw 全 0 = 未校准）
3. GET_FLAGS(0x0A)          estop=0 / traj=0 ⇒ 可以动
4. TEXT_EXEC "s"            先读，再动
5. GET_JOINT_DETAIL(0x04)   任一轴 ok=0 ⇒ 总线有问题，别急着动
6. IK_QUERY(0x22)           想去的点在不在包线内（只算不解）
7. MOVE_JOINTS / TELEOP     才开始动
```

⚠ **`TEXT_EXEC` 敲不动 11 条抢引脚命令是正常的**（输出里会写原因），
不要以为网口坏了。

⚠⚠ **上板前必须先回中位** `m 180 180 180 180 180 180 15`，
**绝不能用 `M a`**（那是标定，会废掉量纲基准）。
烧录/复位必丢力矩、臂会下沉（实测两次同值 J2≈76.4 / J3≈270.9 ⇒ 距限位仅 1.3°/0.1°）。

## 17. 2026-09-29 增补 —— 09-24 以来协议面的变化（重点：TEXT_EXEC 可达的新命令）

> 线格式（§2）、应答规则（§3）、38 条 opcode（§4/§14）、TEXT_EXEC 分页（§15）
> **全部未变**。本节只登记三件事：判版本缺陷、新增控制台命令、危险文本命令完整表。

### 17.1 🔴 `GET_INFO(0x07)` 的 `fw_tag` 硬编码 —— 判版本唯一可信方式是 `TEXT_EXEC "h"`

- `arm_control_api.c` 的 `GetInfo()` 里 fw-tag 是**硬编码字符串**，历次发版未同步
  ⇒ 响应恒为 `ARM-NET-0921A`（2026-09-24 定位，0924AU 仍未修）。
- 后果：上位机拿 `GET_INFO` 判版本会**永远认为板上还是 0921A**。
- 正确做法：`TEXT_EXEC "h"` 读响应首行 `fw-tag ARM-NET-xxxxx`；注意 `h` 全文
  **5406 B > 2048 B 捕获上限** ⇒ 会被截断置 flags.bit0 —— **首行在第一页内，
  判版本只取首页即可**，不必翻完全部页。
- 待修：`GetInfo` 改引用横幅同源 tag 宏（与 main.c 两处横幅、preflight FW_TAGS 一起做）。

### 17.3 ⚠ "看着像 info 的也未必安全" —— TEXT_EXEC 危险文本命令完整表

`TEXT_EXEC` 等于把整台控制台交给你。以下命令**看着无害、实有副作用**，
上位机严禁放进轮询/自动化路径（与 §15.7 的 `_danger` 命名约定同源）：

| 文本 | 真实行为 | 风险 |
|---|---|---|
| `i` | `cmdInit()` = **SERVO_InitAll()** | **力矩 ON 抱闸 + 重设 joint mode** —— 0924L 实测误发过一次，万幸臂无恙 |
| `t J 0` | 单轴松力矩 | 臂下坠（承重轴会掉） |
| `zr` / `zr save` | Home 零点复位 | 废掉量纲基准（协议有类型化 `ZERO_RESET`，带 magic） |
| `M a` | **中心标定**（名字像"一键中位"！） | 把当前姿态写成新零点，`SERVO_OFFSET` 全废。回中位用 `m 180×6 15` |
| `c` | 相位校准向导 | TEXT_EXEC 闸门会拒（§15.4）——但**串口敲单字符 `c` 同样危险** |
| `cx` 等 11 条 | 抢 ETH 引脚 | 网口构建下固件接住并回原因（§15.5）；CAN/串口下**真执行** |

判别纪律（红线 10）：**任何看起来只读的命令，用前先 grep 函数体确认副作用**。
只读白名单：`h` `s` `L` `nx` `pv` `zi` `f` `colj2`（无参）`rc`（无参）`rc diag`。

### 17.4 客户端翻页陷阱（0924L 真机踩坑）

`nx` 全文 1050~1311 B ≈ **23 页**。SDK 里两个 API 只差一个字：
- `text_exec()` = 发 0x0B + **自动翻页**收全量 ✔
- `text_out()`  = **只取第一页**（58 B），不报错、静默丢数据 ✗

用错的表现：正则永远匹配不到字段（`udp cmd=` 在第 20 页附近），功能"看起来没实现"。
**上位机一律用 `text_exec()` 语义**（或按 §15.3 自己按字节拼页）。

### 17.5 `GET_STATUS` 丢读率现状（RC 现场实测，读方须知）

承重轴（J1/J2/J3）单拍至少一轴丢读 **25.5%**（`read_ok=False` 标志正确，
`-32768` 哨兵正确 —— 协议行为无误，是舵机总线层偶发丢响应，未修）。
上位机判读纪律：**任一轴 None ⇒ 丢弃该拍，不要拿 0/-32768 当真值**；
轮询间隔建议 ≥100ms（给运动控制留总线）；重试一次通常即恢复。
